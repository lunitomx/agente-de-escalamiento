# S82.1 — Spike: conectores de Drive

## Método

Se armó una copia **mínima y sin datos reales** de la plantilla del tracker, con las pestañas `START HERE` y una de participante con fórmula a `START HERE`. Se subió como `.xlsx` al Drive del dueño con el conector Google Drive de Claude (claude.ai) y luego se mandó a la papelera. El tracker real no se tocó.

## Hallazgos verificados (conector Google Drive de Claude, 2026-09-30)

| Operación | Resultado |
|---|---|
| Subir `.xlsx` | ✅ Se convierte a Google Sheet por defecto (puede desactivarse) |
| Leer | ✅ Entrega cada pestaña como tabla, con rangos, y **resuelve las fórmulas** (Participant Name → valor de `START HERE`) |
| Buscar el archivo por título o texto | ✅ `search_files` |
| Editar celdas / contenido de un archivo existente | ❌ **No existe.** `update_file` sólo cambia título o carpeta |
| Papelera | ✅ |

## Implicación

Con este conector, ESCALA **puede** identificar al participante, encontrar su hoja y leerla completa. **No puede escribir** en el tracker compartido. Crear un archivo nuevo tampoco sirve: rompería el archivo único del grupo.

## No verificado

- El conector de Drive de ChatGPT y si escribe en Sheets.
- Codex: acepta servidores MCP configurados por el usuario, pero no se probó ninguno de Google Sheets.
- Servidores MCP específicos de Google Sheets con escritura por celda: existen como opción, pero no se evaluaron (seguridad, instalación para no técnicos).

## Recomendación

1. **MVP (S82.2–S82.4):** leer la hoja propia → proponer filas → el usuario las pega. Funciona hoy en Claude sin instalar nada.
2. **S82.6 (nuevo spike):** evaluar un MCP de Google Sheets con escritura y el conector de ChatGPT; adoptarlo sólo si la instalación es viable para un empresario y el permiso se limita al archivo.
