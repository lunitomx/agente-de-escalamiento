# Design: S18.3 — Power of One Interactive (PILOT)

## Problem
El dashboard Power of One existente (E14) es estático — los valores se ingresan manualmente, no persisten entre sesiones, y no hay conexión con el servidor. No se pueden hacer what-if scenarios rápidos con sliders.

## Value
Primer dashboard interactivo con sliders en tiempo real, persistencia vía API y un patrón JS reutilizable que los otros 21 dashboards (S18.4+) pueden heredar. Valida el patrón completo: UI ↔ API ↔ persistencia.

## Approach

1. **Copiar** el HTML existente de Power of One a `escala_server/static/dashboards/cash/power-of-one.html`
2. **Añadir** sliders (range inputs) para cada una de las 7 variables
3. **Simplificar** el modelo: el slider controla el valor "adjusted". El "current" se mantiene como baseline del escenario guardado
4. **Conectar** a la API del server: GET al cargar, POST al guardar
5. **Indicador** de estado: "modificado" / "guardado"
6. **Extraer** el JS de interacción a un módulo `escala_server/static/shared/js/dashboard-interactive.js` que S18.4+ pueda reutilizar

### Components Affected

| Component | Change | Purpose |
|-----------|--------|---------|
| `escala_server/static/dashboards/cash/power-of-one.html` | Create | Copy interactiva del dashboard original |
| `escala_server/static/shared/js/dashboard-interactive.js` | Create | Módulo JS reutilizable: slider, save, load, modified indicator |
| `escala_server/static/shared/js/power-of-one-engine.js` | Create | Motor de cálculo específico para Power of One (extraído del HTML original) |

### Design Decisions

| ID | Decision | Rationale |
|----|----------|-----------|
| DD1 | Copia del HTML, no modificación in-place | Preserva el dashboard original de E14 intacto |
| DD2 | Sliders con range input nativo | Sin dependencias JS externas. Compatible con todos los browsers modernos |
| DD3 | Save on demand (botón), no autosave | El usuario controla cuándo persiste. Evita escrituras innecesarias |
| DD4 | Módulo JS reutilizable para S18.4+ | El patrón slider → API → persistencia es idéntico para los demás dashboards |
| DD5 | fetch API nativa para comunicación con el server | Sin dependencias (axios, jQuery). El server está en localhost |

## Examples

### Slider interaction
```javascript
// Al mover slider de precio de 3 a 5:
// 1. price.adjusted = 5
// 2. Recalcula impacto: (5 - 3) × volume
// 3. Actualiza display del impacto y semáforo
// 4. Marca "modificado"
```

### Save flow
```javascript
// Click "Guardar":
// 1. POST /api/worksheets/cash/power-of-one con {variables, timestamp}
// 2. Server responde {"status": "ok", "data": {...}}
// 3. Indicador cambia a "guardado"
```

### Load flow
```javascript
// Al cargar página:
// 1. GET /api/worksheets/cash/power-of-one
// 2. Si hay datos guardados, posiciona sliders y current values
// 3. Calcula impacto inicial
// 4. Indicador muestra "guardado"
```

## Acceptance Criteria

### MUST
- [ ] 7 sliders (range input) para price, volume, cogs, overheads, ar_days, inv_days, ap_days
- [ ] Mover slider recalcula CF Impact y EBIT Impact en tiempo real
- [ ] Indicador visual "modificado" cuando hay cambios sin guardar
- [ ] Botón "Guardar" → POST a la API → indicador "guardado"
- [ ] Al cargar, GET a la API restaura valores guardados
- [ ] El patrón es reutilizable: el JS de interacción está en un módulo separado

### SHOULD
- [ ] Transiciones suaves en los sliders (CSS)
- [ ] Tooltip con valor actual del slider
- [ ] Rango mínimo/máximo contextual por variable

### MUST NOT
- [ ] Dependencias JS externas (todo fetch + DOM nativo)
- [ ] Modificar el HTML original de E14
