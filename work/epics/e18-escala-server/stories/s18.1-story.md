# Story: Server Core (HTTP + routing + static + CLI)

## User Story
As a coach using Escala,
I want a local server that serves dashboards and provides API endpoints,
so that my dashboards can read and write data in real time.

## Acceptance Criteria

### Scenario: Server starts and serves HTML
```gherkin
Given the Escala server is not running
When I run `escala-server start`
Then the server starts on localhost:8080
And I can open http://localhost:8080 in a browser
And static HTML files are served correctly
```

### Scenario: API endpoints respond
```gherkin
Given the server is running
When I GET /api/companies
Then I receive a JSON response with company data
And the response has status 200
```

### Scenario: Server stops gracefully
```gherkin
Given the server is running
When I run `escala-server stop`
Then the server process terminates
And port 8080 is freed
```

### Scenario: CORS allows local dev
```gherkin
Given the server is running
When I send an OPTIONS request from localhost:3000
Then the response includes Access-Control-Allow-Origin: *
```

## Examples (Specification by Example)

| Input | Action | Expected Output |
|-------|--------|-----------------|
| `escala-server start` | Terminal command | "Server running on http://localhost:8080" |
| `escala-server status` | Terminal command | "Running" or "Stopped" with PID |
| `escala-server stop` | Terminal command | "Server stopped" |
| GET /api/companies | HTTP request | `{"companies": []}` |
| GET /api/worksheets/cash/power-of-one | HTTP request | `{"data": {}}` |

## Notes

- Uses Python http.server (no Flask/FastAPI — DD2)
- DAO layer separated from HTTP handler (DD3)
- CORS enabled for local development only
- Endpoints: /api/companies, /api/worksheets, /api/sessions
- Static serving: all existing HTML dashboards from E14-E17
- CLI implemented with argparse or simple sys.argv
