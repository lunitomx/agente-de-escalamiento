# Alcance S22.7 — Validación E2E, privacidad y release

## In scope

- Ejecutar una matriz reproducible de instalación limpia para Claude Code y
  Codex: bundle instalado, conversación natural, pausa/captura, confirmación,
  nueva sesión y recuperación desde una raíz de empresa aislada.
- Verificar el bundle Hermes con el mismo smoke determinista del runtime y
  declarar una limitación de release concreta si no se puede demostrar el
  descubrimiento y la conversación mediante el cliente Hermes real.
- Probar que los datos de empresa, incluida la base de memoria y sus backups,
  sólo viven bajo la raíz explícita del proyecto y no se copian al runtime ni a
  un estado global durante instalación, actualización o desinstalación.
- Probar backup/restore offline sobre memoria confirmada, y rollback/uninstall
  conservando datos empresariales salvo `--purge` explícito y acotado.
- Actualizar la documentación de instalación, privacidad, límite Hermes y
  evidencia de release para que no prometa una cobertura no demostrada.
- Ejecutar la suite de regresión y los gates definidos en el manifiesto.

## Out of scope

- Cambiar el contrato SQLite, la migración, consentimiento, router, contenido
  de coaching o esquema de memoria salvo una corrección mínima que haga fallar
  una prueba de release de este alcance.
- Añadir cloud, sincronización, telemetría, plugins, embeddings, modelos o una
  base de datos global.
- Declarar que Hermes tiene paridad conversacional real sin evidencia de su
  cliente; el smoke de archivos y runtime no sustituye ese hecho.
- Borrar datos de proyectos ajenos ni automatizar la búsqueda de directorios
  empresariales fuera del destino instalado.

## Done when

- Claude Code y Codex pasan desde destinos temporales limpios el recorrido
  instalar → frase natural → pausar → declaración explícita → `sí` → nueva
  sesión → recuperar la declaración, sin rutas, SQLite, DB, skills, comandos
  ni estado técnico en la respuesta pública.
- La matriz comprueba conteos y digest de la DB: una respuesta distinta de
  `sí` inequívoco no confirma una entrada; una base ausente, vacía o corrupta
  conserva el flujo público y no crea estado accidental.
- Hermes ejecuta el mismo bundle/runtime y recorrido por el front door; si el
  binario del cliente no está disponible o no puede invocarse de forma aislada,
  docs registran exactamente esa limitación y el criterio de evidencia futura.
- Backup/restore conserva una entrada confirmada; restore inválido no reemplaza
  una DB sana; update/uninstall normal preserva `my-company` y memoria, y
  `--purge` sólo elimina el runtime del target solicitado.
- README y demo readiness reflejan solamente lo acreditado, y todos los gates
  de test/lint/formato configurados pasan.
