# Plan S22.4 — Inicio y recuperación contextual

**Story:** S22.4
**Tamaño:** M (6 puntos)
**Fecha:** 2026-08-26
**Estado de entrada:** diseño aprobado; S22.2 y S22.3 integradas en `main`.

## Objetivo de implementación

Entregar `ProjectMemorySessionContext(project_root)` como bridge local de sólo lectura para la memoria SQLite saludable de un proyecto. `load()` devolverá como máximo cinco elementos confirmados y verificables para que S22.6 los consuma sin cambiar el front door, router ni UX.

El bridge no crea, migra, repara ni respalda la DB. No lee YAML/Markdown, `conversation.yaml`, conocimiento, home, red ni el legado `SessionStartOrchestrator`. Runtime no sano devuelve fallback estructurado; memoria sana sin datos devuelve resultado listo y vacío.

`coaching/**`, `.scaleup/install.sh`, front door, skills públicos, fixtures S22.3

fact para que el bridge no publique datos no verificables. El upgrade v3→v4 es
atómico y no añade fuentes, API pública ni una nueva capacidad de migración.

| End of story | `rai gate check gate-tests --scope packages/<pkg>/` | Changed package only — NOT full suite |
| MR creation | `/rai-mr-create` | Full suite — the ONLY place where unscoped tests run |

El scope concreto de fin es `tests/test_project_memory_context.py`; se ejecutan además las regresiones directas `tests/test_project_memory_migration.py` y `tests/test_project_memory_runtime.py`. No se ejecuta una suite sin scope.

## Orden y dependencias

`Contrato read-only → facts con ledger → worksheets/ranking → degradación/aislamiento → integración local`.

El orden es riesgo-primero: la frontera de I/O antes de recuperar datos, autoridad de proveniencia antes de relevancia, y casos de degradación antes del smoke. No hay paralelismo seguro: tareas 2–4 comparten bridge y suite. La cadena es acíclica y cada tarea termina en commit reversible.

## Riesgos, mitigaciones y rollback

| Riesgo | Mitigación | Rollback |
|---|---|---|
| Fact libre se presenta confirmado | Ledger obligatorio y allowlist; fixture adverso | Revertir bridge; DB/fuentes intactas. |
| Worksheet filtra payload | Proyección de metadatos y prueba de secreto | Revertir tarea 3; SQLite intacta. |
| Orden no reproducible | Prioridad constante, fecha/key probados | Revertir ranking; sin estado persistido. |
| DB dañada bloquea/repara lectura | Sólo `health()` y URI read-only; corrupción/digest | S22.6 aún conserva flujo actual. |
| Conversación/YAML se usa como fallback | Sin lector filesystem; fixture señuelo | Retirar módulo; front door intacto. |
