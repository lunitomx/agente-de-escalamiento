# Diseño S22.2 — Runtime SQLite local por proyecto

**Complejidad:** Compleja (runtime, almacenamiento y distribución en tres
clientes).  No afecta UX pública ni inicia HTTP; por ello no requiere
investigación UX previa.

## Problema y valor

El código de E18 contiene una base SQLite, DAOs y motores de memoria/grafo,
pero sus rutas por defecto apuntan a `~/.escala` y `install.sh` no copia el
runtime. El resultado es que una empresa instalada no puede usar esa memoria y
dos proyectos podrían compartir datos accidentalmente.

Esta historia entrega un camino local y recuperable: cada proyecto controla
`.scaleup/memory/escala.db`, puede verificarla y restaurar una copia. Eso prueba
la base de seguridad y continuidad antes de migrar información o inyectarla en
la conversación.

## Gemba y decisiones

| Hallazgo | Decisión |
|---|---|
| `BaseDAO`, `MemoryEngine`, `GraphEngine` aceptan `db_path` e inicializan el esquema existente. | Reutilizarlos; no crear otro ORM, esquema ni proceso. |
| `cli.py`, `scaling_context.py`, migrador y cierre usan `~/.escala`. | El nuevo runtime nunca los invoca; su compatibilidad queda explícita, no es la ruta pública. |
| El instalador copia `coaching` pero no `escala_server`. | Copiar un subconjunto autocontenido del paquete: `__init__`, `schema`, `daos`, motores y runtime local. |
| El instalador sincroniza código gestionado y preserva `my-company`. | Tratar `memory/` como dato empresarial: no se borra en update o uninstall sin `--purge`. |

**Legacy sweep:** `escala_server.cli` y sus defaults globales (V1) coexisten
para los dashboards y uso manual existentes. S22.2 no los llama ni los elimina;
S22.7 verificará que el flujo público no tenga referencias a ellos. No hay V1
huérfano para el nuevo bridge: es net-new en la superficie pública.

**Drift:** no existe `governance/drift-hotspots.json`. AG2 queda mitigado al
reusar `init_db`/DAOs; AG4 afecta cuatro módulos (runtime, schema/DAOs,
instalador, tests), pero el contrato `ProjectMemoryRuntime` delimita el acople.

## Enfoque

Crear `escala_server/project_memory.py` con `ProjectMemoryRuntime(project_root)`
y un resultado pequeño y explícito (`ready`, `db_path`, `reason`). La clase:

1. normaliza una raíz de proyecto y rechaza una ruta cuyo `db_path` salga de
   `<project>/.scaleup/memory/escala.db`;
2. crea la carpeta y llama al esquema existente; `health()` comprueba tablas,
   `PRAGMA integrity_check` y versión de esquema;
3. usa la API SQLite de backup para escribir una copia dentro de
   `.scaleup/memory/backups/` y restaurarla de forma atómica desde una copia
   validada;
4. convierte `OSError`/`sqlite3.Error` en resultado no listo con razón legible,
   sin elevar al front door, iniciar HTTP ni consultar una ruta global.

`install.sh` incorporará `copy_memory_runtime`, que sincroniza únicamente esos
archivos importables y elimina el runtime gestionado obsoleto en una actualización.
El uninstall normal preserva `.scaleup/memory` porque es dato de empresa; el
purge existente puede borrarlo junto con todo el runtime.

No hay dependencia nueva (sólo `sqlite3` de la biblioteca estándar). KISS/DRY:
la nueva clase concentra resolución, health y backup, en vez de duplicar rutas
en router, CLI y sesiones. YAGNI: no migra YAML, no crea sesiones ni guarda
facts en esta historia.

### Contrato de almacenamiento

Antes, los consumidores del runtime público no recibían una base SQLite ni
podían fallar por ella. Después, sólo consumidores internos de E22 usarán
`ProjectMemoryRuntime`: ausencia, corrupción o permiso denegado se expresan con
`ready=False`; los flujos actuales de YAML mantienen su resultado normal.
Una restauración con backup ausente o inválido devuelve un resultado no listo y
deja la base actual intacta. No hay cambio de contrato para `BaseDAO` ni CLI.

## Componentes

| Componente | Cambio | Propósito |
|---|---|---|
| `escala_server/project_memory.py` | Crear | Runtime local, health, backup y restore. |
| `escala_server/__init__.py` | Modificar | Exponer el runtime sin importar servidor HTTP. |
| `.scaleup/install.sh` | Modificar | Distribuir el subconjunto de memoria y preservarlo en upgrades. |
| `tests/test_project_memory_runtime.py` | Crear | Aislamiento de rutas, health, backup/restore y degradación. |
| `tests/test_scaleup_installer.py` | Modificar | Smoke de runtime copiado para Claude, Codex y Hermes. |

## Ejemplos ejecutables

```python
from escala_server.project_memory import ProjectMemoryRuntime

runtime = ProjectMemoryRuntime('/tmp/lumen-casa')
result = runtime.ensure_memory()
assert result.ready is True
assert result.db_path == '/tmp/lumen-casa/.scaleup/memory/escala.db'
assert runtime.health().ready is True
backup = runtime.backup()
assert backup.ready is True
```

```python
blocked = ProjectMemoryRuntime('/proc/scaleup-no-write').ensure_memory()
assert blocked.ready is False
assert blocked.reason
```

```python
# El instalador copia librería, no servidor ni datos empresariales.
# <runtime>/escala_server/project_memory.py existe tras --target all.
# <runtime>/my-company y <project>/.scaleup/memory no se eliminan en update.
```
