# Plan S22.2 — Runtime SQLite local por proyecto

**Tamaño:** L · **Fecha:** 2026-08-26 · **Estado:** listo para implementación

## Orden de ejecución

La ruta es estrictamente secuencial hasta el runtime estable. Primero se prueba
el contrato de aislamiento (riesgo de mezclar empresas), luego health y backup;
sólo entonces se distribuye el paquete. No hay paralelismo seguro: el instalador
debe copiar una API que ya demostró funcionar localmente.

| # | Tarea | Tamaño | Depende de | AC |
|---|---|:---:|---|---|
| 1 | Escribir pruebas RED para resolución y aislamiento de proyecto | S | — | Crear memoria local |
| 2 | Implementar runtime, health y degradación segura | M | 1 | Crear memoria; fallo seguro |
| 3 | Añadir backup/restore atómico y sus casos RED/GREEN | M | 2 | Validar y recuperar copia |
| 4 | Distribuir runtime mínimo y probar los tres destinos | M | 2–3 | Instalación limpia |
| 5 | Smoke manual integrado y gates de historia | S | 1–4 | Todos |

## Tareas ejecutables

### T1 — Contrato RED de aislamiento

- **Archivos:** crear `tests/test_project_memory_runtime.py`.
- **RED:** casos que instancian una raíz temporal, exigen exactamente
  `.scaleup/memory/escala.db`, esquema E18, y que el resultado no contenga una
  ruta bajo `Path.home()`.
- **GREEN:** no se implementa producción aún; confirmar la falla por módulo
  inexistente/contrato ausente.
- **REFACTOR:** helpers de tempdir y comprobación de tablas, sin fixtures
  globales.
- **Verificación:** `rai gate check gate-tests --scope tests/test_project_memory_runtime.py`,
  `rai gate check gate-lint`, `rai gate check gate-format`, `rai gate check gate-types`.

### T2 — Runtime, health y fallback

- **Archivos:** crear `escala_server/project_memory.py`; modificar
  `escala_server/__init__.py`; ampliar `tests/test_project_memory_runtime.py`.
- **RED:** health de una base corrupta y ruta sin permiso dan `ready=False` con
  razón; import no carga servidor/CLI.
- **GREEN:** `ProjectMemoryRuntime` valida contención, inicializa `init_db`,
  comprueba integridad y convierte errores SQLite/E/S en resultado explícito.
- **REFACTOR:** una única estructura de resultado y cierre de conexiones locales
  donde sea necesario.
- **Verificación:** `rai gate check gate-tests --scope tests/test_project_memory_runtime.py`,
  `rai gate check gate-lint`, `rai gate check gate-format`, `rai gate check gate-types`.

### T3 — Backup y restore seguros

- **Archivos:** modificar `escala_server/project_memory.py` y
  `tests/test_project_memory_runtime.py`.
- **RED:** crear compañía, respaldar, alterar/eliminar DB, restaurar y exigir
  misma compañía; backup ausente/corrupto deja DB actual intacta.
- **GREEN:** SQLite backup API a `memory/backups/`, validación de candidato y
  reemplazo atómico sólo tras health correcto.
- **REFACTOR:** nombres de backup deterministas para pruebas y sanitización de
  path.
- **Verificación:** `rai gate check gate-tests --scope tests/test_project_memory_runtime.py`,
  `rai gate check gate-lint`, `rai gate check gate-format`, `rai gate check gate-types`.

### T4 — Instalador de runtime mínimo

- **Archivos:** modificar `.scaleup/install.sh`,
  `tests/test_scaleup_installer.py`.
- **RED:** instalación `--target all` exige runtime importable en Claude,
  Codex/Hermes, sin `server.py`, CLI ni DB compartida; upgrade/uninstall normal
  conserva un archivo dentro de `memory/`.
- **GREEN:** `copy_memory_runtime` sincroniza sólo el subconjunto importable y
  `uninstall_runtime` preserva datos empresariales.
- **REFACTOR:** evitar listas duplicadas de archivos en destinos.
- **Verificación:** `rai gate check gate-tests --scope tests/test_scaleup_installer.py`,
  `rai gate check gate-lint`, `rai gate check gate-format`, `rai gate check gate-types`.

### T5 — Integración real de historia

- **Archivos:** sólo pruebas/ajustes mínimos que revelen el smoke.
- **Manual E2E:** instalar a un directorio temporal, importar el runtime copiado,
  asegurar DB bajo un proyecto temporal, crear una compañía, backup/restore y
  verificar `health()` sin iniciar HTTP.
- **Verificación:** `rai gate check gate-tests --scope tests/test_project_memory_runtime.py`,
  `rai gate check gate-tests --scope tests/test_scaleup_installer.py`,
  `rai gate check gate-lint`, `rai gate check gate-format`, `rai gate check gate-types`.

## Gate Policy

| When | Command | Scope |
|------|---------|-------|
| Per task | `rai gate check gate-tests --scope <test_dir>/` | Only tests for the changed module (e.g. `packages/raise-cli/tests/storage/`) |
| Per task | `rai gate check gate-lint` | Full project (fast) |
| Per task | `rai gate check gate-format` | Full project (fast) |
| Per task | `rai gate check gate-types` | Full project |
| End of story | `rai gate check gate-tests --scope packages/<pkg>/` | Changed package only — NOT full suite |
| MR creation | `/rai-mr-create` | Full suite — the ONLY place where unscoped tests run |

Para esta historia, cada referencia abstracta anterior se concreta en
`tests/test_project_memory_runtime.py` o `tests/test_scaleup_installer.py`.
