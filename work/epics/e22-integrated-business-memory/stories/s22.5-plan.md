# Plan S22.5 — Cierre, hechos y patrones confirmados

**Story:** S22.5  
**Tamaño:** M (7 puntos)  
**Fecha:** 2026-08-26  
**Estado de entrada:** diseño aprobado; S22.2, S22.3 y S22.4 integradas en `main`.

## Objetivo de implementación

Entregar `ProjectMemorySessionClose(project_root)` como frontera local para abrir
una sesión, registrar propuestas estructuradas, recibir confirmación explícita y
cerrar esa sesión. La historia agrega schema v6 y tres tablas aisladas; no
convierte inferencias, transcripciones ni respuestas ambiguas en memoria y no
modifica la proyección read-only de S22.4.

Sólo una respuesta completa `sí`, `si` o `yes` normalizada crea una entrada con
confianza fija `1.0` y razón `explicit_confirmation`. `no` rechaza de forma
auditable; cualquier otra respuesta no escribe y mantiene la propuesta pendiente.

### 3. Confirmar, rechazar y resolver conflictos transaccionalmente

| Per task | `rai gate check gate-lint` | Full project (fast) |

| End of story | `rai gate check gate-tests --scope packages/<pkg>/` | Changed package only — NOT full suite |
| MR creation | `/rai-mr-create` | Full suite — the ONLY place where unscoped tests run |

El scope concreto de fin es `tests/test_project_memory_session_close.py`; se
ejecutan además `tests/test_project_memory_context.py` y
`tests/test_project_memory_runtime.py`. No se ejecuta una suite sin scope.

## Orden y dependencias

`schema/health + contrato → validación/propuesta → confirmación/conflicto →
cierre/privacidad/compatibilidad → integración local`.

Riesgo primero: consentimiento/evolución antes de persistir; transacción antes
de cerrar; compatibilidad/aislamiento antes del smoke. Tareas 2–4 comparten
bridge y DB, por lo que son secuenciales. No hay ciclo ni paralelismo seguro.

## Riesgos, mitigaciones y rollback

| Riesgo | Mitigación | Rollback |
|---|---|---|
| Inferencia registrada como verdad | `origin` cerrado, observations mínimas y falsificación | Revertir bridge; no hay fuente externa ni fact migrado. |
| Confirmación parcial duplica/corrompe | Unique proposal ID y transacción con fallo inyectado | Revertir tarea 3; propuestas previas siguen separadas. |
| Conflicto borra historia | Reemplazo explícito y `superseded`, nunca update destructivo | Revertir transición; filas auditables permanecen. |
| V6 rompe S22.4 | Upgrade v4 real, DDL/health y comparación exacta | Revertir DDL/bridge; DB v4 no se reinterpreta. |
| Se filtra secreto o estado entre proyectos | Política de sensibilidad, dos raíces y señuelos | Retirar bridge; no hay home/YAML/red escritos. |
