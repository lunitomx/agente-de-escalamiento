# S22.4 — Inicio y recuperación contextual

## User story

Como empresario que vuelve a ScaleUp, quiero que una sesión nueva recupere un
resumen breve de información empresarial confirmada y verificable que ya está
en la base local de mi proyecto, para retomar el trabajo sin repetir contexto
ni depender del historial libre de chat.

## Scenarios

```gherkin
Feature: Recuperación local al inicio de sesión

  Scenario: recuperar contexto confirmado y relevante
    Given un proyecto con una base SQLite saludable ya migrada
    And facts de perfil, diagnóstico y foco con fuente verificable
    When el bridge abre el contexto de sesión para esa raíz explícita
    Then devuelve como máximo cinco entradas breves y seguras
    And cada entrada contiene su clave, valor, fuente de migración y fecha
    And prioriza el foco actual, después el diagnóstico y después el perfil
    And no abre, lee ni copia conversation.yaml

  Scenario: memoria vacía pero sana
    Given una base local saludable sin facts confirmados
    When se solicita el contexto inicial
    Then devuelve ready true y un resumen vacío
    And el consumidor puede continuar con el flujo actual sin una pregunta ni texto extra

  Scenario: base ausente, corrupta o fuera de la raíz
    Given una raíz cuyo runtime no puede validar la base local
    When se solicita el contexto inicial
    Then devuelve ready false y un fallback estructurado sin facts
    And no crea datos, no lee YAML como sustituto y no expone rutas, SQLite, comandos ni el error técnico a la persona
```

## Examples

El contrato futuro recibe siempre una raíz explícita y devuelve datos para un
adaptador, no texto de conversación ni un comando nuevo:

```python
context = ProjectMemorySessionContext(project_root).load()

assert context.ready is True
assert context.items[0].key == "profile.focus.current_decision"
assert context.items[0].source == ".scaleup/agent/memory/company-profile.yaml"
assert context.items[0].confirmed is True
assert len(context.items) <= 5
```

Un consumidor que no puede abrir la memoria conserva exactamente su flujo:

```python
context = ProjectMemorySessionContext(project_root_with_bad_db).load()

assert context.ready is False
assert context.items == ()
assert context.user_message is None
assert context.reason is not None  # sólo para logs/test internos; nunca se muestra
```
