# S22.2 — Runtime, instalación y ciclo SQLite local

## User story

Como operador de una empresa que usa ScaleUp, quiero que la memoria empresarial
se cree y opere dentro de mi proyecto, para que la información no se mezcle con
otras empresas ni dependa de un servicio externo.

## Contexto

E18 ya contiene SQLite, DAOs y motores de memoria/grafo, pero el runtime actual
usa por defecto `~/.escala` y el instalador público no lo distribuye. Esta
historia construye el camino mínimo y verificable hacia una base por proyecto;
no migra ni expone aún esa memoria a la conversación.

## Acceptance criteria (Gherkin)

```gherkin
Scenario: Crear memoria en un proyecto nuevo
  Given un directorio de proyecto vacío
  When ScaleUp asegura su memoria local
  Then existe `.scaleup/memory/escala.db` dentro del proyecto
  And no se crea ni consulta una base empresarial en el directorio personal

Scenario: Validar y recuperar una copia
  Given una memoria local válida con una empresa
  When se crea una copia y se restaura en una memoria dañada o ausente
  Then la base restaurada pasa su health check
  And conserva la empresa original

Scenario: Fallo seguro
  Given una ruta de memoria que no se puede abrir
  When el runtime intenta asegurarla
  Then devuelve un resultado de degradación explícito
  And no levanta un servidor HTTP ni bloquea al coach
```

## Ejemplos por especificación

| Entrada | Resultado observable |
|---|---|
| `MemoryBridge('/tmp/acme').ensure_memory()` | `ready=True`, base `/tmp/acme/.scaleup/memory/escala.db` válida. |
| `bridge.backup()` seguido de `bridge.restore()` | Copia local restaurada y mismo conteo de compañías. |
| Directorio de DB no escribible | `ready=False`, razón diagnóstica; no excepción hacia el front door. |
