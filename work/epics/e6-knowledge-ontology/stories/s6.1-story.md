# S6.1 — Ontology Schema Design

## User Story

**As a** agente ScaleUp que necesita responder con precisión metodológica,
**I want** un schema de ontología que defina tipos de nodo, relaciones, y formato de almacenamiento,
**So that** el conocimiento de Scaling Up esté estructurado para retrieval determinístico.

## Acceptance Criteria

```gherkin
Feature: Schema de ontología para el dominio Scaling Up

  Scenario: Tipos de nodo definidos
    Given el schema de ontología
    When se listan los tipos de nodo
    Then existen: concept, tool, worksheet, stage, decision, metric
    And cada tipo tiene campos requeridos y opcionales documentados

  Scenario: Tipos de relación definidos
    Given el schema de ontología
    When se listan las relaciones
    Then existen: belongs-to, requires, feeds-into, measured-by, prerequisite-of
    And cada relación tiene source_type y target_type definidos

  Scenario: Formato de almacenamiento
    Given un nodo de la ontología
    When se serializa
    Then usa formato YAML legible por humanos
    And se almacena en .scaleup/knowledge/ organizado por decisión

  Scenario: Schema valida nodos existentes
    Given el contenido de LlamaParse parseado
    When se mapean las metodologías al schema
    Then las 68 metodologías son representables como nodos válidos
    And los 34 worksheets son representables con metadata completa
```

## Size

M

## Notes

- Schema primero, población después (S6.2-S6.5)
- El schema debe ser simple — YAML files, no base de datos
- Basarse en el contenido real de LlamaParse para validar que el schema funciona
- PAT-L-004: Ontology over RAG — retrieval determinístico, no embeddings
