# S6.2 Design — People Decision: Ontology Population

## Complexity

**Moderate.** Content mapping from LlamaParse to YAML schema. ~15 new nodes across 4 types. Two new subdirectories. No external integrations, no algorithmic logic — but requires judgment on relationship wiring and content fidelity.

## Problem & Value

**Problem:** The People decision exists as raw LlamaParse text (2,729 lines). The agent currently has 2 nodes: one concept and one metric — insufficient for any meaningful coaching retrieval.

**Value:** After S6.2, the agent can deterministically answer "what tools apply to People?", "what does FACe require?", "what worksheets exist for hiring?" — the foundation for all People coaching flows.

## Approach

Pure YAML population — no code, no scripts. Each node is a hand-crafted YAML file following `node-types.yaml` schema. Content is extracted from LlamaParse sources and summarized (not quoted verbatim).

**Intra-People relationship map:**
```
decision-people
  ← belongs-to: all People nodes

concept-core-values
  → feeds-into: tool-topgrading (values used in hiring filter)
  → feeds-into: tool-face (accountable person must fit values)
  → measured-by: metric-values-alignment-score

concept-culture
  → requires: concept-core-values
  → measured-by: metric-employee-satisfaction

concept-right-people-right-seats (existing)
  → feeds-into: tool-face
  → measured-by: metric-employee-satisfaction (existing)

concept-disc-assessment
  → implements: tool-team-assessment
  → feeds-into: concept-love-loathe

concept-love-loathe
  → implements: worksheet-love-loathe

concept-employee-engagement
  → measured-by: metric-employee-satisfaction
  → requires: tool-five-manager-activities

tool-face
  → requires: concept-right-people-right-seats
  → implements: worksheet-face
  → feeds-into: tool-pace

tool-pace
  → requires: tool-face

tool-topgrading
  → requires: concept-core-values
  → measured-by: metric-rehire-rate

tool-oppp
  → implements: worksheet-oppp
  → measured-by: metric-role-fit-score

tool-five-manager-activities
  → measured-by: metric-employee-satisfaction
  → feeds-into: tool-team-assessment

tool-team-assessment
  → implements: worksheet-team-growth

worksheet-face → implements: tool-face
worksheet-love-loathe → implements: concept-love-loathe
worksheet-oppp → implements: tool-oppp
worksheet-team-growth → implements: tool-team-assessment
```

**LEAN gates:**
- KISS: flat YAML files, no nested graphs, no scripting
- DRY: update existing nodes (don't duplicate right-people-right-seats, employee-satisfaction)
- YAGNI: no cross-decision edges (that's S6.6)
- MVP: 15 nodes is the minimum complete People graph; no speculative extras

## Concrete Examples

### Example: tool-face.yaml
```yaml
id: tool-face
type: tool
name: "FACe — Function Accountability Chart"
name_es: "Gráfico de Responsabilidad Funcional (FACe)"
decision: people
summary: >
  A one-page chart listing every business function (Sales, Finance, Operations, HR, etc.),
  the person accountable for each, and their leading KPIs. Forces clarity on who owns what
  at the functional level. The "e" stands for the energy and entrepreneurial spirit the
  accountable person brings.
source:
  book_chapter: "THE LEADERS"
  file: "scaling_up_llamaparse.txt"
  file_line: 686
relationships:
  - type: belongs-to
    target: decision-people
  - type: requires
    target: concept-right-people-right-seats
  - type: implements
    target: worksheet-face
  - type: feeds-into
    target: tool-pace
tags: [people, accountability, structure, FACe, leadership]
metadata:
  difficulty: beginner
  time_estimate: "2-4 hours first time"
  frequency: quarterly
```

```yaml
type: worksheet
name: Love/Loathe Worksheet
name_es: Hoja de Trabajo Amor/Odio

  Individual worksheet where each team member lists their 5 most important weekly tasks
  and marks each as "love" or "loathe." Tasks that are loathed and non-core to the role
  are candidates for delegation, automation, or elimination. Results inform role redesign
  and quarterly personal priorities.
source:
  file: "metodologias_parsed/people_workbook.txt"
  file_line: 2227
relationships:
  - type: belongs-to
    target: decision-people
  - type: implements
    target: concept-love-loathe

metadata:
  fields:
    - "Name, Date"
    - "Tasks I LOVE (ranked 1-5)"
    - "Tasks I LOATHE (ranked 1-5)"
    - "CORE to role: circle love/loathe tasks that cannot be delegated"
    - "Top LOATHE action: delegation/automation plan"
    - "Quarterly priority: reassignment action"
  output: "Clarity on role optimization; delegation candidates; quarterly personal priority"
  difficulty: beginner
  time_estimate: "30 minutes"
  frequency: quarterly
```

## Acceptance Criteria

**MUST:**
1. All 15 new nodes created, conforming to `node-types.yaml` required fields
2. `tool-face` and `tool-pace` exist with correct relationship chain
3. Every node has `belongs-to → decision-people`
4. `decision-people.yaml` `relationships` no longer empty
5. `people/tools/` and `people/worksheets/` directories created

**SHOULD:**
- All source lines traceable to LlamaParse files
- `metadata.time_estimate` and `metadata.frequency` present on all tools and worksheets

**MUST NOT:**
- No cross-decision relationships (belongs in S6.6)
- No placeholder summaries (empty string or "TODO")
- No node IDs that conflict with future decisions (Strategy, Execution, Cash)

## Decisions

| ID | Choice | Rationale | Alternatives |
|----|--------|-----------|--------------|
| D1 | `contains` relationship in decision node | Makes retrieval "give me all People nodes" trivial: traverse decision → contains → all nodes | No relationship (requires filtering by `decision` field) — less explicit |
| D2 | Separate `tools/` and `worksheets/` subdirs | Mirrors the node type hierarchy; makes `ls people/worksheets/` a valid retrieval command | Flat `people/` directory — harder to browse by type |
| D3 | Update existing nodes to add missing `source.file` | Consistency — all nodes should trace to LlamaParse, not just new ones | Leave existing nodes as-is — inconsistency in provenance tracking |
