# S6.1 — Design: Ontology Schema

## Problem & Value

**Problem:** El contenido de Scaling Up está en markdown plano (651K chars). El agente no tiene forma estructurada de navegar las 68 metodologías, 34 worksheets y sus relaciones.

**Value:** Con un schema de ontología, cada pieza de conocimiento es un nodo navegable con relaciones explícitas. El agente puede responder "qué herramienta uso para X" con traversal determinístico, sin RAG.

## Approach

Diseñar un schema YAML minimalista que modela el dominio Scaling Up como un grafo de nodos y relaciones. Los nodos se almacenan como archivos YAML individuales en `.scaleup/knowledge/`. Las relaciones se declaran dentro de cada nodo (adjacency list).

**Decisión clave:** No crear un archivo de grafo monolítico. Cada nodo es un archivo YAML. Esto es inspeccionable, editable por humanos, y compatible con el modelo local-first.

**Componentes:**

| Componente | Tipo | Descripción |
|------------|------|-------------|
| `.scaleup/knowledge/ontology/schema.md` | crear | Documentación del schema |
| `.scaleup/knowledge/ontology/node-types.yaml` | crear | Definición de tipos de nodo |
| `.scaleup/knowledge/ontology/examples/` | crear | 1 ejemplo por tipo de nodo |

## Node Types

| Type | Descripción | Ejemplo |
|------|-------------|---------|
| `decision` | Las 4 decisiones principales | People, Strategy, Execution, Cash |
| `concept` | Conceptos/principios del framework | "Right people right seats", "One-Page Strategic Plan" |
| `tool` | Herramientas/frameworks aplicables | FACe/PACe, 7 Strata, Rockefeller Habits Checklist |
| `worksheet` | Worksheets completables con campos | OPSP worksheet, CCC worksheet, OPPP |
| `stage` | Etapas de madurez/aplicación | Startup, Growth, Scaling, Expansion |
| `metric` | KPIs y métricas medibles | CCC days, NPS, Employee satisfaction |

## Node Schema (YAML)

```yaml
# Cada nodo es un archivo .yaml
id: tool-opsp                    # slug único
type: tool                       # decision|concept|tool|worksheet|stage|metric
name: One-Page Strategic Plan
name_es: Plan Estratégico de Una Página
decision: strategy               # people|strategy|execution|cash|cross
summary: >
  Herramienta central de Scaling Up que consolida la visión,
  estrategia y plan de ejecución en una sola página.
source:
  book_chapter: "THE ONE-PAGE STRATEGIC PLAN"
  book_line: 3944
  workbook: strategy_workbook.md
relationships:
  - type: belongs-to
    target: decision-strategy
  - type: requires
    target: tool-core-values
  - type: feeds-into
    target: tool-priorities-rocks
tags: [strategy, planning, quarterly]
metadata:
  difficulty: intermediate
  time_estimate: "2-4 hours first time"
  frequency: quarterly
```

## Relationship Types

| Type | Source → Target | Descripción |
|------|----------------|-------------|
| `belongs-to` | any → decision | Nodo pertenece a una decisión |
| `requires` | any → any | Prerequisito — hacer A antes de B |
| `feeds-into` | any → any | Output de A es input de B |
| `measured-by` | concept/tool → metric | Cómo se mide el éxito |
| `prerequisite-of` | any → any | Inverso de requires (para traversal) |
| `implements` | worksheet → concept | Worksheet implementa un concepto |

## Acceptance Criteria

### MUST
1. Schema documentado en `.scaleup/knowledge/ontology/schema.md`
2. Node types definidos con campos requeridos/opcionales en YAML
3. Relationship types con source/target constraints
4. Al menos 1 ejemplo concreto por tipo de nodo usando contenido real
5. Directory structure definida y creada

### SHOULD
1. Campos bilingües (name + name_es)
2. Source pointers al contenido LlamaParse (chapter, line)

### MUST NOT
1. No crear un archivo de grafo monolítico
2. No usar embeddings ni vectores
3. No implementar retrieval engine (S6.7)
