# S6.7 Retrospective — Deterministic Retrieval Engine

**Story:** S6.7
**Date:** 2026-04-20
**Estimated size:** M
**Actual time:** ~25 minutes

## Summary

Built `KnowledgeGraph` — a pure Python, zero-external-dep retrieval engine over
the `.scaleup/knowledge/` YAML ontology. Loads on init, all queries in-memory.

**Integration test results:**
- Total nodes: 79 | Total edges: 301 | Cross-decision edges: 12
- `query(decision, node_type)` → filtered node list ✓
- `traverse(start_id, rel_type, depth)` → BFS traversal ✓
- `path(from_id, to_id)` → shortest path via BFS ✓
- `worksheets(decision)` → registry-backed worksheet lookup ✓
- `get(id)` → O(1) node lookup ✓
- `stats()` → graph summary ✓

## API

```python
from retrieval import KnowledgeGraph

g = KnowledgeGraph('.scaleup/knowledge')

# Single node
node = g.get('tool-power-of-one')

# Filter by decision + type
worksheets = g.query(decision='cash', node_type='worksheet')

# BFS traversal
downstream = g.traverse('concept-bhag', rel_type='feeds-into', depth=2)

# Shortest path between any two nodes
path = g.path('concept-core-purpose', 'concept-priorities-rocks')

# Worksheet registry (O(1) index, prerequisite ordering included)
cash_worksheets = g.worksheets(decision='cash')

# Graph summary
stats = g.stats()
```

## What went well

- BFS path traversal correctly discovers cross-decision paths
  (concept-core-purpose → concept-bhag → concept-priorities-rocks in 2 hops)
- Registry-backed `worksheets()` returns pre-computed prerequisite ordering
- Module-level `default_graph()` singleton pattern enables zero-config import

## What to improve

- `path()` is undirected (treats all edges as bidirectional). For coaching context
  it would be more precise to traverse directed edges only. Deferred — current
  use case (sequence guidance) works with undirected paths.

## Heutagogical checkpoint

1. **What did I learn?** 301 edges in a 79-node graph means avg ~4 edges/node.
   The graph is dense enough for meaningful multi-hop traversal without path explosion.

2. **What would I change?** Add directed vs. undirected toggle to `path()` for
   future stories that need "what can I reach FROM here" vs. "how are these connected?"

3. **Framework improvements?** The `stats()` method surfacing `cross_decision_edges: 12`
   could become an automated done-criteria check in future ontology stories.

4. **What am I more capable of?** Can now write deterministic coaching logic that
   traverses the graph to surface sequenced recommendations without any AI inference.

## Patterns

- **PAT-L-023**: BFS traversal over a YAML ontology provides deterministic, inspectable
  reasoning paths — a coaching agent can show its "why" by returning the path, not just
  the result.
- **PAT-L-024**: Module-level singleton `default_graph()` with lazy init lets any skill
  script import and query the graph with zero setup (`from retrieval import default_graph`).
