# Retrospectiva S86.9 — Instalación de un paso

## Qué se entregó

- **`instalar.sh`** (raíz, POSIX `sh`, sin banderas): Mac o Linux (Windows →
  "usa WSL2"); herramientas de Apple si faltan; `uv` con su instalador oficial
  y `uv python install 3.12` (`UV_PYTHON=3.12` para el `.venv`); Claude Code
  con su instalador oficial si falta; copia en `~/ESCALA` (clona, o
  `git pull --ff-only` si ya existe; si la carpeta no es de ESCALA no la toca);
  `install.sh --platform claude --with-specialists`. Última línea:
  "Listo. Pega esta línea, presiona Enter y cuéntale a ESCALA lo que más te
  preocupa de tu negocio:  cd ~/ESCALA && claude". Lo técnico va a
  `~/.config/agente-de-escalamiento/instalacion.log`.
- Si corre desde un archivo dentro de una copia de ESCALA, usa esa copia.
- **El contrato de Claude usa el Python del producto**: el bloque ESCALA de
  `~/.claude/CLAUDE.md` dice que donde una instrucción corra `python3` se use
  `<copia>/.venv/bin/python`.
- `PILOTO-EMPRESARIOS.md` y `README.md`: 3 pasos (Terminal, pegar una línea,
  pegar `cd ~/ESCALA && claude`); actualizar = pegar la misma línea; detalle
  técnico aparte "para quien te ayuda".
- `tests/test_s86_9_one_step_install.py` (17 tests): máquina limpia, segunda
  corrida, herramientas ya instaladas, sin internet al actualizar, git nunca
  destructivo, copia local, carpeta ajena, Mac sin herramientas de Apple,
  Linux sin Git, Windows, sin internet, fallo al descargar, fallo de
  `install.sh`, datos del dueño ignorados por git, ≤3 pasos en la guía,
  sintaxis `sh`/`bash`, contrato de Claude con el Python del producto.
  HOME falso y PATH sólo con stubs: sin red ni instalaciones reales.
- `shellcheck -s sh` limpio (vía `uvx shellcheck-py`; no está instalado).

## Qué salió bien

- El repo es **público** (`gh repo view` → `PUBLIC`): `curl … | sh` desde raw
  de GitHub funciona sin hosting nuevo, en cuanto `instalar.sh` llegue a `main`.
- `install.sh` ya hacía casi todo bien (runtime antes de tocar Claude, sin
  `pip` global). El bootstrap sólo pone lo que faltaba alrededor.
- Probar con un PATH hecho sólo de stubs (y unos pocos programas reales del
  sistema) hace que "falta git" sea de verdad "falta git", aun en una Mac que
  sí tiene `/usr/bin/git`.

## Qué mejorar / sorpresas

- **Hueco que la auditoría no vio:** la puerta y los procedimientos llaman
  `python3 -m coaching…`. En una máquina limpia ese `python3` (el de Apple, 3.9)
  no tiene `pydantic` ni `pyyaml` y ni siquiera cumple `>=3.10`: cada
  procedimiento terminaría en "No pude abrir esa parte de ESCALA". Se cubrió con
  una línea en el contrato de Claude. Depende de que Claude la siga: **no está
  verificado con un Claude real** (va a las sesiones de S86.6).
- **Los datos del dueño viven dentro de la copia** (§6 de la auditoría,
  confirmado). La puerta usa `base_path: "."` y el dueño abre Claude en
  `~/ESCALA`. Lo que escribe el código va a `.escala/my-company/` y
  `.escala/agent/memory/` (ignorados por git) y los entregables a `work/`
  (ignorado). `git pull --ff-only` no toca archivos ignorados y ningún script
  hace `clean`/`reset`/`checkout`. No se movió nada: separar datos y copia no es
  trivial porque `.escala/knowledge/` (contenido del producto, versionado) se
  lee con el mismo `base_path`.
- **El dueño carga instrucciones de desarrollo.** Al abrir Claude en `~/ESCALA`
  se lee el `CLAUDE.md` de la raíz, que es el de RaiSE (equipo de desarrollo:
  "Run /rai-session-start…"), y también `.claude/knowledge/`. Ya pasaba con la
  guía anterior. No se tocó: lo genera `rai init` y lo necesita el equipo.
- En una Mac nueva sin herramientas de Apple hay un paso extra inevitable (la
  ventana de Apple y volver a pegar la línea). El script lo detecta y lo dice.
- Sólo Claude. Codex queda para S86.10 (paridad): una plataforma es una sola
  cosa que verificar en las pruebas con dueños, y el paquete de Codex todavía no
  lleva `catalog.yaml` (retro S86.4).
- `install.sh` sin `--skills-only` ya instalaba los especialistas; la bandera
  `--with-specialists` es redundante pero deja explícita la intención.

## Preguntas abiertas para el dueño

1. **¿Conectamos también Codex cuando ya lo tiene?** Ejemplo: Ana usa Codex en
   su laptop; hoy la línea sólo conecta Claude y ella tendría que pedir ayuda
   para Codex. Propuesta: esperar a S86.10.
2. **¿Separamos tu información del programa?** Hoy vive dentro de `~/ESCALA`.
   Ejemplo: si alguien borra la carpeta ESCALA "para reinstalar", se van también
   tu perfil y tu hoja del grupo. Actualizar no la toca, pero borrar sí.
3. **¿Quitamos las instrucciones del equipo técnico de la copia del dueño?**
   Ejemplo: al abrir Claude en `~/ESCALA`, Claude también lee reglas para
   programadores y podría mencionar "sesiones" o "historias" que no son tuyas.
   Opción: que el dueño reciba el paquete portable (sin esas reglas) en vez del
   repositorio completo.
4. **¿Quién paga la cuenta de Claude en el piloto?** Ejemplo: Claude Code pide
   entrar con una cuenta de pago (Pro o más); sin ella, el paso 3 se detiene.
5. **¿Queremos una dirección corta propia para la línea de instalación?**
   Ejemplo: hoy es `raw.githubusercontent.com/lunitomx/…/instalar.sh`; si el
   repositorio cambia de nombre, de dueño o se vuelve privado, la línea deja de
   funcionar para todos. Algo como `escala.mx/instalar` se podría mover sin
   cambiar la guía. No se inventó hosting en esta historia.
6. **Verificar en S86.6 que Claude use el Python de ESCALA.** Ejemplo: en una Mac
   recién instalada, "bajaron mis ventas" debe llegar a Strategy y no a "No pude
   abrir esa parte de ESCALA". Si falla, la salida es fijar la ruta del Python en
   cada procedimiento en lugar de una línea en el contrato.
