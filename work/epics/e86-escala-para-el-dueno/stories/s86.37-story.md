# S86.37 — Las pruebas no dependen de archivos locales que git no sigue

## Objetivo

La suite debe dar el mismo resultado en la copia principal de Eduardo y en una
copia limpia. Hoy da 8 fallas en la principal y 3 en una limpia. Ninguna es un
error del producto: todas leen archivos que git ignora.

## Mapa de fallas (gemba 2026-10-16, base 232e19e2)

| Prueba | Dónde falla | Archivo local que la tumba |
|---|---|---|
| `test_claude_adapter::test_checkout_claude_surface_exposes_only_escala` | principal | 79 skills `rai-*` en `.claude/skills/` (ignoradas: `.claude/skills/rai-*/`) |
| `test_legacy_skill_aliases::test_legacy_aliases_are_not_in_discoverable_skill_roots` | principal | `.agents/skills/scaleup-*` del 30-sep (ignoradas: `.agents/`) |
| `test_s67_4_parity_migration` (5 pruebas) | principal | las mismas `.agents/skills/scaleup-*` → `legacy_alias_publicly_discoverable` |
| `test_scope_inventory::test_current_scope_inventory_is_exhaustive` | principal | 11 `scope.md` viejos de E13, E48 y E50 en `work/` sin versionar |
| `test_e61_e62_fidelity_regression` (2 pruebas) | limpia | evidencia E61/E62 en `work/…/evidence/` sin versionar |
| `test_foundation_relations::test_real_e59_relation_queue_validates_against_real_manifest` | limpia | evidencia E59 en `work/…/evidence/` sin versionar |

## Diseño

- Un ayudante `validators/versioned_files.py` lista los archivos que git sigue
  o seguiría (`git ls-files --cached --others --exclude-standard`): ignora solo
  lo que `.gitignore` excluye. Sin git, recorre el disco (más estricto, nunca
  más laxo).
- El inventario de alcances, la paridad S67.4 y las dos pruebas de superficie
  usan ese ayudante en vez de `glob`/`iterdir`.
- Las 3 pruebas de evidencia se saltan con `pytest.skip` y razón explícita
  cuando el archivo de evidencia no existe **y** git no lo sigue. Si git lo
  sigue y falta, la prueba falla. Donde existe, corre igual que hoy.
  No se versiona la evidencia: deriva del libro y del corpus (material fuera de git).

## Criterios de aceptación

1. Suite en 0 fallas en la copia principal (tras fusionar) y en una copia limpia.
2. Cada prueba sigue fallando si el problema aparece en un archivo versionado:
   pruebas con un repo git temporal que meten el caso malo con `git add -f`.
3. No se borra ningún archivo local de la copia principal.
4. Suite, pyright y ruff en verde.
