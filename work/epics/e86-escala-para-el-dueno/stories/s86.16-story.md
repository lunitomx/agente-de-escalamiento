# S86.16 — Una sola calculadora, que viaja con ESCALA

## Objetivo

ESCALA hace las cuentas del curso de cash con código, nunca con el modelo.
Una sola calculadora toma los estados ya revisados (S86.15) y devuelve cada
número con su fórmula en palabras, de dónde sale (con las cifras) y la lámina
del curso. Si un número no se puede calcular, lo dice con la razón; nunca pone 0.
La calculadora viaja dentro de cada paquete (Claude Code, Codex, Agent Plugin).
Los procedimientos de cash dejan de pedir al modelo que calcule y dejan de
traer límites inventados (CCC > 90, DSO > 60, margen < 30 %, rangos por industria).

## Gemba: lo que hay hoy

- El motor del poder del uno (S86.13) vive en `escala_server/cash/__init__.py`.
  Usa 365 días fijos y sus `metrics` ponen 0 cuando la base es 0.
- `benchmark_by_industry()` trae rangos por industria inventados.
- `escala-cash-finanzas` pide «usar las capacidades nativas» para calcular y
  trae alertas CCC > 90, DSO > 60, margen < 30 %.
- `escala-cash-ccc` y el agente `escala-cash` traen tablas de CCC sano/peligro y
  benchmarks por industria; el agente dice «Tú (el LLM) eres el motor».
- Los paquetes (Agent Plugin, Codex) llevan la puerta, el catálogo, los
  procedimientos y las fichas, pero ningún código: un paquete no puede calcular.

## Diseño

```
estados revisados (JSON)                 paquete (Agent Plugin / Codex)
 { revision: RevisionDeEstados,          skills/escala/references/calculadora/
   resultados: LecturaEstados }            escala_server/cash/calcular.py  ← lanzador
          │                                escala_server/cash/curso.py
          ▼                                escala_server/financial/...     (byte a byte)
 curso.calcular_curso()
   cajas → CT, deuda neta, otras, financiamiento   (una sola definición: cajas.py)
   resultados → UB, UO                              (suma de renglones, con origen)
   días con los días reales del periodo
   poder del uno → PowerOfOneEngine (S86.13)
          │
          ▼
 JSON: cada número = valor + fórmula + «sale de: …» + lámina
       o { "no_calculable": "razón" } / { "no_aplica": "razón" }
```

- Entrada interna: `python -m escala_server.cash.curso <archivo>`.
- En un paquete: `python3 references/calculadora/escala_server/cash/calcular.py <archivo>`.
  El lanzador sólo usa la biblioteca estándar; si falta Python ≥ 3.10 o pydantic,
  responde `{"no_calculable": …}` y ESCALA lo dice sin calcular de memoria.
- Días del periodo: los del periodo revisado (365 en Mi Empresa); la columna
  anterior de un comparativo usa los mismos días, como el curso.

## Criterios de aceptación

1. Mi Empresa al centavo contra `verifica.py` (tabla del ticket).
2. Ventas 0, UB negativa, sin inventario, sin costo → «no calculable»/«no aplica».
3. La prueba de aceptación construye el Agent Plugin y el adaptador Codex en una
   carpeta temporal y corre la calculadora desde adentro.
4. Una prueba recorre los procedimientos de cash y su conocimiento y falla si
   piden calcular con el modelo o traen rangos inventados.
