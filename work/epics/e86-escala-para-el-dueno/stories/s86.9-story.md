# S86.9 — Instalación de un paso

## Objetivo

Hoy instalar ESCALA son ~8 pasos con terminal, Git, Python y `uv`, y el dueño
elige banderas (`--platform`, `--skills-only`, `--with-specialists`…). Con esta
historia, en una máquina limpia:

1. Abre la Terminal.
2. Pega una línea: `curl -fsSL https://raw.githubusercontent.com/lunitomx/agente-de-escalamiento/main/instalar.sh | sh`
3. Pega la línea que le muestra al final (`cd ~/ESCALA && claude`) y cuenta qué le preocupa.

≤3 pasos, 0 decisiones técnicas.

## Hechos verificados antes de diseñar

- `origin` = `https://github.com/lunitomx/agente-de-escalamiento.git`, rama
  `main`, **repo público** (`gh repo view` → `PUBLIC`): `curl | sh` desde raw
  de GitHub funciona en cuanto esté en `main`. No hace falta hosting nuevo.
- `install.sh` exige `.git` (o el manifiesto portable), `uv` y `claude` en el
  PATH. Sin `--skills-only` ya instala los cuatro especialistas en Claude.
- La puerta llama `python3 -m coaching.tracker` con `base_path: "."`: necesita
  que el agente se abra **en la carpeta del clon** y un Python con `pydantic` y
  `pyyaml`. El `python3` del sistema en una máquina limpia no los tiene; el
  `.venv` que crea `install.sh` sí.
- Datos del dueño que escribe el código: `.escala/my-company/` y
  `.escala/agent/memory/` (ya en `.gitignore`); entregables en `work/`
  (ignorado). `.escala/knowledge/` es contenido del producto (versionado) y se
  lee con el mismo `base_path`, así que separar datos y clon **no** es trivial.

## Diseño (lo más simple que cumple)

1. **`instalar.sh` en la raíz, POSIX `sh`** (corre con `curl … | sh` en Mac y
   Linux). Sin banderas. Pasos:
   - Sistema: Mac o Linux; Windows → mensaje "usa WSL2".
   - Git: en Mac, si faltan las herramientas de Apple (`xcode-select -p`
     falla), abre su instalador y pide volver a pegar el mismo comando
     (no hay forma segura de evitar esa ventana). En Linux, si falta, lo dice.
   - `uv`: si falta, instalador oficial (`astral.sh/uv/install.sh`); Python con
     `uv python install 3.12` y `UV_PYTHON=3.12` para el `.venv`.
   - Claude Code: si falta, instalador oficial (`claude.ai/install.sh`).
   - Producto en `~/ESCALA` (fijo): clona si no existe; si ya es la copia de
     ESCALA, `git pull --ff-only` (si falla, sigue con lo que hay y lo dice);
     si existe y no es de ESCALA, no la toca y lo dice.
   - Si el script corre desde un archivo dentro de una copia de ESCALA, usa esa
     copia (no clona).
   - `bash install.sh --platform claude --with-specialists`.
   - Salida técnica a `~/.config/agente-de-escalamiento/instalacion.log`; en
     pantalla sólo líneas en español y, al final, una línea: qué pegar y qué
     escribir.
   - Nunca `git clean`, `reset`, `checkout` ni `rm`.
   - **Sólo Claude.** Codex queda para S86.10 (paridad): una sola plataforma
     es una sola cosa que verificar en las pruebas con dueños.
2. **Python del producto para Claude**: el bloque ESCALA de `~/.claude/CLAUDE.md`
   (plantilla `adapters/claude/CLAUDE.template.md`) dice que donde un
   procedimiento diga `python3` se use `<copia>/.venv/bin/python`.
3. **Docs**: `PILOTO-EMPRESARIOS.md` y la sección del dueño de `README.md` con
   los 3 pasos.
