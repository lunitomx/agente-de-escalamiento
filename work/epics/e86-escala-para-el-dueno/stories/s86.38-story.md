# S86.38 — El requisito de instalación describe la instalación de una línea

## Objetivo

El libro maestro de aceptación todavía dice que en Mac ESCALA se instala «sin
la estructura de un repositorio de desarrollo» (REQ-E41-001). Desde S86.35
(ESCALA-103) la instalación real es una línea del README: `instalar.sh` clona el
repositorio público con git en `~/ESCALA` y corre
`install.sh --platform claude --with-specialists`. Volver a pegar la línea
actualiza (`git pull --ff-only`). El requisito debe decir eso.

## Qué hay hoy para Windows (gemba 2026-10-16)

- `instalar.sh` detecta Windows nativo (MINGW/MSYS/CYGWIN), no instala y pide
  WSL2: «Instala WSL2 (el Linux de Windows), ábrelo y pega ahí el mismo comando».
- README → Requisitos: «Una Mac o Linux (en Windows, WSL2)».
- La calificación E41 sólo prepara carpetas locales, marcador de versión y
  SQLite con `platform="windows"` (simulado). No hay instalador nativo.

Decisión: REQ-E41-002 dice honestamente que no hay instalación nativa en
Windows; la ruta soportada es WSL2 con la misma línea, y lo calificado en
Windows es la preparación local. La plataforma declarada sigue `windows`.

## Criterios de aceptación

1. REQ-E41-001 nombra `instalar.sh`, `git clone`, `~/ESCALA`,
   `install.sh --platform claude --with-specialists` y que repetir la línea
   actualiza. No dice «no repository-development layout» ni equivalente.
2. REQ-E41-002 dice que no hay instalación nativa en Windows y nombra WSL2.
3. Una prueba falla si el texto vuelve a negar el clon, o si alguna pieza que
   el requisito nombra deja de aparecer en el README o en `instalar.sh`.
4. Recibos E37–E41 recalificados (el hash del libro cambia con cualquier
   texto), línea base s36.6 regenerada: 36 probados, 6 sin probar.
5. La misión `escala-local-v2-plan-maestro-…` no cambia.
6. `governance/pilot-readiness-2026-09-12.md` recibe sólo una nota fechada al
   final: «bundle lifecycle» ya no es un paquete.
