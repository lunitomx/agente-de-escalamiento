# Retrospectiva S86.37 — Las pruebas no dependen de archivos locales que git no sigue

## Resultado

- Antes: copia principal 8 fallas; copia limpia 3 fallas.
- Después (copia limpia): 3483 pasan, 5 se saltan (2 previos + 3 de evidencia local), 0 fallas.
- Caso malo versionado (`git add -f` de `.agents/skills/scaleup-pulse`, `.claude/skills/rai-debug`
  y `work/epics/e13-auditoria-cierre/scope.md`): vuelven a fallar exactamente las mismas 8 pruebas.
- Simulación de la copia principal (sus archivos ignorados copiados al worktree): 38 de 38 pasan,
  y las 3 pruebas de evidencia corren de verdad.

## Qué funcionó

- Un solo ayudante (`validators/versioned_files.py`) con `git ls-files --cached --others
  --exclude-standard`: cuenta lo versionado y lo nuevo sin agregar, ignora solo lo que
  `.gitignore` excluye. Sin git recorre el disco (más estricto).
- Pruebas con un repo git temporal: el mismo archivo malo pasa cuando está ignorado y falla
  cuando se fuerza con `git add -f`. Eso demuestra que no bajamos la protección.

## Decisiones

- Evidencia E59/E61/E62: `pytest.skip` con razón explícita si falta y git no la sigue. No se
  versionó una copia: deriva del libro con licencia (material fuera de git). Si git la sigue
  y falta, la prueba falla.
- No se borró nada de la copia principal.

## Aprendizaje

- Una prueba de «superficie del checkout» debe preguntar a git, no al disco: el disco de un
  desarrollador siempre tiene restos locales.
