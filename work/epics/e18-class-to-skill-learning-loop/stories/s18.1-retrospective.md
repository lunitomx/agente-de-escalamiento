# Story Retrospective: S18.1 — Class intake + source bundling

**Date:** 2026-06-02
**Size:** M
**Commits:** 3 (init + plan + implement)

## What We Built

A Python module `coaching/class_intake.py` that:

- Defines a `ClassBundle` dataclass with all required metadata fields
- `ingest_class()` function that accepts transcript path + metadata and persists as YAML
- `load_bundle()` and `summary()` for retrieval and human display
- CLI with `ingest` and `load` subcommands via `argparse` (no external CLI deps)
- `class_id` auto-generation with NFKD-normalized slug

## What Went Well

- All 14 tests pass on first implementation attempt
- Single fix needed (NFKD normalization for ñ/accents) — caught by test
- Zero external dependencies (stdlib + pyyaml only)
- Clean separation: dataclass → persistence → CLI → edge cases

## What Could Be Better

- pyyaml was not pre-installed — added as a lightweight dependency
- The `escala-skills/` directory wasn't a real Python package, so the module went under `coaching/` instead. This is the correct location since `coaching` is the actual Python package.

## Patterns Identified

- Slug generation: NFKD normalization before regex stripping
- Bundle path: `work/classes/{class_id}/bundle.yaml` — used by S18.2+

## Open Questions

- Should S18.2 use the `ClassBundle` dataclass directly or re-read from YAML? The `load_bundle()` function supports both.
- Future: add support for downloading transcripts from BigBlueButton automatically (not in scope for S18.1).
