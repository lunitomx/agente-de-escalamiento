# S31.1: Guided ScaleUp Pipeline Runner Scope

## In Scope
- Add a first guided runner surface for ScaleUp pipeline discovery, inspection, and run evidence.
- Reuse the canonical registry in `.raise/pipelines/scaleup.yaml`.
- Reuse or extend existing validation/data loading helpers instead of parsing YAML ad hoc.
- Add tests for listing, inspecting, unknown pipeline handling, stopped runs, and evidence serialization.
- Keep the CLI/API surface narrow enough to support the next hardening story.

## Out of Scope
- Generic runtime execution for arbitrary pipeline registries.
- Automatic invocation of every ScaleUp skill without human gate review.
- Scheduler, daemon, remote execution, retries, or async orchestration.
- Refactoring existing ScaleUp skills unless needed to satisfy the runner contract.
- GitLab synchronization.

## Done when
- A user can list pipelines and inspect one pipeline from the registry.
- A guided run can produce evidence with selected pipeline, phase review, gate decisions, and final state.
- Unknown pipeline and stop-condition paths are tested.
- The implementation passes targeted tests, type check, lint, and the relevant registry validation.
