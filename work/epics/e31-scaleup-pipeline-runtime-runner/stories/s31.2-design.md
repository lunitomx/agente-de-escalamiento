# S31.2 Design: Evidence and Resume Hardening

## Complexity
Moderate. The change extends one existing runner module plus its focused tests. It adds state validation and resume semantics, but does not introduce new infrastructure.

## Problem
S31.1 writes evidence, but there is no supported way to inspect or resume a previously written run. Interrupted work can only be understood by manually opening YAML.

## Value
Operators can continue guided pipeline work with a deterministic audit trail instead of losing phase/gate context after interruption.

## Gemba Findings
- Existing implementation lives in `validators/pipeline_runner.py`.
- Existing tests live in `tests/test_pipeline_runner.py`.
- `PipelineRunEvidence` already provides a typed boundary for evidence output.
- No duplicate pipeline runner exists elsewhere.
- Existing `coaching/worksheet` resume behavior is action-based, but its state shape is worksheet-specific and should not be reused.

## Approach
Extend the existing file-backed runner with:
- A validated evidence loader.
- A compact run inspection view.
- A resume helper that appends a deterministic event and returns the next incomplete phase.
- CLI subcommands for evidence inspection and resume.

## Components
| Component | Change | Purpose |
| --- | --- | --- |
| `validators/pipeline_runner.py` | Modify | Add event model, load/inspect/resume helpers, and CLI commands. |
| `tests/test_pipeline_runner.py` | Modify | Add tests for inspect, resume, corrupt evidence, and append-only behavior. |
| `work/epics/e31-scaleup-pipeline-runtime-runner/stories/s31.2-progress.md` | Create | Track implementation progress. |

## Decisions
- Keep YAML file storage. This story hardens existing evidence, not storage architecture.
- Use Pydantic validation for corrupt/missing evidence fields.
- Use append-only `events` for resume history so prior evidence is preserved.
- Compute `next_phase` from `phases_reviewed` versus registry phase order.

## Legacy Sweep
Nothing becomes orphaned. This extends the S31.1 runner and keeps existing `run_guided_pipeline` behavior compatible.

## Drift Risk
- AG2 clone amplification: low. We extend the existing runner rather than introduce another module.
- AG4 fan-out: low. Scope remains two source/test files plus story artifacts.

## Supply Chain
No new external dependencies.

## Examples

Inspect evidence:
```bash
python validators/pipeline_runner.py evidence inspect run.yaml
```

Expected output:
```text
pipeline: scaleup-session-start
state: stopped
next_phase: load-tasks
events: 1
```

Resume evidence:
```bash
python validators/pipeline_runner.py resume scaleup-session-start --evidence run.yaml
```

Expected output:
```text
scaleup-session-start: resumed at load-tasks
```

## Acceptance Criteria
- MUST load existing evidence through `PipelineRunEvidence` validation.
- MUST inspect evidence with pipeline id, state, next phase, event count, and path.
- MUST append a resume event without changing prior phase/gate evidence.
- MUST reject corrupt evidence without overwriting the file.
- MUST keep S31.1 CLI/tests compatible.
