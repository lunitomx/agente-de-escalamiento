# S31.2: Evidence and Resume Hardening

## User Story
As a ScaleUp operator running a guided pipeline,
I want run evidence to be inspectable and resumable after interruption,
so that pipeline work can continue without losing the current phase, decisions, or audit trail.

## Acceptance Criteria

### Scenario: Inspect Existing Run Evidence
Given a guided pipeline run has written evidence
When I inspect the run by id
Then I can see the pipeline id, current phase, status, selected gates, and evidence path.

### Scenario: Resume An Interrupted Run
Given a guided pipeline run stopped after a phase review
When I resume the run by id
Then the runner starts from the next incomplete step instead of creating a new run.

### Scenario: Reject Corrupt Evidence
Given an evidence file is missing required fields
When I try to resume it
Then the runner reports a validation error and does not overwrite the evidence file.

### Scenario: Preserve Existing Evidence
Given a run has existing phase and gate entries
When I append a resume event
Then previous evidence remains unchanged and the new event is appended deterministically.

## Notes
- This story hardens the S31.1 runner; it does not turn the pipeline runner into a scheduler or daemon.
- Durable evidence should stay simple and file-backed unless a real need for a storage migration appears.
