# Story: Guided ScaleUp Pipeline Runner

## User Story
As a ScaleUp operator,
I want a guided runner for the canonical ScaleUp pipelines,
so that I can select a pipeline, understand its phases and gates, and leave evidence of what was executed or stopped.

## Acceptance Criteria

### Scenario: List canonical pipelines
```gherkin
Given `.raise/pipelines/scaleup.yaml` defines valid ScaleUp pipelines
When I ask the runner to list pipelines
Then I see each pipeline id, purpose, phase count, and primary entrypoint
```

### Scenario: Inspect a pipeline before running
```gherkin
Given a valid pipeline id
When I ask the runner to show details
Then I see phases, skill entrypoints, gates, and stop conditions in registry order
```

### Scenario: Guided run records evidence
```gherkin
Given a valid pipeline id and an evidence output path
When I start a guided run
Then the runner records the selected pipeline, reviewed phases, gate decisions, and final state
```

### Scenario: Unknown pipeline is rejected
```gherkin
Given the ScaleUp registry is valid
When I request a pipeline id that does not exist
Then the runner fails with a clear message and does not write misleading evidence
```

### Scenario: Stop condition prevents completion
```gherkin
Given a guided run reaches a declared stop condition
When the stop condition is not cleared
Then the runner records a stopped state and the unresolved condition
```

## Examples (Specification by Example)

| Input | Action | Expected Output |
|-------|--------|-----------------|
| `scaleup-start` | list | Pipeline appears with purpose, phase count, and entrypoint summary |
| `scaleup-cash` | inspect | Output includes declared phases, gates, stop conditions, and skill references |
| `missing-pipeline` | run | Non-zero result, clear unknown-pipeline message, no success evidence |
| `scaleup-execution` with blocked gate | run | Evidence state is `stopped` with the gate/condition that blocked progress |

## Notes
- Build against the existing `.raise/pipelines/scaleup.yaml` registry and `validators/pipelines.py`.
- Prefer a guided CLI/user-flow over a generic execution engine.
- Evidence should be deterministic enough for session close, audits, and interrupted-session recovery.
