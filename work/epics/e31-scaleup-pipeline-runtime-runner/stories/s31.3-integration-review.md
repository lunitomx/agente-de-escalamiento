# S31.3 Integration Review — ScaleUp Pipeline Runner

## Verdict

PASS. The E31 runner integrates with every canonical ScaleUp pipeline as a
guided evidence recorder. It should not be expanded into a generic execution
engine in this epic.

## Evidence

- Registry source: `.raise/pipelines/scaleup.yaml`
- Runtime model and CLI: `validators/pipeline_runner.py`
- Integration coverage: `tests/test_pipeline_runner.py::test_runner_integrates_with_every_canonical_scaleup_pipeline`

The integration test iterates every registered pipeline and verifies that a
guided run evidence file preserves:

- pipeline id and entrypoint
- all phase ids in registry order
- all gate names
- stop conditions
- expected outputs
- expected evidence

## Limitations

- The runner records guided evidence; it does not execute skill phases.
- Gate decisions remain `not_checked`; human or code-gate evaluation is future work.
- The runner is intentionally ScaleUp-registry-shaped, not a generic workflow engine.

## Pattern Candidates

- **Guided evidence recorder:** first runtime step for a declarative pipeline
  should preserve registry intent without executing or mutating domain work.
- **Registry round-trip test:** every canonical pipeline should be loadable,
  renderable, runnable to evidence, and reloadable from evidence.
- **Human gate preservation:** unresolved gates should be explicit
  `not_checked` records rather than silently passing.
