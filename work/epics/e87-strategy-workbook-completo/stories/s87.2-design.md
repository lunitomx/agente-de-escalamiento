# S87.2 · Diseño: raíz única del conocimiento, contrato de herramienta y vista HTML

## Flujo en una pantalla (para aprobar sin leer el resto)

```
 Dueño: "/escala-worksheet cliente central"
    │
    ▼
 Skill escala-worksheet ──► coaching.worksheet.run(action=start|step|save)
    │
    │  knowledge_root(base)
    │    ¿existe el ARCHIVO <base>/.escala/knowledge/registry/worksheets.yaml?
    │      sí → <base>/.escala/knowledge          (registro propio del cliente)
    │      no → <paquete>/conocimiento            (repo y clientes: 15 hojas)
    │  registro + node_path + progreso leen de ESA misma raíz
    │
    │  ¿la hoja trae guide.steps?  (ToolGuide la valida)
    │    sí → cada paso: pregunta · cómo llenarlo · ejemplo · tips con fuente
    │    no → metadata.fields como hoy (las 15 hojas viejas)
    ▼
 Dueño responde paso a paso
    │  action=save
    ▼
 <base>/.escala/my-company/worksheets/<hoja>.yaml             respuestas (ya existía)
 <base>/.escala/my-company/vistas/AAAA-MM-DD-<hoja>.html      vista (nuevo)

    │  artifacts.view = {html, md, open_cmd}
    ▼
 Último paso del skill
    open_cmd = ["open", html]      (macOS, sys.platform == "darwin")
             | ["xdg-open", html]  (Linux)
             | null                (otro)
    ├─ corre open_cmd → el navegador muestra la hoja
    └─ si es null o falla → muestra el .md en el chat + su ruta
```

## Problema y valor

- **Problema.** `list_worksheets()` da 0 hojas: busca un archivo que no existe. Las hojas solo tienen una lista de textos, sin ejemplo ni tips. Al guardar, el dueño solo recibe un YAML.
- **Valor.** El motor encuentra las 15 hojas. Cada paso trae pregunta, ejemplo real y tips con fuente. Al guardar se abre una página clara con lo que el dueño llenó.
- **Medida.** `list_worksheets(base_path=Path("."))` da 15 en el repo. Guardar `worksheet-core-customer` escribe 3 archivos y devuelve `open_cmd`.

## Evaluación de complejidad

Moderada: 4 componentes (raíz, contrato, vista, skill), 8 puntos, 0 integraciones externas, lógica propia sin algoritmo nuevo. No es historia de frontend (sin prototipo) ni de integración. Riesgo marcado en la épica: cambio de raíz (ver Riesgos).

### C1 · Raíz del conocimiento

```python
PACKAGE_ROOT = Path(__file__).resolve().parents[2]          # repo / instalación editable
PACKAGE_KNOWLEDGE = PACKAGE_ROOT / "conocimiento"
CLIENT_KNOWLEDGE = Path(".escala") / "knowledge"
REGISTRY_FILE = Path("registry") / "worksheets.yaml"

def knowledge_root(base_path: Path | None = None) -> Path:
    base = base_path if base_path is not None else PACKAGE_ROOT
    client = base / CLIENT_KNOWLEDGE
    return client if (client / REGISTRY_FILE).is_file() else PACKAGE_KNOWLEDGE

def registry_path(base_path: Path | None = None) -> Path:
    return knowledge_root(base_path) / REGISTRY_FILE
```

- `list_worksheets`, `find_worksheet` y `progress._get_worksheets` leen `registry_path(base)`.
- `load_worksheet_content` lee `knowledge_root(base) / node_path`. Así registro y contenido salen siempre de la misma raíz.
- `base_path=None` conserva el sentido de hoy (la raíz del paquete). En el repo da `conocimiento/` porque el paquete no tiene `.escala/knowledge/registry/`.
- Ejemplo: en el repo, `.escala/knowledge/` existe sin `registry/` → raíz `conocimiento/` → 15 hojas. La prueba `test_worksheet_save.py` siembra `tmp_path/.escala/knowledge/registry/worksheets.yaml` → usa ese registro y lee `cash/tools/test.yaml` de `tmp_path/.escala/knowledge/`.
- `progress` se incluye aunque el alcance nombra solo dos funciones. Razón: es la misma falla copiada; sin el cambio, `/escala-worksheet list` diría 15 y `/escala-progress` diría 0. Costo: una línea. Sus pruebas siembran el registro en `tmp_path`, así que siguen igual.

### C2 · Contrato `ToolGuide` (Pydantic, `coaching/worksheet/guide.py`)

Forma YAML que acepta (extensión de la hoja; todo lo demás de la hoja se ignora):

```yaml
guide:
  steps:
    - id: necesidad                       # slug: ^[a-z0-9]+(-[a-z0-9]+)*$
      question: "¿Qué necesidad de tu Cliente central llena tu producto?"
      how: "Una frase: el problema que tiene y qué cambia cuando te compra."
      example: "Tortillería El Sol: la fonda de la esquina necesita tortilla caliente a las 13:00 todos los días, sin ir a buscarla."
tips:
  - text: "Describe a una persona real: qué quiere lograr y qué teme."
    source: "work/research/e87-tips/core-customer.md#f1"
    step: quien-es                        # opcional; null = tip de toda la hoja
ai_prompt:
  text: "<paráfrasis en español del prompt>"   # opcional
view:
  layout: cards                           # cards | canvas
  sections:
    - title: "Quién es"
      steps: [quien-es, atributos]
derived_from: []                          # solo forma; la lógica es de S87.7
```

Modelos (todos `ConfigDict(extra="forbid")`, salvo `ToolGuide` que usa `extra="ignore"` porque recibe la hoja entera):

| Modelo | Campos | Reglas |
|---|---|---|
| `GuideStep` | `id`, `question`, `how`, `example` | `id` slug; los otros 3 con `min_length=1` tras `strip` |
| `Guide` | `steps: list[GuideStep]` | `min_length=1`; ids únicos |
| `Tip` | `text`, `source`, `step: str \| None = None` | `text` y `source` no vacíos |
| `AiPrompt` | `text` | no vacío. **Sin `page`**: `extra="forbid"` lo rechaza (addendum C2) |
| `ViewSection` | `title`, `steps: list[str]` | `steps` no vacío |
| `ViewSpec` | `layout: Literal["cards","canvas"] = "cards"`, `sections: list[ViewSection] = []` | — |
| `DerivedSource` | `sheet`, `fields: list[str]`, `into`, `required: bool = True` | solo forma (S87.7 valida contra el registro) |
| `ToolGuide` | `guide`, `tips`, `ai_prompt: AiPrompt \| None = None`, `view: ViewSpec = ViewSpec()`, `derived_from: list[DerivedSource] = []` | ver abajo |

Reglas de `ToolGuide` (`model_validator(mode="after")`):

1. `tips` tiene al menos 3 elementos (`min_length=3`). Cada uno ya exige `source`.
2. Todo `tip.step` no nulo es un `id` de paso.
3. Todo paso nombrado en `view.sections` existe.
4. Si `view.sections` no está vacío, cada paso aparece en al menos una sección. Así la vista muestra todo. Si está vacío, la vista arma una sección por paso.
5. No hay `source.pages` ni `ai_prompt.page` en ningún modelo (addendum C2).

`parse_guide(content: dict[str, Any]) -> ToolGuide | None`: devuelve `None` si la hoja no trae la llave `guide`. Si la trae, `ToolGuide.model_validate(content)` y deja subir el `ValidationError`.

Ejemplos:

| Entrada | Resultado |
|---|---|
| paso `promesa-principal` sin `example` | `ValidationError` |
| 2 tips con fuente | `ValidationError` (menos de 3) |
| tip sin `source` | `ValidationError` |
| `ai_prompt: {text: "…", page: 20}` | `ValidationError` (`page` no permitido) |
| `tip.step: nadie` y no hay paso `nadie` | `ValidationError` |
| `worksheet-face` (solo `metadata.fields`) | `parse_guide` → `None`; la hoja carga como hoy |

### C3 · Fuentes de tips y frontera pública (decisión D5)

- La regla de vocabulario **no** se codifica en `guide.py`. Escribir los términos prohibidos en `coaching/` rompería la regla.
- La frontera la cuida la prueba que ya existe, `tests/test_public_boundary.py`, que revisa el texto de `conocimiento/`. Esta historia agrega un caso dirigido en `tests/` (no público): cada `tip.source` de toda hoja con `guide` es un ancla `work/research/e87-tips/<herramienta>.md#f<N>` que existe en ese archivo, **o** una fuente que no tiene ningún término de `vocabulary_rules`. La prueba lee los términos de `governance/public-boundary.yaml`; no los escribe.
- Ejemplo: `source: "https://<sitio del libro>/blog/…"` en una hoja → la prueba falla y nombra la hoja. `source: "work/research/e87-tips/core-customer.md#f1"` → pasa, porque el ancla `<a id="f1">` existe.
- Solo se copian hallazgos con `triangulated: true` (f1-f5 de core-customer; f6 no).

### C4 · Motor: pasos guiados

- Función privada `_steps(content) -> list[GuideStep]`: si `parse_guide(content)` no es `None`, sus pasos; si no, un paso por texto de `metadata.fields` con `id` = el texto, `question` = el texto, `how` = "", `example` = "". Las dos ramas de `start` y `step` usan solo esta lista.
- Un paso guiado muestra:
  ```
  ### Paso 2: ¿Quién es tu Cliente central?
  **Cómo llenarlo:** …
  **Ejemplo:** Tortillería El Sol: …
  **Tips:**
  - … (fuente: work/research/e87-tips/core-customer.md#f1)
  ```
  Tips del paso + tips con `step: null` en el primer paso. Un paso de hoja vieja se ve como hoy.
- Si `guide` es inválido, `start` devuelve `errors: ["La hoja <id> no cumple el contrato: <mensaje>"]` y no escribe estado.
- `total_steps = len(steps) + 1`, igual que hoy.

### C5 · Vista (`coaching/worksheet/view.py`, `# pyright: strict`)

```python
VIEWS_DIR = Path(".escala") / "my-company" / "vistas"

class ViewItem(BaseModel):      # extra="forbid"
    label: str                  # question del paso (o el texto del campo viejo)
    answer: str | None          # None → "Falta"
    how: str

class ViewBlock(BaseModel):
    title: str
    items: list[ViewItem]

class SheetView(BaseModel):
    sheet_id: str
    title: str
    layout: Literal["cards", "canvas"]
    made_on: date
    blocks: list[ViewBlock]

def build_view(content: dict[str, Any], answers: dict[str, Any], made_on: date) -> SheetView
def render_html(view: SheetView) -> str
def render_markdown(view: SheetView) -> str
def view_path(base: Path, view: SheetView, suffix: str) -> Path
def save_view(base: Path, view: SheetView) -> list[Path]          # [html, md]
def open_command(html: Path, platform: str) -> list[str] | None
```

- **Desviación de la épica (C3):** la épica escribe `render_html(sheet, answers)` y `save_view(base, sheet, answers, made_on)`. Se usa el patrón de E84 (`build_board → Board → render_*`): primero `build_view` arma un modelo; luego se renderiza. Razón: una sola función decide qué se muestra, y HTML y MD no pueden diferir.
- `build_view`: título = `name_es` o `name`. Bloques = `view.sections` (o uno por paso). Una respuesta vacía, ausente o solo espacios da `answer=None`. Todo texto pasa por `safe_text` (texto con `http`, `<script`, `src=`… se cambia por `HIDDEN`).
- Texto de un campo vacío: `"Falta: <label>. Cómo llenarlo: <how>"`; sin `how` (hoja vieja): `"Falta: <label>."`.
- HTML: `<!doctype html>`, `lang='es'`, meta viewport, `<style>{BASE_CSS}{_SHEET_CSS}</style>`, `LOCAL_ONLY` arriba, `<h1>`, subtítulo "Hecho el 20 de octubre de 2026." con `spanish_date`.
  - `cards`: una `<section class='card'>` por bloque, en una columna (`main` de 640px, como el tablero).
  - `canvas`: `<main class='wide'>` con `<div class='canvas'>`; CSS `.canvas{display:grid;grid-template-columns:repeat(auto-fit,minmax(240px,1fr));gap:12px}` y `main.wide{max-width:1100px}`. En el teléfono `auto-fit` deja una columna sin media query.
  - Sin JavaScript, CDN, fuentes, imágenes ni `url(`. Termina en `\n`.
- MD: el mismo contenido en el mismo orden: `> LOCAL_ONLY`, `# título`, subtítulo, `## bloque`, `- **label**: respuesta` o `- Falta: …`.
- Determinista: sin hora, sin `dict` sin ordenar, sin rutas absolutas dentro del HTML. Mismos datos y misma fecha → mismos bytes.
- `view_path`: `<base>/.escala/my-company/vistas/AAAA-MM-DD-<sheet_id>.<suffix>`.
- `save_view` escribe HTML y MD con `atomic_write`. No rechaza una hoja vacía: una vista con todo "Falta" sirve para ver qué falta.
- `open_command`: `"darwin"` → `["open", str(html)]`; si `platform.startswith("linux")` → `["xdg-open", str(html)]`; otro → `None`. Pura; **ningún módulo ejecuta el comando** (D6 de la épica).

### C8 · `escala-skills/escala-worksheet/SKILL.md` (reescritura)

Pasos:

1. Listar (`action: list`).
2. Empezar o reanudar (`start` / `resume`). Mostrar pregunta, cómo, ejemplo y tips tal como vienen en `output`.
