# S40.2: Visual Cockpit and Pain Drill-Down — Design

## Complexity

Complex: a typed projection, deterministic artifact renderer, HTML escaping and authority-checked writes cross three modules, but no network or framework is added.

## Gemba and legacy sweep

`coaching.dashboard` renders Markdown from legacy YAML and has no source IDs, freshness or drill-down. Existing E38/E39 report modules write local artifacts after validating `WorkspaceConfig` and use redacted receipts. E40 should compose those conventions rather than modify every legacy dashboard. No executive cockpit model or writer exists.

## Approach

Add `cockpit.py` with `build_cockpit`, `render_cockpit_html`, `render_cockpit_json` and `write_cockpit`. The builder selects the lowest supported score in stable decision order, never selecting an evidence-limited decision as a pain claim when a supported alternative exists. Cards carry score/status/freshness/evidence count. The writer calls `validate_workspace`, writes a deterministic HTML and JSON pair atomically beneath `data_root/.escala-executive/`, and returns only relative artifact names.

## Concrete examples

```python
cockpit = build_cockpit(diagnostic)
assert cockpit.focus_decision == "cash"
assert cockpit.drill_down.source_ids == ("cash-source",)

artifact = write_cockpit(config, cockpit)
assert artifact.html_path == ".escala-executive/cockpit.html"
assert "/" not in artifact.json_path
```

## Acceptance criteria

### MUST

- Focus identifies the highest supported pain and exposes evidence, freshness, blockers, questions and next action.
- Every decision card includes a current score/status; evidence-limited cards remain visibly limited.
- HTML is escaped, deterministic and local; JSON contains only stable safe fields.
- Invalid workspace authority fails before any file is written.

### MUST NOT

- Write to `exchange_root`, create SQLite, call a network service or include raw source text/machine paths.
- Treat missing evidence as a score of zero or a negative person/team finding.
