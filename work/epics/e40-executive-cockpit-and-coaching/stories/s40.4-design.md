# S40.4: Persistent Execution and Honest Guidance — Design

## Complexity

Moderate: a closed execution snapshot, atomic local writer/reader and guidance projection; no external system or schema migration.

## Gemba and legacy sweep

Legacy `coaching.summary`, `coaching.progress` and `escala_server/session` expose summaries and SQLite DAOs, but their payloads are open dictionaries and do not enforce E37 authority at this seam. E38/E39 writers establish atomic local JSON and redacted relative receipts. E40 will add a small derived execution snapshot that composes the typed profile/diagnostic/strategy contracts without changing legacy session commands.

## Approach

Define immutable `Goal`, `Priority`, `ExecutionTask`, `SessionContinuity` and `ExecutionState` models. `save_execution_state` validates `WorkspaceConfig`, atomically writes `.escala-executive/execution.json` below `data_root` and returns a safe `StateReceipt`; `load_execution_state` validates the same boundary before reading. `build_honest_guidance` accepts explicit facts/inferences/unknowns and returns a status plus material questions; it never synthesizes a missing company value.

## Concrete examples

```python
state = ExecutionState(
    goals=(Goal(id="g1", title="Cobrar cartera", owner="Ana", due_date="2026-08-01", progress=40),),
    continuity=SessionContinuity(session_id="s1", next_prompt="Confirmar CCC"),
)
receipt = save_execution_state(config, state)
assert load_execution_state(config) == state

guidance = build_honest_guidance(GuidanceRequest(
    topic="cash",
    facts=("Ventas de junio: 1.2M",),
    inferences=("Cobranza podría ser el cuello de botella",),
    unknowns=("cash_conversion_cycle",),
))
assert guidance.status == "evidence_limited"
```

## Acceptance criteria

### MUST

- Goals/priorities/tasks/continuity retain owners, due dates, progress and stable IDs across a local round trip.
- Writes validate installer-machine authority and never target exchange/database state.
- Guidance preserves facts/inferences/unknowns and asks material questions for unknowns.
- Corrupt/invalid state fails explicitly without an invented fallback.

### MUST NOT

- Use timestamps, machine paths or cloud endpoints as required state fields.
- Convert an inference or unknown into a fact, score or person judgment.
