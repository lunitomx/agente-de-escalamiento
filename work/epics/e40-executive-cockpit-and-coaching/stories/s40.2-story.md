# Story: Visual Cockpit and Pain Drill-Down

## User Story

Como director,
quiero ver un cockpit local con mis cuatro scores y abrir el dolor principal hasta su evidencia,
para decidir qué pregunta responder y qué acción tomar sin depender de una UI hospedada.

## Acceptance Criteria

### Scenario: pain drill-down
```gherkin
Given a diagnostic with supported scores and a lower Cash score with a blocker
When build_cockpit runs
Then Cash is the pain focus and the drill-down contains its evidence, blocker, question/action and freshness
```

### Scenario: visual artifact
```gherkin
Given a valid installer-local WorkspaceConfig and an ExecutiveCockpit
When write_cockpit runs
Then HTML and JSON are written under data_root with relative paths and no exchange/database writes
```

### Scenario: evidence-limited cockpit
```gherkin
Given a diagnostic with missing Strategy evidence
When render_cockpit_html runs
Then the cockpit labels Strategy as evidence-limited and does not show it as a failing score
```

## Examples

| Input | Action | Expected Output |
|-------|--------|-----------------|
| People 64, Strategy 51, Execution 73, Cash 42 + blocker | `build_cockpit` | `focus_decision=cash`, `recommended_action` present |
| `WorkspaceConfig(data_root=data, exchange_root=exchange)` | `write_cockpit` | `.escala-executive/cockpit.html` and `.json` below data root |
| HTML value `<script>` | `render_cockpit_html` | escaped text, no executable markup |

## Notes

E40 remains local-only. This story consumes S40.1 models and E37 authority; it does not add a web server, browser automation, cloud API or database migration.
