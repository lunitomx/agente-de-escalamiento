# S40.1: Guided Onboarding and Diagnostic — Design

## Complexity

Complex: five typed boundaries (profile, evidence, answer, assessment, diagnostic) and fail-closed aggregation, but no external integration or storage.

## Gemba and legacy sweep

`coaching/welcome` validates only three fields and writes a timestamped YAML profile; `coaching/diagnose` asks 1–5 questions but stores no source/evidence state. `coaching/router` supplies the four decision vocabulary. E37–E39 models prove the repository convention of immutable Pydantic contracts and redacted provenance. No existing 0–100 evidence-backed contract exists, so a new `escala_server/executive/models.py` plus pure onboarding/diagnostic functions is warranted.

## Approach

Create pure functions that accept tuples of typed answers. Profile answers have explicit state (`fact`, `inference`, `unknown`) and questions. Diagnostic answers are attributed either to a stable source ID or an explicit `owner_input` locator; a decision is `supported` only when at least one usable answer has attribution. Average scores are rounded deterministically and bounded to 0–100. Missing/ambiguous decisions return `evidence_limited` and material questions without a negative score.

## Concrete examples

```python
profile = build_company_profile((
    ProfileAnswer(key="company_name", value="Nopal Foods", status="fact"),
    ProfileAnswer(key="critical_number", value=None, status="unknown"),
))
assert profile.status == "needs_clarification"
assert "critical_number" in profile.unresolved_fields

diagnostic = build_diagnostic((
    DiagnosticAnswer(decision="cash", score=42, source_ids=("fin-001",)),
))
assert diagnostic.assessment_for("cash").score == 42
assert diagnostic.assessment_for("cash").evidence_status == "supported"
assert diagnostic.assessment_for("people").evidence_status == "evidence_limited"
```

## Acceptance criteria

### MUST

- Profile validation preserves facts, inferences, unknowns and material questions.
- Exactly the four decision keys are emitted in stable order; supported scores are integers in 0–100.
- Every supported assessment has attribution, freshness and evidence count; missing data is evidence-limited.
- Invalid input, arbitrary model fields and path-bearing evidence fail closed.

### MUST NOT

- Read or write files, call network services or inspect transcripts in this story.
- Infer a company score or a person judgment from absence alone.
