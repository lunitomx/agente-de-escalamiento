# Retrospective: S40.4 — Persistent Execution and Honest Guidance

**Dates:** 2026-07-22 → 2026-07-22  
**Estimated:** M | **Actual:** one focused implementation cycle  
**Tests added:** 6

## Summary

S40.4 cierra el loop de E40 con una instantánea JSON derivada local para goals, priorities, tasks y session continuity, más un contrato de guidance que separa hechos, inferencias y desconocidos. La autoridad se valida antes de escribir y un JSON corrupto falla explícitamente en vez de inventar una sesión vacía.

## What went well

- El round-trip comprueba owners, fechas, progreso y preguntas, no solo que el archivo exista.
- `data_root` y exchange se probaron con el mismo negativo de SQLite usado por E37/E40.2.
- La guía conserva las tres categorías como listas estructuradas, lo que permite al director cuestionar una inferencia.

## What could be improved

- La instantánea derivada aún no se integra con los DAOs SQLite legacy; esa migración debe ser una decisión de esquema posterior, no un side effect de E40.
- La continuidad usa un `session_id` explícito y no una hora automática; esto mejora determinismo pero requiere que el caller lo provea.

## Heutagogical checkpoint

1. **¿Qué aprendí?** Persistencia confiable no significa guardar todo: significa guardar lo necesario con un límite de autoridad y poder volver a leerlo sin reinterpretación.
2. **¿Qué cambiaría del proceso?** Haría el negative test de corrupción desde el primer RED en cualquier snapshot local.
3. **¿Mejoras al framework?** Un helper común de atomic JSON + receipt reduciría repetición entre reuniones, cockpit y ejecución.
4. **¿En qué soy más capaz ahora?** Construir continuidad local que puede decir “no sé” y dejar una pregunta accionable, en vez de rellenar el contexto para parecer útil.

## Improvements applied

- Añadido `PersistenceError("state_invalid")` fail-closed.
- Receipts de ejecución solo exponen una ruta relativa y hash.
