# S64.2 — Integridad del release canónico

## User story

Como responsable de la ontología interna, quiero validar de forma fail-closed
la integridad del release canónico seguro de S64.1, para que E65 no consuma
referencias, relaciones o metadatos estructuralmente inválidos.

## Criterios de aceptación

```gherkin
Feature: Integridad del release canónico

  Scenario: Release sin relaciones publicadas
    Given un release S64.1 válido sin un manifiesto de relaciones público
    When se ejecuta el gate de integridad
    Then devuelve `not-assessed` y código de salida no-cero con el resultado
      explícito "no-relations-published"
    And no infiere relaciones a partir de nombres o fuentes

  Scenario: Relación inválida
    Given un manifiesto público de relaciones para S64.1
    When una relación apunta a un nodo inexistente o se duplica
    Then el gate falla cerrado y reporta sólo el identificador seguro

  Scenario: Contratos mínimos de dominio
    Given una herramienta, regla o métrica en el release
    When no declara la referencia segura requerida
    Then el gate falla por herramienta sin decisión, regla sin evidencia o
    métrica sin definición/unidad
```

## Guardrails

- Sólo consume releases, manifests y referencias opacas versionadas; nunca
  colas privadas, corpus, locators, rutas privadas o texto fuente.
- La ausencia de relaciones publicadas es un resultado explícito, no una
  afirmación de que el grafo esté completo.
- No cambia el release S64.1 ni crea relaciones inferidas.
- Todo error debe mencionar únicamente IDs, campos o reason codes seguros.
