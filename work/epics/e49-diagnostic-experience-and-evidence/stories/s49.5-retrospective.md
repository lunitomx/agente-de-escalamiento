# S49.5 Retrospective

## Summary

- Story: S49.5 — Resultado diagnóstico y ruta de 90 días
- Estimated size: M (5–8 SP)
- Actual: one focused implementation pass with export compatibility test fix

## What went well

- One `DiagnosticResult` feeds both Markdown and JSON, avoiding divergent
  scoring or route logic.
- The default route is deliberately limited to two actions and includes owner
  and metric slots rather than pretending they are known.
- Invalid input is rejected before local artifacts are created.

## What to improve

- A future story should add a local evidence detail view for the IDs shown in
  the result; copying raw source locations into reports would weaken privacy.
- Global RaiSE pattern/calibration persistence remains readonly in this
  checkout and is not claimed as complete.

## Heutagogical checkpoint

1. **Learned:** a result is trustworthy when all renderers consume one typed
   object, not when the Markdown looks complete.
2. **Process change:** test invalid artifact paths before adding presentation
   polish.
3. **Framework improvement:** every action route should expose an owner/metric
   slot and a limit, so recommendations remain bounded.
4. **Capability gained:** Escala can now leave a local, machine-readable,
   explainable handoff after a diagnostic.
