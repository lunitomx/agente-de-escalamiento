# Story: Contrato canónico de evidencia diagnóstica

## User Story

As the Escala coaching engine,
I want typed diagnostic evidence with applicability, provenance, freshness,
confidence, and stable IDs,
so that scores and recommendations can be explained without treating estimates
or non-applicable questions as facts.

## Acceptance Criteria

### Scenario: valid evidence serializes safely
```gherkin
Given a local evidence item with an answer, source, timestamp, and confidence
When it is validated and serialized
Then its stable ID and provenance fields are retained and no absolute path is emitted
```

### Scenario: not applicable is distinct from zero
```gherkin
Given a commercial question that does not apply because the company has no sellers
When the evidence is validated
Then applicability is not_applicable and the value is not coerced to zero
```

### Scenario: invalid provenance fails closed
```gherkin
Given an evidence locator outside the local `.escala/` authority
When the contract is validated
Then validation returns an error
```

## Examples (Specification by Example)

| Input | Action | Expected Output |
|-------|--------|-----------------|
| `applicability="applicable", status="estimate"` | Build evidence | Valid item with `confidence="medium"` or lower |
| `applicability="not_applicable"` | Build evidence | `included_in_score=False` |
| `locator="/Users/private.csv"` | Build evidence | Pydantic validation error |

## Notes

The contract must remain small and be consumed by scoring and result rendering;
it must not become a generic survey framework. See E49-1 and epic design.
