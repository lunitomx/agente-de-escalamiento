# S49.6 Design

## Approach

Add `coaching/diagnose/prefill.py` with a pure `build_prefill` and
`confirm_prefill`. It maps only known profile/OPSP fields into
`DiagnosticEvidence`; unknown fields are ignored rather than persisted, and
missing/old dates become visible questions.

## Components

| Component | Change |
|-----------|--------|
| `coaching/diagnose/prefill.py` | New typed prefill/confirmation logic |
| `coaching/diagnose/__init__.py` | Export prefill functions/models |
| `coaching/diagnose/tests/test_prefill.py` | Freshness, provenance, and confirmation tests |

## Data mutation strategy

No mutation. The function returns new models; the caller decides whether and
where to persist after human confirmation.
