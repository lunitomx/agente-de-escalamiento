## Summary

- Story: S49.6 — Prefill, frescura y ciclo de confirmación
- Estimated size: S (3–5 SP)

## What went well

- Prefill remains a proposal until explicit confirmation; no accidental write
  path was introduced.
- Source and freshness are visible in the same evidence model consumed by
  scoring.
- The allowlist prevents unrelated profile/OPSP keys from becoming diagnostic
  claims by accident.

## What to improve

- The eventual result renderer should show the confirmation status without
  exposing internal source references as implementation jargon.
- Global RaiSE pattern/calibration writes remain unavailable in this checkout's
  readonly shared DB.

## Heutagogical checkpoint

1. **Learned:** freshness is a lifecycle property, not a confidence synonym;
   a user confirmation can update capture time without hiding original source.
2. **Process change:** test stale and unknown dates before integrating prefill
   into scoring.
3. **Framework improvement:** make “proposed vs fact” a reusable acceptance
   vocabulary in future ingestion stories.
4. **Capability gained:** profile/OPSP context can enrich a diagnosis without
   silently overruling the user.
