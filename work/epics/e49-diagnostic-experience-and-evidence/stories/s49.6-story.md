# Story: Prefill, frescura y ciclo de confirmación

## User Story

As a returning Escala user,
I want existing profile/OPSP values shown with their source and freshness,
so that I can confirm or correct them before they influence a diagnosis.

## Acceptance Criteria

### Scenario: profile facts are proposed, not silently accepted
```gherkin
Given a local profile with company facts and a capture date
When prefill is built
Then each fact is marked inference with source and freshness visible
```

### Scenario: stale facts require confirmation
```gherkin
Given a profile older than the freshness window
When prefill is built
Then freshness is stale and a confirmation question is emitted
```

### Scenario: confirmation is explicit and pure
```gherkin
Given prefilled evidence IDs selected by the user
When confirmation is applied
Then only those items become facts and no file is written
```

## Examples

| Input | Action | Expected Output |
|-------|--------|-----------------|
| profile `updated=2026-08-19` | prefill | current, inference, profile source |
| profile `updated=2025-01-01` | prefill | stale and confirmation question |
| confirm `company.name` | apply | answer_status fact |
