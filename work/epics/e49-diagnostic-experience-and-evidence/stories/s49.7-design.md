# S49.7 Design

## Approach

Use a deterministic pytest dogfood fixture with temporary local authority. It
starts with `begin_welcome`, routes a concrete concern, builds a typed intake,
scores it, and calls `run_diagnostic`. The receipt records only structural
capabilities and synthetic values. Skill docs are updated as the integration
surface; no live browser or hosted call is part of acceptance.

## Components

| Component | Change |
|-----------|--------|
| `tests/test_e49_acceptance.py` | New synthetic end-to-end acceptance test |
| `escala-skills/escala-welcome/SKILL.md` | Document two-speed/provisional-value handoff |
| `escala-skills/escala-diagnose/SKILL.md` | Document evidence-aware score/result contract |
| `work/epics/e49.../evidence/e49-acceptance-2026-08-19.md` | Redacted receipt |

## Why analysis type

The story adds no production runtime module; it verifies the already-built
contract and records whether the epic's product promise is proven.
