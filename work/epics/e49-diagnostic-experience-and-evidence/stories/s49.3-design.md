# S49.3 Design

## Approach

Add `FunnelMetrics` and a pure `build_diagnostic_intake` function to the diagnose
domain. Keep all source values in `DiagnosticEvidence`; source-specific file
adapters remain outside this story and can feed the builder later.

## Components

| Component | Change |
|-----------|--------|
| `coaching/diagnose/models.py` | Add typed funnel and normalize intake field |
| `coaching/diagnose/intake.py` | New source-neutral intake builder |
| `coaching/diagnose/__init__.py` | Export builder/model |
| `coaching/diagnose/tests/test_intake.py` | Mixed-source and funnel boundary tests |

## Data mutation strategy

The builder is pure and never silently drops a supplied field: invalid values
raise Pydantic validation errors; absent optional values remain `None`.

## Value preservation

The domain intelligence is applicability/source/status semantics, not generic
pass-through. The builder keeps those distinctions visible for S49.4.
