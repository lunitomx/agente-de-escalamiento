# S49.2 Retrospective

## Summary

- Story: S49.2 — Walking skeleton de bienvenida conversacional
- Estimated size: M (5–8 SP)
- Actual: one focused implementation pass with one classifier correction

## What went well

- Tests forced the contract to keep internal routes separate from user-facing
  prompts.
- Reusing the existing decision classifier preserved the Four Decisions
  vocabulary while adding only the observed CCC/cash and sales terms.
- The resulting path reaches a source question after one answer instead of
  presenting a questionnaire wall.

## What to improve

- The classifier needs dogfood examples before it grows; generic keyword
  expansion would turn the walking skeleton into a taxonomy project.
- The global pattern/calibration writes remain blocked by the readonly RaiSE DB,
  as documented in S49.1.

## Heutagogical checkpoint

1. **Learned:** one-turn routing is more reliable when the prompt and internal
   route are separate values, so UI language can evolve without changing
   decision semantics.
2. **Process change:** add the no-command assertion at the first test, not as a
   late polish check.
3. **Framework improvement:** story design should treat prompt leakage as an
   explicit acceptance criterion for conversational skills.
4. **Capability gained:** we can route a real concern to a decision and next
   action without forcing the user to know Escala's internal catalog.
