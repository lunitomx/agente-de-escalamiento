# S49.5 Design

## Approach

Add a result builder in `coaching/diagnose/result.py` and a pure Markdown
renderer plus local writer in `coaching/export/diagnostic.py`. The writer uses
the existing `.escala/my-company/exports/` authority and writes a dated Markdown
file plus a JSON sidecar; it never calls a network service.

## Components

| Component | Change |
|-----------|--------|
| `coaching/diagnose/models.py` | Add route/result models |
| `coaching/diagnose/result.py` | Build bounded default route/result |
| `coaching/diagnose/__init__.py` | Export result builder |
| `coaching/export/diagnostic.py` | Render/write local result |
| `coaching/export/__init__.py` | Export diagnostic runner |
| `coaching/diagnose/tests/test_result.py` | Result/routing tests |
| `coaching/export/tests/test_diagnostic.py` | Artifact and renderer tests |

## Constraints

- Route generation is deterministic and limited to two actions.
- Existing action-plan export remains unchanged.
- Result JSON contains the same contract as Markdown; no hidden score logic in
  the renderer.
