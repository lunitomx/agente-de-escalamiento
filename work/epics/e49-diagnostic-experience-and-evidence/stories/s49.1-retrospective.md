# S49.1 Retrospective

## Summary

- Story: S49.1 — Canonical diagnostic evidence contract
- Estimated size: S (3–5 SP)
- Implementation result: typed Pydantic contract plus seven boundary tests
- Actual: one focused implementation pass; no code blocker

## What went well

- Reused the local locator safety principle already present in
  `coaching.evidence` instead of creating a second persistence boundary.
- RED tests caught the contract boundary before implementation.
- The existing diagnose API remained backward compatible; targeted diagnose
  tests stayed green.

## What to improve

- The repository has no readable `.raise/manifest.yaml`, so gates required
  explicit fallback commands and a task-specific `UV_CACHE_DIR`.
- Global RaiSE DB writes (`rai pattern add`) are blocked by the checkout's
  readonly shared database; the pattern is recorded here until a writable
  governance home is available.

## Heutagogical checkpoint

1. **Learned:** Pydantic's `Any` value is appropriate at the evidence boundary
   only when the surrounding status, applicability, and provenance fields are
   strict; otherwise an estimate looks like a fact.
2. **Process change:** Write the negative/N/A tests before choosing field names;
   this prevents a numeric-only score model from becoming the hidden contract.
3. **Framework improvement:** RaiSE story gates should surface readonly DB and
   missing manifest conditions as explicit non-blocking environment evidence.
4. **Capability gained:** We can now carry a safe, explainable evidence item
   from a conversational answer toward scoring without leaking absolute paths.

## Patterns

- Pattern intended for `rai pattern add`: diagnostic evidence must distinguish
  `not_applicable` and `unknown` from numeric scores, and every
  recommendation-supporting fact needs provenance, freshness, confidence, and a
  safe local or redacted reference.
- CLI persistence was attempted and failed with `OperationalError: attempt to
  write a readonly database`; no external pattern mutation was claimed.
