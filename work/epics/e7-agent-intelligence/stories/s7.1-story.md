# S7.1 — Session Lifecycle Pipeline

## User Story

**As** a ScaleUp user,
**I want** the agent to automatically load my company context when I start a session and save a session log when I close it,
**So that** the coaching experience has continuity between sessions without me repeating information.

## Size: M

## Acceptance Criteria

```gherkin
Feature: Session Lifecycle Pipeline

  Scenario: Start session with existing profile
    Given a user runs `/scaleup-start`
    When company profile exists in `.scaleup/my-company/profile.md`
    Then context is loaded and presented to the user
    And last 3 session summaries are shown (if previous sessions exist)

  Scenario: Start session without profile
    Given a user runs `/scaleup-start`
    When no company profile exists
    Then the user is redirected to `/scaleup-welcome`

  Scenario: Start session with previous sessions
    Given a user runs `/scaleup-start`
    When previous sessions exist in `.scaleup/my-company/sessions/`
    Then the last 3 sessions are summarized and presented

  Scenario: Close session with activity
    Given a user runs `/scaleup-close`
    When session has had activity
    Then a session log is written to `.scaleup/my-company/sessions/YYYY-MM-DD.md`
    And the log contains YAML frontmatter with date, duration, focus, and artifacts

  Scenario: Session log quality gate
    Given a session log is written
    Then a Python quality gate validates the YAML frontmatter schema
    And validation errors are reported before finalizing
```

## Technical Notes

- This is the first skill built with the orchestration pattern (each phase = subagent)
- `/scaleup-start` orchestrates sub-skills: load-profile, load-sessions, load-tasks, present-context
- `/scaleup-close` orchestrates sub-skills: capture, log, sync
- Quality gates are code-based (Python), not prompt-based
- Session log format: one file per session in `.scaleup/my-company/sessions/YYYY-MM-DD.md`
- YAML frontmatter fields: date, duration, focus, artifacts
