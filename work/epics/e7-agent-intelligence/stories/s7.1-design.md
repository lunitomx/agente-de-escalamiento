# S7.1 Design — Session Lifecycle Pipeline

## Problem & Value

**Problem:** Every session starts from zero. The user must re-explain their company, recall what they did last time, and manually track commitments. There is no continuity mechanism.

**Value:** `/scaleup-start` loads company context, recent sessions, and open tasks automatically. `/scaleup-close` captures session activity into a structured log. Together they create session continuity — the foundation every subsequent E7 story builds on.

**Architecture proof:** This story proves the orchestration pattern (ADR-0) — each phase as a subagent with code-based quality gates. If this pattern works, all of E7 follows it.

## Approach

### Orchestration Pattern

Each orchestrator skill is a SKILL.md that sequences sub-skills. The orchestrator:

1. Launches each phase as a **subagent** via Task tool, passing the sub-skill's SKILL.md path
2. Receives the subagent's artifact (file or structured output)
3. Runs a **Python quality gate** (code, not LLM) to validate the artifact
4. Passes minimal context to the next phase

The orchestrator never does substantive work — it sequences, validates, and routes.

**Concrete subagent invocation example:**

```
# Inside scaleup-start/SKILL.md, Step 2:
Launch subagent with Task tool:
  prompt: "Execute the skill at .claude/skills/scaleup-start-load-sessions/SKILL.md"
  context passed: "Company name: {company_name}. Sessions dir: .scaleup/my-company/sessions/"

# The subagent runs in its own inference context, reads files, produces output.
# Orchestrator receives the result and continues.
```

### `/scaleup-start` Pipeline

```
scaleup-start (orchestrator)
  │
  ├─ Phase 1: scaleup-start-load-profile
  │    → Reads .scaleup/agent/memory/company-profile.yaml
  │    → Produces: context bundle (company name, stage, scores, focus)
  │    → If profile empty/missing → HALT, redirect to /scaleup-welcome
  │
  ├─ Phase 2: scaleup-start-load-sessions
  │    → Reads .scaleup/my-company/sessions/*.md
  │    → Sorts filenames lexicographically (YYYY-MM-DD.md), takes last 3
  │    → Produces: summary of recent sessions (date, focus, key outcomes)
  │    → If no sessions exist → produces empty summary, continues
  │
  ├─ Phase 3: scaleup-start-load-tasks
  │    → Reads .scaleup/my-company/tasks.md
  │    → Parses sections: En Progreso, Próximo, Completado
  │    → Produces: task counts + list of in-progress items
  │
  ├─ Quality Gate: validate_context_bundle (Python)
  │    → Validates: profile has company name, scores are numeric
  │    → On failure: report what's missing, suggest /scaleup-welcome
  │
  └─ Phase 4: scaleup-start-present
       → Receives: profile data + session summaries + task state
       → Presents formatted context summary to user
       → Proposes session focus based on lowest score or pending tasks
```

### `/scaleup-close` Pipeline

```
scaleup-close (orchestrator)
  │
  ├─ Phase 1: scaleup-close-capture
  │    → Asks user: what did we work on? what decisions were made?
  │    → Collects: decision focus, worksheets touched, tasks created/completed
  │    → Produces: structured capture data
  │
  ├─ Phase 2: scaleup-close-log
  │    → Takes capture data
  │    → Writes session log to .scaleup/my-company/sessions/YYYY-MM-DD.md
  │    → Format: YAML frontmatter + markdown body (see schema below)
  │    → If file for today already exists: append suffix -2, -3, etc.
  │
  ├─ Quality Gate: validate_session_log (Python)
  │    → Validates YAML frontmatter has all required keys
  │    → Validates date format, duration is positive int
  │    → On failure: report errors, let orchestrator retry log phase
  │
  └─ Phase 3: scaleup-close-sync
       → Stub in S7.1: only ensures sessions/ directory exists
       → Full YAML→markdown rendering deferred to S7.2 (Persistent Memory)
```

### Session Log Schema (ADR-2, canonical)

```yaml
---
date: 2026-04-25
duration_minutes: 45
decision_focus: people
worksheets_completed: [core-values-worksheet]
tasks_created: [task-1, task-2]
tasks_completed: [task-0]
score_changes: {people: "2→3"}
---
## Session Notes
- What was discussed
- Decisions made
- Next steps identified
```

**Required fields:** `date`, `duration_minutes`, `decision_focus`
**Optional fields:** `worksheets_completed`, `tasks_created`, `tasks_completed`, `score_changes`

## Python Quality Gates

Location: `.scaleup/agent/validators/session.py`

```python
"""Quality gate validators for session lifecycle pipeline.

Code-based validation (ADR-5) — the LLM never evaluates its own output.
"""
from __future__ import annotations

import pathlib
import re
from datetime import date
from typing import Any

try:
    import yaml
except ImportError as e:
    raise ImportError("PyYAML required: pip install pyyaml") from e


_REQUIRED_FRONTMATTER = {"date", "duration_minutes", "decision_focus"}
_VALID_DECISIONS = {"people", "strategy", "execution", "cash"}
_FRONTMATTER_RE = re.compile(r"^---\s*\n(.+?)\n---", re.DOTALL)


def validate_session_log(log_path: pathlib.Path) -> list[str]:
    """Validate a session log file. Returns list of errors (empty = valid)."""
    errors: list[str] = []

    if not log_path.exists():
        return [f"File not found: {log_path}"]

    text = log_path.read_text(encoding="utf-8")

    # Extract YAML frontmatter
    match = _FRONTMATTER_RE.match(text)
    if not match:
        return ["No YAML frontmatter found (must start with ---)"]

    try:
        frontmatter: dict[str, Any] = yaml.safe_load(match.group(1))
    except yaml.YAMLError as exc:
        return [f"Invalid YAML in frontmatter: {exc}"]

    if not isinstance(frontmatter, dict):
        return ["Frontmatter is not a mapping"]

    # Required keys
    missing = _REQUIRED_FRONTMATTER - frontmatter.keys()
    if missing:
        errors.append(f"Missing required keys: {', '.join(sorted(missing))}")

    # date validation
    if "date" in frontmatter:
        d = frontmatter["date"]
        if not isinstance(d, date):
            errors.append(f"'date' must be a valid date, got: {d!r}")

    # duration_minutes validation
    if "duration_minutes" in frontmatter:
        dur = frontmatter["duration_minutes"]
        if not isinstance(dur, int) or dur <= 0:
            errors.append(f"'duration_minutes' must be a positive integer, got: {dur!r}")

    # decision_focus validation
    if "decision_focus" in frontmatter:
        focus = frontmatter["decision_focus"]
        if focus not in _VALID_DECISIONS:
            errors.append(
                f"'decision_focus' must be one of {_VALID_DECISIONS}, got: {focus!r}"
            )

    return errors


def validate_context_bundle(
    profile_path: pathlib.Path,
) -> list[str]:
    """Validate that company profile has minimum required data.

    Returns list of errors (empty = valid).
    """
    errors: list[str] = []

    if not profile_path.exists():
        return [f"Profile not found: {profile_path}"]

    try:
        data: dict[str, Any] = yaml.safe_load(
            profile_path.read_text(encoding="utf-8")
        )
    except yaml.YAMLError as exc:
        return [f"Invalid YAML: {exc}"]

    if not isinstance(data, dict):
        return ["Profile is not a mapping"]

    company = data.get("company", {})
    if not company.get("name"):
        errors.append("Company name is empty — run /scaleup-welcome first")

    scores = data.get("scores", {})
    for key in ("people", "strategy", "execution", "cash"):
        val = scores.get(key)
        if val is not None and not isinstance(val, (int, float)):
            errors.append(f"Score '{key}' must be numeric, got: {val!r}")

    return errors
```

## Decisions Made During Design

### D1: Sub-skill naming convention

**Problem:** Three sources used inconsistent names (`load-profile` vs `scaleup-start-load` vs inline).

**Decision:** Use fully namespaced names: `scaleup-start-load-profile`, `scaleup-start-load-sessions`, etc. Each sub-skill gets its own directory under `.claude/skills/`. Names are unique, greppable, and indicate their parent orchestrator.

**Reason:** `.claude/skills/` is a flat directory. Names like `load-profile` would collide when other orchestrators need similar sub-skills.

### D2: Session log schema — canonical version

**Problem:** `s7.1-story.md` says minimal schema (`date, duration, focus, artifacts`); ADR-2 in `design.md` specifies a richer schema.

**Decision:** ADR-2 is canonical. Required fields: `date`, `duration_minutes`, `decision_focus`. Optional fields: `worksheets_completed`, `tasks_created`, `tasks_completed`, `score_changes`. Story.md was stale.

### D3: Scope boundary with S7.2 (sync sub-skill)

**Problem:** `scaleup-close-sync` could overlap with S7.2's `scaleup-memory-render` (YAML to markdown).

**Decision:** In S7.1, `scaleup-close-sync` is a stub — it only ensures the `sessions/` directory exists and the log file was written. Full YAML-to-markdown rendering of company profile and other state files belongs to S7.2.

### D4: Validator location

**Decision:** All session-related validators live in `.scaleup/agent/validators/session.py`. This parallels `.scaleup/knowledge/retrieval.py` for the knowledge graph. Future validators (task board, memory) go in the same directory.

### D5: "Last 3 sessions" retrieval rule

**Decision:** Lexicographic sort on filenames in `.scaleup/my-company/sessions/`, take the last 3. Since filenames are `YYYY-MM-DD.md`, lexicographic order equals chronological order. No LLM judgment needed.

### D6: Subagent launch mechanism

**Decision:** Orchestrator launches each sub-skill as a subagent via the Task tool, passing the sub-skill's SKILL.md path as instruction. Each subagent gets its own inference context (per ADR-0). The orchestrator passes only the minimal data the subagent needs — not the entire conversation history.

## Complexity Assessment

**Moderate** — 10 new components (2 orchestrators, 7 sub-skills, 1 Python module), custom orchestration logic, but no external integrations and no complex data transforms. The risk is in proving the orchestration pattern, not in the individual components.
