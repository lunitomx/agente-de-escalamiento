# S27.3 — Tests de resiliencia

**Epic:** E27 — Resiliencia Runtime
**Size:** S (1h)
**Status:** Draft
**Dependencies:** S27.1, S27.2

## Objetivo

Agregar tests de integración que verifiquen que el servidor sobrevive a errores y sigue respondiendo. Actualmente 0 tests de este tipo.

## Archivos

- `tests/test_server_resilience.py` (nuevo)

## Tests

1. **test_invalid_json_returns_400:** Iniciar server en `localhost:0` (puerto aleatorio). POST con body `{invalid`. Verificar status 400 y JSON de error.

2. **test_handler_exception_returns_500:** Mockear un handler para que lance `RuntimeError`. POST válido. Verificar status 500.

3. **test_server_survives_error:** POST con error → 400. Inmediatamente GET `/api/health` → 200. El servidor sigue vivo.

4. **test_cors_default_restrictive:** GET con `Origin: https://evil.com`. Verificar que `Access-Control-Allow-Origin` NO es `*`.

## Criterios de Aceptación

- [ ] 4 tests pasan
- [ ] Tests no dejan procesos huérfanos (usar `atexit` o `try/finally` para shutdown)
- [ ] Puerto aleatorio (`port=0`) para no colisionar con servidor corriendo

## Trampas

- `make_server` retorna `HTTPServer` — llamar `server.shutdown()` en cleanup
- Usar `threading.Thread` para correr server en background durante el test
- `time.sleep(0.1)` después de iniciar para dar tiempo al socket
