# S27.1: Error handling en handlers HTTP

**As a** usuario del dashboard de Escala
**I want** que el servidor no se caiga cuando hay un error
**So that** siempre vea una respuesta clara, no una pantalla blanca

## Gherkin

**Scenario 1: JSON malformado**
- GIVEN el servidor está corriendo
- WHEN envío un POST con body `{invalid`
- THEN recibo status 400 y `{"status": "error", "message": "Invalid JSON"}`

**Scenario 2: Handler lanza excepción**
- GIVEN el servidor está corriendo
- WHEN un handler lanza `ValueError` internamente
- THEN recibo status 500 y `{"status": "error", "message": "Internal server error"}`

**Scenario 3: Servidor sobrevive al error**
- GIVEN ocurrió un error en un request
- WHEN envío un GET a `/api/health`
- THEN recibo status 200 y `{"status": "ok"}`

## Acceptance Criteria

- [ ] POST con `{invalid` → 400 (MUST)
- [ ] Handler exception → 500 sin traceback (MUST)
- [ ] GET /api/health sigue funcionando después de error (MUST)
- [ ] Tests existentes pasan sin cambios (MUST)
- [ ] `KeyboardInterrupt` y `SystemExit` NO se capturan (MUST NOT)
