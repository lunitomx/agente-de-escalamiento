# S27.1 — Error handling en handlers HTTP

**Epic:** E27 — Resiliencia Runtime
**Size:** S (1h)
**Status:** Draft

## Objetivo

Agregar try/except en `do_POST` y `do_PATCH` de `EscalaRequestHandler` para evitar que excepciones no capturadas crasheen el worker thread del servidor.

## Archivos

- `escala_server/server.py` (líneas 50-68)

## Cambios

1. Extraer lógica común de `do_POST` y `do_PATCH` a un método `_handle_api_request(self, method)`:
   - Parsear body como JSON
   - Envolver en try/except
   - `json.JSONDecodeError` → `_send_json_error(400, "Invalid JSON")`
   - `Exception` → `_send_json_error(500, "Internal server error")`

2. Modificar `do_POST` y `do_PATCH` para delegar al nuevo método.

3. `do_GET` NO se modifica — solo hace dispatch sin parseo de body.

## Criterios de Aceptación

- [ ] POST a `/api/companies` con body `{invalid` devuelve 400 y `{"status": "error", "message": "Invalid JSON"}`
- [ ] Handler que lanza `ValueError` devuelve 500 (sin traceback en respuesta)
- [ ] Servidor sigue aceptando requests después del error
- [ ] Tests existentes pasan sin cambios

## Trampas

- `http.server` crea un thread por request — el error mata el thread, no el proceso. Pero sin handler, el cliente recibe conexión cerrada sin respuesta. Con fix, recibe JSON de error.
- No capturar `KeyboardInterrupt` ni `SystemExit` — esos deben propagarse.
