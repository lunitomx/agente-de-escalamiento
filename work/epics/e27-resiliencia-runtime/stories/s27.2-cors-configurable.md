# S27.2 — CORS configurable

**Epic:** E27 — Resiliencia Runtime
**Size:** S (1h)
**Status:** Draft

## Objetivo

Hacer que los orígenes CORS permitidos sean configurables por CLI. Default: solo `localhost`. Si el usuario explícitamente pasa `--cors-origins *`, advertir en stderr.

## Archivos

- `escala_server/cors.py` — `CORSHandler` acepta lista de orígenes
- `escala_server/server.py:157-191` — `make_server` pasa orígenes al handler
- `escala_server/__main__.py` — nuevo argumento `--cors-origins`

## Cambios

**cors.py:**
```python
class CORSHandler:
    def __init__(self, origins: list[str] | None = None):
        self._origins = origins or ["http://localhost:8080"]
    
    def get_headers(self) -> dict[str, str]:
        return {"Access-Control-Allow-Origin": ", ".join(self._origins), ...}
```

**__main__.py:**
```python
parser.add_argument("--cors-origins", nargs="*", default=["http://localhost:8080"])
```

## Criterios de Aceptación

- [ ] Default: `curl -H "Origin: https://evil.com" http://localhost:8080/api/health` → sin `Access-Control-Allow-Origin` para evil.com
- [ ] Con `--cors-origins *`: advierte en stderr "WARNING: CORS allow all origins"
- [ ] Con `--cors-origins https://miapp.com`: solo ese origen en header

## Trampas

- Si es herramienta solo local, esto es defensa en profundidad. Si el servidor solo escucha en `localhost`, CORS es irrelevante (el browser ni siquiera permite cross-origin a localhost desde origen remoto).
