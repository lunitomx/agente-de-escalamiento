# S27.1 Design: Error handling HTTP

**Complexity:** Simple (1 file, trivial logic)

## Problem
`do_POST` y `do_PATCH` en `EscalaRequestHandler` no capturan excepciones. Un `json.JSONDecodeError` o un handler que lance `ValueError` crashea el worker thread — el cliente recibe conexión cerrada sin respuesta.

## Value
El dashboard de Escala nunca muestra pantalla blanca. Errores controlados = confianza del usuario.

## Approach
Extraer lógica duplicada de `do_POST` y `do_PATCH` a `_handle_api_request(self, method)`. Envolver en try/except. Delegar desde `do_POST`/`do_PATCH`.

## Components

| Component | Change | Purpose |
|-----------|--------|---------|
| `escala_server/server.py` L50-68 | Modify | Agregar `_handle_api_request`, simplificar `do_POST`/`do_PATCH` |

## Design Decisions

| ID | Decision | Rationale |
|----|----------|-----------|
| D1 | Extraer a método privado | Evita duplicación entre do_POST y do_PATCH |
| D2 | No tocar do_GET | do_GET no parsea body, no tiene riesgo de JSONDecodeError |
| D3 | Capturar Exception, no BaseException | KeyboardInterrupt y SystemExit deben propagarse |
| D4 | Mensaje genérico en 500 | No leak de traceback al cliente |

## Legacy Sweep
Nada queda huérfano — es refactor interno, API externa no cambia.

## Examples

**Success (sin cambios):**
```
POST /api/companies {"name": "Test"}
→ 200 {"data": {...}, "status": "ok"}
```

**Error: JSON inválido:**
```
POST /api/companies {invalid
→ 400 {"status": "error", "message": "Invalid JSON"}
```

**Error: handler lanza:**
```
POST /api/worksheets/cash/test {"data": null}
→ 500 {"status": "error", "message": "Internal server error"}
```

## Acceptance Criteria

- [ ] MUST: POST con `{invalid` → 400
- [ ] MUST: Handler exception → 500 (sin traceback)
- [ ] MUST: `GET /api/health` → 200 después de error
- [ ] MUST: Tests existentes pasan
- [ ] MUST NOT: KeyboardInterrupt capturado

## Testing Strategy

- Unit: `TestRouter` y `TestCORSHandler` existentes deben pasar
- Nuevo test: `test_invalid_json_returns_400` — iniciar server, POST con body inválido
- Nuevo test: `test_server_survives_error` — POST error → GET health → 200
