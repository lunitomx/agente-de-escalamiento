# S58.2 — Diseño

`CandidateNode` contiene un nodo propuesto aún no canónico. `ReviewQueue`
valida unicidad, referencias y una sola decisión por candidato. `ReviewDecision`
prohíbe conservar estado `candidate` y exige evidencia si aprueba.

La cola canónica inicia vacía: no se rellena con los activos E6 ni con
inferencias. S58.3 será la única historia autorizada para convertir inventario
heredado en candidatos/migraciones explícitas.
