## Overview

S14.1 is the **walking skeleton** for all E14–E17 visual dashboards. It establishes the framework (Vanilla HTML/CSS/JS + Chart.js v4 vendored), the shared CSS token system, and delivers the first self-contained dashboard: the CASh Board (Cash Acceleration Strategies).

Every downstream story (S14.2, S14.3, S14.4, E15–E17) depends on the vendor file and base CSS created here. This makes T1 and T2 the highest-impact tasks in the epic.

**Framework decision:** D1 — Vanilla HTML/CSS/JS + Chart.js v4 vendored locally (no build step).
**Key constraint:** Dashboard is read-only. Data entry stays in the coaching skill flow.
**Self-contained:** Each `index.html` references `../shared/vendor/chart.umd.min.js` via relative path.

### T2: Shared Base CSS

**Description:** Create `components/shared/styles/dashboard-base.css` with all shared CSS custom properties, semáforo classes, and responsive grid utilities. This file is the single source of truth for all visual tokens used across E14–E17.

**Must include:**

   - Spacing tokens: `--space-xs`, `--space-sm`, `--space-md`, `--space-lg`
   - Border radius: `--radius-sm`, `--radius-md`
   - Font: system-ui stack (no external font dependency)

2. **Semáforo classes:**
   - `.semaforo-green` — background-color: var(--color-green)
   - `.semaforo-yellow` — background-color: var(--color-yellow)
   - `.semaforo-orange` — background-color: var(--color-orange)
   - `.semaforo-red` — background-color: var(--color-red)

   - `.metric-value` — large numeric display
   - `.metric-label` — small label below metric

**Verification:**

### T3: CASh Board HTML

**Description:** Create `components/cash-board/index.html` — the complete, self-contained CASh dashboard. This is the primary deliverable of S14.1.

**Files to create:**
- `work/epics/e14-cash-dashboards/components/cash-board/index.html`

**Structure:**

1. **HTML head:**
   - `<link rel="stylesheet" href="../shared/styles/dashboard-base.css">`
   - `<script src="../shared/vendor/chart.umd.min.js"></script>` (no-op if file not used in S14.1; included for compatibility)
   - Inline `<style>` for grid specific to this dashboard (4 row × 3 col layout)

2. **Inline JS data object** (`window.CASH_DATA`) matching the JSON contract from design §5:
   - 4 cycles: sales, production, delivery, billing
   - Each cycle: `id`, `label`, `label_es`, `current_days`, `benchmark_days`, `strategies` (shorten/eliminate/improve with description + `potential_days_saved`)
   - Totals: `current_ccc_days`, `target_ccc_days` (81), `potential_improvement_days`
   - Seed with representative demo data (not all zeros) so traffic lights show at least two colors on first render

3. **Dashboard grid layout:**
   - **Header row:** Company name + date + Total CCC + grand-total traffic light dot
   - **Column headers row:** empty label column + "Acortar (Shorten)" + "Eliminar (Eliminate)" + "Mejorar (Improve)"
   - **4 cycle rows:** left column = cycle name + traffic light dot + current_days + benchmark_days + CSS progress bar; three strategy columns = description + potential_days_saved
   - **Footer (grand total CCC row):** spanning full width, total CCC days + target + traffic light + potential improvement days

4. **Traffic light JS function** `getTrafficLight(cycleId, days)`:
   - Returns class string (`semaforo-green`, `semaforo-yellow`, `semaforo-orange`, `semaforo-red`, `semaforo-gray`)
   - When `days === 0` → always returns `semaforo-gray` (placeholder mode)
   - Per-cycle thresholds from design §6:
     - Sales: ≤30 green, 31–60 yellow, >60 red
     - Production: ≤14 green, 15–30 yellow, >30 red
     - Delivery: ≤7 green, 8–14 yellow, >14 red
     - Billing: ≤30 green, 31–45 yellow, >45 red
   - Grand total: ≤30 green, 31–81 yellow, 82–120 orange, >120 red

5. **Progress bar rendering:**
   - `width = Math.min((current_days / benchmark_days) * 100, 100) + '%'`
   - Bar fill color class matches traffic light state
   - Shows "—" label when `current_days === 0`

6. **Responsive breakpoint (`@media (max-width: 768px)`):**
   - Grid collapses from 4-column to single column
   - Each cycle becomes a stacked card
   - Strategy boxes stack vertically within each cycle card

**Verification:**
- File renders in browser with no console errors
- 4 cycle rows visible in desktop layout
- Traffic lights show at least 2 different colors with demo data
- Progress bars render with correct widths
- Grand total row shows at footer
- Layout collapses at 768px (resize browser to verify)

**Size:** L (2 SP) — largest task; most HTML/JS/CSS to write
**Dependencies:** T1 (vendor file), T2 (base CSS)
