# S14.2: Power of One — Visual Dashboard Design

**Story:** s14.2-power-of-one-visual  
**Epic:** e14-cash-dashboards  
**Designed:** 2026-05-27  
**Status:** Ready for implementation

---

## Problem

The `/scaleup-cash-power1` coaching skill produces text output only. There is no visual way for an entrepreneur to see — at a glance — how each of the 7 Power of One levers impacts their Cash Flow and EBIT simultaneously. Without a visual, it is hard to compare levers and prioritize which one to move first.

## Value

A read-only visual dashboard allows the entrepreneur to instantly identify which of the 7 levers has the highest monetary impact on Cash Flow or EBIT, making data-driven prioritization faster and clearer.

---

- **Size:** L (~8–10 story points)
- **Components:** 1 new HTML file + reuses existing shared CSS and vendor
- **External integrations:** 0 (no new CDN or API; Chart.js is already vendored)
- **Algorithm complexity:** Moderate — monetary impact formulas per variable category, traffic-light logic, summary totals
- **Level:** Moderate-to-Complex → full spec with examples required

## Approach

### Architecture

Single self-contained HTML file following the S14.1 cash-board pattern exactly:

```
work/epics/e14-cash-dashboards/components/power-of-one/index.html
```

**Shared assets reused (no modification):**
- `../shared/styles/dashboard-base.css` — all tokens, semáforo classes, grid utilities
- `../shared/vendor/chart.umd.min.js` — included via script tag (establishes vendor pattern; not used for charts in this story — dashboard is table-based)

**No new external CDN dependencies.** ADR-001 remains unchanged.

### Data Injection

Data is injected as `window.CASH_DATA.powerOfOne` — extending the existing S14.1 contract rather than creating a separate global. This follows Scope Assumption 1: *"The data contract from S14.1 (`window.CASH_DATA`) is extended with a `powerOfOne` key — no new loading mechanism needed."*

> **Do NOT use `window.POWER_OF_ONE_DATA`.** The story and scope already decided this; `window.CASH_DATA.powerOfOne` is canonical.

### Layout

**Desktop (≥769px):** Table-style grid with 6 columns:

| Variable | Current | Adjusted | Cash Flow Impact | EBIT Impact | Status |
|----------|---------|---------|-----------------|-------------|--------|

**Mobile (≤768px):** Each variable collapses to a card (stacked layout). Current / Adjusted shown vertically. No horizontal scroll.

**Summary footer row:** Total Cash Flow Impact | Total EBIT Impact | Overall status badge.

### Calculation Engine

Variables split into two categories with different formulas:

#### Category A — Revenue / Cost variables (affect both EBIT and Cash Flow)

| Variable | EBIT Impact | Cash Flow Impact |
|----------|------------|-----------------|
| Price | `(adjPrice − curPrice) × curVolume` | same as EBIT |
| Volume | `(adjVol − curVol) × curPrice` | same as EBIT |
| COGS % | `−(adjCOGS − curCOGS)/100 × revenue` | same as EBIT |
| Overheads | `−(adjOverheads − curOverheads)` | same as EBIT |

Where `revenue = curPrice × curVolume`.

> Note: positive delta on COGS means it went up → negative impact, hence the negation.

#### Category B — Working Capital variables (affect Cash Flow only; EBIT = 0)

Daily revenue: `dailyRevenue = curPrice × curVolume / 365`

| Variable | EBIT Impact | Cash Flow Impact |
|----------|------------|-----------------|
| A/R Days | 0 | `−(adjARdays − curARdays) × dailyRevenue` |
| Inventory Days | 0 | `−(adjInvDays − curInvDays) × dailyRevenue` |
| A/P Days | 0 | `+(adjAPdays − curAPdays) × dailyRevenue` |

> A/R and Inventory: more days = cash tied up (negative). A/P: more days = cash freed (positive). Formula converts day-delta to monetary value via `dailyRevenue`. This is the correct Power of One working capital formula — a raw day delta without monetization has no meaning.

### Traffic Light Logic

Per variable row:
- **Green:** Combined impact (CF + EBIT) > +5% of total revenue  
- **Yellow:** −5% to +5% of total revenue (neutral / minimal)  
- **Red:** Combined impact < −5% of total revenue (worsens position)

If no data or all zeros: **Gray**.

Summary traffic light: same thresholds applied to total combined impact.

### DOM Construction

All DOM built via `el()` helper (createElement + textContent only). **No `innerHTML` usage.** This is enforced to avoid the CSP issues encountered in S14.1 (see commits cadcde0, e9152db).

## Acceptance Criteria

### MUST

**AC1 — Seven variable rows render correctly**  
Dashboard renders all 7 variable rows (Price, Volume, COGS, Overheads, A/R Days, Inventory Days, A/P Days) with current value and adjusted value displayed side by side.  
*Maps to Story AC1.*

**AC2 — Cash Flow impact computed correctly**  
Cash Flow impact uses monetary formulas:
- Revenue/Cost variables: direct P&L delta
- Working capital variables: `Δdays × dailyRevenue` (where dailyRevenue = Price × Volume / 365)
- Summary row shows total Cash Flow impact across all 7 variables.  
*Maps to Story AC2.*

**AC3 — EBIT impact computed correctly**  
EBIT impact uses P&L deltas for revenue/cost variables only. Working capital variables show "—" or $0 for EBIT (they are cash-neutral on EBIT). Summary row shows total EBIT impact.  
*Maps to Story AC3.*

**AC4 — Traffic lights per variable row**  
Each row shows a semáforo indicator: green (positive net impact), yellow (neutral ±5% of revenue), red (negative impact). Summary traffic light reflects overall net impact. Gray shown when no data.  
*Maps to Story AC4.*

**AC5 — Responsive layout**  
Desktop (≥1024px): table grid fully visible. Mobile (≤768px): stacked card layout per variable — no horizontal scroll on standard mobile widths (375px tested).  
*Maps to Story AC5.*

**AC6 — Data injected via `window.CASH_DATA.powerOfOne`**  
Dashboard reads from `window.CASH_DATA.powerOfOne`. Renders with placeholder/demo data when absent. No external API calls.  
*Maps to Story AC6. Canonical data key is `window.CASH_DATA.powerOfOne`, NOT a separate `window.POWER_OF_ONE_DATA` global.*

**AC7 — Reuses S14.1 tech stack**  
Uses `../shared/styles/dashboard-base.css` for base tokens. References `../shared/vendor/chart.umd.min.js` via relative path (no CDN at runtime). No new external dependencies.  
*Maps to Story AC7.*

**AC8 — No innerHTML usage**  
All DOM construction via `createElement` / `textContent` / `el()` helper. No `innerHTML` anywhere in the script. Enforced by the project's CSP meta tag (lesson from S14.1 fix commits cadcde0, e9152db).

### SHOULD

**AC9 — Consistent visual language with S14.1**  
Same header gradient pattern (`linear-gradient(135deg, #0f172a → #1e40af)`), same board-eyebrow / board-title classes, same semaforo-badge and semaforo-dot classes from shared CSS.

**AC10 — CSP meta tag present**  
`<meta http-equiv="Content-Security-Policy" content="default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'">` in `<head>`.

### MUST NOT

**AC11 — No server-side rendering or build step**  
Dashboard must open directly as a static HTML file. No npm, webpack, or bundler required.

**AC12 — Must not modify shared/ assets**  
`components/shared/styles/dashboard-base.css` and `components/shared/vendor/` are read-only for this story. All Power of One styles go in a `<style>` block inside `power-of-one/index.html`.

## Rendering Notes for Implementation

1. The `el()` helper from S14.1 (`buildCycleRow` pattern) should be copied verbatim into the new file. It is the canonical DOM builder.
2. Render order: header → variable rows table → summary footer → legend → placeholder notice.
3. Monetary values formatted with `toLocaleString('en-US', { style: 'currency', currency: 'USD', maximumFractionDigits: 0 })` or equivalent.
4. Day values formatted as integers with "d" suffix.
5. Percent values formatted as `X.X%`.
6. The `allZero` guard (same as S14.1): if all current values are zero or data is missing, show placeholder notice and gray semáforos.
7. Error banner (same as S14.1 catch block): on render failure, prepend a red DOM error banner — no innerHTML.
