### T2: Calculation Engine

**Size:** M  
**Depends on:** T1  
**Description:**  
Implement the JavaScript calculation functions inside the `<script>` block. All pure functions — no DOM interaction yet.

**Functions to implement:**

`calcImpacts(variables)` → returns array of `{ key, cfImpact, ebitImpact }` for all 7 variables:

- `revenue = variables.price.current × variables.volume.current`
- `dailyRevenue = revenue / 365`

Category A — Revenue/Cost variables (affect EBIT and Cash Flow equally):
- **Price:** `(adjPrice − curPrice) × curVolume`
- **Volume:** `(adjVol − curVol) × curPrice`
- **COGS %:** `−(adjCOGS − curCOGS)/100 × revenue` (positive delta = cost went up = negative impact)
- **Overheads:** `−(adjOverheads − curOverheads)` (positive delta = cost went up = negative impact)

Category B — Working Capital variables (Cash Flow only; EBIT = 0):
- **A/R Days:** `−(adjARdays − curARdays) × dailyRevenue` (more days = cash tied up = negative)
- **Inventory Days:** `−(adjInvDays − curInvDays) × dailyRevenue` (more days = cash tied up = negative)
- **A/P Days:** `+(adjAPdays − curAPdays) × dailyRevenue` (more days = cash freed = positive)

`calcTotals(impacts)` → `{ totalCF, totalEBIT }` (sum of all cfImpact / ebitImpact)

**Verification:**  
`console.log(calcImpacts(window.CASH_DATA.powerOfOne.variables))` in DOMContentLoaded. Verify with example data from design doc:
- Price: CF=+$5,000, EBIT=+$5,000
- Volume: CF=+$5,000, EBIT=+$5,000
- COGS: CF=+$2,100 (approx), EBIT=+$2,100
- Overheads: CF=+$1,000, EBIT=+$1,000
- A/R: CF≈+$2,740 (10d × 274/d), EBIT=0
- Inventory: CF≈+$1,370 (5d × 274/d), EBIT=0
- A/P: CF≈+$1,370 (5d × 274/d), EBIT=0
- Totals: CF≈+$18,580, EBIT≈+$13,100

### T3: Table Layout & DOM Rendering

**Size:** M  
**Depends on:** T2  
**Description:**  
Implement the table layout in HTML/CSS and the `buildTable(data)` DOM function.

**HTML structure (desktop, ≥769px):**
- 6-column grid: Variable | Current | Adjusted | Cash Flow Impact | EBIT Impact | Status
- `.po1-header-row` with 6 `.po1-col-header` cells
- `.po1-rows-wrapper` container populated by JS
- Each variable row: `.po1-row` with 6 cells built via `el()` helper

**CSS (inside `<style>` block):**
- `.po1-header-row`: 6-column CSS grid, border, background using `var(--color-surface)` and `var(--color-border)` tokens
- `.po1-row`: same grid template, border-bottom, hover filter (matching S14.1 `.cycle-row` pattern)
- `.po1-cell`: padding, border-right (last-child: none)
- `.po1-label-cell`: stronger left border, font-weight 700
- Value cells: `font-variant-numeric: tabular-nums` for alignment

**`buildVariableRow(key, varData, impact)` function:**
- Uses `el()` helper — no innerHTML anywhere
- Cells: label | formatted current | formatted adjusted | formatted CF impact | formatted EBIT impact | status placeholder (gray dot)
- `formatCurrency(n)`: `n.toLocaleString('en-US', { style: 'currency', currency: 'USD', maximumFractionDigits: 0 })`
- `formatValue(v, unit)`: unit prefix/suffix logic ($ prefix for $, % suffix for %, 'd' suffix for days, 'u' suffix for units)
- Working capital EBIT cell: text content '—'
- Positive delta: prepend '+' sign to currency format

**`buildTable(data)` function:**
- Calls `calcImpacts(data.variables)` and `calcTotals(impacts)`
- Builds header row, all 7 variable rows, placeholder summary row (gray, text '—')
- Appends to `#po1-rows`

**Verification:**  
Table renders in browser with all 7 rows visible. All 6 columns present. Values display correctly formatted (e.g., "$100", "1,000u", "+$5,000"). No console errors.

### T4: Traffic Lights & Status Indicators

**Size:** S  
**Depends on:** T3  
**Description:**  
Implement the `statusFor(cfImpact, ebitImpact, revenue)` function and apply CSS status classes to each row.

**Traffic light logic (per design AC4):**
- `combinedImpact = cfImpact + ebitImpact`
- `threshold = revenue × 0.05` (5% of base revenue)
- Green: `combinedImpact > +threshold`
- Yellow: `combinedImpact >= −threshold && combinedImpact <= +threshold`
- Red: `combinedImpact < −threshold`
- Gray: revenue is 0 or both impacts are 0

**CSS classes:**
- `.status-green` → uses `var(--color-green)` (inherits from `semaforo-green` pattern in shared CSS)
- `.status-yellow` → uses `var(--color-yellow)`
- `.status-red` → uses `var(--color-red)`
- `.status-gray` → uses `var(--color-gray-text)`

**DOM update:**
- Status cell in each row: `semaforo-dot` + `semaforo-badge` elements (matching S14.1 classes)
- Row background: `.row-green` / `.row-yellow` / `.row-red` / `.row-gray` (same classes as S14.1 `rowBgClass()`)
- `statusLabel(cls)`: returns human text — "Mejora" (green), "Neutral" (yellow), "Retroceso" (red), "Sin datos" (gray)

**Verification:**  
With Acme Corp example data, all 7 rows should show green (all variables improving). Manually edit one variable to make it worse (e.g., `adjusted: 120` for A/R days) — that row should turn red. Edit another to ±1% — that row should turn yellow.

## Risks

### R1 — Calculation formula correctness (HIGH priority)

The monetary impact formulas differ per variable category:
- Revenue/cost variables: P&L delta (same for CF and EBIT)
- Working capital variables: `Δdays × dailyRevenue` (CF only; EBIT = 0)

Risk: confusing the two categories or applying the wrong formula to working capital variables. Mitigation: T2 validates with known expected values from the design doc (e.g., A/R impact at 10d delta should be ≈ $2,740, not $10 or $10,000). Console verification before building UI on top.

### R2 — Mobile responsiveness of wide table (MEDIUM priority)

The 6-column table is wide on desktop. At 375px, a horizontal-scroll approach is explicitly excluded by design (AC5: "no horizontal scroll on standard mobile widths"). The stacked card layout requires each cell to know its column label.

Mitigation: T6 adds `data-label` attributes to each cell in `buildVariableRow()` and uses CSS `::before { content: attr(data-label); }` to display them on mobile. This is the canonical approach for responsive tables without horizontal scroll.

### R3 — Traffic light threshold calibration (LOW priority)

The ±5% threshold (relative to total revenue) may produce all-yellow rows for small absolute changes on high-revenue businesses, or all-red/all-green for low-revenue businesses. This is a design decision already documented in the design doc — implementation should not re-open this decision. If during T4 verification the thresholds produce unexpected results with the Acme Corp example, consult the design before changing.
