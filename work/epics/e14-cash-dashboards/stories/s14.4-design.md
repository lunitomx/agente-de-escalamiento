# S14.4: Fundability Visual Dashboard Design

**Story:** s14.4-fundability-visual  
**Epic:** e14-cash-dashboards  
**Designed:** 2026-05-28  
**Status:** Ready for implementation

---

## Problem

The `/scaleup-cash` fundability coaching skill produces text output only. There is no visual way for an entrepreneur to see — at a glance — their investor-readiness across the 8 fundability dimensions. Without a visual, it is hard to spot the weakest criteria and prioritize improvement.

## Value

A radar chart lets the entrepreneur instantly see the shape of their fundability profile — which dimensions are Weak, Solid, or Great — enabling faster, clearer prioritization of what to improve before seeking investment.

---

## Complexity Assessment

- **Size:** M (~5–7 story points)
- **Components:** 1 new HTML file + reuses existing shared CSS and vendor
- **External integrations:** 0 (Chart.js already vendored; no new CDN)
- **Algorithm complexity:** Moderate — introduces Chart.js radar type (new to E14), scale mapping, color-zone logic, and summary table via DOM el() helper
- **Level:** Moderate → full spec with examples required

## Approach

### Architecture

Single self-contained HTML file following the S14.1/S14.2 pattern exactly:

```
work/epics/e14-cash-dashboards/components/fundability/index.html
```

**Shared assets reused (no modification):**
- `../shared/styles/dashboard-base.css` — all tokens, semáforo classes, grid utilities
- `../shared/vendor/chart.umd.min.js` — Chart.js v4, vendored (ADR-001: radar type confirmed supported)

**No new external CDN dependencies.** ADR-001 remains unchanged.

### Data Injection

Data is injected as `window.CASH_DATA.fundability` — extending the existing `window.CASH_DATA` contract introduced in S14.1 and used in S14.2. The `||` guard pattern from S14.2 is reused to ensure real data injected by `/scaleup-cash` is never overwritten by the inline placeholder block.

> **Do NOT use a separate global like `window.FUNDABILITY_DATA`.** The canonical key is `window.CASH_DATA.fundability`.

### Layout

**Two-panel layout (desktop ≥ 769px):**
- Radar chart centered (max-width ~500px), filling the upper section
- Summary scorecard table below chart: 8 rows (criterion | rating badge)

**Mobile (≤ 768px):**
- Radar chart scales to 100% width via Chart.js `responsive: true` — no horizontal scroll
- Summary table uses full column width

### Chart.js Radar Configuration

Chart type: `'radar'`  
Scale: `min: 0`, `max: 3`, `stepSize: 1`  
Tick labels: `0 → ""`, `1 → "Weak"`, `2 → "Solid"`, `3 → "Great"`  
Axes (fixed order for consistent polygon shape):
```
['Leadership', 'Business Model', 'Values', 'Industry', 'Exit', 'House', 'Consistency', 'Assets']
```

Rating → numeric mapping: `{ Weak: 1, Solid: 2, Great: 3 }`

Fill area color is determined by the average score of all 8 criteria:
- **Green** (avg ≥ 2.5): `rgba(22, 163, 74, 0.25)` border `rgba(22, 163, 74, 1)`
- **Yellow** (avg 1.5–2.49): `rgba(217, 119, 6, 0.25)` border `rgba(217, 119, 6, 1)`
- **Red** (avg < 1.5): `rgba(220, 38, 38, 0.25)` border `rgba(220, 38, 38, 1)`

The color zone is derived from the computed average, not from a per-axis comparison, so the fill always reflects holistic investor-readiness.

Chart.js config sketch:
```javascript
new Chart(ctx, {
  type: 'radar',
  data: {
    labels: ['Leadership', 'Business Model', 'Values', 'Industry', 'Exit', 'House', 'Consistency', 'Assets'],
    datasets: [{
      data: [2, 3, 2, 1, 1, 2, 3, 2],
      fill: true,
      backgroundColor: 'rgba(217, 119, 6, 0.25)',   // yellow for mixed
      borderColor:     'rgba(217, 119, 6, 1)',
      pointBackgroundColor: 'rgba(217, 119, 6, 1)',
      pointBorderColor: '#fff',
      pointHoverBackgroundColor: '#fff',
      pointHoverBorderColor: 'rgba(217, 119, 6, 1)'
    }]
  },
  options: {
    responsive: true,
    maintainAspectRatio: true,
    scales: {
      r: {
        min: 0,
        max: 3,
        ticks: {
          stepSize: 1,
          callback: function(v) { return ['', 'Weak', 'Solid', 'Great'][v] || ''; }
        },
        pointLabels: { font: { size: 12 } }
      }
    },
    plugins: { legend: { display: false } }
  }
});
```

### Summary Table (below radar)

8-row table built entirely via `el()` helper. No `innerHTML`. Columns: Criterion name | Rating badge.

Rating badge CSS classes follow the same semáforo pattern as S14.1/S14.2:
- Great → `semaforo-badge semaforo-green`
- Solid → `semaforo-badge semaforo-yellow`
- Weak  → `semaforo-badge semaforo-red`

### DOM Construction

All DOM built via `el()` helper (createElement + textContent only). **No `innerHTML` usage.** Chart.js `canvas` element is the only exception — Chart.js manages its own internal canvas rendering.

## Data Contract Example

```javascript
window.CASH_DATA = window.CASH_DATA || {};

window.CASH_DATA.fundability = window.CASH_DATA.fundability || {
  company: "Acme Corp",
  period:  "Q2 2026",
  criteria: [
    { key: "leadership",     label: "Leadership",     rating: "Solid" },
    { key: "business_model", label: "Business Model", rating: "Great" },
    { key: "values",         label: "Values",         rating: "Solid" },
    { key: "industry",       label: "Industry",       rating: "Weak"  },
    { key: "exit",           label: "Exit",           rating: "Weak"  },
    { key: "house",          label: "House",          rating: "Solid" },
    { key: "consistency",    label: "Consistency",    rating: "Great" },
    { key: "assets",         label: "Assets",         rating: "Solid" }
  ]
};
```

**Rating → numeric:** `{ Weak: 1, Solid: 2, Great: 3 }`

**Average score for example data:**  
`(2+3+2+1+1+2+3+2) / 8 = 2.0` → Yellow zone

**Placeholder mode:** When `window.CASH_DATA.fundability` is absent, all 8 criteria default to "Solid" rating and a placeholder notice appears (same pattern as S14.1/S14.2 `placeholder-notice`). This ensures the radar renders a non-empty polygon and the component is instructive rather than blank.

## Acceptance Criteria

### MUST

**AC1 — Radar chart renders all 8 criteria on correct axes**  
Chart.js radar renders with 8 axes in the fixed order: Leadership, Business Model, Values, Industry, Exit, House, Consistency, Assets. Each axis position is stable (no reordering on re-render).  
*Maps to Story AC1.*

**AC2 — Weak/Solid/Great rating maps to 1/2/3; scale shows labels not numbers**  
The radar scale shows axis tick labels "Weak" (1), "Solid" (2), "Great" (3) — not raw integers. The polygon data points are the numeric equivalents.  
*Maps to Story AC2.*

**AC3 — Fill area color reflects overall fundability score zone**  
Average score of all 8 criteria determines fill color:
- avg ≥ 2.5 → Green fill  
- avg 1.5–2.49 → Yellow fill  
- avg < 1.5 → Red fill  
Color applies to both `backgroundColor` and `borderColor` of the Chart.js dataset.  
*Maps to Story AC3.*

**AC4 — Summary table below chart shows all 8 criteria with rating badges**  
DOM-only table (via `el()`) renders 8 rows: criterion name + rating badge. Badge color: green for Great, yellow for Solid, red for Weak.  
*Maps to Story AC4.*

**AC5 — Rating badge colors: green=Great, yellow=Solid, red=Weak**  
Badge CSS classes follow the semáforo token convention:
- Great → `semaforo-badge semaforo-green`
- Solid → `semaforo-badge semaforo-yellow`
- Weak  → `semaforo-badge semaforo-red`

**AC6 — Responsive: chart readable at 375px mobile viewport**  
Chart.js `responsive: true` + `maintainAspectRatio: true` ensures radar scales to fit without horizontal scroll. Point labels remain legible on small screens.  
*Maps to Story AC5.*

**AC7 — `window.CASH_DATA.fundability` injection with `||` guard; fallback to all-Solid placeholder**  
The `||` guard prevents overwriting real injected data. When absent, renders placeholder with all 8 criteria as Solid — rendering a full octagon to indicate "no data yet" without a blank chart.  
*Maps to Story AC6.*

**AC8 — No innerHTML — el() for DOM, Chart.js canvas for chart only**  
All criterion names, rating labels, and badges are inserted via `textContent` or `setAttribute` only. No `innerHTML` for any dynamic content.  
*Maps to Story AC7.*

### SHOULD

**AC9 — Visual consistency with S14.1/S14.2**  
Same header pattern: `linear-gradient(135deg, #0f172a 0%, #1e40af 100%)`, same `.board-eyebrow` / `.board-title` / `.board-title-accent` / `.board-meta-text` classes, same `.placeholder-notice` component.

### MUST NOT

## Key Decisions

**D1 — Chart.js radar type**  
Use Chart.js v4 `'radar'` chart type. This is the first real Chart.js usage in E14 (S14.1/S14.2 only referenced the vendor file for future stories). ADR-001 explicitly lists S14.4 as the radar story and confirms this chart type is supported.

**D2 — Scale 0–3 numeric with string tick labels**  
Radar scale uses integers (0=empty, 1=Weak, 2=Solid, 3=Great). The `ticks.callback` converts them to human labels. This gives Chart.js clean numeric comparison while showing meaningful labels to the user.

**D3 — `||` injection guard (inherited from S14.2)**  
`window.CASH_DATA.fundability = window.CASH_DATA.fundability || { ... }` ensures that when a coaching skill injects real data before this script runs, the inline placeholder block is skipped. When no data exists, the fallback renders a full "all Solid" octagon rather than a blank canvas, which is more instructive.

---

## Rendering Notes for Implementation

1. The `el()` helper from S14.1/S14.2 is copied verbatim — it is the canonical DOM builder.
2. Render order: header → radar canvas → summary table → placeholder notice.
3. The Chart.js `canvas` element is created via `el('canvas', { id: 'fundability-radar' })` and appended to its container before `new Chart(ctx, ...)` is called.
4. The `allSolid` guard (fallback detection): if `window.CASH_DATA.fundability` is absent or the `criteria` array is empty/missing, inject the all-Solid placeholder and show the placeholder notice.
5. Error banner: same as S14.1/S14.2 catch block — prepend a red DOM error banner with `createElement` on render failure; no innerHTML.
6. The radar chart instance should be stored in a module-scoped variable to allow future destroy/reinitialize if needed (chart does not need hot-reload in this story, but clean teardown avoids "canvas already in use" errors in preview tools).
