# S14.3 Scope: Recurring Revenue — Visual Dashboard

## In Scope

| # | Item |
|---|------|
| 1 | 4-tier visual hierarchy: None, Weak, Solid, Exceptional |
| 2 | Value Assessment block per tier (business meaning + actionable guidance) |
| 3 | Customer/stream listing per tier with name, monthly value, tenure |
| 4 | Empty-state messaging for tiers with no assigned customers |
| 5 | Summary metrics banner: Total MRR, customer count, tier distribution |
| 6 | Responsive layout: 2×2 grid desktop, stacked mobile |
| 7 | Read-only dashboard — data injected via `window.CASH_DATA.recurringRevenue` |
| 8 | Placeholder/demo data mode so dashboard renders before user fills in values |
| 9 | Reuse of `components/shared/styles/dashboard-base.css` and vendored Chart.js from S14.1 |
| 10 | Self-contained HTML file — no external API calls, no backend required |

## Out of Scope

| # | Item | Why excluded |
|---|------|-------------|
| 1 | Editable form inputs inside the dashboard | Dashboard is read-only; data entry stays in the coaching skill flow |
| 2 | Real-time data from accounting/billing APIs | Epic-level exclusion |
| 3 | PDF or Excel export | Epic-level exclusion |
| 4 | Translation / i18n | Epic-level exclusion |
| 5 | Animated transitions / micro-interactions | Nice to have; deferred to polish pass |
| 6 | Chart.js radar or bar charts | S14.3 is badge/card hierarchy — no chart library needed (simpler visual) |
| 7 | Historical trend lines or MRR growth charts | Out of scope for this dashboard; future epic |
| 8 | Drill-down per customer (individual detail page) | Out of Recurring Revenue hierarchy methodology scope |

## Assumptions

1. The data contract from S14.1 (`window.CASH_DATA`) is extended with a `recurringRevenue` key
2. The 4-tier system (None/Weak/Solid/Exceptional) is intentionally different from S14.4's 3-tier (Weak/Solid/Great)
3. Chart.js is NOT needed — this is a card/badge hierarchy, not a chart (simpler than S14.4)
4. Customer tenure is displayed as months or years based on the data payload's `tenureUnit` field

## Risks

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|-----------|
| 4-tier visual differentiation unclear at a glance | Low | Medium | Use distinct color + shape + icon per tier (not color-only) |
| Mobile 2×2 grid collapses awkwardly | Low | Low | On <=768px collapse to single-column stacked view |
| Tenure calculation mismatch with coaching skill | Low | Low | Tenure is passed as a pre-calculated field in the data payload |
