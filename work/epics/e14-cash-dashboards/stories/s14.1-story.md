# S14.1: CASh — Cash Acceleration Strategies Board

## User Story (Connextra Format)

**As a** ScaleUp user working on the Cash decision,
**I want** a visual dashboard showing all 4 cash conversion cycles with their 3 acceleration strategies each,
**So that** I can immediately see where my business is healthy or bleeding cash, and what actions to take.

---

## Acceptance Criteria (Gherkin)

### AC1 — Grid renders correctly

```gherkin
Given the user opens the CASh dashboard
When the component loads with default or placeholder data
Then a 4×3 grid is displayed (4 ciclos: Sales, Production, Delivery, Billing × 3 estrategias: Shorten, Eliminate, Improve)
And each cell shows the strategy label and a placeholder or real value
```

### AC2 — Cycle day meters render

```gherkin
Given the CASh dashboard is loaded
When the user views any of the 4 ciclos
Then a numeric "days" meter is displayed for that ciclo
And it visually represents the day count (number + visual bar or ring)
```

### AC3 — Health traffic lights render

```gherkin
Given the CASh dashboard is loaded with day values for each ciclo
When the system evaluates each ciclo against thresholds
Then a traffic-light indicator (green / yellow / red) is shown for each ciclo
And green = healthy (days within target), yellow = warning, red = critical
```

### AC4 — Visualization framework is defined and documented

```gherkin
Given this is the walking skeleton story for the epic
When the developer implements the dashboard
Then a framework decision (vanilla HTML/CSS/JS, Alpine.js, Chart.js, or equivalent) is chosen
And the choice is documented in work/epics/e14-cash-dashboards/adr-visualization-framework.md
And all subsequent stories (S14.2, S14.3, S14.4) can reuse the same framework without rework
```

### AC5 — Responsive layout

```gherkin
Given the CASh dashboard
When viewed on a desktop viewport (≥1024px)
Then the 4×3 grid displays in a full table/grid layout
When viewed on a mobile viewport (≤768px)
Then the grid stacks into readable cards per ciclo
```

### AC6 — Self-contained component

```gherkin
Given the ScaleUp coaching system
When the CASh dashboard component is integrated into the skill output
Then it renders without external API calls
And all data is passed via a JSON payload or inline template variables
```

---

## Implementation Notes

- **Walking skeleton priority:** Framework choice (AC4) must be resolved first — it gates S14.2, S14.3, S14.4
- **Data contract:** Component should accept a JSON object with the 4 ciclos and their day values + strategy entries
- **Placeholder mode:** Dashboard must render meaningfully with placeholder/zero data so the skill works before the user fills in values
- **No backend required:** All logic is client-side; data comes from the coaching session context
