# S14.3: Recurring Revenue — Visual Dashboard

## User Story (Connextra Format)

**As a** ScaleUp user working on the Cash decision,
**I want** a visual dashboard showing my recurring revenue hierarchy with a 4-tier value assessment,
**So that** I can identify which revenue streams are stable, which are at risk, and where to focus retention efforts.

---

## Acceptance Criteria (Gherkin)

### AC1 — 4-tier hierarchy renders correctly

```gherkin
Given the user opens the Recurring Revenue dashboard
When the component loads with data or placeholder values
Then a visual hierarchy displays 4 levels: None, Weak, Solid, Exceptional
And each level shows its distinct visual treatment (color, badge, or indicator)
And the levels are ordered from lowest (None) to highest (Exceptional)
```

### AC2 — Value Assessment per level

```gherkin
Given the dashboard renders the 4-tier hierarchy
When the user views each level
Then a "Value Assessment" block is shown per level summarizing:
  - What this tier means for the business
  - Actionable guidance for moving to the next tier
And the assessment is readable without horizontal scroll
```

### AC3 — Customer/stream listing per tier

```gherkin
Given a tier has recurring revenue data assigned
When the component renders that tier's section
Then customer or revenue stream names are listed under their corresponding tier
And each entry shows at minimum: name, monthly value, and tenure indicator
And tiers with no assigned customers display an empty-state message
```

### AC4 — Summary metrics banner

```gherkin
Given the recurring revenue data is loaded
When the dashboard renders
Then a summary banner at the top shows:
  - Total Monthly Recurring Revenue (MRR)
  - Number of recurring customers/streams
  - Tier distribution (count per level)
And the banner updates when window.CASH_DATA changes
```

### AC5 — Responsive layout

```gherkin
Given the Recurring Revenue dashboard
When viewed on a desktop viewport (>=1024px)
Then the 4 tiers display side-by-side or in a 2×2 grid with full detail visible
When viewed on a mobile viewport (<=768px)
Then the tiers stack vertically with summary banner on top
And no horizontal scroll occurs
```

### AC6 — Data injection via window.CASH_DATA

```gherkin
Given the self-contained dashboard HTML file
When the component initializes
Then it reads data from window.CASH_DATA.recurringRevenue (or renders placeholder/demo data if absent)
And no external API calls are made
And the dashboard renders meaningfully with zero/placeholder values
```

### AC7 — Reuses E14 tech stack

```gherkin
Given the visualization framework established in S14.1
When the Recurring Revenue dashboard is implemented
Then it uses the same vendor files from components/shared/vendor/
And it imports components/shared/styles/dashboard-base.css for base styles
And no new external CDN dependencies are introduced
```

---

## Implementation Notes

- **4-tier system:** None → Weak → Solid → Exceptional (NOT the 3-tier Weak/Solid/Great from S14.4)
- **Data contract:** `window.CASH_DATA.recurringRevenue` — object with `customers` array and `summary` object
- **Visual pattern:** Badge/card hierarchy (not radar, not heavy table) — each tier is a visual card or panel
- **Placeholder mode:** Demo data with 2-3 example customers across tiers
- **Simpler than S14.2:** No heavy calculation logic — primarily display + categorization
- **Reference patterns:** DOM structure from power-of-one (cards/grid), CSS tokens from dashboard-base.css
