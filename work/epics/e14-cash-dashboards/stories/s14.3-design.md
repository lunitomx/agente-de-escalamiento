# S14.3 Design: Recurring Revenue — Visual Dashboard

## Problem

El sistema Escala guía al usuario por el diagnóstico de Cash pero la decisión de Recurring Revenue carece de representación visual. El usuario necesita ver de un vistazo la calidad de sus flujos recurrentes — cuáles son estables, cuáles están en riesgo, y dónde enfocar la retención.

## Value

Un dashboard visual que categoriza los ingresos recurrentes en 4 niveles jerárquicos (None → Weak → Solid → Exceptional) reduce el tiempo de diagnóstico de minutos a segundos. El usuario identifica inmediatamente su distribución de calidad de revenue sin leer hojas de cálculo.

## Approach

Componente HTML autocontenido usando cards + badges para los 4 tiers. Sin Chart.js — este dashboard es puramente tipográfico y de layout (jerarquía visual). Cada tier es una card colapsable con: nombre del tier, color/badge distintivo, conteo de customers, Value Assessment (qué significa + cómo avanzar), y lista de customers con MRR y tenure.

## Design Decisions

### D1 — Card hierarchy, not chart

**Rationale:** Recurring Revenue es categorización, no comparación numérica. Un radar/bar chart forzaría una metáfora visual incorrecta. Cards con badges de color comunican jerarquía de forma inmediata y accesible (no color-only: cada tier tiene icono + label + color).

### D2 — 4-tier system (None/Weak/Solid/Exceptional)

**Rationale:** Es intencionalmente diferente del 3-tier de S14.4 (Weak/Solid/Great). Recurring Revenue tiene un estado "None" (sin revenue recurrente) que no existe en Fundability. "Exceptional" reemplaza "Great" para reflejar que el revenue recurrente excepcional es aspiracional (pocos lo alcanzan).

### D3 — Summary banner siempre visible

**Rationale:** El usuario necesita ver MRR total, customer count y distribución de tiers sin hacer scroll. El banner va fijo arriba (sticky no necesario — es un dashboard de una página).

### D4 — Value Assessment inline por tier

**Rationale:** Cada card incluye el "qué significa este tier" y "cómo avanzar al siguiente". Esto evita tooltips/hovers que no funcionan en mobile y hace el dashboard autosuficiente sin documentación externa.

## Acceptance Criteria

### MUST (required for completion)

| ID | Description |
|----|-------------|
| AC1 | 4-tier cards render: None (red), Weak (amber), Solid (blue), Exceptional (green) |
| AC2 | Summary banner: Total MRR, customer count, tier distribution (count per level) |
| AC3 | Customer listing per tier: name, monthly value (formatted), tenure indicator |
| AC4 | Value Assessment text per tier: business meaning + action to advance |
| AC5 | Empty state: tiers with no customers show "No customers in this tier" message |
| AC6 | Responsive: 2×2 grid at >=1024px, stacked single-column at <=768px |
| AC7 | Data injection via `window.CASH_DATA.recurringRevenue`; falls back to demo data |

### SHOULD (nice to have)

| ID | Description |
|----|-------------|
| S1 | Cards are collapsible (click header to toggle customer list) |
| S2 | Tier transition hint: "Add $X MRR to reach {next_tier}" when adjacent tiers have clear thresholds |

### MUST NOT

| ID | Description |
|----|-------------|
| MN1 | No innerHTML for dynamic/user-controlled content |
| MN2 | No new external CDN dependencies |
| MN3 | No Chart.js — this is a card hierarchy, not a chart |
