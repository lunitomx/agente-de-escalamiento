# Plan: S20.1 — Knowledge Context API

**Story:** S20.1 | **Size:** M | **Date:** 2026-05-29
**Branch:** `story/s20.1/knowledge-context-api`

## Overview

El endpoint `GET /api/knowledge/context` ya existe en `knowledge_handler.py` (creado en S19.4) y ya tiene cobertura de tests unitarios en `TestKnowledgeContext`. El único delta es agregar validación de 400 cuando no se pasan parámetros (hoy devuelve 200 vacío) y añadir test HTTP end-to-end.

## Tasks

### T1: Agregar validación 400 en route handler
- **File:** `escala_server/server.py` — función `knowledge_context`
- **Qué:** Si no hay `tool` ni `category`, retornar 400 con mensaje
- **Verificación:** `rai gate check gate-tests --scope tests/test_knowledge_api.py`

### T2: Agregar test HTTP end-to-end
- **File:** `tests/test_knowledge_api.py` — nueva clase `TestKnowledgeContextHTTP`
- **Qué:** Test HTTP real: levanta servidor, llama al endpoint, verifica respuesta JSON
- **Scenarios:** tool existente, category existente, sin parámetros (400), tool inexistente
- **Verificación:** `rai gate check gate-tests --scope tests/test_knowledge_api.py`

### T3: Verificar tests existentes
- **Qué:** Correr todos los tests de knowledge_api y knowledge_ingester para asegurar que S19.4 sigue estable
- **Verificación:** `rai gate check gate-tests --scope tests/`

## Execution Order

1. T1 (validación 400) — riesgo más alto (modifica código existente)
2. T2 (test HTTP) — construye sobre T1
3. T3 (verificación final) — gate de calidad
