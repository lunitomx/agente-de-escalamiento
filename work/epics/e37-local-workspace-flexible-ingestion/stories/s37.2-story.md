# Story: Flexible File Ingestion

## User Story

As an entrepreneur,
I want to give ESCALA the spreadsheets, delimited files, documents, PDFs and
transcripts I already use,
so that ESCALA can describe what it understood, ask only the questions needed
to resolve material ambiguity, and preserve a repeatable source identity
without requiring a new template.

## Acceptance Criteria

### Scenario: supported tabular source is profiled without a template

```gherkin
Given a local CSV, TSV or XLSX source inside the configured exchange root
When the source profiler runs
Then it reports candidate tables/sheets, headers, units, date fields and entity fields
And the report uses relative provenance and contains no machine-absolute path
```

### Scenario: material ambiguity becomes an explicit question

```gherkin
Given a source with multiple plausible header rows, date columns or entity columns
When the profiler cannot select a materially important interpretation safely
Then the source state is needs_clarification
And the receipt contains bounded question codes and candidate choices
And no canonical business state is written
```

### Scenario: unsupported or unavailable format fails explicitly

```gherkin
Given a declared document, PDF, transcript or unknown extension
When no safe local adapter can profile it
Then the result is unsupported or provider_unavailable with a stable reason code
And the original source remains untouched
```

### Scenario: source identity is stable across reruns

```gherkin
Given the same source bytes and relative provenance
When profiling is repeated
Then fingerprint, source identity and deterministic receipt are identical
And changing the bytes creates a new identity without exposing an absolute path
```

## Examples (Specification by Example)

| Input | Action | Expected Output |
|-------|--------|-----------------|
| `ventas.csv` with a header row and `fecha`, `cliente`, `importe` columns | Profile twice | `ready`, same fingerprint and source identity, relative provenance only |
| `cash.tsv` with two plausible header rows | Profile | `needs_clarification` with a question and no canonical write |
| `estado.pdf` or encrypted workbook without a local adapter | Profile | `unsupported` or `provider_unavailable`, stable safe code, source unchanged |
| Same filename with one byte changed | Profile | New fingerprint and source identity |

## Notes

This story implements the E37 boundary after S37.1. Runtime and authoritative
SQLite remain on the installer machine; an ordinary local/Google Drive/OneDrive
folder is only an exchange location. No cloud API, OAuth, hosted runtime,
telemetry, OCR promise, or mandatory user template is introduced. The exact
adapter capabilities and ambiguity thresholds are fixed during
`rai-story-design` and proved with committed fixtures and receipts.
