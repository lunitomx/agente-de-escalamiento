# S37.1 Plan: Local Workspace & Data Authority

## Overview

S37.1 es una story M de riesgo alto y alcance acotado. La ejecución sigue
`RED → GREEN → REFACTOR` y un commit por task. El camino crítico prueba primero
la frontera de autoridad, después conecta el guard antes de SQLite y finalmente
lo califica en un filesystem temporal real. No se consolidan los dos esquemas
SQLite existentes ni se añaden dependencias.

No existe learning record de `rai-story-design` ni calibración formal para este
tipo de story; se registrará el tiempo real, no una estimación inventada.

## Ordered Tasks

### T1 — Strict workspace contract and safe dispositions

- **Size:** M
- **Depends on:** story scope/design only
- **Files:** create `escala_server/workspace/__init__.py`,
  `escala_server/workspace/authority.py`,
  `tests/test_workspace_authority.py`
- **AC:** story Gherkin — valid workspace and incomplete/unknown config.
- **RED:** tests for `ConfigDict(extra="forbid", frozen=True)`, schema version,
  supported platform, missing roots and closed finding codes; assert no raw
  validation value is serialized.
- **GREEN:** implement `WorkspaceConfig`, `SafeFinding`, `CheckResult`,
  `WorkspaceReceipt` and stable `WorkspaceAuthorityError` using existing
  Pydantic conventions.
- **REFACTOR:** keep the public export surface minimal and separate internal
  resolved paths from the redacted receipt.
- **Verification:** `uv run pytest --tb=short`; `uv run ruff check`;
  `uv run ruff format --check`; `uv run pyright`.

### T2 — Resolved path containment and symlink guard

- **Size:** M
- **Depends on:** T1
- **Files:** modify `escala_server/workspace/authority.py` and
  `tests/test_workspace_authority.py`
- **AC:** story Gherkin — database inside exchange, symlink escape,
  data/exchange overlap, Windows-shaped fixtures.
- **RED:** use `tmp_path` with existing and non-existing roots, symlinked
  parents, case/path separator fixtures and a database path equal to or below
  `exchange_root`; assert stable fail-closed codes.
- **GREEN:** resolve with `Path.resolve(strict=False)`, compare parent
  containment instead of string prefixes, and reject uncertain/unreadable
  resolution.
- **REFACTOR:** centralize resolution/containment helpers and ensure sorted
  findings/checks are deterministic.
- **Verification:** `uv run pytest --tb=short`; `uv run ruff check`;
  `uv run ruff format --check`; `uv run pyright`.

### T3 — Pre-initialization authoritative DB seam and receipt rendering

- **Size:** M
- **Depends on:** T2
- **Files:** modify `escala_server/daos/schema.py` minimally; modify
  `escala_server/workspace/authority.py`; extend
  `tests/test_workspace_authority.py` and existing DAO tests only if the seam
  requires a compatibility assertion.
- **AC:** story Gherkin — unsafe target fails before SQLite and exchange is
  ordinary filesystem documents only.
- **RED:** instrument the existing initializer with a sentinel callback; for an
  unsafe config assert callback is not called and before/after tree fingerprints
  match. For a safe config assert the callback receives only a resolved local
  database target.
- **GREEN:** add a wrapper such as `init_authoritative_db(config, initializer)`
  that validates, raises a typed error on fail, and invokes the existing
  initializer only on pass. Render stable JSON/Markdown from the same receipt.
- **REFACTOR:** avoid duplicating guard logic in both schema modules, preserve
  legacy `init_db(db_path)` behavior, and keep cloud/API capability absent.
- **Verification:** `uv run pytest --tb=short`; `uv run ruff check`;
  `uv run ruff format --check`; `uv run pyright`.

### T4 — Manual local integration qualification and evidence handoff

- **Size:** S
- **Depends on:** T3
- **Files:** extend `tests/test_workspace_authority.py`; create bounded
  `work/epics/e37-local-workspace-flexible-ingestion/evidence/` receipts only
  when the evidence writer is implemented, plus no untracked source changes.
- **AC:** all story criteria and REQ-E37-001/002 evidence.
- **RED:** construct a real temporary workspace with a valid DB target, a
  forbidden exchange target, and a symlink case; run the seam twice and assert
  deterministic receipt bytes and no unexpected paths/SQLite side effects.
- **GREEN:** qualify the integrated flow and write only redacted, relative,
  deterministic evidence. If a required artifact writer is not yet owned by
  S37.1, record the exact gap instead of fabricating a proof.
- **REFACTOR:** run project-wide quality commands and inspect the final diff,
  status and generated-file boundary.
- **Verification:** `uv run pytest --tb=short`; `uv run ruff check`;
  `uv run ruff format --check`; `uv run pyright`; relevant RaiSE gates if
  registered. The installed registry has no `gate-plan`, so this plan uses the
  manifest commands and records that tool gap.

## Execution Order and Dependencies

```text
T1 contract ──► T2 containment ──► T3 pre-init seam ──► T4 real qualification
```

The tasks are intentionally sequential: T2 cannot be trusted before the typed
contract exists, T3 must consume one containment implementation, and T4 must
exercise the final seam against real filesystem state. Fixture authoring inside
T2 may be prepared independently but is committed with its owning task.

## Risks and Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| `Path.resolve` behavior differs by OS or missing parent | High | Test existing/non-existing paths, symlink parents and Windows-shaped inputs; fail closed on resolution uncertainty. |
| Guard is added after a DAO creates directories | High | T3 sentinel initializer and before/after filesystem fingerprint prove ordering. |
| Receipt serialization leaks `Path` values through nested models | High | Separate safe models, deny raw validation errors, test serialized JSON/Markdown for absolute path and sentinel strings. |
| Existing DAOs regress from an over-broad signature change | Medium | Keep legacy `init_db(db_path)` compatibility and run full project commands after each task. |
