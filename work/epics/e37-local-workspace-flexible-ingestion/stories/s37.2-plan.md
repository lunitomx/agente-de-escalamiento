## Execution order and rationale

The dependency graph is strictly sequential: identity and authority first,
then the lowest-risk tabular adapter, then XLSX/text, then shared failure and
receipt semantics, then the consumer seam, and finally a real temporary
workspace run. This is risk-first and prevents S37.3 from consuming an API
whose identity or redaction behavior has not been proved. No parallel work is
planned because all adapters share the same structural profile and receipt
contract.

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| Header heuristics silently choose the wrong meaning | Equal material candidates become `needs_clarification`; no canonical write. |
| XLSX parser becomes a universal parser | Minimal safe ZIP/XML subset; unsupported/provider-unavailable is explicit. |
| Source data leaks into receipts | Ordinal/coded candidates only, path redaction tests and deterministic renderers. |
| New adapter duplicates authority logic | Every profile call reuses S37.1 validation and the one shared seam. |
| Story grows into inbox/quarantine | Moves, retries, duplicate disposition and quarantine remain S37.3. |
