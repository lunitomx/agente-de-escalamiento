# S37.1 Design: Local Workspace & Data Authority

## Problem

El runtime actual permite pasar cualquier `db_path` a los inicializadores
SQLite y crea sus directorios antes de que exista un concepto de carpeta de
intercambio. Eso deja abierta la posibilidad de que un usuario ponga por error
SQLite dentro de una carpeta sincronizada. Los receipts actuales del intake
también serializan rutas absolutas, por lo que no sirven como evidencia segura.

## Value

Después de esta story, el sistema puede demostrar —antes de abrir SQLite— que
la autoridad está en la máquina del instalador y que el exchange solo contiene
documentos. Una configuración insegura falla sin crear archivos, sin mutar el
workspace y sin exponer la ruta local.

## Complexity and Gates

- **Complexity:** moderate — un modelo/guard de autoridad, un seam de inicialización,
  receipts y pruebas reales de filesystem.
- **Risk gate:** alto; un bypass de ruta puede corromper autoridad o compartir
  datos sensibles. Se cubre con fail-closed y no-mutation tests.
- **UX gate:** no aplica como UI. La configuración es una interfaz técnica local;
  sus errores deben ser accionables y redacted.
- **Integration gate:** no aplica por nombre de story, pero la prueba usa un
  initializer real/instrumentado y un filesystem temporal, no mocks de Path.
- **Storage migration:** no aplica; no se modifica DDL ni se consolidan los dos
  esquemas existentes.
- **Supply chain:** no se agrega dependencia; Pydantic ya es runtime.

## PRIME Context

Las consultas de grafo devolvieron E36 y E1802 como precedentes de frontera
local-only y servidor local, además de los guardrails de fail-closed y no
generar sin entender. No apareció un guard existente de SQLite que pueda
reutilizarse directamente.

## Gemba Findings

1. `escala_server/daos/schema.py` resuelve `db_path`, crea el parent y abre
   SQLite; no recibe `exchange_root` ni puede decidir autoridad.
2. `escala_server/schema.py` tiene otro inicializador con soporte para URI y
   `:memory:`; ambas implementaciones deben seguir funcionando para sus tests.
3. `escala_server/__main__.py`, `escala_server/cli.py` y `server.py` construyen
   el runtime local con `~/.escala/escala.db`, pero no validan un workspace.
4. `coaching/class_intake.py` prueba persistencia de cursos y exige paths
   absolutos; no es un contrato de datos empresariales y no se modifica en esta
   story.
5. `validators/master_acceptance.py` y `validators/repository_truth.py`
   demuestran Pydantic estricto, hashes estables y receipts sanitizados; ese es
   el patrón a seguir para el nuevo módulo.

No se crea un segundo guard en cada DAO. El único componente nuevo contiene la
regla y un wrapper recibe el initializer existente como seam; los entrypoints
que opten por un workspace usarán ese wrapper.

## Approach

Crear `escala_server.workspace.authority` con un modelo interno estricto,
resolución de rutas y un resultado seguro. `init_authoritative_db` (o un seam
equivalente con el mismo contrato) llama primero a la validación y solo invoca
el initializer SQLite cuando pasa. El receipt expone únicamente roles,
versiones, checks, códigos estables y estados; nunca serializa el `Path`.

### Components

| Component | Change | Purpose |
|---|---|---|
| `escala_server/workspace/__init__.py` | Create | Exportar el contrato público mínimo, sin imports cloud. |
| `escala_server/workspace/authority.py` | Create | Pydantic models, resolve/containment, policy, redaction, receipt y guard wrapper. |
| `escala_server/daos/schema.py` | Modify minimally | Exponer/integrar el seam antes de `init_db` sin cambiar DDL ni soporte legacy. |
| `tests/test_workspace_authority.py` | Create | Casos válidos, overlap, symlink, unknown fields, no-mutation, determinism y redaction. |
| `.raise/artifacts/s37.1-design.yaml` | Create | Artefacto tipado de esta fase; no es evidencia de implementación. |

### Lean Gates and Value Preservation

- **KISS:** una sola regla de containment y un solo wrapper; no se introduce un
  motor de políticas general.
- **DRY:** el guard vive en `workspace.authority`; los dos esquemas no copian la
  lógica.
- **YAGNI:** no se detecta si una carpeta está sincronizada por heurística y no
  se agregan APIs cloud.
- **MVP:** el valor mínimo es aceptar un workspace local seguro o detenerse
  antes de SQLite; el profiling llega en S37.2.
- **Value preservation:** la capa aporta conocimiento real de roles de datos,
  prohibición de SQLite sincronizado y redacción; no es un pass-through de
  `Path`.

## Data Contracts

```python
class WorkspaceConfig(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)
    schema_version: Literal[1] = 1
    platform: Literal["macos", "windows"]
    data_root: Path
    database_path: Path
    exchange_root: Path

class WorkspaceReceipt(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)
    schema_version: Literal[1] = 1
    status: Literal["pass", "fail"]
    checks: tuple[CheckResult, ...]
    findings: tuple[SafeFinding, ...]
    runtime_authority: Literal["installer_machine"]
    data_authority: Literal["installer_machine"]
    team_exchange: Literal["ordinary_filesystem_documents_only"]
    authoritative_sqlite_sync: Literal["forbidden"]
```

`WorkspaceConfig` puede contener `Path` internamente, pero no se serializa en
un receipt. `SafeFinding` solo acepta códigos cerrados como
`unknown_field`, `path_unreadable`, `database_inside_exchange`,
`symlink_inside_exchange`, `ambiguous_root` y `unsupported_schema`.

## Runnable Examples

### Valid local workspace

```python
from pathlib import Path
from escala_server.workspace.authority import WorkspaceConfig, validate_workspace

config = WorkspaceConfig(
    platform="macos",
    data_root=Path("/tmp/acme-local/data"),
    database_path=Path("/tmp/acme-local/data/escala.sqlite"),
    exchange_root=Path("/tmp/acme-local/team-inbox"),
)

receipt = validate_workspace(config)
assert receipt.status == "pass"
assert receipt.authoritative_sqlite_sync == "forbidden"
assert all("/tmp" not in str(item) for item in receipt.model_dump().values())
```

Expected safe result (paths intentionally absent):

```json
{
  "status": "pass",
  "runtime_authority": "installer_machine",
  "data_authority": "installer_machine",
  "team_exchange": "ordinary_filesystem_documents_only",
  "authoritative_sqlite_sync": "forbidden",
  "findings": []
}
```

### Invalid database target before initializer

```python
from pathlib import Path
from escala_server.workspace.authority import (
    WorkspaceConfig,
    init_authoritative_db,
    WorkspaceAuthorityError,
)

config = WorkspaceConfig(
    platform="macos",
    data_root=Path("/tmp/acme-local/data"),
    database_path=Path("/tmp/acme-local/team-inbox/company.sqlite"),
    exchange_root=Path("/tmp/acme-local/team-inbox"),
)

called = False

def initializer(_: str):
    global called
    called = True

try:
    init_authoritative_db(config, initializer=initializer)
except WorkspaceAuthorityError as exc:
    assert exc.code == "authoritative_sqlite_sync_forbidden"
assert called is False
```

The test creates a temporary `team-inbox` and compares a before/after tree
fingerprint; no `company.sqlite`, `-wal`, `-journal` or parent directory may be
created by the failed call.

### Symlink negative case

```python
link = tmp_path / "local-link"
link.symlink_to(tmp_path / "team-inbox", target_is_directory=True)
unsafe = WorkspaceConfig(
    platform="macos",
    data_root=tmp_path / "data",
    database_path=link / "company.sqlite",
    exchange_root=tmp_path / "team-inbox",
)
receipt = validate_workspace(unsafe)
assert receipt.status == "fail"
assert {f.code for f in receipt.findings} == {"symlink_inside_exchange"}
```

## Algorithm Sketch

```text
validate(config):
  reject schema != 1, unknown fields, missing roots, and unsupported platform
  resolve data_root, exchange_root, database_path with strict=False
  reject unresolved/ambiguous roots and data_root == exchange_root
  if database_path == exchange_root or database_path is_relative_to(exchange_root):
      fail authoritative_sqlite_sync_forbidden
  if any parent symlink resolves inside exchange_root:
      fail symlink_inside_exchange
  return deterministic redacted receipt with closed roles and checks

init_authoritative_db(config, initializer):
  receipt = validate(config)
  if receipt.status != pass:
      raise WorkspaceAuthorityError(receipt)
  return initializer(str(resolved_database_path))
```

No exception text or incoming path is copied into the receipt. If resolution
fails, the result uses a stable code and `status=fail`.

## Acceptance Criteria (refined)

### MUST

1. Strict local config and containment guard pass all positive/negative path
   tests, including symlinks and Windows-shaped fixtures.
2. The authoritative initializer is never called for an unsafe config, and the
   temporary filesystem remains unchanged.
3. Receipts are deterministic and contain roles/codes only; no absolute paths,
   cloud settings, credentials, contents or raw errors.
4. Existing legacy SQLite initializers remain green; integration adds no DDL or
   network dependency.

### SHOULD

- Provide a small CLI/test helper that renders the same receipt as JSON and
  Markdown without duplicating policy logic.
- Add an explicit safe label for a user-selected exchange role, independent of
  the folder's display name.

### MUST NOT

- Detect synchronization by folder name or attempt Drive/OneDrive API calls.
- Open SQLite before validation or silently fall back to a path under exchange.
- Modify `coaching/class_intake.py`, private company files, the public candidate,
  or any remote repository.

## Testing Strategy

- Unit: Pydantic extra-field and schema checks; route resolution; containment;
  stable code mapping; receipt serialization.
- Filesystem integration: `tmp_path` with existing/non-existing roots,
  symlinks, Windows-style relative fixtures and before/after fingerprints.
- Runtime seam: instrument both current schema initializers and assert an
  invalid config invokes neither.
- Regression: focused `tests/test_workspace_authority.py`, then all tests,
  Ruff, format check, Pyright and relevant RaiSE gates before story close.
