## In Scope

- A filesystem-only inbox scanner rooted in the user-declared exchange folder.
- Local source ledger in the installer data root for rerun-safe source IDs and
  duplicate disposition; no SQLite schema migration.
- Accepted, duplicate, changed, needs_clarification and quarantined/report-only
  dispositions with deterministic receipts.
- Explicit limits for symlinks, directories, unreadable/corrupt/encrypted,
  oversized and unsupported entries.
- Atomic local ledger/report writes, no source deletion or overwrite, and tests
  for repeated scans and changed bytes.
- Real temporary-folder qualification for ordinary filesystem semantics,
  including a folder that represents a Drive/OneDrive sync without any API.

## Out of Scope

- Google Drive or OneDrive SDK/API, OAuth, webhooks, hosted runtime,
  collaboration or telemetry.
- SQLite schema changes, synchronized databases or multi-writer state.
- Financial reconstruction, dailies/weeklies analysis, strategy, dashboard or
  executive diagnosis (E38-E40).
- Packaged installer/update/rollback (E41) and final entrepreneur E2E/PDF (E42).
- OCR, universal format parsing or destructive moves of user documents.

## Done when

- [ ] Two scans of the same folder yield one accepted identity and a duplicate
      disposition without changing the local ledger on the second run.
- [ ] A changed source creates a new identity while preserving the old ledger
      entry.
- [ ] Every failure class has a stable report/quarantine code and the original
      file and authoritative SQLite remain untouched.
- [ ] The ledger and receipts contain relative provenance only, no secrets,
      contents, absolute paths or cloud/API metadata.
- [ ] A temporary real-folder qualification passes idempotency, failure and
      non-mutation assertions.
- [ ] Focused tests, full tests, lint, format, types and story retrospective
      pass before close.
