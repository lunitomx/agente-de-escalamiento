## Heutagogical Checkpoint

### 1. ¿Qué aprendimos?

Que resolver una ruta no basta: la detección de symlinks debe tener un límite
semántico. Inspeccionar todos los padres hasta `/` convirtió un alias legítimo
del sistema operativo en una falsa señal de que el SQLite estaba sincronizado.

### 2. ¿Qué cambiaríamos del proceso?

Ejecutar el flujo manual temporal antes de cerrar T2/T3. Así la diferencia entre
filesystem de prueba y filesystem de una máquina macOS se observa mientras la
corrección aún está aislada.

### 3. ¿Qué mejora para RaiSE/framework queda?

Las plantillas de story deberían incluir una matriz de symlink por plataforma y
exigir que la evidencia de implementación se mantenga separada del proof del
ledger. Los gates de requisito también necesitan un registro instalable o una
disposición explícita `unavailable`.

### 4. ¿Qué hacemos mejor ahora?

Podemos conectar un initializer SQLite existente a una autoridad local sin
duplicar guardas, generar receipts humanos/JSON con el mismo contrato y probar
que una negativa no crea ni modifica estado.
