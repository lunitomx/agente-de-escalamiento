# Story: Local Workspace & Data Authority

## User Story

Como empresario que instala ESCALA en su propia computadora,
quiero declarar una raíz de datos local y una carpeta de intercambio separada,
para que mi SQLite y el estado autoritativo no puedan terminar dentro de una
carpeta sincronizada o compartida.

## Acceptance Criteria

### Scenario: Workspace local válido

```gherkin
Given una raíz local de datos y una carpeta de intercambio configuradas
And la ruta de SQLite está fuera de la carpeta de intercambio
When se valida el workspace
Then la configuración es aceptada
And identifica la máquina instaladora como autoridad de runtime y datos
And el resultado no expone rutas absolutas de la máquina
```

### Scenario: SQLite dentro del exchange falla cerrado

```gherkin
Given `database_path` está dentro de `exchange_root`
When se valida el workspace antes de inicializar SQLite
Then la validación falla con un código estable de autoridad
And no crea el directorio, archivo, WAL ni conexión SQLite
And no escribe un receipt que contenga la ruta absoluta
```

### Scenario: Symlink no evade la frontera

```gherkin
Given una ruta aparente fuera del exchange apunta por symlink a una ubicación dentro
When se resuelven las rutas del workspace
Then se compara la ubicación resuelta
And la configuración se rechaza de forma fail-closed
And ninguna ruta no resuelta se trata como autoridad segura
```

### Scenario: Carpeta sincronizada solo intercambia documentos

```gherkin
Given `exchange_root` representa una carpeta local, Drive o OneDrive ya sincronizada
When se carga la configuración
Then se clasifica como `ordinary_filesystem_documents_only`
And no se invoca API, OAuth, red, telemetría ni servicio remoto
And SQLite y el estado autoritativo permanecen bajo `data_root`
```

### Scenario: Configuración incompleta o ambigua falla cerrado

```gherkin
Given falta una raíz, hay campos desconocidos o las rutas son iguales/ambiguas
When se valida el modelo estricto
Then la validación falla con errores redacted y accionables
And no se infieren defaults que coloquen datos en el exchange
```

## Examples (Specification by Example)

| Input | Expected result |
|---|---|
| `data_root=/local/data`, `exchange_root=/team/inbox`, `db=/local/data/company.sqlite` | `valid`, local authority, no network capability |
| `db=/team/inbox/company.sqlite` | `invalid`, stable `authoritative_sqlite_sync_forbidden`, no file/connection |
| `db=/local/link/company.sqlite`, link resolves into `/team/inbox` | `invalid`, symlink containment finding |
| Windows-style relative paths resolved under a local temp root | same containment semantics; no string-prefix shortcut |
| unknown field `cloud_database_url` | `invalid`, unknown-field error, value never serialized |
