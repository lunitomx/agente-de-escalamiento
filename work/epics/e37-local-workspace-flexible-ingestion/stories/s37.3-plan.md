## Execution order and rationale

Persistence and safe contracts come first, then enumeration limits, then the
profile/idempotency walking skeleton, then report rendering, and finally the
real folder run. This is strictly sequential because each layer protects the
next; no watcher or parallel adapter is needed.

| When | Command | Scope |

Direct `uv run pytest` is not used for per-task verification; the RaiSE gate
commands above are the tracked specification checks.

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| Ledger syncs accidentally through Drive/OneDrive | Derive it under data_root, validate it is outside exchange, and test no exchange writes. |
| Duplicate scan mutates local history | First disposition wins; second scan is read-only except its report. |
| Symlink escapes exchange | Reject `is_symlink()` before identity resolution; never follow or move it. |
| Failure handling becomes destructive quarantine | Report-only disposition; original files remain untouched. |
| Inbox grows into a daemon/API | Direct bounded scan only; watcher/cloud/OAuth are explicit MUST NOT. |
