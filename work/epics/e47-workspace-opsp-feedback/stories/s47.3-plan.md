# S47.3 — Plan de implementación: OPSP completo y coherente

## Resumen

Tamaño M (5 puntos). El riesgo principal es cambiar el contrato estratégico sin
romper E40 ni recrear la contradicción entre código y recursos. Se trabaja
riesgo-primero y se mantiene S47.4 fuera: no habrá persistencia, exportación ni
dependencia de RaiSE como producto.

## T1 — Especificar el modelo completo (S)

- **RED:** añadir casos que exijan siete columnas, filas Actions/Goals/Targets,
  accountability por persona, Key Capabilities a 3–5 años y pendientes
  explícitos.
- **GREEN:** los casos fallan con el modelo actual, dejando la frontera
  verificable.
- **REFACTOR:** conservar los ocho campos públicos de `StrategyPlan`.
- **Archivos:** `tests/test_e40_executive_cockpit.py`.
- **AC:** AC-1, AC-2, AC-3.
- **Verificación:** `rai gate check gate-tests --scope tests/test_e40_executive_cockpit.py`;
  `rai gate check gate-lint`; `rai gate check gate-format`;
  `rai gate check gate-types`.
- **Dependencia:** ninguna.

## T2 — Implementar el contrato y constructor (M)

- **RED:** ejecutar los casos de T1 y confirmar que fallan por campos/estructura
  inexistentes.
- **GREEN:** extender `StrategyPlan`, sus submodelos y
  `build_strategy_plan` para derivar sólo datos explícitos y dejar preguntas
  para cada pendiente.
- **REFACTOR:** exportar únicamente los contratos públicos necesarios y mantener
  compatibilidad de E40.
- **Archivos:** `escala_server/executive/models.py`,
  `escala_server/executive/coaching.py`,
  `escala_server/executive/__init__.py`.
- **AC:** AC-1, AC-2, AC-3, AC-5.
- **Verificación:** `rai gate check gate-tests --scope tests/test_e40_executive_cockpit.py`;
  `rai gate check gate-lint`; `rai gate check gate-format`;
  `rai gate check gate-types`.
- **Dependencia:** T1.

## T3 — Alinear fuentes y skills instaladas (S)

- **RED:** añadir pruebas que fallen si aparece “last four” contra columnas
  5–7, si faltan filas/responsables/capabilities o si las skills refieren
  plantillas/guardado inexistentes.
- **GREEN:** actualizar ambos YAML y los tres mirrors de la skill con la misma
  estructura; declarar que persistencia/exportación pertenece a S47.4.
- **REFACTOR:** mantener los espejos byte-a-byte idénticos cuando corresponda.
- **Archivos:** `.scaleup/knowledge/strategy/tools/opsp.yaml`,
  `.scaleup/knowledge/strategy/worksheets/opsp.yaml`,
  `escala-skills/escala-strategy-opsp/SKILL.md`,
  `.agents/skills/scaleup-strategy-opsp/SKILL.md`,
  `.claude/skills/scaleup-strategy-opsp/SKILL.md`,
  `tests/test_strategy_voice_of_customer_prompting.py`.
- **AC:** AC-4, AC-5.
- **Verificación:** `rai gate check gate-tests --scope tests/test_strategy_voice_of_customer_prompting.py`;
  `rai gate check gate-lint`; `rai gate check gate-format`;
  `rai gate check gate-types`.
- **Dependencia:** T2.

## T4 — Integración manual del contrato (XS)

- Construir un OPSP con datos parciales y uno completo usando el API público;
  revisar que el primero declare pendientes y el segundo tenga siete columnas,
  tres filas y responsables, sin escritura en base de datos.
- **AC:** AC-1 a AC-5.
- **Verificación:** `rai gate check gate-tests --scope tests/test_e40_executive_cockpit.py`;
  `rai gate check gate-tests --scope tests/test_strategy_voice_of_customer_prompting.py`;
  `rai gate check gate-lint`; `rai gate check gate-format`;
  `rai gate check gate-types`.
- **Dependencia:** T2 y T3.

## Orden y riesgos

`T1 → T2 → T3 → T4`. El modelo se prueba primero porque es la dependencia de
las fuentes; la actualización de recursos queda separada para detectar deriva.
No hay tareas paralelas: ambas capas comparten la semántica canónica.

| Riesgo | Mitigación |
|---|---|
| Romper el consumidor E40 | Pruebas existentes y campos públicos conservados. |
| Inventar datos | Estados, pendientes y preguntas se prueban con input parcial. |
| Deriva entre mirrors | Prueba de igualdad y aserciones semánticas sobre YAML/skills. |
| Confundir modelo con persistencia | T4 verifica que no hay escritura; S47.4 toma la persistencia. |
