# S47.1 — Contrato Workspace Codex/MCP

## User story

**Como** persona que instala ESCALA y trabaja desde Codex,
**quiero** que el agente use el canal MCP de RaiSE cuando el sandbox no puede
escribir la base global,
**para** continuar el trabajo sin ampliar permisos sobre secretos ni recibir un
traceback técnico.

## Reglas de negocio

- El diagnóstico no expone valores de `~/.rai`, tokens ni archivos sensibles.
- Un error SQLite de sólo lectura orienta hacia `rai-workspace` MCP; no sugiere
  desactivar el sandbox.
- El provisionado de un worktree debe ser reproducible y no dejar artefactos
  generados como drift inesperado.

## Acceptance criteria

### Scenario: Fallback seguro en Codex

- **Given** un proceso Codex en modo workspace-write
- **When** una operación de estado RaiSE requiere escritura global
- **Then** el contrato indica usar `rai-workspace` MCP
- **And** no solicita acceso de escritura a `~/.rai`

### Scenario: Provisionado limpio

- **Given** un checkout limpio de ESCALA
- **When** se prepara un worktree para una historia
- **Then** los artefactos generados no aparecen como drift inesperado
- **And** la configuración MCP es ejecutable en el worktree

### Scenario: Límites explícitos

- **Given** una instalación donde el CLI no es escribible dentro de Codex
- **When** la persona pide continuar el trabajo RaiSE
- **Then** el mensaje diferencia fallback de acceso a secretos
- **And** no presenta la limitación como un fallo de Jira o credenciales
