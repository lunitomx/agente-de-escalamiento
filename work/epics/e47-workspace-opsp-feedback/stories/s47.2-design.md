# S47.2 — Diseño: Instalador, recursos y migración

## Problema y valor

El worktree no propagaba el manifiesto de RaiSE: ningún gate podía ejecutarse.
Además, la instalación editable dejaba `escala_coaching.egg-info/` visible en
Git. Corregir ambos permite trabajo gobernado sin copiar la base SQLite ni
secretos.

## Enfoque

La configuración local de worktrees declara sólo `.raise/manifest.yaml`; no se
copia `.raise/rai/`, credenciales ni tokens. `.gitignore` absorbe la metadata
reproducible del paquete editable. No se instalan dependencias ni se cambian
permisos.

## Decisiones

- **S47.2-D1:** propagar únicamente el manifiesto: es la mínima configuración
  para resolver gates.
- **S47.2-D2:** ignorar `*.egg-info/`: no es código fuente ni evidencia de
  producto.

## Ejemplo

```text
rai worktree register ...
# .raise/manifest.yaml presente
# .raise/rai/raise.db ausente
```

## Criterios de aceptación

- [ ] Un worktree registrado recibe `.raise/manifest.yaml` sin SQLite ni tokens.
- [ ] `*.egg-info/` no aparece como drift Git-visible.
- [ ] Un gate resuelve el manifiesto desde el worktree.
- [ ] No hay instalación global ni cambio de permisos.

## Riesgos

- Copiar toda `.raise/` duplicaría estado y secretos; se limita a un archivo.
- Los artefactos `work/` no se propagan entre ramas; se deja como limitación a
  revisar al cerrar la historia.
