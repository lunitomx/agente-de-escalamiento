# S47.3 — Retrospectiva: modelo OPSP completo y coherente

## Resultado

S47.3 reemplazó el conocimiento parcial del Plan Estratégico de Una Página (OPSP) por un modelo explícito de siete columnas y tres filas. Mantiene los campos compatibles que ya consumía ESCALA, proyectados a celdas canónicas, y no inventa información cuando una respuesta falta.

El estado `ready` exige tanto los datos requeridos como un responsable para cada celda de ejecución (columnas 4–7). Las capacidades clave se modelan a un horizonte fijo de 3–5 años. La persistencia, reanudación y exportación permanecen deliberadamente fuera de este alcance: son S47.4.

## Evidencia

- Modelo Pydantic validado: 7 columnas ordenadas; filas Actions, Goals y Targets; celdas con pregunta, estado y accountability.
- Recursos y las tres superficies de skill alineados; no remiten a plantillas ausentes.
- Pruebas enfocadas del cockpit y de voz de estrategia en verde, más lint, formato y tipos.
- Integración manual: el plan parcial devuelve `needs_clarification`; el completo devuelve `ready`; la persistencia sigue siendo `none`.
- Revisión de calidad: PASS. Revisión arquitectónica atestada para `gate-ar-story`.

## Qué funcionó

1. Las pruebas guiaron dos correcciones esenciales: conservar la proyección compatible de `brand_promise` y bloquear ejecución sin responsabilidad asignada.
2. Convertir los campos antiguos a celdas evitó una migración incompatible y dio trazabilidad a cada respuesta.
3. Separar explícitamente S47.4 impidió que el modelo de dominio adquiriera una dependencia de almacenamiento prematura.

## Qué mejorar

1. El pipeline no materializó el plan de historia aunque el ciclo lo exige; se ejecutó el subgate manualmente y quedó publicado.
2. El completado de tareas clasificó erróneamente un skill ya rastreado bajo `.agents/` como archivo ignorado. Se verificó su seguimiento y se añadió de forma forzada, sin alterar otros archivos.
3. La ejecución de la suite completa no devolvió un resumen capturable; se conservan las puertas enfocadas aprobadas como evidencia verificable.

## Aprendizaje

Patrón creado: **PAT-14** — En modelos de planificación estructurada, proyectar campos heredados a celdas canónicas y exigir responsable en cada celda de ejecución antes de declarar el plan listo.

## Preguntas heutagógicas

1. ¿Qué parte del OPSP puede responderse con evidencia de negocio y cuál requerirá decisión humana explícita?
2. ¿Quién debe ser responsable de cada celda trimestral antes de que el plan cambie a `ready`?
3. ¿Qué contrato de guardado y reanudación permitirá a S47.4 persistir este modelo sin exponer datos del cliente?
4. ¿Qué vista exportable permite revisar las siete columnas sin volver a convertirlas en texto libre?
