# Story Design: S20.1 — Knowledge Context API

## Problem

El endpoint `GET /api/knowledge/context` fue creado en S19.4 pero:
- No tiene tests de integración que verifiquen datos reales del grafo
- No se ha verificado que el grafo de E19 esté poblado correctamente
- Los dashboards (S20.2) necesitan un contrato API estable antes de integrarse

## Value

Sin esta verificación, S20.2 (Dashboard Context Panel) se implementaría contra un endpoint que podría no funcionar con datos reales, causando retrabajo.

## Approach

1. Verificar que el grafo de E19 tenga datos poblados (entidades, relaciones)
2. Ejecutar el endpoint real contra el grafo y capturar su respuesta
3. Escribir tests de integración que validen:
   - Consulta por tool (ej: "Power of One")
   - Consulta por category (ej: "cash")
   - Consulta sin parámetros → 400
   - Consulta con tool inexistente → respuesta vacía
4. Documentar el contrato API para S20.2

## Components Affected

| Component | Change | Purpose |
|-----------|--------|---------|
| `tests/test_knowledge_context_api.py` | create | Tests de integración contra endpoint real |
| `escala_server/knowledge_handler.py` | (none — verify only) | El código ya existe |
| `work/epics/e20-contextual-skills/stories/s20.1-design.md` | create | Este documento |

## Design Decisions

| ID | Decision | Rationale |
|:--:|----------|-----------|
| D1 | Tests contra endpoint HTTP real, no unitarios | Validar el stack completo: route → handler → graph_engine → SQLite |
| D2 | Usar base de datos temporal poblada con fixtures | Misma estrategia que `test_knowledge_api.py` existente |
| D3 | No modificar `get_context()` a menos que falle con datos reales | El código ya pasó revisión en S19.4 |

## Legacy Sweep

Nada — esto es net-new (testing + verificación). El endpoint en `main` no se modifica.

## Examples

```python
# Consulta por tool
GET /api/knowledge/context?tool=Power of One
# → {
#     "tool": {"name": "Power of One", "type": "tool", ...},
#     "entities": [...],
#     "principles": [...],
#     "habits": [...],
#     "status": "ok"
# }

# Consulta por category
GET /api/knowledge/context?category=cash
# → {
#     "entities": [{"name": "Cash Conversion Cycle", ...}, ...],
#     "principles": [...],
#     "habits": [...],
#     "category": "cash",
#     "status": "ok"
# }

# Sin parámetros
GET /api/knowledge/context
# → 400 Bad Request: {"status": "error", "message": "...requires tool or category"}
```

## Acceptance Criteria

### MUST
- [ ] Test: GET /api/knowledge/context?tool=power-of-one devuelve 200 con entidades + relaciones del grafo real
- [ ] Test: GET /api/knowledge/context?category=cash devuelve entidades de la categoría cash
- [ ] Test: GET /api/knowledge/context (sin params) devuelve 400
- [ ] Test: GET /api/knowledge/context?tool=inexistente devuelve 200 con respuesta vacía
- [ ] Tests usan base de datos temporal con fixtures como los tests existentes

### SHOULD
- [ ] Documentar el formato exacto de respuesta para S20.2

### MUST NOT
- [ ] Modificar la lógica existente de `get_context()` — solo tests
