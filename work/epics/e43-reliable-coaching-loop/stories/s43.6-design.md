# S43.6 — Calificar las cuatro decisiones: diseño

## Problem

El ciclo de coaching confiable (S43.1-S43.5) se ha probado principalmente con
casos Cash y Execution. E43 promete que las mismas reglas de evidencia y
honestidad funcionen en las cuatro decisiones (People, Strategy, Execution,
Cash), incluyendo casos negativos con evidencia faltante, contradicción o
datos dañados.

## Value

Demostrar que el ciclo no solo funciona con Cash; conserva las mismas reglas de
evidencia y honestidad en People, Strategy, Execution y Cash, tanto en casos
positivos como negativos.

## Complexity

**Moderate** — 4×2 casos de prueba + un runner que ejecuta el ciclo completo.
No requiere nuevo módulo de producción; es un módulo de calificación/tests.

## Approach

Crear `coaching/qualifier/` como módulo de pruebas y fixtures. Incluir:

- Un conjunto de casos (fixtures) para cada una de las cuatro decisiones,
  divididos en positivos (respuesta ejecutiva esperada) y negativos
  (`clarify`/`blocked` esperado).
- Un runner `qualify(context)` que ejecute el ciclo completo reutilizando
  `coaching.evidence`, `coaching.selector`, `coaching.reviewer` y
  `coaching.responder`.
- Tests parametrizados que validen cada caso.
- Skill adapter `escala-qualifier/SKILL.md` para documentar el contrato.

## Components Affected

| Component | Change | Purpose |
|-----------|--------|---------|
| `coaching/qualifier/cases.py` | create | Fixtures con casos positivos y negativos para las cuatro decisiones. |
| `coaching/qualifier/runner.py` | create | Ejecuta el ciclo completo sobre un caso. |
| `coaching/qualifier/__init__.py` | create | Punto de entrada `qualify(context)`. |
| `coaching/qualifier/__main__.py` | create | CLI para ejecutar todos los casos. |
| `coaching/qualifier/tests/test_qualifier.py` | create | Tests parametrizados de los 8 casos. |
| `escala-skills/escala-qualifier/SKILL.md` | create | Skill adapter. |

## Design Decisions

| ID | Title | Rationale |
|----|-------|-----------|
| D1 | Módulo de calificación separado | No ensucia los módulos de producción con casos de prueba. |
| D2 | Casos como datos Python | Facilita la parametrización de tests y la ejecución manual. |
| D3 | Reutilizar el ciclo real | Los casos usan `evidence.run`, `selector.run`, `reviewer.run`, `responder.run`. |
| D4 | Criterio de éxito por caso | Positivos deben llegar a `responded`; negativos a `clarify` o `blocked` antes de responder. |

## Acceptance Criteria

### MUST

- **AC1:** Casos positivos para People, Strategy, Execution y Cash generan
  `responded`.
- **AC2:** Casos negativos para cada área generan `clarify` o `blocked`.
- **AC3:** El runner ejecuta el ciclo completo sin duplicar lógica.
- **AC4:** Tests parametrizados pasan localmente.

### MUST NOT

- **AC5:** No se crea lógica de producción adicional innecesaria.

## Dependencies

- S43.1-S43.5 completos.
