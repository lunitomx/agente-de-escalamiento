# S43.5 — Entregar la respuesta ejecutiva: diseño

## Problem

Después de S43.4, ESCALA está autorizada a responder, pero la respuesta puede
llegar como un informe técnico largo o sin estructura fija. El empresario
necesita leerla en menos de cinco minutos y entender cuál es la decisión
siguiente.

## Value

El empresario recibe una respuesta ejecutiva consistente con cinco bloques
breves: qué veo, por qué importa, evidencia relevante, qué no sé todavía, y
acción recomendada o siguiente pregunta.

## Complexity

**Low** — 3-4 componentes, lógica pura de renderizado a partir de datos ya
revisados, tests que cubren los cinco bloques.

## Approach

Crear el módulo puro `coaching.responder` que, a partir de la decisión, el
paquete de evidencia, el recibo de selección y el informe de revisión de S43.4,
genere una respuesta ejecutiva en markdown con los cinco bloques obligatorios.
Si S43.4 devolvió `clarify` o `blocked`, la respuesta debe reflejarlo sin
inventar recomendaciones.

## Components Affected

| Component | Change | Purpose |
|-----------|--------|---------|
| `coaching/responder/__init__.py` | create | Punto de entrada `run(context)`. |
| `coaching/responder/engine.py` | create | Lógica pura de ensamblaje de la respuesta. |
| `coaching/responder/models.py` | create | Modelos Pydantic para `ExecutiveResponse`. |
| `coaching/responder/formatter.py` | create | Renderiza los cinco bloques como markdown. |
| `coaching/responder/tests/test_responder.py` | create | Tests de los cinco bloques. |
| `coaching/responder/__main__.py` | create | CLI. |
| `escala-skills/escala-responder/SKILL.md` | create | Skill adapter. |

## Design Decisions

| ID | Title | Rationale |
|----|-------|-----------|
| D1 | Módulo puro `coaching.responder` | Separa la generación de la respuesta de la revisión y la selección. |
| D2 | Cinco bloques fijos | El formato ejecutivo es el valor de S43.5; no se negocia. |
| D3 | No inventar cuando la revisión bloquea | Si `report.can_proceed` es False, la respuesta explica el límite y pide la información. |
| D4 | Reutilizar modelos existentes | Consume `DecisionRef`, `EvidencePackage`, `SelectionReceipt`, `ReviewReport`. |

## Examples

### Entrada: revisión aprobada

```json
{
  "decision": { ... },
  "package": { ... },
  "selection": { "receipt": { ... } },
  "review": { "report": { "can_proceed": true, ... } }
}
```

### Salida

```markdown
## Respuesta ejecutiva

### 1. Qué veo
Tienes un worksheet de Cash completo y reciente.

### 2. Por qué importa
Conocer la liquidez de agosto evita sorpresas de cobro.

### 3. Evidencia relevante
- Cash Conversion Cycle Worksheet (2026-07)

### 4. Qué no sé todavía
No tengo proyecciones de cobros futuros.

### 5. Acción recomendada
Ejecutar `/escala-cash` para profundizar en CCC y Power of One.
```

## Acceptance Criteria

### MUST

- **AC1:** La respuesta incluye los cinco bloques en orden.
- **AC2:** Cuando `can_proceed` es False, el bloque 5 pide la información faltante.
- **AC3:** La evidencia relevante se extrae del paquete y del recibo.
- **AC4:** Los tests validan los cinco bloques y el caso bloqueado.

### MUST NOT

- **AC5:** No se inventan datos para llenar un bloque.
- **AC6:** No se genera una recomendación cuando la revisión bloquea.
