# S35.2 Design: Core Skill Golden Cases

## Complexity

Moderate. The story expands fixture coverage and adds directory-level loading
helpers, but it still avoids live model calls and drift scoring.

## Problem

S35.1 created a fixture contract, but a contract without representative core
cases does not protect the ScaleUp methodology. The highest-value entrypoints
need explicit expected behavior before S35.3 can detect drift.

## Value

The fixtures turn methodology into testable data. They make future prompt or
skill edits reviewable against concrete expectations instead of relying on old
draft epics or informal memory.

## Gemba Findings

- `scaleup-strategy` now includes a Voice of Customer evidence gate and forbids
  invented Core Customer, Brand Promise, positioning, OPSP, 7 Strata, and
  Strategy Canvas claims when evidence is missing.
- `scaleup-cash` routes through CCC, Power of One, and acceleration moves, and
  explicitly states that it does not provide financial advice.
- `scaleup-people` routes through FAC, values, and topgrading, with gates for a
  single accountable owner and observed-not-invented values.
- `scaleup-execution` routes through Rockefeller Habits, rhythms, priorities,
  and task creation, with a gate for a single Critical Number.
- `.agents/skills` is a local runtime mirror and is not complete in git for all
  selected skills. `.claude/skills` contains the tracked source used by tests.

## Legacy Sweep

This story narrows the useful part of old E22 into current E35 fixtures. It
does not revive E22 as complete and does not claim release-gate coverage until
S35.5.

## Approach

Add directory-level helpers to `validators/skill_golden_cases.py`:

- `load_golden_case_directory(path)`: load all YAML fixtures in a directory.
- `validate_golden_case_directory(path, skills_root)`: validate a directory and
  prefix errors with the fixture file name.

Add one fixture file per selected skill under
`tests/fixtures/skill_golden_cases/core/`.

## Core Fixture Intent

| Skill | Golden behavior protected |
|---|---|
| `scaleup-strategy` | Requires Voice of Customer evidence before strategic claims. |
| `scaleup-cash` | Guides CCC, Power of One, and acceleration moves without financial advice. |
| `scaleup-people` | Requires accountable ownership and observed behavioral evidence for values. |
| `scaleup-execution` | Requires Critical Number, rhythms, and accountability before tasking. |

## Components

| Component | Change | Purpose |
|---|---|---|
| `validators/skill_golden_cases.py` | extend | Directory-level fixture loading and validation. |
| `tests/test_skill_golden_cases.py` | extend | Prove selected core skills are covered and deterministic. |
| `tests/fixtures/skill_golden_cases/core/*.yaml` | create | Core golden cases for Strategy, Cash, People, and Execution. |

## Acceptance Criteria

### MUST

- Each selected skill has at least one golden case.
- Every case declares expected sections and prohibited weak behavior.
- Core fixture validation uses tracked skill files.
- Cases require no external services.

### MUST NOT

- Do not score generated prose yet.
- Do not add release gates yet.
- Do not mark E35 complete.

## Testing Strategy

| Layer | Test | Purpose |
|---|---|---|
| Unit | core fixture directory validates | Proves all YAML cases satisfy the contract. |
| Unit | selected skills are covered | Proves Strategy, Cash, People, and Execution each have a case. |
| Unit | core cases carry methodology properties | Proves cases are not empty shells. |
| Unit | directory loader rejects empty directories | Proves accidental empty coverage fails. |
