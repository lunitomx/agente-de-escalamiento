# S35.3 Design: Drift Check Implementation

## Complexity

Moderate. This adds real behavior validation, but it remains deterministic:
plain text output files are checked against required properties from YAML
fixtures.

## Problem

S35.1 and S35.2 validate golden case definitions, but they do not catch a skill
response that omits methodology, invents unsupported claims, or ignores an
evidence requirement.

## Value

The drift checker turns the fixture set into an executable quality gate. It
creates independent evidence that a skill output still respects the method
properties selected in S35.2.

## Gemba Findings

- Existing project validators return lists of readable errors rather than
  raising for normal validation failures.
- Golden case properties are intentionally shape/property based:
  `expected_sections`, `required_methodology_terms`,
  `forbidden_claim_patterns`, and `evidence_required`.
- Release gate integration is intentionally delayed to S35.5.

## Approach

Extend `validators/skill_golden_cases.py` with:

- `GoldenCaseOutput`: typed mapping of `case_id` to an output file.
- `validate_golden_case_output(case, output_text)`: deterministic text checks.
- `validate_golden_case_output_file(case, output_path)`: file wrapper.
- `validate_golden_case_output_directory(cases, outputs_dir)`: aggregate check.

Text checks:

- Expected sections pass when the section label appears in the output.
- Required methodology terms pass when each term appears case-insensitively.
- Forbidden claim patterns fail when a pattern appears case-insensitively.
- Evidence-required cases pass only when output includes an evidence behavior
  marker such as `evidence id`, `evidence ids`, `citation`, `cited`, or
  `missing evidence`.

## Components

| Component | Change | Purpose |
|---|---|---|
| `validators/skill_golden_cases.py` | extend | Drift validation helpers. |
| `tests/test_skill_golden_case_drift.py` | create | Passing and failing drift tests. |
| `tests/fixtures/skill_golden_cases/outputs/*.md` | create | Compliant and regression output fixtures. |

## Acceptance Criteria

### MUST

- Missing section failures name the missing section.
- Forbidden pattern failures name the forbidden pattern.
- Evidence failures name the case.
- Compliant output passes without errors.

### MUST NOT

- Do not call live models.
- Do not compare full prose snapshots.
- Do not register a release gate yet.

## Testing Strategy

| Layer | Test | Purpose |
|---|---|---|
| Unit | compliant strategy output passes | Proves happy path. |
| Unit | missing section output fails | Proves output shape check. |
| Unit | forbidden pattern output fails | Proves unsupported-claim control. |
| Unit | missing evidence output fails | Proves evidence-required control. |
| Unit | output directory aggregation fails missing outputs | Proves release-oriented reporting. |
