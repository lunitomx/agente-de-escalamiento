# S35.5 Design: Release Gate Integration

## Complexity

Moderate. The script composes existing S35 validators and produces readable
release evidence. It avoids adding a fake CLI gate id that `rai gate list` does
not know about.

## Problem

S35.1-S35.4 created the machinery, but release reviewers still need a single
visible check and a documented citation path.

## Value

The release check makes golden-case status operational. It gives reviewers one
command and one checklist location instead of asking them to remember several
test files and validators.

## Gemba Findings

- `rai gate list -f json` exposes built-in gates but no versioned project-local
  gate registry in this repo.
- Existing E30/E31/E32 validators cover registry structure, runner evidence,
  and closure truth. S35.5 must cite those as complementary rather than
  duplicating them.

## Approach

Create `scripts/check_skill_golden_cases.py`:

- Validate core fixtures against `.claude/skills`.
- Validate changelog hashes.
- Validate release output fixtures under
  `tests/fixtures/skill_golden_cases/release_outputs/`.
- Print a JSON report with `status`, `checks`, and `errors`.
- Exit `0` when all checks pass, `1` when any check fails.

Create `.raise/release/skill-golden-cases.md`:

- Command to run.
- Evidence fields to cite.
- Relationship to E30/E31/E32.
- Known boundaries.

## Components

| Component | Change | Purpose |
|---|---|---|
| `scripts/check_skill_golden_cases.py` | create | Release check entrypoint. |
| `.raise/release/skill-golden-cases.md` | create | Release checklist. |
| `tests/test_skill_golden_case_gate.py` | create | Script success/failure tests. |
| `tests/fixtures/skill_golden_cases/release_outputs/*.md` | create | Passing output set for release check. |

## Acceptance Criteria

### MUST

- One command reports golden-case status.
- Failure output names failed cases.
- Release checklist explains boundaries versus E30/E31/E32.
- Tests cover pass and fail paths.

### MUST NOT

- Do not claim a native `rai gate` id exists.
- Do not run live skills or models.
- Do not mark E35 complete until final audit and retrospective exist.

## Testing Strategy

| Layer | Test | Purpose |
|---|---|---|
| Unit/subprocess | release check passes with full release outputs | Proves citable status. |
| Unit/subprocess | release check fails with missing outputs | Proves failed case names appear. |
| Unit | JSON report contains fixture, changelog, and drift checks | Proves release evidence shape. |
