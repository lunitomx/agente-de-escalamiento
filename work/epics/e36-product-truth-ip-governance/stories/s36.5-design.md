# S36.5 Design: Clean Export, License & Third-Party Contract

## Artifact authority

The installed RaiSE CLI has no `artifact` command and no configured artifact
MCP surface. This versioned Markdown document is therefore the canonical local
design artifact. It will also be written through the local filesystem docs
adapter; no remote documentation target is configured.

## Problem

The private repository now has an executable public-vocabulary boundary, but it
does not have a release artifact boundary. The 285 S36.3 candidate paths are a
review canary, not permission to distribute them. A broad copy or Git mirror
would still admit internal validators, governance, tests, course material,
private state, generated evidence, and any future unclassified file.

The legal state is also contradictory. The root `LICENSE` says there is no
formal license and prohibits commercial use, while ESCALA is being prepared as
a commercial product. No human legal or IP approval has been performed. A
technical export must neither preserve that contradiction nor turn missing
approval into an inferred public license.

Finally, the current execution dashboard loads Chart.js from a public CDN even
though the repository already vendors a newer local copy. That is a concrete
violation of the product requirement: ESCALA functionality must install and run
on the user's machine, with Drive or OneDrive used only as optional filesystem
folders for ordinary documents.

## Value

S36.5 creates one reproducible local artifact from one immutable private Git
commit, verifies the resulting filesystem independently, and reports technical,
legal, publication, dependency, and local-only states separately. It gives E41
a trusted input for installers without publishing anything or treating a clean
source scan as proof of a clean package.

## Complexity and risk gates

This is a **complex, high-risk** story:

- **IP and privacy risk — high:** one implicit path expansion could disclose
  governance, evidence, reference, or company material.
- **Supply-chain and legal risk — high:** the artifact carries Python and
  vendored JavaScript dependencies but has no reviewed distribution posture.
- **Filesystem risk — high:** the builder creates an external tree and must
  reject traversal, links, occupied targets, case collisions, and special Git
  modes.
- **False-evidence risk — high:** a builder cannot prove its own output merely
  by saying the source scan passed.
- **Determinism risk — high:** timestamps, temporary roots, manifest
  self-reference, and worktree reads would make the same source produce
  different evidence.
- **Hosted-runtime risk — high:** one remaining CDN reference already proves
  that prose saying “local only” is insufficient.
- **Mutation risk — high:** the real M3 check observes both the private
  repository and the existing dirty public candidate, neither of which may be
  cleaned, reset, copied over, or published.
- **UX gate:** no new coaching interaction is introduced. The operator flow is
  a local release command with fixed safe errors, so separate UX research would
  not reduce the material uncertainty.
- **Integration gate:** mandatory. Two real Git-object builds, independent
  staged-tree verification, a real tamper, and strong before/after repository
  fingerprints are required. Fixtures alone cannot close M3.

## PRIME and gemba

All five bounded design queries returned no relevant established pattern. The
code-context query also returned no relevant symbol ranking. The design is
therefore based on direct repository evidence.

### Existing components to reuse

- `validators/public_boundary.py` owns the source-neutral path vocabulary,
  forbidden YAML keys, bounded UTF-8 handling, safe locators, and semantic
  policy hash.
- `validators/exposure_inventory.py` owns the only credential-shape regexes and
  redaction rules. Package validation must call a public pure seam in this
  module rather than duplicate those patterns.
- `validators/repository_truth.py` owns strong, path-free Git fingerprints and
  an isolated read-only Git environment.
- `validators/governance_contract.py` owns the semantic hashes for S36.4's
  closure and identity policies.
- The existing checker scripts establish the thin-CLI pattern: typed core,
  deterministic renderers, fixed safe failure text, and no raw exception or
  subprocess output.
- `escala_server/static/shared/vendor/chart.umd.min.js` already contains
  Chart.js 4.5.1 and `@kurkle/color` 0.3.2 with MIT notices.

### Components that are not substitutes

- `validators/export.py` checks headings in an action-plan document. It retains
  that responsibility and name; it is not a software-package exporter.
- `governance/public-boundary.yaml` defines a canary plus denials. It does not
  select the final product file set.
- `governance/exposure-policy.yaml` is the immutable S36.2 before-state
  contract. It is not changed to manufacture a passing distribution scan.
- The existing public candidate is a dirty historical repository, not an input,
  destination, or verification oracle for the clean artifact.
- Root `install.sh`, `update.sh`, and `uninstall.sh` are current product inputs,
  but their cross-platform redesign remains E41.

## Design decisions

### 1. One product-boundary policy and one dependency inventory

S36.5 creates:

- `governance/public-export.yaml`: source selection, generated metadata,
  immutable policy bindings, local-only invariants, license/publication state,
  artifact limits, and safe receipt contract.
- `governance/third-party.yaml`: complete sorted dependency/system-prerequisite
  records plus source evidence and notice/review states.

The first policy references the semantic hash of the second. Unknown, missing,
null, duplicate, overlapping, contradictory, or unsupported fields fail before
any staging directory is created.

### 2. Immutable Git commit is the only source

The builder requires an explicit full commit ID. It resolves the object as a
commit, requires it to equal the repository's current `HEAD`, and reads the
policy, inventory, source entries, modes, and blobs through Git object commands.
It never copies from the worktree.

This is how dirty-source ambiguity is rejected without destroying intentional
unrelated work: an omitted, symbolic, abbreviated, nonexistent, or non-HEAD
source is invalid; an explicitly named immutable `HEAD` remains unambiguous even
if unrelated worktree files exist. Untracked additions can never enter the
artifact.

All Git subprocesses use argument arrays, the established read-only Git
environment, bounded output, and fixed timeouts. A blob path is validated
before it is combined with a commit selector.

### 3. Explicit selection, default absence

Each source selection has exactly one path, one kind (`file` or `tree`), and one
artifact role:

- `operator_documentation`
- `installer_or_updater`
- `local_runtime`
- `business_knowledge`
- `agent_skill`
- `business_template`
- `business_validator`

Policy validation rejects absolute paths, backslashes, dot segments, glob
metacharacters, duplicate/case-fold-equivalent paths, nested roots, files under
selected roots, generated-path collisions, and any path classified `denied` by
the S36.3 policy. Every Git path not selected is absent by construction.

Initial bounded roots are:

```text
conocimiento/
escala-skills/
escala_server/cash/
escala_server/daos/
escala_server/session/
escala_server/static/
templates/
```

Exact files include the root operator/package scripts, source-root server
modules, runtime coaching modules without `tests/` or class-course learning
files, the business validators actually used by skills, and
`scripts/escala-server`. The policy itself contains the authoritative complete
list; this prose is not an alternative allowlist.

### 4. Source-neutral scanner seams

`validators/public_boundary.py` adds a pure function that accepts one validated
relative path and bytes and returns sorted content/path violations without
assuming a Git surface. Existing private/public scans wrap those violations in
their current receipt models. The artifact verifier calls the same pure
function for every staged payload file.

`validators/exposure_inventory.py` adds a pure function that returns the sorted
credential shapes detected in bytes. It owns and reuses the existing assignment,
bearer-token, and private-key regexes. The package verifier maps any detected
shape to one redacted rule code and a safe relative locator; matched values are
never returned.

No vocabulary term, forbidden YAML key, secret regex, or sensitive-locator
formula is copied into the export module.

### 5. Local staging only

The caller supplies a destination under the resolved operating-system temporary
root. The destination itself must not exist. The builder creates it exactly once
after all source/policy validation passes. It refuses symlinked parents,
destinations outside the temporary root, synchronized-folder destinations,
occupied paths, or a destination inside either Git repository.

The builder accepts only Git modes `100644` and `100755`. Symlinks (`120000`),
submodules (`160000`), special/unknown modes, traversal paths, Unicode/case-fold
destination collisions, and parent escapes fail closed. On failure after
creation, the incomplete staging tree remains visibly failed and is never
reported as a passing artifact; test-owned temporary cleanup is external to the
builder.

### 6. Manifest without self-reference

The builder writes three generated files:

- `ESCALA-PACKAGE.json`: product version, immutable source/policy bindings,
  local-only invariants, license review state, and publication authorization.
- `THIRD_PARTY_NOTICES.md`: deterministic human inventory generated from the
  reviewed dependency records.
- `ESCALA-MANIFEST.json`: exact sorted payload paths, modes, byte sizes, and
  SHA-256 values.

The manifest hashes every selected/generated payload file except itself. Its
own SHA-256 is recorded in the external verification receipt. No file contains
its own hash, and no timestamp, temporary directory, machine root, username, or
remote URL participates in artifact bytes.

### 7. Independent filesystem verifier

The verifier receives only a staging directory, its in-stage manifest, and the
private source policies needed to evaluate it. It does not call the builder and
does not trust builder memory or a source-scan result.

It performs, in order:

1. resolve and bound the staging root without following a staged symlink;
2. enumerate the real staged filesystem with `lstat`;
3. reject links, special files, unsafe names, case collisions, or escape;
4. strictly parse the manifest and generated package metadata;
5. compare the exact enumerated path set with manifest entries;
6. recompute every payload size, mode, and SHA-256;
7. validate source, export, public-boundary, S36.2 baseline, S36.4 governance,
   and third-party semantic bindings;
8. apply public vocabulary/YAML and credential scans to every payload file;
9. apply private/internal/raw/SQLite filename and path bans;
10. verify local-only runtime and generated license/publication metadata; and
11. emit PASS only when every named technical check passes.

Added, removed, changed, renamed, unexpected, unreadable, or linked content
therefore fails even when the original source commit is valid.

### 8. Executable local-only contract

The policy records these required values:

```yaml
runtime_mode: local_machine_only
hosted_product_service: forbidden
cloud_database: forbidden
telemetry: forbidden
oauth_requirement: forbidden
drive_api_requirement: forbidden
onedrive_api_requirement: forbidden
authoritative_sqlite_in_sync_folder: forbidden
team_sharing: ordinary_filesystem_documents_only
```

The verifier rejects authoritative database filenames (`*.db`, `*.sqlite`,
`*.sqlite3`) anywhere in staging. It scans files classified as local runtime or
agent skills for remote executable asset/service references. Loopback addresses
are local; external documentation and Git-based update locators in files whose
role is `operator_documentation` or `installer_or_updater` are not reclassified
as hosted ESCALA runtime.

`escala_server/static/dashboards/execution/daily-analyzer.html` changes from the
jsDelivr script to:

```html
<script src="../../shared/vendor/chart.umd.min.js"></script>
```

All static `script`, stylesheet, CSS asset, fetch, WebSocket, and equivalent
runtime references must then be relative/local or loopback. A negative fixture
with a CDN script proves the check fails.

### 9. Truthful interim license posture

S36.5 does not choose a final open-source or commercial license. It replaces the
current contradictory educational/non-commercial wording with a factual interim
status notice and the following typed state:

```yaml
license_status: no_formal_distribution_license_selected
interim_posture: proprietary_no_license_grant
human_review_gate: human_legal_and_ip_release_review
human_review_status: required
approval_evidence_status: absent
publication_authorized: false
allowed_artifact_use: internal_technical_validation_only
```

The named gate is an executable state transition requirement, not a claim that
counsel has reviewed the product. `publication_authorized: true` is invalid
unless a later policy version carries a reviewed, source-bound approval record.
No publish command exists in this story.

A technically passing artifact therefore reports:

```text
technical_artifact_status: pass
human_legal_review_status: required
publication_authorized: false
```

Technical PASS is allowed with this posture because it means only “the staged
filesystem satisfies the engineering contract.” It never means “safe to
publish” or “legally approved.”

### 10. Third-party completeness contract

Every inventory entry contains:

- stable dependency ID and display name;
- relationship (`direct`, `transitive`, `vendored`, or
  `system_prerequisite`);
- required purpose and importing/component parent;
- version constraint and optional observed local version;
- source-evidence kind plus safe repository locator;
- bundling state;
- declared license identifier/status;
- notice requirement/status; and
- human review state.

Completeness is checked three ways:

1. declared build/runtime constraints in `pyproject.toml` must map one-to-one to
   direct/build inventory entries;
2. every top-level non-stdlib import found by Python AST across staged source
   must map to either a staged local module or an inventory import name; and
3. every vendored static component/header declared by policy must map to an
   inventory entry with matching name/version/license markers.

The transitive parent graph must be closed and acyclic. System prerequisites
are explicitly non-bundled. The inventory may be technically complete while
legal review remains required; those states are never collapsed.

## Typed models

The new module uses frozen Pydantic models with `extra="forbid"` and complete
type annotations. Representative models are:

```python
class ExportSourceSelection(StrictModel):
    path: str
    kind: Literal["file", "tree"]
    role: ArtifactRole

class LicensePosture(StrictModel):
    license_status: LicenseStatus
    interim_posture: InterimPosture
    human_review_gate: str
    human_review_status: HumanReviewStatus
    approval_evidence_status: ApprovalEvidenceStatus
    publication_authorized: bool
    allowed_artifact_use: ArtifactUse

class ThirdPartyEntry(StrictModel):
    id: str
    name: str
    relationship: DependencyRelationship
    purpose: str
    parents: tuple[str, ...]
    version_constraint: str
    observed_version: str
    source_evidence: tuple[DependencyEvidence, ...]
    bundling: BundlingState
    license_identifier: str
    license_status: DependencyLicenseStatus
    notice_required: bool
    notice_status: NoticeStatus
    review_state: DependencyReviewState

class ArtifactEntry(StrictModel):
    path: str
    mode: Literal["100644", "100755"]
    size_bytes: int
    sha256: str

class ArtifactManifest(StrictModel):
    schema_version: Literal[1]
    product_id: Literal["escala"]
    product_version: str
    source_commit: str
    export_policy_sha256: str
    public_boundary_policy_sha256: str
    third_party_inventory_sha256: str
    entries: tuple[ArtifactEntry, ...]

class VerificationCheck(StrictModel):
    id: str
    status: Literal["pass", "fail"]
    finding_count: int

class PublicExportReceipt(StrictModel):
    schema_version: Literal[1]
    technical_artifact_status: Literal["pass", "fail"]
    human_legal_review_status: HumanReviewStatus
    publication_authorized: bool

    policy_hashes: PolicyHashes

```

No optional field uses `None` to mean “not reviewed.” Explicit enum values such
as `absent`, `required`, and `not_applicable` preserve truth and reject YAML
nulls.

## Build algorithm

```text
build_public_export(repo, full_commit, absent_temp_destination):
    resolve repo and destination boundaries
    require full_commit == immutable HEAD commit
    read export/public/dependency/governance policies from that commit
    validate strict models, cross-policy hashes, license posture, selections
    enumerate commit tree once with modes and object IDs
    expand exact selections; reject missing, overlapping, unsafe, or non-blob paths
    validate every selected path against public denials and case-fold uniqueness
    render deterministic package metadata and third-party notice bytes
    create destination exactly once
    materialize blobs with fixed regular/executable modes
    write generated payload metadata
    compute sorted payload entries and write manifest last
    return bounded build result; do not call verifier
```

## Verification algorithm

```text
verify_public_export(staging, committed_policies):
    lstat and enumerate staging without following links
    parse strict manifest and package metadata
    recompute exact file set, modes, sizes, hashes, and manifest hash
    independently scan every file for public, secret, private, raw, database rules
    validate local-only runtime references by artifact role
    validate Python import and vendored dependency inventory completeness
    validate license/legal/publication cross-field invariants
    sort named checks and safe findings
    return deterministic receipt
```

## Real M3 qualification

The implementation qualification uses real temporary directories and separate
verifier invocations:

```text
fingerprint private repo and existing public candidate
build immutable commit -> temp artifact A
verify A -> receipt A
build same commit -> temp artifact B
verify B -> receipt B
assert manifest bytes A == B
assert receipt bytes A == B
copy B to a third test-owned temp tree
tamper one known payload byte
verify tampered tree -> exact expected hash_mismatch failure
fingerprint private repo and public candidate again
assert both strong fingerprints unchanged
write sanitized versioned M3 receipt
```

The tampered tree is test-owned disposable output, not a repository or public
candidate. The versioned receipt records only hashes, counts, named checks,
technical/legal/publication states, and mutation booleans. It contains no
temporary roots, usernames, remote URLs, raw subprocess output, matched secret,
source excerpt, or public-candidate dirty filename.

## CLI contract

Build from a full immutable commit into a nonexistent local temporary path:

```bash
.venv/bin/python scripts/build_public_export.py \
  --repo . \
  --commit 0123456789abcdef0123456789abcdef01234567 \
  --staging /private/tmp/escala-artifact-a \
  --format json
```

Verify the staged filesystem in a separate invocation:

```bash
.venv/bin/python scripts/verify_public_export.py \
  --repo . \
  --commit 0123456789abcdef0123456789abcdef01234567 \
  --staging /private/tmp/escala-artifact-a \
  --format text \
  --json-output /private/tmp/escala-verification.json \
  --markdown-output /private/tmp/escala-verification.md
```

Successful technical verification exits 0 even when publication is false and
prints the three separate status lines. Build or verification failure exits 1
with fixed messages:

```text
public export: unable to build a safe local artifact
public export: staged artifact did not pass independent verification
```

Raw Pydantic/YAML errors, Git output, filesystem roots, manifest content, remote
locators, and matched values are never printed on failure.

## Testing strategy

| Layer | Required coverage |
|---|---|
| Export policy | Valid complete document; unknown/missing/null/duplicate fields; unsupported version; unsafe and overlapping selections; generated collision; denied path; invalid legal/local-only state |
| Dependency policy | Direct/transitive/vendored/system records; missing parent; cycles; duplicate import name; invalid constraint/status; incomplete notices; deterministic semantic hash |
| Public seam | Path term, text term, forbidden YAML key, invalid YAML, binary/oversized content, safe sensitive locator, unchanged existing boundary receipts |
| Secret seam | Assignment, bearer, private key, clean bytes, multiple shapes, no matched value returned, unchanged existing inventory receipts |
| Git source | Full HEAD accepted; HEAD/symbolic/abbreviated/non-commit/non-HEAD rejected; untracked file absent; selected missing file; link/submodule/special mode; read-only environment |
| Selection | Exact file/root expansion, default exclusion, nested overlap, traversal, case collision, generated-name collision, deterministic ordering |
| Builder | Destination absent, occupied, symlinked, outside temp, inside repo, partial failure; mode/byte preservation; no verifier call |
| Verifier | Exact PASS; added/removed/changed/renamed file; changed mode; symlink; unsafe name; manifest/package metadata tamper; unexpected generated file |
| Boundary/security | Prohibited identity, YAML provenance, credential sentinels, private paths, raw assets, SQLite payloads, no leaked values/roots |
| Local only | CDN script, remote stylesheet/fetch/WebSocket fail; relative vendored asset and loopback pass; updater/docs URL not misclassified |
| Dependency completeness | AST external import mapped/unmapped; direct pyproject constraint mapped; vendored header mapped/mismatched; notice generation |
| License state | Technical PASS plus legal required/publication false; missing review status; contradictory non-commercial text; unauthorized true transition |
| Determinism | Two separate real builds have byte-identical manifests and two separate verifications have byte-identical receipts |
| Tamper | One real payload mutation returns the exact safe `artifact.hash_mismatch` rule and no content |
| Mutation | Strong private/public-candidate fingerprints match before/after the complete real M3 flow |
| Regression | Existing public boundary, exposure, repository truth, action-plan export, server/dashboard, lint, format, and type gates |

All tests execute through `rai gate check`; pytest, Ruff, and Pyright are not
invoked directly.

## Acceptance criteria

### MUST

1. One strict policy explicitly selects every source file/tree and rejects
   unknown, missing, null, unsafe, overlapping, or contradictory input.
2. The builder reads an explicit full immutable `HEAD` commit only; it never
   copies arbitrary worktree or untracked content.
