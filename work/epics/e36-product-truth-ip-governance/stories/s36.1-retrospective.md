## What Went Well

- The policy, domain model, verifier, CLI, and evidence use one shared canonical
  contract instead of duplicating rule vocabulary.
- Tests use temporary Git repositories, so the behavior is exercised against
  real Git state rather than mocks that could hide command or config behavior.
- The verifier remains read-only and fail-closed while the one authorized local
  repair was executed separately and documented.
- Credential-bearing remote values remain inside a non-serializable inspection
  boundary; public results expose only stable rule IDs and remote names.
- The review did real defect discovery rather than simply repeating green gates.

## What Could Improve

- The original public-candidate fingerprint covered HEAD and status shape but
  not enough repository state to prove byte-level non-mutation. Review added
  worktree, config, logical-index, and refs hashes in `3d61fac`.
- Git probes originally inherited caller `GIT_*` variables. That allowed
  `GIT_DIR`, `GIT_WORK_TREE`, or `GIT_CONFIG_*` to redirect observed truth.
  Review removed inherited Git variables before setting read-only controls in
  `7a5eddd`.
- The scope's gate sentence is stricter than the current lifecycle execution:
  the full suite was not run before every implementation commit. Future scopes
  should distinguish focused per-task gates from the full merge-request gate.
- Installed tooling does not provide artifact emit, session-topic persistence,
  gate-plan registration, the expected progress template, or a configured
  backlog adapter. Versioned Markdown and session journal evidence were used,
  but these capability gaps should remain visible.

## Learning Checkpoint

### 1. What surprised us?

HEAD plus porcelain status was not a sufficient non-mutation proof. Two dirty
repositories can present the same status shape while containing different file
bytes, config, index entries, or refs.

### 2. Which assumption proved false?

Changing `main` to track `origin/main` does not establish synchronization.
Tracking became correct, yet the honest divergence remained `0/3`; equality
requires an explicitly authorized private push followed by a new observation.

### 3. What evidence would have caught the defects earlier?

Two adversarial tests: mutate a dirty file without changing its status shape,
and run the verifier with injected `GIT_DIR`, `GIT_WORK_TREE`, and
`GIT_CONFIG_*` variables. Both cases are now covered.

### 4. What must the next story preserve?

S36.2 must treat the public surface as an inventory and generated-artifact
boundary. It must not synchronize with, clean, reset, or otherwise mutate the
dirty public-candidate repository, and it must never treat source references as
public product claims.
