# Story: Canonical Repository & Remote Truth

## User Story

As the ESCALA product owner and release operator,
I want one explicit private canonical remote, upstream, and repository-role
contract,
so that every future artifact is traceable and obsolete or credential-bearing
remote configuration cannot silently become the source of truth.

## Acceptance Criteria

### Scenario: Canonical private repository is synchronized

```gherkin
Given the local development branch is `main`
And the canonical private remote is named `origin`
When repository truth is verified after the story is integrated
Then `main` tracks `origin/main`
And local `main` and `origin/main` have zero divergence
And the result identifies the private repository as the canonical source
And no remote URL or credential value appears in the result
```

### Scenario: Obsolete remote configuration fails closed

```gherkin
Given an obsolete or disallowed remote is configured
When repository truth is verified
Then verification fails with a stable rule ID
And the finding contains only the remote name and redacted risk classification
And the finding never contains the remote URL or credential value
```

### Scenario: Local commits are not published implicitly

```gherkin
Given local `main` is ahead of `origin/main`
When repository truth is verified during local story work
Then the result reports non-zero sanitized divergence counts
And the result remains not synchronized
And the verifier does not push, pull, merge, rewrite history, or change a remote
```

### Scenario: Public distribution is a derived artifact

```gherkin
Given the repository-role policy is loaded
When canonical and public roles are inspected
Then the private repository is the only development source
And public distribution is classified as an allowlisted generated artifact
And no public candidate repository is configured as an automatic mirror target
```

## Examples (Specification by Example)

| Input state | Action | Expected output |
|-------------|--------|-----------------|
| `main → origin/main`, divergence `0/0`, no disallowed remote | Run the verifier | PASS receipt with remote name, branch/upstream, counts, policy hash, and no URLs |
| `gitlab` remote exists with any URL | Run the verifier | FAIL finding `obsolete_remote` naming `gitlab`; URL omitted |
| `main → gitlab/main` | Run the verifier | FAIL finding `wrong_upstream`; configured URL omitted |
| `main → origin/main`, local ahead by three | Run the verifier | FAIL/not-synchronized receipt with counts `0/3`; no mutation performed |
| Private source plus public artifact role | Load policy | Private canonical source and generated allowlisted public artifact are distinct |

## Notes

- Architecture: `../design.md` and
  `../adr-private-canonical-source-and-clean-export.md`.
- This story may sanitize local Git configuration, but it cannot rewrite
  history, publish a public artifact, or modify the dirty public candidate
  repository.
- The intentional raw PDF deletion is preserved outside this story and belongs
  to S36.3.
- Any push remains an explicit external action; local verification must be
  complete before that boundary is reached.
