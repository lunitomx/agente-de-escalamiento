# S36.3 Plan: Reference Removal & Public Vocabulary Boundary

## Overview

Implement S36.3 in six risk-ordered TDD tasks with one commit per task. The
epic's original M label is retained for traceability, but direct gemba evidence
reassesses the work as L-complexity: the boundary spans a strict control plane,
six source families, 78 public provenance blocks, 75 affected product files,
an ontology/handler rename, and a real dirty-repository integration check.

S36.2 completed in 47m 32s and is the only current M-story calibration. S36.3
has materially greater semantic fan-out, so that duration is not multiplied or
presented as an estimate. Actual task times will be recorded.

## Execution Order

```text
T1 Strict boundary policy + typed contract
  └──► T2 Bounded scanner + safe CLI
          ├──► T3 Auditable raw-asset deletion
          └──► T4 Atomic identity/path migration
                    └──► T5 Public source/provenance neutralization
                              └──► T6 Live S36.2-linked boundary receipt
```

T3 and the preparation work for T4 are logically independent after T2, but
they are executed sequentially in this checkout to keep the deliberately dirty
tree and migration commits easy to recover. T6 cannot start until T3–T5 are
committed because its canonical subject is `HEAD`, not an uncommitted worktree.

The graph is acyclic. Risk is handled in this order:

1. make the deny/default/output contract executable before mass edits;
2. prove the scanner cannot leak values or mutate repositories;
3. commit the already-authorized deletion separately;
4. migrate source-identifying public APIs/IDs atomically;
5. perform the large semantic-preserving content change under the gate; and
6. collect real evidence only from committed source.

## Control-Plane Bootstrap Rule

The policy, tests, migration records, story evidence, and governance documents
necessarily contain prohibited tokens so they can detect and explain them.
They are explicit denied control-plane paths and never part of the public
canary. `validators/public_boundary.py` and its CLI remain generic: prohibited
tokens come from the denied policy file rather than hard-coded production
strings. S36.5 must not copy control-plane policy/tests/evidence into its staged
artifact unless its own manifest explicitly and safely designs an exception.

## T1 — Strict Policy, Baseline Link, and Typed Contract

**Size:** M

**Depends on:** None
**Commit intent:** `feat(s36.3): add public boundary contract`

### Description

Create the versioned deny-first policy and frozen typed models. The contract
classifies safe relative paths as `candidate_public`, `denied`, or
`not_eligible`; validates deterministic deny precedence; rejects ambiguous or
unsafe rules; loads the immutable S36.2 baseline link; and models safe grouped
findings without scanning real content yet.

### Files

- Create `governance/public-boundary.yaml`.
- Create `validators/public_boundary.py`.
- Create `tests/test_public_boundary.py`.
- Create/update `stories/s36.3-progress.md`.

### TDD Cycle

**RED**

1. Import the nonexistent public-boundary module and require strict enums,
   models, policy loader, stable policy hash, safe locator, path classifier,
   baseline-link model, and grouped summary.
2. Add negative policies for unknown keys/enums, duplicate IDs, missing raw/
   derived/private/internal denies, unsafe globs/paths, contradictory defaults,
   ambiguous public-public or deny-deny overlaps, and undeclared precedence.
3. Add models with sentinel values/URLs/roots/exceptions as extra fields and
   require rejection.
4. Require the committed S36.2 file hash, scan status, policy hash, verifier
   commit, and raw-reference surface states to match the typed baseline link.

**GREEN**

1. Add the minimum strict Pydantic models and PyYAML loader.
2. Define the canary and denied rule families from the design; default unknown
   paths to `not_eligible`.
3. Make explicit deny precedence deterministic while rejecting same-class
   ambiguity.
4. Normalize policy semantics and compute stable SHA-256 values.
5. Store prohibited strings only in the denied governance policy, not the
   generic validator source.

**REFACTOR**

Keep path validation/model invariants at boundaries. Do not add a general rule
engine, database, plugin layer, or final export manifest.

## T2 — Bounded Scanner, Non-Mutation, and Safe CLI

**Size:** M

**Depends on:** T1
**Commit intent:** `feat(s36.3): scan public boundary safely`

### Description

Implement deterministic worktree/`HEAD` scanning for candidate-public paths,
root-level YAML provenance detection, raw-asset current/history observation,
public-candidate `HEAD` legacy finding counts, strong before/after fingerprints,
JSON/Markdown rendering, explicit writers, and a fixed-error CLI. Existing
public-candidate findings remain unresolved evidence and do not become proof of
mutation or cleanup.

### Files

- Modify `validators/public_boundary.py`.
- Create `scripts/check_public_boundary.py`.
- Modify `tests/test_public_boundary.py`.
- Update `stories/s36.3-progress.md`.
- Reuse `validators/repository_truth.py` unchanged.

### TDD Cycle

**RED**

Create real temporary Git repositories containing:

1. a raw asset absent from worktree but present in `HEAD` and history;
2. candidate-public generic business text that must pass;
3. prohibited path/text variants and a root YAML `source:` key;
4. denied private/reference paths containing prohibited text;
5. unknown tracked paths;
6. binary, symlink, non-UTF-8, oversized, and malformed required content;
7. a dirty public candidate with tracked legacy text plus unrelated dirty and
   untracked sentinel content;
8. injected `GIT_DIR`, `GIT_WORK_TREE`, and `GIT_CONFIG_*` values;
9. sentinel secret/URL/root/error text checked across model repr, JSON,
   Markdown, stdout, stderr, and written files.

Require failure because scan/render/write/CLI APIs do not exist.

**GREEN**

1. Enumerate tracked paths and Git blobs deterministically with the reviewed
   read-only environment boundary.
2. Scan worktree or `HEAD` explicitly; never infer one from the other.
3. Parse bounded YAML only for configured canary globs and detect prohibited
   root keys without serializing values.
4. Observe raw path history metadata without historical blob extraction.
5. Fingerprint private and public repositories before/after; require exact
   equality for a scan-only run.
6. Render detailed safe JSON and grouped bounded Markdown.
7. Write only complete passing private-boundary receipts. On failure, emit one
   fixed sentence and create no outputs.
8. Treat public-candidate legacy findings as `legacy_findings_unresolved`, not a
   failure of scan completeness and never a clean claim.

**REFACTOR**

Reuse fingerprinting and safe Git primitives. Keep raw bytes, match values,
YAML values, Git output, and exception payloads in private local variables.

## Gate Policy

| When | Command | Scope |
|------|---------|-------|
| Per task | `rai gate check gate-tests --scope <test_dir>/` | Only tests for the changed module (e.g. `packages/raise-cli/tests/storage/`) |
| Per task | `rai gate check gate-lint` | Full project (fast) |
| Per task | `rai gate check gate-format` | Full project (fast) |
| Per task | `rai gate check gate-types` | Full project |
| End of story | `rai gate check gate-tests --scope packages/<pkg>/` | Changed package only — NOT full suite |
| MR creation | `/rai-mr-create` | Full suite — the ONLY place where unscoped tests run |

**NEVER run test commands directly** (for example `uv run pytest` or
`npm test`). Always use `rai gate check`; direct invocation bypasses gate
tracking and floods raw output.

## Cross-Task Guardrails

- Exact staging only. T1/T2 must leave the PDF unstaged; T3 is the sole task
  authorized to stage it; T4–T6 must prove no raw/public-candidate path slipped
  into their commits.
- Never modify S36.2 policy/evidence or the existing public candidate.
- Never use a public compatibility alias containing a prohibited identity.
- Policy/tests/work/governance are denied control-plane content; their tokens do
  not make product source eligible.
- No history rewrite, remote mutation, push, public publication, hosted runtime,
  SaaS, telemetry, cloud database, or Drive/OneDrive database sync.
- Generic business concepts and verified behavior must survive; source
  neutralization is not permission to thin the product.
- Any credential-shaped live finding stops implementation without printing or
  committing its value.

## Risks and Mitigations

| Risk | Mitigation |
|---|---|
| Bulk edits create a half-migration | T4 atomic rename matrix + exact caller/graph integrity tests |
| Scanner flags its own prohibited policy tokens | Policy/tests/evidence are denied control plane; generic validator hard-codes no prohibited terms |
| Public provenance removal thins domain knowledge | Delete only configured `source:` metadata; preserve node fields/edges and run golden/integrity tests |
| Broad canary accidentally acts as final allowlist | Typed disposition names it `candidate_public`; unknown stays closed; S36.5 owns actual manifest |
| Passing private tree is described as public cleanup | Receipt has no release/history/public-clean field; candidate remains unresolved |
| Dirty public candidate is overwritten | HEAD-only scan + strong before/after fingerprint + no writes in its root |
| Historical private source is confused with current tree | Baseline-linked current/history fields remain independent |
| E11 completion prose is reused as proof | Live S36.2/S36.3 receipts outrank old retrospective claims |
| Gate-generated lock/coverage/bytecode enters commits | Observe status before gates, remove only proven generated artifacts, inspect exact staged names |
