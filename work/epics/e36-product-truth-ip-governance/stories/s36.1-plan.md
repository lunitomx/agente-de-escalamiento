# S36.1 Plan: Canonical Repository & Remote Truth

## Overview

Implement a strict repository-role policy, a read-only credential-safe Git
verifier, a deterministic CLI, and local evidence/remediation in three atomic
TDD tasks. Each task produces one commit. The intentional PDF deletion remains
unstaged throughout S36.1.

No historical calibration exists, so this plan records actual duration after
execution instead of inventing estimates.

## Execution Order

```text
T1 Policy + repository contract
  └──► T2 Security boundary + CLI + fingerprints
          └──► T3 Live integration + exact local remediation + evidence
```

The order is risk-first and acyclic. T1 fixes the domain contract; T2 proves the
secret/non-mutation boundary before any live configuration change; T3 exercises
the real repository and performs only the two scoped local repairs.

No tasks run in parallel because all three modify or exercise the same contract,
and a failed redaction guarantee must block live remediation evidence.

## Task 1 — Strict Policy and Core Repository Contract

**Size:** S

**Depends on:** none

**Commit intent:** `feat(s36.1): add repository truth contract`

### Description

Create the versioned policy, strict Pydantic models, safe policy hashing, fixed
Git probe boundary, and core pass/fail evaluation for canonical remote,
development branch, upstream, remote branch, and divergence.

### Files

- Create `governance/repository-truth.yaml`.
- Create `validators/repository_truth.py`.
- Create `tests/test_repository_truth.py`.

### TDD Cycle

**RED**

1. Add a valid-policy test asserting exact private/public roles and stable hash.
2. Add invalid-policy cases for extra fields, bad role/mode, wrong upstream,
   duplicate/conflicting remote lists, and unsafe Git identifiers.
3. Build real temporary bare/work Git repositories and assert synchronized
   `main → origin/main` passes.
4. Add failures for missing canonical remote, missing branch/ref, wrong/missing
   upstream, remote-ahead, local-ahead, and missing remote branch.
5. Run the focused test gate and retain RED evidence before implementation.

**GREEN**

Implement the minimum strict models, YAML loader, policy SHA-256, closed Git
runner, safe-name normalization, typed checks/findings, and deterministic receipt
needed to pass the new tests.

**REFACTOR**

Consolidate check construction and Git command handling without broadening the
command allowlist. Keep policy truth separate from observed receipt truth.

### Acceptance References

- Story scenario: canonical private repository is synchronized.
- Story scenario: public distribution is a derived artifact.
- Scope: strict fail-closed policy and wrong/missing/diverged-state rejection.

### Verification

- `rai gate check gate-tests --scope tests/test_repository_truth.py`
- `rai gate check gate-lint`
- `rai gate check gate-format`
- `rai gate check gate-types`
- `git diff --check`
- Inspect the staged diff and confirm the PDF deletion is absent.

### Exit Evidence

- Focused RED then GREEN gate receipts.
- Valid/invalid policy and real synchronized/diverged Git tests.
- Commit contains only policy, validator, and focused tests.

## Task 2 — Redaction, Deterministic CLI, and Witness Fingerprints

**Size:** M

**Depends on:** T1

**Commit intent:** `feat(s36.1): secure repository truth evidence`

### Description

Complete the security boundary: inspect remote URLs only in memory, prove raw
sensitive values cannot escape, add privacy-preserving repository fingerprints,
and expose the contract through a thin deterministic JSON/text CLI.

### Files

- Modify `validators/repository_truth.py`.
- Modify `tests/test_repository_truth.py`.
- Create `scripts/check_repository_truth.py`.

### TDD Cycle

**RED**

1. Configure a sentinel HTTP(S) username/token and assert it is absent from
   model dumps, JSON, Markdown, stdout, stderr, and exception text.
2. Prove normal SSH identity syntax is not misclassified as embedded HTTP
   credentials.
3. Snapshot `.git/config` and refs before/after verification and assert exact
   equality.
4. Create a dirty witness repository and assert fingerprints omit root and
   filenames while remaining stable.
5. Add CLI tests for pass/fail exit codes, sorted deterministic JSON, readable
   Markdown, byte-identical repeated outputs, and safe command failures.
6. Run the focused test gate and retain RED evidence.

**GREEN**

Implement in-memory credential-bearing URL detection, sanitized failure mapping,
fingerprinting, deterministic renderers, requested-file writing, and the thin
CLI. Do not add a repair/mutation option.

**REFACTOR**

Route every output through the typed receipt/fingerprint models. Remove any
string path that could serialize subprocess stdout/stderr or local filesystem
paths.

### Acceptance References

- Story scenario: obsolete remote configuration fails closed.
- Story scenario: local commits are not published implicitly.
- Scope: no URL/credential disclosure, deterministic evidence, public-candidate
  fingerprint, and verifier non-mutation.

### Verification

- `rai gate check gate-tests --scope tests/test_repository_truth.py`
- `rai gate check gate-lint`
- `rai gate check gate-format`
- `rai gate check gate-types`
- `git diff --check`
- Search staged output models/CLI for prohibited raw `stdout`, `stderr`, URL, or
  absolute-path fields.
- Inspect the staged diff and confirm the PDF deletion is absent.

### Exit Evidence

- Sentinel-secret negative proof across every output surface.
- Before/after Git config/ref equality.
- Deterministic CLI and fingerprint tests.
- Commit contains no live receipt, remote mutation, or PDF deletion.

## Task 3 — Manual Live Integration, Scoped Remediation, and Evidence

**Size:** S

**Depends on:** T2

**Commit intent:** `chore(s36.1): record repository truth integration`

### Description

Run the finished verifier against the real private repository, fingerprint the
dirty public candidate before/after without touching it, remove only the exact
obsolete local remote, set `main` upstream to `origin/main`, and record truthful
sanitized evidence. This is the mandatory manual integration test.

### Files and Local State

- Create generated evidence under
  `work/epics/e36-product-truth-ip-governance/stories/s36.1-evidence/`.
- Modify local `.git/config` only through normal Git commands; never stage it.
- Do not write inside the public candidate repository.

### TDD/Integration Cycle

**RED / Baseline**

1. Run the CLI on the live repo and require a FAIL receipt identifying the
   obsolete remote and/or wrong upstream by sanitized rule ID only.
2. Generate the public-candidate `before` fingerprint and capture no path or
   filenames.
3. Confirm the PDF deletion is the only unrelated working-tree change.

**GREEN / Exact local remediation**

1. Resolve remote names without printing URLs.
2. Remove only the exact `gitlab` local remote entry.
3. Set `branch.main` to track `origin/main`.
4. Rerun the verifier. Canonical remote/upstream/credential checks must pass.
5. If divergence remains because private E36 commits are not yet integrated and
   pushed, preserve the truthful non-zero result; never force a false PASS.
6. Generate the public-candidate `after` fingerprint and require exact equality
   with `before`.

**REFACTOR / Evidence minimization**

Keep only sanitized JSON/Markdown receipts, check IDs, hashes, counts, and the
fingerprint equality proof. Remove transient commands, URLs, paths, usernames,
or raw Git output from tracked evidence.

### Acceptance References

- All four story scenarios.
- Scope: exact local remote/upstream repair, deterministic receipts, unchanged
  public candidate, and preserved PDF deletion.

### Verification

- `rai gate check gate-tests --scope tests/test_repository_truth.py`
- `rai gate check gate-lint`
- `rai gate check gate-format`
- `rai gate check gate-types`
- Run `python scripts/check_repository_truth.py` manually against the live repo
  using only the design-approved arguments.
- Compare typed public-candidate before/after fingerprints for equality.
- Inspect sanitized local upstream/divergence names/counts without printing
  remote URLs.
- `git diff --check`
- Inspect staged files and prove the PDF deletion and `.git/config` are absent.

### Exit Evidence

- Live pre-remediation and post-local-repair receipts.
- Public-candidate fingerprint equality proof.
- Canonical remote/upstream checks pass; divergence is recorded truthfully.
- Remaining final `0/0` requirement, if any, is explicitly bound to the later
  private integration/push boundary and cannot be claimed complete early.

## Final Synchronization Boundary

S36.1 cannot honestly produce a durable tracked post-push `0/0` receipt before
its own commits are merged and pushed: committing a receipt creates another
commit. Therefore:

1. T3 records the complete local verifier/remediation evidence and any current
   divergence.
2. Story review verifies code and scope without claiming final synchronization.
3. At the explicitly authorized private integration/push boundary, merge/push
   the story, run the same verifier again from synchronized `main`, and retain
   the final untracked/local RaiSE evidence receipt plus its SHA-256/session
   journal reference.
4. Only then may S36.1 close and E36 mark the `main == origin/main` criterion.

This avoids an impossible self-referential tracked receipt and preserves
truthful current-state evidence.

### Repository-Specific Gate Scopes

- End of story: `rai gate check gate-tests --scope tests/test_repository_truth.py`
- Lint, format, and type gates remain full-project as required above.
- Unscoped tests run only during `/rai-mr-create` or an equivalent full private
  integration gate explicitly required by project governance.

Direct test commands are prohibited. The manual CLI invocation in T3 exercises
the operator interface and does not replace the test gate.

## Risks and Mitigations

| Risk | Mitigation |
|------|------------|
| Sensitive remote value appears in failure output | Sentinel-secret tests cover models, renderers, CLI streams, exceptions, and evidence files before live remediation. |
| Verifier mutates Git | Closed command set plus config/ref before/after equality tests; no repair option. |
| Real Git semantics differ from mocks | Core acceptance tests create real temporary bare/work repositories. |
| Wrong local remote is removed | Resolve and validate exact remote name against policy; mutate only after pre-remediation receipt. |
| Dirty public candidate is modified | Read-only fingerprint before/after; no command runs with it as working directory except status/hash probes. |
| PDF deletion leaks into a task commit | Stage explicit paths only and inspect cached names before every commit. |
| Story claims completion while main is ahead | Preserve failed divergence receipt; final `0/0` proof occurs only after authorized private integration/push. |

## Definition of Implementation Complete

- T1-T3 each have a focused RED/GREEN record and one scoped commit.
- All repository-specific test, lint, format, and type gates pass.
- The verifier is demonstrably read-only, deterministic, and credential-safe.
- Local obsolete remote/upstream configuration is repaired and evidenced.
- The public candidate fingerprint is unchanged.
- The PDF deletion remains outside every S36.1 commit.
- Any non-zero main/origin divergence is reported, not hidden, and carried to
  the explicit final synchronization boundary.
