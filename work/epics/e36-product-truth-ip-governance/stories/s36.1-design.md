# S36.1 Design: Canonical Repository & Remote Truth

## Problem

The local development branch tracks an obsolete remote while the private
`origin` repository is the intended canonical source. That configuration can
misdirect routine Git operations and currently gives no deterministic,
credential-safe proof of repository identity, upstream, or synchronization.

## Value

After S36.1, any operator can run one read-only command and prove which private
source, branch, and policy produced the result. Unsafe configuration fails
closed without exposing a URL or credential, and later E36 receipts inherit a
trustworthy source commit.

## Complexity and Gates

- **Complexity:** moderate — one policy, one domain validator, one thin CLI,
  focused tests, and generated evidence.
- **Risk gate:** high security impact but narrow mutation boundary. Primary
  failure modes are leaking a remote URL, silently accepting divergence, or
  modifying the wrong repository.
- **UX gate:** not applicable; this is an operator CLI with machine-readable
  output, not a user workflow.
- **Integration gate:** no client/server seam. Tests still use real temporary
  Git repositories rather than mocking subprocess behavior.
- **Storage migration:** not applicable.
- **Schema coordination:** not applicable; no SQLite DDL changes.
- **Supply chain:** no new dependency. Pydantic and PyYAML are existing,
  established project dependencies.

## Gemba Findings

1. `validators/voice_of_customer.py` and
   `validators/skill_golden_cases.py` establish strict Pydantic models with
   `ConfigDict(extra="forbid")`, safe YAML loading, stable hashes, and readable

2. `scripts/check_skill_golden_cases.py` establishes the thin CLI pattern:
   domain logic remains in `validators/`, JSON is sorted, text output is compact,
   and exit code `0/1` represents pass/fail.
3. Existing `validators/export.py` validates business-document sections; it is
   unrelated and must not be expanded into repository security.
4. No repository-truth, remote-sanitization, or canonical-source component was
   found. This story is net-new.
5. `governance/drift-hotspots.json` and `governance/drift-catalog.md` are absent.
   AG2 clone amplification is avoided by one validator implementation; AG4
   context-window fan-out is low because the change has three cohesive code
   surfaces plus policy/evidence.
6. `rai schema sum check` reported a missing advisory file; it was refreshed.
   The story does not alter a storage schema.
7. The installed RaiSE CLI has no `artifact emit` command and no equivalent MCP
   tool is available. This Markdown file is the versioned design evidence for
   this phase; the lifecycle journal records the tool-version gap.

## Approach

Create a strict YAML policy and a read-only Git verifier. The verifier executes
only fixed Git argument vectors, evaluates remote URLs only in memory, emits
sanitized typed results, and never performs a Git mutation. A thin script
serializes the same receipt as deterministic JSON or readable Markdown.

Local remediation is deliberately outside the verifier: after RED tests prove
the safety contract, the implementation phase removes only the exact obsolete
`gitlab` remote and points local `main` at `origin/main`. Merge/push remains a
separate external boundary needed for the final `0/0` synchronization receipt.

### Components

| Component | Change | Purpose |
|-----------|--------|---------|
| `governance/repository-truth.yaml` | Create | Versioned canonical/private/public-role and allowed/disallowed-remote policy. |
| `validators/repository_truth.py` | Create | Strict models, policy loader, safe Git probing, checks, fingerprints, and receipt rendering. |
| `scripts/check_repository_truth.py` | Create | Thin CLI for JSON/text output and optional receipt files; returns `0` on pass, `1` on fail/error. |
| `tests/test_repository_truth.py` | Create | Real temporary Git repository tests for pass, failure, non-mutation, determinism, and redaction. |
| `work/epics/e36-product-truth-ip-governance/stories/s36.1-evidence/` | Create/generated | Redacted baseline/final receipts, gate evidence, and public-candidate fingerprints. |
| `.git/config` | Local modify | Remove only `gitlab`; set `branch.main` upstream to `origin/main`. Never committed. |

### Value Preservation

The validator supplies domain knowledge a generic command wrapper cannot:

- canonical/private/public role semantics;
- fail-closed upstream and divergence interpretation;
- credential-bearing URL detection without serialization;
- deterministic rule IDs and policy/source hashes;
- privacy-preserving repository fingerprints.

No pass-through abstraction or generalized policy engine is introduced.

### Legacy Sweep

Nothing becomes orphaned: this is net-new. Existing business export validators,
golden-case gates, installers, and repositories keep their responsibilities. The
only removed legacy state is the exact local `gitlab` remote entry after tests
prove the configured policy; no tracked V1 module is replaced.

## Data Contracts

All models use `ConfigDict(extra="forbid")` and validate stable Git identifiers.
Unsafe identifiers are represented by a hash-derived redacted label, never by
their original text.

### `RepositoryTruthPolicy`

```yaml
schema_version: 1
canonical_source:
  role: private_canonical
  remote: origin
  development_branch: main
  required_upstream: origin/main
allowed_remotes:
  - origin
disallowed_remotes:
  - gitlab
public_distribution:
  role: generated_artifact
  mode: allowlisted_clean_export
  automatic_mirror: false
```

Rules:

- schema version must equal `1`;
- canonical remote must be allowed and cannot be disallowed;
- `required_upstream` must equal `{remote}/{development_branch}`;
- lists are unique, sorted for hashing, and contain only safe Git names;
- public role/mode and `automatic_mirror: false` are exact enums/constant state;
- unknown keys or role values fail policy loading.

### `RepositoryTruthReceipt`

```json
{
  "schema_version": 1,
  "status": "fail",
  "policy_sha256": "64-lowercase-hex",
  "verifier_source_commit": "40-or-64-hex",
  "checked_branch": "main",
  "checked_branch_commit": "40-or-64-hex",
  "upstream": "origin/main",
  "behind": 0,
  "ahead": 3,
  "remotes": ["origin", "gitlab"],
  "checks": [
    {"id": "canonical_remote", "status": "pass"},
    {"id": "allowed_remotes", "status": "fail"},
    {"id": "synchronized", "status": "fail"}
  ],
  "findings": [
    {"code": "disallowed_remote", "subject": "gitlab"},
    {"code": "branch_diverged", "subject": "main"}
  ]
}
```

The receipt has no timestamp, absolute path, URL, username, token, command
stdout/stderr, or exception representation. Arrays are sorted and JSON keys are
serialized deterministically.

### Finding Codes

- `invalid_policy`
- `git_command_failed`
- `missing_canonical_remote`
- `unexpected_remote`
- `disallowed_remote`
- `credential_bearing_remote_url`
- `missing_branch`
- `missing_upstream`
- `wrong_upstream`
- `missing_remote_branch`
- `branch_diverged`

Unknown internal state is mapped to a safe `git_command_failed` finding and a
failed check, not to a raw exception.

### `RepositoryFingerprint`

A witness fingerprint contains only a caller-provided safe label, HEAD hash,
safe branch label, dirty-entry count, and SHA-256 of raw porcelain output. It
never contains the witness root or dirty filenames. Equal before/after
fingerprints prove the public candidate repository was not modified by S36.1.

## Git Probe Security Boundary

The verifier uses `subprocess.run(..., shell=False, check=False, timeout=10)` and
a closed command set:

- `git -C ROOT remote`
- `git -C ROOT config --get-regexp ^remote\..*\.url$`
- `git -C ROOT rev-parse HEAD`
- `git -C ROOT rev-parse refs/heads/BRANCH`
- `git -C ROOT rev-parse --abbrev-ref BRANCH@{upstream}`
- `git -C ROOT show-ref --verify refs/remotes/REMOTE/BRANCH`
- `git -C ROOT rev-list --left-right --count UPSTREAM...BRANCH`
- `git -C ROOT symbolic-ref --short HEAD`
- `git -C ROOT status --porcelain=v1 -z`

The URL-producing config command is the sole sensitive probe. Its stdout is
parsed in memory to associate a safe/redacted remote label and detect embedded
HTTP(S) userinfo. Its raw text cannot enter models, errors, logs, test failure
messages, or receipts. Normal SSH identities such as `git@github.com:path` are
not treated as embedded HTTP credentials.

The CLI has no repair, push, pull, fetch, merge, reset, clean, or delete option.
Tests fingerprint `.git/config` and refs before/after verification to prove
non-mutation.

## Concrete Examples

### Successful verification

```bash
python scripts/check_repository_truth.py \
  --repo . \
  --policy governance/repository-truth.yaml \
  --format json
```

```json
{
  "ahead": 0,
  "behind": 0,
  "checked_branch": "main",
  "findings": [],
  "remotes": ["origin"],
  "status": "pass",
  "upstream": "origin/main"
}
```

The actual receipt also includes schema version, commits, policy hash, and every
named check. Exit code is `0`.

### Disallowed remote without URL disclosure

```bash
python scripts/check_repository_truth.py \
  --repo /tmp/s36-repo \
  --policy governance/repository-truth.yaml \
  --format json
```

```json
{
  "findings": [
    {"code": "disallowed_remote", "subject": "gitlab"},
    {
      "code": "credential_bearing_remote_url",
      "subject": "gitlab"
    }
  ],
  "status": "fail"
}
```

If the configured value were
`https://example-secret@example.invalid/private.git`, neither stdout, stderr,
receipt files, nor raised errors may contain `example-secret` or the URL. Exit
code is `1`.

### Deterministic evidence files

```bash
python scripts/check_repository_truth.py \
  --repo . \
  --policy governance/repository-truth.yaml \
  --json-output work/epics/e36-product-truth-ip-governance/stories/s36.1-evidence/baseline.json \
  --markdown-output work/epics/e36-product-truth-ip-governance/stories/s36.1-evidence/baseline.md
```

The command may write only the requested receipt files. Running it twice against
unchanged policy/repository state produces byte-identical files.

### Public candidate witness

```python
before = fingerprint_repository(candidate_root, label="public_candidate")
# S36.1 verification and exact local configuration repair happen elsewhere.
after = fingerprint_repository(candidate_root, label="public_candidate")
assert before == after
```

## Decisions

### D36.1-1 — Policy and evidence are separate

The tracked policy describes expected truth; generated receipts describe
observed truth. A receipt cannot change policy and policy cannot claim a check
passed.

### D36.1-2 — Inspect sensitive URLs, serialize only findings

Avoiding all URL inspection would miss credential-bearing configuration.
Inspecting in memory and enforcing a typed output boundary detects the risk
without reproducing it.

### D36.1-3 — Real Git repositories over subprocess mocks

Temporary bare/work repositories exercise upstream syntax, refs, divergence,
and config behavior that mocks commonly misrepresent. A small command-runner
failure test may inject a process failure, but acceptance depends on real Git.

### D36.1-4 — Repair remains an explicit operator action

The verifier is safe to run repeatedly because it cannot mutate Git. The two
permitted local repairs use normal Git commands outside the CLI and are recorded
in evidence. Publication/push is not automated.

## Testing Strategy

| Layer | Test | Purpose |
|-------|------|---------|
| Policy | valid strict YAML | Loads canonical/private/public contract and stable policy hash. |
| Policy | extra key, bad role, conflicting remote lists | Fails closed with no partial policy. |
| Real Git | synchronized `main` tracking bare `origin/main` | Produces PASS and stable commits/counts. |
| Real Git | disallowed remote and wrong upstream | Produces stable findings without URLs. |
| Real Git | local ahead, remote ahead, missing remote branch | Produces correct sanitized divergence failures. |
| Security | HTTP URL with sentinel username/token | Sentinel absent from model dump, JSON, text, stdout, stderr, and exception text. |
| Safety | snapshot `.git/config` and refs before/after | Verifier is read-only. |
| Fingerprint | dirty witness repository | Output omits root/filenames and is stable; before equals after. |
| CLI | JSON/text and output files | Exit codes, deterministic bytes, sorted output, and parent error handling. |
| Repository | live baseline after remediation | `gitlab` absent; main upstream correct; remaining divergence truthfully reported. |

## Acceptance Criteria

### MUST

1. The strict policy represents exactly one private canonical source and a
   generated allowlisted, non-mirrored public artifact.
2. Real-Git tests prove correct pass/fail behavior for remote, upstream, refs,
   URL credential detection, and both divergence directions.
3. No URL, credential value, absolute path, dirty filename, or raw Git output is
   serializable through any receipt/finding/fingerprint model or CLI error.
4. Verification is read-only and deterministic; repeated unchanged runs produce
   identical JSON and Markdown bytes.
5. The exact obsolete local remote is removed, `main` tracks `origin/main`, and
   final integration evidence reports divergence `0/0` before story close.

### SHOULD

1. Text output fits a short operator handoff: overall status, each check, and
   sanitized remediation category.
2. Public-candidate fingerprints prove no mutation without storing its local
   path or filenames.

### MUST NOT

1. The verifier must not expose a repair flag or execute a mutating Git command.
2. S36.1 must not stage/commit the intentional PDF deletion, rewrite history,
   touch the public candidate repository, or publish/push automatically.
3. S36.1 must not expand into full content/history secret scanning or clean
   export; those belong to S36.2 and S36.5.

## Dependencies and Open Boundary

- Depends on E36 ADR `Private Canonical Source and Verified Clean Export` and the
  three existing local E36 commits.
- Does not depend on network access for unit/integration tests.
- Final `main == origin/main` evidence depends on a later explicitly authorized
  private integration/push. All code, tests, local remediation, and baseline
  evidence can be completed before that boundary.
