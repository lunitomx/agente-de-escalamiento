# S36.2 Scope: IP, Secret & Reference Exposure Inventory

## In Scope

- Define a strict, versioned exposure policy covering source/reference,
  public-vocabulary, credential/secret, private-data, internal-path, and
  distribution-eligibility risks.
- Add typed models and a deterministic read-only inventory for explicitly
  bounded surfaces: working tree, canonical `HEAD`, Git history metadata, local
  Git configuration, tracked distribution candidates, and the existing public
  candidate repository.
- Distinguish current worktree absence, current canonical tracking, historical
  presence, public-candidate presence, and future generated-staging eligibility.
- Emit only safe relative locators, hashes, stable rule IDs, counts, and
  classifications; redact all secret values, authenticated URLs, contents, and
  raw subprocess payloads.
- Classify every relevant finding by severity, remediation owner, and intended
  S36.3/S36.5 disposition without claiming remediation has already occurred.
- Prove inventory non-mutation for the private working repository and dirty
  public candidate using strong before/after fingerprints.
- Produce machine-readable JSON and a readable Markdown baseline that S36.3 and
  S36.5 can consume without rescanning or weakening the public boundary.

## Out of Scope

- Commit or restore the intentionally deleted raw PDF; S36.3 owns its auditable
  canonical-tree removal.
- Rewrite Git history, purge remote objects, rotate/revoke credentials, delete
  branches/tags, or change any remote URL.
- Modify, clean, reset, stash, index, synchronize, or publish the dirty public
  candidate repository.
- Build the clean export, license package, notices, or public release; S36.5 owns
  those artifacts.
- Treat heuristic secret matches as confirmed live credentials without stronger
  evidence.
- Scan arbitrary home directories, cloud accounts, Google Drive, OneDrive, or
  other repositories not explicitly named by E36.
- Add hosted runtime, telemetry, SaaS, remote database, or cloud processing.

## Done When

- [ ] A strict exposure-policy schema rejects unknown fields, surfaces,
      classifications, severities, and dispositions.
- [ ] Tests prove worktree, `HEAD`, history, local-config, distribution, and
      public-candidate findings remain distinct and deterministic.
- [ ] Secret-shaped fixtures prove no result, exception, JSON, Markdown, CLI
      stream, or evidence file contains the sentinel secret or a remote URL.
- [ ] The real baseline identifies the raw reference's current-worktree,
      canonical-`HEAD`, and historical state without staging or committing it.
- [ ] Repository-relative reference/public-vocabulary findings are classified
      for S36.3, while unclassified distribution paths fail closed as
      `not_eligible` for S36.5.
- [ ] Local Git configuration findings expose remote names and risk booleans
      only; no configured URL is serialized.
- [ ] Strong before/after fingerprints prove both bounded repositories remain
      unchanged by inventory execution.
- [ ] Deterministic sanitized JSON and Markdown baseline receipts are committed
      with the verifier source commit and policy hash.
- [ ] Focused per-task gates pass before implementation commits; the full
      repository and architecture gates pass before local story merge.

## Acceptance Evidence

- Exposure policy and strict schema tests.
- Real temporary-repository positive/negative tests with sentinel secrets.
- Redacted real baseline JSON and Markdown.
- Private and public-candidate strong before/after fingerprint comparisons.
- Current-tree versus history classification summary.
- Gate and source-commit receipts in the story retrospective.

## Constraints

- Fail closed on unknown classification, missing bounded root, malformed Git
  output, unsafe locator, scan failure, or unclassified distribution state.
- Never serialize a secret/credential value, authenticated remote URL, file
  content, or subprocess stdout/stderr from sensitive probes.
- Use strict Pydantic models and full Python type annotations for all new data
  structures.
- Keep the scanner deterministic and local-only; no network access is required
  for inventory execution.
- Treat plans and source notes as claims until current evidence proves their
  state.
