# S36.4 Scope: Typed Governance Taxonomy & Unique Epic IDs

## In Scope

- Define `governance/closure-dispositions.yaml` as the strict, versioned source
  of truth for every accepted closure posture and its terminal, completed,
  reviewable, and activation-eligible semantics.
- Add strict Pydantic parsing and typed queries in a governance-contract
  validator; reject unknown fields, unsupported schema versions, missing
  semantics, duplicate IDs, and internally contradictory postures.
- Migrate `validators/epic_closure.py` to consume the typed contract instead of
  normalizing its own independent status vocabulary.
- Preserve the exact fail-closed outcomes proved by ESCALA-001 for complete,
  deferred/backlog, absorbed/descoped, superseded/discarded, and
  deprecated/discarded scopes, while expanding positive and negative coverage
  to every accepted policy entry.
- Define `governance/epic-identities.yaml` with one canonical identity for each
  of the ten legacy folders that currently collide under E18, E19, E20, E21,
  and E22, plus explicit traceable aliases and dispositions.
- Add typed identity validation and deterministic resolution that rejects
  duplicate canonical IDs, duplicate resolvable aliases, unknown folders,
  missing in-scope folders, ambiguous bare numeric references, and aliases that
  point to no canonical entry.
- Add the smallest repository-owned graph identity seam needed for the real
  `rai graph build` to emit collision-free E18–E22 nodes without discarding a
  legacy folder or silently choosing whichever path is enumerated first.
- Prove old folder-qualified references resolve to the intended canonical
  identities and that terminal/deferred dispositions remain attached to the
  correct legacy work.
- Commit a deterministic local receipt covering policy hashes, all ten legacy
  folders, alias-resolution results, and the real graph-build duplicate count.

## Out of Scope

- Treat a plan, retrospective, tag, folder name, numeric ID, or prose alias as
  proof that an epic is complete.
- Add permissive substring aliases or retain a second hard-coded closure
  vocabulary for compatibility.
- Rewrite Git history, renumber unrelated modern epics, delete legacy work, or
  rename folders before reference impact and rollback are proved.
- Modify installed RaiSE packages or suppress duplicate diagnostics instead of
  fixing repository identity truth.
- Reopen, implement, or reactivate any deferred, superseded, deprecated, or
  absorbed legacy epic.
- Change product coaching, dashboards, local data schemas, ingestion, financial
  analysis, meeting automation, or public vocabulary behavior.
- Build the clean public export, choose a license, publish a repository, or
  populate the E37–E42 acceptance ledger; S36.5 and S36.6 own those outcomes.
- Add SaaS, hosted APIs, cloud databases, telemetry, or automatic synchronized-
  folder processing. SQLite remains outside Drive/OneDrive synchronized paths.

## Done When

- [ ] The closure-disposition policy is strict, versioned, and accepted only
      when every entry has complete, non-contradictory typed semantics.
- [ ] The closure validator consumes that policy and contains no competing
      normalization table or permissive substring interpretation.
- [ ] Tests cover every accepted disposition plus unknown, malformed, missing,
      duplicate, contradictory, legacy-only, and unsupported-version cases.
- [ ] Existing audited/backlog closure tests remain green and cannot promote
      non-complete terminal or deferred work to complete.
- [ ] The epic-identity policy accounts for all ten duplicate E18–E22 folders
      with unique canonical IDs and non-colliding resolvable aliases.
- [ ] Folder-qualified legacy references resolve deterministically; unknown and
      ambiguous bare numeric references fail closed without first-match logic.
- [ ] The real canonical `rai graph build` reports zero duplicate epic node IDs
      for E18–E22 and the receipt proves no legacy folder was omitted.
- [ ] Any required repository normalization has focused rollback/link tests and
      no unproved folder rename or destructive migration.
- [ ] Deterministic sanitized JSON/Markdown evidence records policy hashes,
      verifier source commit, ten-folder coverage, resolution checks, and graph
      diagnostics without absolute roots or raw subprocess output.
- [ ] Focused per-task tests, lint, format, and type gates pass before commits;
      full repository and architecture gates pass before local story merge.

## Acceptance Evidence

- Closure-disposition YAML, strict parser, and policy exhaustiveness tests.
- Epic-closure consumer migration and ESCALA-001 regression suite.
- Epic-identity YAML, strict parser, folder inventory, and alias-resolution
  positive/negative tests.
- Real graph-build receipt with ten-folder coverage and zero E18–E22 duplicate
  canonical node diagnostics.
- Git diff proving no hidden deletion, history rewrite, external package patch,
  public-candidate mutation, push, or publication.
- Gate receipts and source commits recorded in the retrospective.

## Constraints

- Fail closed on missing policy, unknown field/value, unsupported schema,
  contradictory disposition semantics, duplicate canonical ID/alias, ambiguous
  reference, missing in-scope folder, or graph diagnostic mismatch.
- Use strict Pydantic models and complete type annotations for new Python data
  structures; serialize stable lowercase enum values.
- Registry and evidence ordering must be deterministic across repeated local
  runs.
- Do not serialize absolute filesystem roots, remote URLs, raw subprocess
  payloads, private content, or secret values.
- Preserve existing closure evidence semantics atomically across canonical
  policy, validator, and positive/negative tests.
- Keep all execution local-only and require no network access.
