# Retrospective: S36.5 — Clean Export, License & Third-Party Contract

**Dates:** 2026-07-21 → 2026-07-21
**Estimated implementation:** 310m | **Recorded task time:** 45m

## Summary

S36.5 produced one explicit public allowlist, a truthful provisional no-license
posture, a 13-entry third-party dependency closure, an immutable-current-commit
Git-object builder, an independent staged-filesystem verifier, separate safe
CLIs, and real M3 qualification evidence. The qualified source commit
`faad022c3e42786178bada757f19101b9a292d83` generates a deterministic 264-file
local artifact that passes all ten technical checks. Human legal review remains
required and publication remains unauthorized.

The first real M3 attempt correctly stopped on one prohibited product-identity
term in selected `pyproject.toml`. A focused RED reproduced it, commit `faad022`
neutralized the portable configuration, and the full double-build/verify/tamper
sequence was rerun from that new immutable commit. The failed run remains
recorded as diagnostic truth, not qualification evidence.

## What went well

- TDD established strict policy, dependency graph, builder, verifier, and CLI
  boundaries before the real artifact was built.
- Builder and verifier remained separate. The verifier reads `lstat`, manifest,
  payload bytes, imports, vendored headers, license state, and local-only rules
  without calling the builder or accepting its in-memory result.
- The real M3 gate found a configuration leak that all minimal fixtures missed,
  proving the value of exact staged-artifact qualification.
- The product boundary stayed local-only: the dashboard now uses vendored
  Chart.js, the portable server no longer imports the excluded private ingester,
  and no hosted service, cloud database, Drive/OneDrive API, telemetry, OAuth,
  or synchronized SQLite behavior was added.
- Private and public-candidate strong fingerprints matched before and after.
  The public candidate's observed dirty count was 18 for both snapshots; it was
  not normalized to an older expected count.

## What to improve

- T4 fixtures were intentionally minimal and therefore did not exercise every
  canonical selected root. Future clean-export stories should add one canonical
  selected-metadata smoke check before the manual M3 phase. The focused
  `pyproject.toml` regression added after the live defect now covers this case.
- `validators/public_export.py` owns several cohesive but large sub-boundaries.
  Architecture review should monitor change pressure and split builder,
  verifier, and presentation only when separate evolution justifies it; a
  speculative refactor during qualification would have increased risk.
- The first M3 orchestration was ad hoc. A reusable local qualification command
  may be warranted after the receipt contract stabilizes, but it must retain
  separate builder/verifier processes and must not introduce publication.
- Legal identifiers and notice obligations are technically inventoried, not
  legally approved. The human legal/IP gate remains an explicit downstream
  dependency rather than being inferred from tests.

## Heutagogical Checkpoint

1. **What did I learn?** A source-neutral code scan is insufficient for public
   qualification. `pyproject.toml` was selected payload and retained a private
   control-plane identifier even though product code and knowledge were clean.
   Only the real independent artifact verifier exposed it.
2. **What would I change about the process?** After implementing the verifier,
   run a canonical selected-file smoke build before CLI polish. That would move
   metadata/config drift earlier while preserving the mandatory final M3 run.
3. **Framework improvements?** RaiSE should reliably emit design, plan, and
   implement learning records and should offer a first-class format-diff mode.
   All three S36.5 learning records were absent, and review graph queries returned
   mostly unrelated dashboard patterns for an export-governance story.
4. **What am I more capable of now?** I can produce and prove a local-only clean
   artifact from immutable Git objects, distinguish technical/legal/publication
   states, identify dependency and public-boundary drift in exact staged bytes,
   and preserve safe non-mutation evidence around a dirty external candidate.
