# S36.5 Scope: Clean Export, License & Third-Party Contract

## In Scope

- Define one strict, versioned product-boundary/export policy that owns the
  explicit public allowlist, required metadata, local-only invariants, artifact
  checks, and safe evidence contract.
- Consume the S36.3 public vocabulary/deny rules, immutable S36.2 baseline
  binding, and S36.4 governance-policy hashes without creating competing
  source, identity, or disposition vocabularies.
- Admit only exact Git-tracked regular files or bounded roots. A path being
  `candidate_public` is evidence for review, never implicit export permission.
- Make the current license contradiction executable and truthful: record the
  selected interim posture, the required human legal-review gate, and an
  explicit `publication_authorized: false` state until that gate is satisfied.
- Create a deterministic third-party inventory for every runtime/build
  dependency required by the staged product, including name, version or
  constraint, purpose, source of truth, license identifier/status, notice
  requirement, and review state.
- Build a local artifact only into a new empty caller-supplied staging directory
  outside synchronized data authority. Never overwrite an occupied destination.
- Enumerate source inputs from the canonical Git commit, not arbitrary
  untracked worktree files, and reject unsafe paths, symlinks, special files,
  duplicate destinations, case-fold collisions, and out-of-root resolution.
- Independently verify the staged artifact's exact path set, hashes, required
  metadata, license posture, third-party inventory, version/provenance,
  reference vocabulary, secrets, private paths/data, and local-only invariants.
- Emit deterministic bounded JSON and Markdown evidence with source commit,
  semantic policy/dependency hashes, sorted artifact file hashes, named check
  results, technical-artifact status, legal/publication status, and no private
  values or machine roots.
- Run the real M3 flow twice from a clean canonical commit into separate local
  temporary directories, prove byte identity, tamper one copy to prove the
  independent verifier fails, and preserve a safe versioned receipt.
- Prove the private repository and the existing dirty public candidate have
  identical strong before/after fingerprints across the E2E observation.
- Add focused positive/negative tests for every strict policy field and each
  builder/verifier boundary, then pass lint, format, types, full story-close
  gates, and architecture review before local merge.

## Out of Scope

- Choosing or claiming final legal approval for a software license without the
  named human review; the story records and enforces the pending posture.
- Publishing, pushing, replacing, resetting, cleaning, merging into, or copying
  over the existing public candidate repository.
- Making the private repository public, mirroring it, rewriting Git history, or
  removing truthful historical exposure records.
- Building E41 installers/updaters, archives for a release channel, code signing,
  notarization, CI/CD, or Windows validation.
- Implementing ingestion, OCR, Cockpit, financial interpretation, meeting
  automation, team workflows, or other E37–E41 product capabilities.
- Adding a hosted application, SaaS endpoint, cloud database, telemetry,
  Google Drive/OneDrive API, OAuth, or multi-writer SQLite design.
- Exporting authoritative company SQLite state, private inbox contents,
  generated company reports, credentials, local configuration, governance work,
  test evidence, or training/reference material.
- Treating an S36.2/S36.3 source scan, candidate-public count, unit-test fixture,
  or plan as proof that the exact staged artifact passes.

## Done When

- [ ] The export policy is strict, versioned, typed, deterministic, and rejects
      null/missing/unknown fields, invalid rules, unsafe paths, overlapping
      allow/deny scope, duplicate destinations, and unsupported schema versions.
- [ ] The allowlist admits every intended portable product path explicitly and
      excludes every unlisted, private, reference, governance, work, test,
      company-state, database, and generated-evidence path by default.
- [ ] License status and publication authorization are separate typed fields;
      the current no-formal-license/commercial-use contradiction is resolved
      without claiming unperformed legal approval.
- [ ] The third-party inventory is complete for the staged dependency surface,
      source-bound, sorted, reviewable, and enforced by the verifier.
- [ ] The builder reads only the canonical Git commit and refuses dirty-source
      ambiguity, occupied staging, symlinks, special files, traversal, case-fold
      collisions, untracked additions, or destinations outside staging.
- [ ] The independent verifier detects added, removed, changed, unexpected, or
      unsafe staged files and cannot be bypassed by a passing source scan.
- [ ] Prohibited public vocabulary, credential sentinels, private paths/data,
      raw source assets, unsafe provenance, hosted-service dependencies, and
      SQLite payloads all have negative tests with redacted output assertions.
- [ ] Two real clean builds from the same source/policy produce byte-identical
      sorted manifests and sanitized receipts outside the repository.
- [ ] One real tampered artifact fails independent verification for the exact
      expected rule without leaking its matched value or external locator.
- [ ] A versioned M3 receipt proves the real staged artifact's file count/hash,
      every named check, technical PASS, legal/publication posture, source/policy
      binding, and private/public-candidate non-mutation.
- [ ] The existing public candidate remains byte-identical and no push,
      publication, history rewrite, hosted runtime, database migration, or
      synchronized SQLite path occurs.
- [ ] Focused implementation gates pass before every task commit; full tests,
      lint, format, types, architecture review, retrospective, and local merge
      pass before story closure.

## Acceptance Evidence

- Strict export policy, license-status metadata, and third-party inventory.
- Typed builder/verifier models plus positive and negative contract tests.
- Deterministic sorted artifact manifest and bounded JSON/Markdown receipts.
- Real temporary-directory build comparison and tamper-failure receipt.
- S36.2 baseline, S36.3 policy, and S36.4 governance hash bindings.
- Strong private/public-candidate before/after fingerprints.
- RaiSE gate and architecture-review receipts recorded in the retrospective.

## Constraints

- Fail closed on unknown or incomplete policy, dependency, metadata, license,
  provenance, path, hash, artifact, or publication state.
- Use strict Pydantic models and complete type annotations for new Python data
  structures; use stable lowercase enum values in serialized output.
- Preserve deterministic ordering and source-bound semantic hashes.
- Do not serialize absolute paths, remote URLs, matched secrets, source excerpts,
  private content, raw subprocess payloads, or temporary directory names.
- Keep execution local-only and require no network, hosted service, cloud
  database, Drive/OneDrive API, OAuth, or synchronized SQLite file.
- Do not change the existing Action Plan export validator's responsibility or
  name; public-package export must have an unambiguous separate API.
