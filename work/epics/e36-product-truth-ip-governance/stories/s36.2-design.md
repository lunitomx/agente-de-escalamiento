# S36.2 Design: IP, Secret & Reference Exposure Inventory

## Problem

The repository contains multiple kinds of potentially unsafe material, but the
current evidence does not distinguish what is absent from the working tree,
still tracked in `HEAD`, present only in history, present in the dirty public
candidate, or merely mentioned in plans. Remediation without that distinction
can either publish prohibited material or make false deletion and security
claims.

## Value

S36.2 produces one deterministic, redacted baseline that lets S36.3 remove the
right source-facing material and lets S36.5 build a fail-closed clean export.
An operator can reproduce every risk classification without seeing a secret,
credential-bearing URL, sensitive file content, or unbounded local path.

## Complexity Assessment

**Complex.** The story spans policy, typed domain models, bounded filesystem and
Git inspection, sanitized rendering, a CLI boundary, real-repository tests, and
live evidence. It uses custom deterministic classification logic across six
surfaces. There is no network or hosted integration, and no novel cryptography.

Risk gates:

- **Security/IP risk:** high. A scanner that prints a matched value or raw Git
  error would create the exposure it is meant to report.
- **Mutation risk:** high for the dirty public candidate. Every inspection is
  read-only and wrapped in strong before/after fingerprints.
- **False-claim risk:** high. Worktree absence, `HEAD` presence, historical
  presence, and distribution eligibility are separate facts.
- **UX gate:** not applicable; this is an operator CLI and evidence contract,
  not an end-user coaching interaction.
- **Integration gate:** the live acceptance run uses real private and public
  candidate repositories. Mock-only proof is insufficient.

## Gemba Findings

### Existing components to reuse

- `validators/repository_truth.py` already owns strict Pydantic conventions,
  deterministic JSON/Markdown rendering, credential-safe Git subprocesses,
  `GIT_*` environment isolation, and strong repository fingerprints.
- `scripts/check_repository_truth.py` establishes the thin CLI pattern: parse
  paths, keep raw failures behind a safe boundary, render only typed results,
  and use exit status for completeness.
- `tests/test_repository_truth.py` provides real temporary Git repositories,
  sentinel-secret assertions, environment-injection tests, deterministic
  receipt checks, and non-mutation proof patterns.

### Components that are not substitutes

- `validators/export.py` validates five headings in a private action-plan file;
  it is not a distribution allowlist or public-artifact verifier.
- `coaching/export/` writes company-specific action plans. It remains private
  runtime behavior and must not be reused as a public repository exporter.
- `governance/guardrails.md` currently recommends public attribution to a named
  external methodology. That is inventory evidence for S36.3, not the desired
  final public rule.

### Observed baseline facts to verify in implementation

- The raw reference asset is absent from the working tree by deliberate user
  deletion but remains tracked in the current `HEAD` until S36.3.
- Source-facing terminology occurs across skills, knowledge, server code,
  dashboards, templates, attribution files, and historical epic artifacts.
- The public candidate has unrelated dirty work and is evidence-only; its
  content and Git state must not be modified.
- S36.1 removed the obsolete local remote and credential-bearing configuration;
  S36.2 must re-observe, not assume, that state.

### Legacy sweep

Nothing becomes orphaned: this is a net-new inventory capability. The existing
action-plan export validator and coaching export remain in place because they
serve a different private-runtime contract. The new implementation extends and
reuses repository-truth primitives rather than replacing them.

### Drift review

- No `governance/drift-hotspots.json` or drift catalog is present.
- **AG2 clone amplification:** mitigated by importing the existing strong
  fingerprint and following its safe Git boundary instead of copying it.
- **AG4 context fan-out:** the implementation has one domain module, one policy,
  one thin CLI, and one focused test module; evidence is output, not a fifth
  behavioral owner.
- `rai schema sum check` passes at schema version 32; no storage migration is
  introduced.

## Approach

Build a policy-driven, typed inventory that inspects explicitly bounded local
surfaces and returns sanitized observations. Findings describe risk; scan status
describes whether the observation was complete. The presence of expected risks
does not make the inventory itself fail, but an unreadable surface, unsafe
locator, malformed policy, or non-mutation mismatch makes it incomplete and
causes a non-zero CLI exit.

### Bounded surfaces

| Surface | Observed state | Content policy |
|---|---|---|
| `worktree` | Tracked path existence and safe text content for tracked files | Read only; missing tracked paths remain explicit |
| `git_head` | Paths and blobs from the current canonical commit | Read in memory; never write extracted blobs |
| `git_history` | Historical path and commit-presence metadata | No historical content or commit-message serialization |
| `local_git_config` | Remote names and credential-risk booleans | URL values inspected only in memory |
| `distribution_candidate` | Tracked-path count and deterministic set hash | Default is `not_eligible`; no per-file allowlist is invented here |
| `public_candidate` | Canonical `HEAD` content plus dirty-state summary | Do not inspect untracked/dirty contents; fingerprint before and after |

Generated staging is represented as `not_built` in S36.2. S36.5 owns creation
and independent inspection of a real staged artifact.

### Sensitive-boundary rules

- Reference and public-vocabulary findings may expose a validated
  repository-relative path because S36.3 needs an actionable private locator.
- Secret, credential, and private-data findings expose a deterministic locator
  hash plus optional line number; they never expose content or a sensitive
  filename.
- Local Git configuration exposes only a validated remote name and boolean risk
  classification.
- Subprocess stdout/stderr and exception messages never cross the domain/CLI
  boundary. A stable finding code replaces them.
- Repository roots and the public-candidate absolute path are inputs only and
  never appear in models, JSON, Markdown, stdout, or stderr.

### History contract

History inspection answers only whether a reference-relevant path appeared in
reachable history and returns a safe path plus a count/digest. It does not scan
historical blob contents, does not claim a purge, and does not use history as
evidence of public eligibility. This is sufficient for E36's current-versus-
historical truth requirement without creating a destructive rewrite feature.

### Distribution contract

S36.2 does not design the future allowlist. It records the number and stable
digest of current tracked paths and sets distribution eligibility to
`not_eligible` by default. S36.5 must explicitly admit paths through its own
manifest; absence of a classification can never become implicit permission.

## Design Decisions

### D1 — Separate observation completeness from risk presence

The receipt has `scan_status = complete|incomplete` and an independent severity
summary. Expected findings can coexist with a complete scan. This prevents a
baseline inventory from being called broken simply because it found the risks
it was designed to locate.

### D2 — Reuse repository fingerprints, do not fork them

Both repositories use `fingerprint_repository()` before and after inspection.
Equality across HEAD, status, worktree bytes, local config, logical index, and
refs is mandatory. This preserves the reviewed S36.1 contract and avoids clone
drift.

### D3 — Typed safe models are the only serializable boundary

Raw match objects, file contents, Git outputs, URLs, and exceptions stay in
private local variables. Renderers accept only frozen strict Pydantic models.
Safe validation happens before any locator enters a finding.

### D4 — Historical metadata, not historical secret extraction

History scanning is path/presence metadata only. Current `HEAD` and bounded
tracked worktree content receive reference and secret-shape inspection. This
meets current security/export needs without implementing an expensive and risky
full-history secret forensics tool.

### D5 — Aggregate unclassified distribution state

Thousands of identical `not_eligible` findings would add noise without value.
The receipt stores tracked-path count and a stable set hash, while actionable
reference/public-vocabulary findings remain path-level. S36.5 will introduce
the per-path allowlist.

### D6 — No new dependency

Existing Pydantic, PyYAML, Git, and the Python standard library cover the
contract. Supply-chain review is therefore not applicable.

## Data Contract

Key enums:

```python
class ExposureSurface(str, Enum):
    WORKTREE = "worktree"
    GIT_HEAD = "git_head"
    GIT_HISTORY = "git_history"
    LOCAL_GIT_CONFIG = "local_git_config"
    DISTRIBUTION_CANDIDATE = "distribution_candidate"
    PUBLIC_CANDIDATE = "public_candidate"

class ExposureClass(str, Enum):
    RAW_REFERENCE = "raw_reference"
    DERIVED_REFERENCE = "derived_reference"
    PUBLIC_VOCABULARY = "public_vocabulary"
    SECRET_CANDIDATE = "secret_candidate"
    CREDENTIAL_RISK = "credential_risk"
    PRIVATE_DATA = "private_data"
    INTERNAL_PATH = "internal_path"
    NOT_ELIGIBLE = "not_eligible"

class ScanStatus(str, Enum):
    COMPLETE = "complete"
    INCOMPLETE = "incomplete"
```

Each serialized finding contains only:

```json
{
  "rule_id": "reference.raw_asset",
  "surface": "git_head",
  "classification": "raw_reference",
  "severity": "critical",
  "locator_kind": "relative_path",
  "locator": "reference-asset.pdf",
  "disposition": "remove_in_s36_3"
}
```

For sensitive matches, `locator_kind` is `sha256` and `locator` is a 64-character
digest. No matched string is a model field.

## Processing Flow

```text
load strict policy
  -> fingerprint private and public candidates
  -> enumerate bounded paths deterministically
  -> inspect worktree and HEAD independently
  -> inspect historical path metadata
  -> inspect remote URL values inside non-serializable memory
  -> classify distribution candidate as not eligible by default
  -> build and validate typed receipt
  -> fingerprint both repositories again
  -> require before == after
  -> render deterministic JSON/Markdown
```

Missing entities fail closed:

- Missing private root, public-candidate root, `HEAD`, or Git metadata produces
  an `incomplete` receipt and CLI exit 1.
- An unreadable individual bounded file produces a stable scan-error finding;
  it is never silently dropped.
- Malformed or unsafe relative paths are rejected, not normalized into a
  possibly different target.
- The CLI never writes partial output after an unsafe exception; it emits one
  fixed safe error sentence.

## Runnable Examples

### Complete scan with findings

```bash
python scripts/check_exposure_inventory.py \
  --repo . \
  --public-candidate ../agente-de-escalamiento \
  --policy governance/exposure-policy.yaml \
  --format json \
  --json-output /tmp/s36.2-baseline.json \
  --markdown-output /tmp/s36.2-baseline.md
```

Expected exit: `0` when all bounded surfaces were inspected and fingerprints
match, even if the risk count is non-zero.

For a test fixture whose complete sorted tracked-path set is `README.md`,
`reference-asset.pdf`, and `src/app.py`, the aggregate is:

```json
{
  "distribution": {
    "default_eligibility": "not_eligible",
    "tracked_path_count": 3,
    "tracked_path_set_sha256": "60999c6cd7ead91059f9d36c6e2c5f27e7d8df6bbc275e91de37f7b308506990"
  },
  "scan_status": "complete",
  "schema_version": 1
}
```

The complete receipt also contains sorted findings, counts, policy hash,
verifier source commit, surface summaries, and before/after fingerprint hashes.
It never contains either absolute root.

### Incomplete scan

```bash
python scripts/check_exposure_inventory.py \
  --repo /missing/private-root \
  --public-candidate ../agente-de-escalamiento \
  --policy governance/exposure-policy.yaml
```

Expected exit: `1`.

```text
exposure inventory: unable to produce a safe receipt
```

No missing path, exception payload, environment value, or Git stderr is printed.

For a fixture with one raw-reference finding and one public-vocabulary finding:

```markdown
# Exposure Inventory Receipt

- Generated staging: `not_built`

- `critical`: `1`
- `high`: `1`
```

## Acceptance Criteria

### MUST

1. Strict policy and frozen typed models reject unknown fields and vocabulary.
2. Real-Git tests prove worktree, `HEAD`, history, config, distribution, and
   public-candidate facts remain distinct and deterministically sorted.
3. Sentinel tests prove secrets, URLs, contents, raw subprocess output, and
   absolute roots cannot cross any model, renderer, CLI, or evidence surface.
4. Both real repositories have identical strong fingerprints before and after
   the live inventory.
5. The live baseline truthfully records the raw asset as absent from worktree,
   present in canonical `HEAD`, and historically present, while distribution
   remains fail-closed.
6. Focused gates pass per task; full repository and AR gates pass before merge.

### SHOULD

1. Markdown groups findings by severity and classification for rapid S36.3
   planning without changing the deterministic JSON order.
2. The receipt includes explicit remediation ownership for S36.3 and S36.5.

### MUST NOT

1. Do not stage, restore, commit, or modify the intentionally deleted raw PDF.
2. Do not mutate the public candidate, Git config, index, refs, worktree, or
   history.
3. Do not add network calls, hosted services, cloud storage, telemetry, or new
   dependencies.
4. Do not claim a secret is live, history is purged, or a file is publicly
   eligible from heuristic or planning evidence.

## Testing Strategy

| Layer | Test | Purpose |
|---|---|---|
| Policy | Strict schema matrix | Reject unknown enums, keys, unsafe patterns, overlaps, and incoherent dispositions |
| Domain | Safe-model boundary | No sensitive value or root can validate into serializable models |
| Git integration | Surface distinction | Real repository with tracked-missing, committed, historical-only, and dirty states |
| Security | Sentinel matrix | Secret and authenticated URL absent from receipt, JSON, Markdown, repr, stdout, stderr, and exceptions |
| Mutation | Strong fingerprint equality | Private and public candidates unchanged across success and failure |
| Determinism | Double-run byte comparison | JSON, Markdown, order, counts, and hashes are byte-identical |
| CLI | Success/failure contract | Complete scan exits 0; unsafe/incomplete scan exits 1 with fixed safe error |
| Live | Bounded repository baseline | Real evidence matches current Git truth and preserves the PDF deletion |
