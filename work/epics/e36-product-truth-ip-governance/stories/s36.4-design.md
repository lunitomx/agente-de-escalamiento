# S36.4 Design: Typed Governance Taxonomy & Unique Epic IDs

## Artifact authority

The installed RaiSE CLI has no `artifact emit` command and no
`raise_artifact_emit` MCP tool is available. This versioned Markdown design is
therefore the canonical local artifact for this phase. It is also published
through the filesystem docs adapter; no remote docs target is configured.

## PRIME and complexity

The three mandatory PRIME queries returned no established design pattern, and
the branch code-context query returned no ranked symbols. Five bounded JIT
queries later returned general patterns about anchored section matching, YAML
null handling, and writer/validator integration, but no precedent for typed
epic identity migration.

This is a **complex** story despite its M estimate:

- it replaces one in-code semantic vocabulary with a strict external contract;
- it keeps two public validation entry points behaviorally compatible;
- it adds a second cross-record identity policy and resolver;
- it migrates ten colliding legacy epic directories and their live references;
- it must pass a real installed-tool graph build, not only unit tests; and
- it produces deterministic integration evidence without hiding legacy truth.

There is no user-facing workflow or prompt change, so the UX research gate is
not applicable. There is no new external service, database, or network
integration. The real graph-build scenario remains mandatory because the defect
exists at the repository/tool boundary.

## Problem

`validators/epic_closure.py` currently encodes closure semantics through literal
status strings and permissive substring normalization, while the same truth is
also expressed in Markdown. That duplication already caused ESCALA-001.

Separately, the installed RaiSE epic parser derives graph IDs only from each
directory's leading digits. The repository contains two `scope.md` files for
every bare ID E18 through E22, so normal builds silently keep the first path and
skip the second; strict builds fail on the first collision.

## Value

After S36.4, a closure posture has one typed semantic authority and the real
graph represents all ten legacy epics without first-path selection. Unknown,
missing, contradictory, and ambiguous inputs remain visibly unproved rather
than being promoted to complete.

## Gemba findings

### Closure contract

- `validators/epic_closure.py` owns `EpicClosureRule`, two rule tables, status
  extraction, and `_normalize_status()` substring precedence.
- Only `tests/test_epic_closure_governance.py` imports the two public validator
  functions. Their contract is `Path -> list[str]`; callers receive errors as
  values instead of exceptions.
- ESCALA-001 intentionally repaired exact status/evidence drift but deferred the
  single-source migration to E36.
- Current top-level epic scopes use eight observable postures: `active`,
  `complete`, `Deferred/Backlog`, `Superseded/Discarded`,
  `Deprecated/Discarded`, `Absorbed/Descoped`, the source string
  `CANCELLED — Absorbido por E11`, and two E18 scopes with no status line.
- E29's final closure audit and canonical tags prove both E18 scopes complete;
  their missing scope statuses can be migrated to explicit `Complete` without
  inferring completion from a folder name alone.

### Proven strict-model pattern

`validators/public_boundary.py`, `validators/exposure_inventory.py`, and
`validators/repository_truth.py` already use frozen Pydantic models with
`extra="forbid"`, literal schema versions, deterministic sorting, strict YAML
loading, normalized semantic hashes, and safe CLI boundaries. S36.4 reuses this
pattern rather than creating a new configuration framework.

### Graph identity

- The installed parser in `raise_cli/governance/parsers/epic.py` matches
  `^e(\d+)` on the parent directory and emits `epic-e{number}`. It does not read
  canonical epic IDs from YAML or Markdown frontmatter.
- The builder's normal mode warns and drops later duplicates; `--strict` raises
  immediately. S36.4 must not patch that installed package or filter warnings.
- Real baseline: `rai graph build --strict --no-diff` fails at `epic-e18` and
  normal mode reports exactly five E18-E22 duplicate-node warnings.
- A temporary archive probe renamed all ten folders to the mapping below. The
  real installed strict builder then passed with 37 epic concepts and no
  duplicate. The global RaiSE graph was immediately rebuilt from the untouched
  canonical worktree afterward, restoring the five truthful baseline warnings.
- IDs E1801–E2202 are unused in tracked project content before this story.

### Drift and schema

- `governance/drift-hotspots.json` and `governance/drift-catalog.md` are absent.
- AG2 risk exists if YAML and Python both encode disposition semantics; the
  design prevents that duplication.
- AG4 risk exists because migration touches policies, validators, tests, ten
  directories, and live references. Atomic mapping and a bounded resolver keep
  those edges explicit.
- `rai schema sum check` passes at schema version 32. No SQLite or storage schema
  migration is introduced.

## Approach

Create one strict governance-contract module that loads two versioned YAML
policies: closure dispositions and epic identities. The existing closure
facades consume those typed records while preserving their `list[str]` error
contract. Directory identity is made compatible with the actual installed
parser by atomically renumbering all ten colliding folders; bare E18–E22 remain
explicit ambiguous aliases rather than being assigned to whichever legacy epic
happens to sort first.

### Closure disposition matrix

The policy contains exact lowercase IDs and complete booleans. It has no
permissive aliases.

| ID | Terminal | Completed | Reviewable | Activation eligible | Meaning |
|---|:---:|:---:|:---:|:---:|---|
| `active` | no | no | yes | yes | Currently authorized work |
| `complete` | yes | yes | yes | no | Evidence-backed completion; normal gates still apply |
| `unresolved/review-required` | no | no | yes | no | Known record whose posture lacks sufficient proof |
| `deferred/backlog` | no | no | yes | no | Not active; requires a new explicit scope before activation |
| `cancelled/absorbed` | yes | no | no | no | Cancelled because another epic absorbed the work |
| `absorbed/descoped` | yes | no | no | no | Terminal non-complete record absorbed or removed from scope |
| `superseded/discarded` | yes | no | no | no | Terminal draft replaced by a trusted successor |
| `deprecated/discarded` | yes | no | no | no | Terminal draft that must not be revived as the same epic |

Policy validation enforces these cross-field invariants:

1. completed implies terminal and reviewable;
2. completed and activation-eligible cannot both be true;
3. activation-eligible implies non-terminal and reviewable;
4. every ID is unique, lowercase, path-safe, and exact;
5. YAML null, unknown fields, missing booleans, unsupported versions, and
   duplicate entries are invalid.

The Markdown extractor may strip surrounding quotes, normalize case, and
collapse whitespace. It may not match substrings, remove arbitrary suffixes, or
translate an unlisted label. E12's source string becomes the exact canonical
`Cancelled/Absorbed`; both E18 scopes become exact `Complete` using E29's audit
evidence.

Each identity entry contains its canonical ID, canonical folder, exact closure
disposition, and old folder-qualified alias. Root-level ambiguous aliases map
E18–E22 to their sorted two-candidate sets. Bare numeric resolution therefore
returns an explicit ambiguity; canonical IDs and old/new folder-qualified names
resolve uniquely.

Historical receipts such as the immutable S36.2 baseline retain their old path
observations. Executable validators, current indexes, and live links move to the
canonical paths. Historical evidence is not rewritten merely to make old paths
look current.

### Data mutation strategy

The identity migration is all-or-nothing in one green task commit:

1. add the validated identity policy and expected mapping;
2. `git mv` all ten directories to their canonical numeric prefixes;
3. update current executable paths and live indexes;
4. preserve historical evidence text as historical aliases;
5. run folder inventory and resolver tests; and
6. run the installed strict graph build.

Any missing source folder, occupied destination, unresolved live reference,
policy mismatch, or graph failure aborts the task. No partial success or silent
skip is accepted. Git provides the rollback boundary; no history rewrite or
remote mutation is involved.

### Existing public-function contract

This story replaces in-code semantic storage with YAML but preserves both
public facades:

```python
validate_audited_epic_closures(root: Path) -> list[str]
validate_backlog_draft_closures(root: Path) -> list[str]
```

- Before: missing scopes return error strings; unknown status returns an exact
  mismatch; policy corruption is impossible because semantics are compiled in.
- After: those behaviors remain. A missing, unreadable, or invalid policy adds
  one stable safe error and no scope can pass. The facades do not leak Pydantic,
  YAML, filesystem-root, or raw exception text.
- Low-level policy loaders may raise typed contract exceptions to callers that
  explicitly request parsing. The closure facades catch them at the safe
  boundary and remain list-returning.

Tests that construct temporary repositories must install the real canonical
policy fixture; this deliberately proves writer/validator integration instead
of relying on module-global semantics.

## Legacy sweep

- V1 `_normalize_status()` and its permissive substring precedence in
  `validators/epic_closure.py` are deleted. Exact extraction plus policy lookup
  replaces them.
- The two hard-coded rule tables may retain epic-specific paths and required
  evidence phrases, but their disposition strings are validated through the
  loaded policy and carry no independent semantics.
- `work/epics/legacy-disposition-index.md` remains as a human-readable derived
  index, explicitly subordinate to the two YAML policies.
- All ten old E18–E22 folder paths become aliases in the identity policy and are
  removed from the current filesystem through auditable `git mv` operations.
  No compatibility `scope.md` stubs remain at the old paths because the real
  graph parser would recreate the collisions.
- The installed RaiSE parser is not V1 owned by this repository and is not
  modified. Unique repository identities make its existing strict behavior
  correct.

## Resolution algorithm

```text
load_contract(closure_path, identity_path):
    parse both YAML documents with strict schema_version=1 models
    validate disposition semantic invariants
    validate unique canonical IDs and folder aliases
    require every identity disposition to exist in closure policy
    require each ambiguous alias candidate set to equal its referencing entries
    return immutable normalized contract

resolve_epic(reference):
    normalize only safe case and path separators
    if reference is a declared ambiguous alias:
        return AMBIGUOUS with sorted canonical candidates
    if reference matches exactly one canonical ID or folder alias:
        return RESOLVED with that identity
    return UNKNOWN

validate_identity_inventory(repo, contract):
    enumerate work/epics/*/scope.md paths
    require all ten policy folders exactly once
    reject an occupied old alias scope path
    derive numeric graph ID from each canonical folder
    reject duplicate derived graph IDs
    return deterministic receipt without absolute roots

validate_closure_scope(scope, expected, closure_policy):
    extract anchored status field
    resolve exact disposition through policy
    reject missing, unknown, or unexpected disposition
    apply epic-specific required evidence and open-item rules
    return safe errors as values
```

## Concrete examples

### Closure policy

```yaml
schema_version: 1
dispositions:
  - id: active
    terminal: false
    completed: false
    reviewable: true
    activation_eligible: true
  - id: complete
    terminal: true
    completed: true
    reviewable: true
    activation_eligible: false
  - id: deferred/backlog
    terminal: false
    completed: false
    reviewable: true
    activation_eligible: false
```

An unknown field or `completed: null` fails policy loading; it never receives a
default.

### Identity policy excerpt

```yaml
schema_version: 1
identities:
  - canonical_id: E2001
    folder: work/epics/e2001-contextual-skills
    closure_disposition: complete
    legacy_folder_aliases:
      - work/epics/e20-contextual-skills
  - canonical_id: E2002
    folder: work/epics/e2002-voice-of-customer-evidence-capture
    closure_disposition: superseded/discarded
    legacy_folder_aliases:
      - work/epics/e20-voice-of-customer-evidence-capture
ambiguous_aliases:
  - alias: E20
    canonical_ids: [E2001, E2002]
```

### Python resolution

```python
contract = load_governance_contract(
    Path("governance/closure-dispositions.yaml"),
    Path("governance/epic-identities.yaml"),
)

assert resolve_epic_identity(contract, "E2001").canonical_id == "E2001"
assert (
    resolve_epic_identity(contract, "work/epics/e20-contextual-skills")
    .canonical_id
    == "E2001"
)

ambiguous = resolve_epic_identity(contract, "E20")
assert ambiguous.code.value == "ambiguous"
assert ambiguous.candidates == ("E2001", "E2002")
```

### Safe local CLI

```bash
.venv/bin/python scripts/check_governance_contract.py \
  --repo . \
  --closure-policy governance/closure-dispositions.yaml \
  --identity-policy governance/epic-identities.yaml \
  --format text \
  --json-output /tmp/s36.4-governance.json \
  --markdown-output /tmp/s36.4-governance.md
```

Success prints only normalized counts, hashes, result, and canonical IDs. An
invalid contract exits 1 with the fixed message:

```text

```

It never prints a matched status line, absolute root, raw YAML error, or raw
graph subprocess output.

## Acceptance criteria

### MUST

1. One strict closure policy owns all disposition semantics; the closure
   validator has no substring normalization or competing semantic table.
2. Both public closure facades preserve their `Path -> list[str]` contract and
   fail safely on missing/corrupt policy, missing scope, unknown status, open
   done criteria, or missing required evidence.
3. The identity policy covers exactly the ten migrated E18–E22 folders, and
   canonical IDs, current folders, and resolvable aliases are unique.
4. Bare E18–E22 references resolve as explicit ambiguity with their exact two
   candidates; old/current folder-qualified references resolve uniquely.
5. The actual installed `rai graph build --strict --no-diff` exits 0 after the
   atomic migration and accounts for all ten canonical epic nodes.
6. Deterministic safe receipts prove policy hashes, ten-folder coverage, alias
   outcomes, source commit, and graph result without leaking absolute roots,
   raw errors, URLs, or private content.

### SHOULD

1. The legacy disposition index remains a concise rendered human view of the
   typed policy and canonical paths.
2. Error codes and ordering remain stable enough for S36.5 and S36.6 to consume
   without parsing prose.

### MUST NOT

1. Do not patch the installed RaiSE package, suppress duplicate warnings,
   retain old `scope.md` stubs, or silently drop one legacy epic.
2. Do not infer completion from tags, folder names, substring matches, plans,
   or retrospectives without the existing audit evidence and exact disposition.
3. Do not rewrite Git history, mutate a public candidate, publish/push, add a
   hosted runtime, or change SQLite/Drive/OneDrive boundaries.

## Decisions

### D1 — Policy IDs are data, not a duplicated Python enum

Disposition IDs remain strict validated strings in YAML. Python enums are used
only for result/status codes whose semantics are code-owned. This prevents a
second disposition list from recreating ESCALA-001.

### D2 — Renumber both members of every colliding pair

Keeping one bare E18–E22 as canonical would make the same historical reference
sometimes valid and sometimes ambiguous. Renumbering both members preserves
fail-closed truth: bare legacy numbers are always ambiguous, while new IDs are
always unique.

### D3 — Use folder-derived IDs because that is the real tool contract

Frontmatter-only IDs would pass repo unit tests yet leave `rai graph build`
broken. Canonical folder prefixes make the installed parser correct without an
external patch or a wrapper-only illusion.

### D4 — Preserve historical evidence, migrate operational references

Past receipts keep the paths they actually observed. Current validators and
indexes move to canonical paths. The alias registry bridges them without
rewriting history.

### D5 — Safe facades return errors; strict loaders raise

This preserves existing callers while giving new code a precise typed boundary.
No raw Pydantic/YAML/subprocess detail crosses the CLI or closure facade.
