# S36.1 Scope: Canonical Repository & Remote Truth

## In Scope

- Define a versioned repository-role policy with `origin` as the canonical
  private source and public distribution as a generated allowlisted artifact.
- Add a typed, deterministic, read-only repository-truth verifier and focused
  positive/negative tests.
- Ensure verifier output is sanitized: remote names, branch/upstream names,
  rule IDs, counts, and hashes are allowed; URLs and credential values are not.
- Remove the obsolete local `gitlab` remote after resolving its exact name and
  set local `main` to track `origin/main`.
- Record a redacted repository-truth receipt with source commit, policy hash,
  upstream, divergence counts, checks, and result.
- Verify the dirty public candidate repository is not changed or configured as
  an automatic synchronization target.
- Establish a safe local `main` upstream and record truthful divergence without
  pushing; the exact `0/0` equality proof remains an E36 epic-close criterion,
  where RaiSE performs remote integration.

## Out of Scope

- Force-push, rebase of shared history, destructive history rewrite, or deletion
  of any repository other than removal of the exact obsolete local remote entry.
- Publication or migration of a public repository or package.
- Modification, cleanup, reset, stash, or synchronization of the existing dirty
  public candidate repository.
- Removal or classification of the raw reference PDF and derived source-facing
  material; S36.2 and S36.3 own those concerns.
- Full content/history credential scanning and public export construction;
  S36.2 and S36.5 own those concerns.
- Runtime, database, ingestion, dashboard, meeting, installer, or cloud work.

## Done When

- [ ] The repository-role policy is strict, versioned, and describes one private
      canonical source plus a generated allowlisted public artifact.
- [ ] The verifier rejects wrong upstreams, disallowed remotes, divergence,
      malformed policy, and missing branch/remote state without mutating Git.
- [ ] Positive and negative tests prove no result or finding contains a remote
      URL or credential value.
- [ ] The obsolete `gitlab` remote is absent from local Git configuration and no
      unsafe URL is printed into evidence or committed content.
- [ ] Local `main` tracks `origin/main`; S36.1 records its truthful divergence
      and E36 retains the mandatory post-integration `0/0` proof before epic
      close.
- [ ] A deterministic JSON receipt and readable summary contain only sanitized
      fields and prove each repository-truth check.
- [ ] Read-only before/after fingerprints prove the dirty public candidate
      repository was not modified.
- [ ] The intentional PDF deletion remains unstaged and uncommitted by S36.1.
- [ ] Focused tests plus lint, format, and type gates pass before implementation
      commits; the full repository and architecture gates pass before local
      story merge.

## Acceptance Evidence

- Policy file and schema-validation tests.
- Repository-truth verifier tests with synthetic Git repositories/configuration.
- Redacted pre-remediation and post-local-repair receipts, plus the explicit E36
  post-integration `0/0` evidence contract.
- Sanitized branch/upstream/divergence output.
- Public-candidate before/after read-only fingerprint.
- Commit and gate receipts recorded in the story retrospective.

## Constraints

- Fail closed on unknown policy fields, unknown repository roles, missing
  upstreams, disallowed remotes, or command failures.
- Never log or serialize a remote URL, credential, token, username, or embedded
  authentication material.
- Use strict Pydantic models and full Python type annotations for new data
  structures.
- Git mutation is limited to the exact local remote/upstream repair described in
  this scope; the verifier itself remains read-only.
