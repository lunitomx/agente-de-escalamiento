# S36.3 Scope: Reference Removal & Public Vocabulary Boundary

## In Scope

- Commit the already intentional raw-reference deletion as its own auditable
  current-tree change, using the S36.2 receipt as before-state evidence.
- Define a strict, versioned, path-aware public-vocabulary policy that separates
  prohibited source/author/book/methodology attribution from generic business
  concepts that ESCALA may express in its own product language.
- Define explicit public-eligible, private/internal, derived-reference, and
  denied path classes; unknown or overlapping classification fails closed.
- Add typed validation and deterministic safe JSON/Markdown receipts for public
  vocabulary and path eligibility without serializing excerpts, absolute roots,
  secret values, URLs, or raw subprocess output.
- Neutralize prohibited attribution/source vocabulary in canonical files that
  are intended to become public-eligible, while preserving verified ESCALA
  capabilities and generic business meaning.
- Deny parsed workbooks, source personas, book-ingestion artifacts, private
  knowledge, company state, governance internals, and work evidence from future
  public distribution instead of treating their presence as permission.
- Prove the dirty existing public candidate is not modified and keep its known
  vocabulary findings explicitly unresolved/candidate-only.
- Produce a post-remediation delta against the immutable S36.2 baseline that
  distinguishes current-tree removal, retained private material, historical
  presence, candidate risk, and future-export eligibility.

## Out of Scope

- Rewrite, filter, purge, or garbage-collect Git history, refs, tags, branches,
  or remote objects.
- Modify, reset, clean, stash, merge, synchronize, publish, or otherwise repair
  the existing public-candidate repository.
- Delete useful private business knowledge merely because a legacy source term
  occurs; private retention and public eligibility are separate decisions.
- Build the final export allowlist, copy a staged artifact, select the software
  license, generate third-party notices, or publish a release; S36.5 owns those
  outcomes.
- Redesign product workflows, dashboards, coaching behavior, local databases,
  ingestion, OCR, financial analysis, or meeting automation.
- Add SaaS, hosted APIs, cloud databases, telemetry, or automatic Drive/OneDrive
  processing. Synced folders remain user-controlled local filesystem paths.
- Claim the existing public candidate or Git history is clean after only the
  private canonical current tree has been remediated.

## Done When

- [ ] The raw reference path is absent from the S36.3 canonical `HEAD`, its
      deletion is committed, and the receipt explicitly preserves historical
      truth without claiming a history rewrite.
- [ ] A strict typed public-vocabulary policy rejects unknown fields, unsafe or
      overlapping path classes, prohibited public terms, ambiguous eligibility,
      and implicit allow behavior.
- [ ] Positive and negative tests prove generic ESCALA business vocabulary is
      preserved while book, author, source-methodology, and attribution language
      fails on public-eligible fixtures.
- [ ] Derived reference, private company, governance, work-evidence, and raw
      source paths are explicitly denied from public eligibility.
- [ ] Real canonical paths intended for future public export have zero
      prohibited-vocabulary findings under the S36.3 policy, or remain blocked
      with an explicit owner and reason.
- [ ] Unknown tracked paths remain `not_eligible`; S36.3 does not manufacture a
      complete export allowlist ahead of S36.5.
- [ ] Strong before/after fingerprints prove the existing dirty public
      candidate was unchanged, and its legacy findings remain candidate-only.
- [ ] Deterministic sanitized JSON and Markdown delta receipts are committed
      with policy hash, verifier source commit, and S36.2 baseline linkage.
- [ ] Local-only/SQLite/Drive/OneDrive invariants remain unchanged.
- [ ] Focused per-task tests, lint, format, and type gates pass before commits;
      full repository and architecture gates pass before local story merge.

## Acceptance Evidence

- Git deletion commit and canonical-tree absence proof.
- Strict policy/schema and boundary-validator tests.
- Positive generic-language and negative prohibited-attribution fixtures.
- Current-tree public-eligible scan plus explicit blocked-path summary.
- S36.2-to-S36.3 deterministic delta receipt.
- Public-candidate strong before/after fingerprint comparison.
- Gate receipts and source commits recorded in the retrospective.

## Constraints

- Fail closed on missing policy, unsafe locator, unreadable required file,
  unknown path class, overlapping rule, ambiguous eligibility, scan failure, or
  public-candidate fingerprint mismatch.
- Do not serialize matched text, file contents, absolute roots, URLs, private
  filenames, secret values, or raw exception/subprocess payloads.
- Use strict Pydantic models and complete Python type annotations for new data
  structures.
- Keep all execution deterministic and local-only; no network is required for
  validation.
- Preserve S36.2 evidence unchanged as the authoritative before baseline.
- Treat plans, term searches, and path names as leads until typed current-state
  evidence proves the final classification.
