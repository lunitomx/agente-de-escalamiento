# S36.2 Plan: IP, Secret & Reference Exposure Inventory

## Overview

Implement the design in four risk-ordered TDD tasks, with one commit per task.
The first three commits establish the strict contract, real Git scanner, and
safe CLI. The fourth is the mandatory manual integration task that records the
sanitized baseline from the real private repository and dirty public candidate.

No comparable completed M-story calibration is available. S36.1 is an observed
S story at 44m 06s and is not used to invent a duration for this larger scope.
Actual start/completion times will be recorded per task.

## Dependency Graph

```text
T1 Policy + safe typed contract
  └──► T2 Bounded Git surfaces + non-mutation
          └──► T3 Deterministic CLI + serialized security boundary
                  └──► T4 Live private/public baseline + evidence
```

The sequence is acyclic. T1 and T2 deliberately place the highest-risk model
and raw-data boundaries before the CLI can print or write anything. T4 cannot
start until every serialized surface has sentinel coverage.

## T1 — Exposure Policy and Safe Typed Contract

**Size:** M

**Depends on:** None

**Commit intent:** `feat(s36.2): add exposure inventory contract`

### Description

Define the strict versioned policy, frozen Pydantic models, stable enums,
policy hash, safe locator rules, deterministic finding order, severity summary,
and distribution aggregate. Findings and summaries are serializable; match
objects, file bytes, URLs, exceptions, and repository roots are not model
fields.

### Files

- Create `governance/exposure-policy.yaml`.
- Create `validators/exposure_inventory.py`.
- Create `tests/test_exposure_inventory.py`.

### Policy Contract

- Fixed schema version and exact bounded surfaces.
- Explicit reference/public-vocabulary rules with stable IDs and dispositions.
- High-confidence secret-shape rule IDs; heuristics never claim liveness.
- Safe internal control paths that remain private and are never public-eligible.
- Text/binary and maximum-size handling: path-level classification remains
  possible without reading a raw reference or oversized/binary payload.
- Default distribution state `not_eligible` and generated staging `not_built`.
- Unknown keys, enums, rule IDs, duplicate IDs, unsafe relative paths,
  incoherent severity/disposition pairs, and invalid limits fail closed.

### TDD Cycle

**RED**

1. Add strict-policy tests importing `validators.exposure_inventory`; require
   the focused gate to fail because the module and models do not exist.
2. Add negative fixtures for unknown keys/enums, duplicate rule IDs, unsafe
   relative paths, zero/oversized limits, and contradictory dispositions.
3. Add safe-model tests proving raw content, URLs, roots, and exception payload
   fields are rejected as extra data.

**GREEN**

1. Add the minimum strict enums/models and YAML loader required by the tests.
2. Normalize policy semantics and produce a stable SHA-256.
3. Validate path locators as normalized repository-relative POSIX paths; reject
   absolute, parent-traversal, NUL, control-character, and ambiguous paths.
4. Validate sensitive locators as SHA-256 only.
5. Sort findings by surface, classification, rule ID, and locator.

**REFACTOR**

Keep validation in model boundaries and keep the future scanner free of
duplicate string vocabularies. Do not add generalized plugin, rule-engine, or
storage abstractions.

- Scope Done 1: strict policy.
- Story scenario: distribution eligibility fails closed.
- Design D1, D3, D5, and D6.

## T2 — Bounded Git Surfaces and Non-Mutation

**Size:** M

**Depends on:** T1

**Commit intent:** `feat(s36.2): inventory bounded repository surfaces`

### Description

Implement the local scanner over a real Git repository. Worktree, canonical
`HEAD`, history path metadata, local remote configuration, distribution
aggregate, and public-candidate `HEAD` are observed separately. Reuse
`fingerprint_repository()` before and after each repository and use the same
`GIT_*` isolation semantics for exposure-specific read-only probes.

### Files

- Modify `validators/exposure_inventory.py`.
- Modify `tests/test_exposure_inventory.py`.
- Reuse `validators/repository_truth.py` without changing its S36.1 contract.

### TDD Cycle

**RED**

Create real temporary repositories that include:

1. a raw reference committed in `HEAD` but deliberately deleted only from the
   worktree;
2. a reference path committed and later removed, so it is history-only;
3. a tracked text fixture with a sentinel secret-shaped value;
4. an authenticated remote with a sentinel credential value;
5. an unclassified tracked-path set with a known count and newline-joined SHA;
6. a dirty public candidate containing unrelated untracked sentinel content;
7. injected `GIT_DIR`, `GIT_WORK_TREE`, and `GIT_CONFIG_*` environment values.

Require focused failures because scan APIs do not exist.

**GREEN**

1. Enumerate `HEAD` paths and tracked worktree paths deterministically using a
   closed read-only Git command set.
2. Observe tracked-path existence without following symlinks.
3. Read safe bounded text only; classify binary, symlink, non-UTF-8, and
   over-limit entries path-only as not eligible and explicitly unscanned.
4. Inspect historical path metadata without historical blob contents or commit
   messages.
5. Inspect remote URL values only in memory and emit validated remote names and
   risk booleans.
6. Hash sensitive locators before model construction.
7. Inspect public-candidate canonical `HEAD`, never its untracked/dirty content.
8. Require strong before/after fingerprint equality for both repositories.
9. Return `scan_status=incomplete` for a missing root, malformed Git response,
   unsafe locator, unreadable required surface, or fingerprint mismatch.

**REFACTOR**

Centralize sorting, hashing, bounded decoding, and safe Git calls inside the
domain module. Raw command results remain private and never appear in return
models or raised public exceptions.

### Acceptance References

- Story scenarios: current/history distinction, sensitive locator boundary,
  read-only public candidate, and fail-closed distribution.
- Scope Done 2, 4, 5, 6, and 7.
- Design D2, D3, D4, and D5.

### Verification

- `rai gate check gate-tests --scope tests/test_exposure_inventory.py`
- `rai gate check gate-lint`
- `rai gate check gate-format`
- `rai gate check gate-types`
- `git diff --check`
- Inspect staged names and prove the PDF deletion is absent.

### Exit Evidence

- Real Git surface-distinction tests pass.
- Sentinel URL/value/absolute-root assertions pass for typed results and repr.
- Same-shape dirty content plus config/index/ref mutations change fingerprints.
- Scanner leaves config, index, refs, worktree, and dirty public content intact.

## T3 — Deterministic CLI and Serialized Security Boundary

**Size:** S

**Depends on:** T2

**Commit intent:** `feat(s36.2): add sanitized exposure inventory CLI`

### Description

Add deterministic JSON and Markdown renderers, explicit receipt writers, and a
thin CLI. A complete scan exits 0 even when findings exist; an incomplete or
unsafe scan exits 1. The exception boundary prints one fixed sentence and never
echoes arguments, roots, URLs, Git output, or exception text.

### Files

- Modify `validators/exposure_inventory.py`.
- Create `scripts/check_exposure_inventory.py`.
- Modify `tests/test_exposure_inventory.py`.

### TDD Cycle

**RED**

1. Add renderer double-run tests for byte-identical JSON and Markdown.
2. Add CLI success tests with risk findings and exit 0.
3. Add CLI incomplete/failure tests with exit 1 and one fixed safe error.
4. Assert the sentinel secret, authenticated URL, repository roots, dirty
   filenames, raw Git stderr, and exception payload are absent from stdout,
   stderr, repr, JSON, Markdown, and written evidence.
5. Assert only explicitly requested output paths are written.

**GREEN**

1. Render sorted model dumps with stable newline behavior.
2. Render a concise Markdown surface/risk/disposition summary with no excerpts.
3. Write receipts only after a complete typed result exists.
4. Keep parsing and exception handling in the CLI; keep policy and scanning in
   the validator module.
5. Return 0 for complete observation and 1 for incomplete/unsafe observation.

**REFACTOR**

Remove any duplicate output vocabulary and keep all renderers model-only. Do
not add logging, telemetry, network access, or a generic reporting framework.

### Acceptance References

- Story scenario: sensitive findings contain locators, never values.
- Scope Done 3 and 8.
- Design runnable success and failure examples.

### Verification

- `rai gate check gate-tests --scope tests/test_exposure_inventory.py`
- `rai gate check gate-lint`
- `rai gate check gate-format`
- `rai gate check gate-types`
- `git diff --check`
- Inspect staged names and prove the PDF deletion is absent.

### Exit Evidence

- CLI tests prove complete-with-findings is success.
- Failure boundary is fixed, non-reflective, and credential-safe.
- Repeat CLI runs produce byte-identical receipts.
- No output file is created on unsafe pre-model failure.

## T4 — Live Private/Public Baseline and Evidence

**Size:** S

**Depends on:** T3

**Commit intent:** `chore(s36.2): record exposure inventory baseline`

### Description

Run the finished CLI against the actual private repository and explicitly
resolved dirty public candidate. This is the mandatory manual integration test.
Record the sanitized baseline and prove the scan changed neither repository.
Do not remediate findings in this task.

### Files and Local State

- Create sanitized evidence only under
  `work/epics/e36-product-truth-ip-governance/stories/s36.2-evidence/`.
- Create/update `stories/s36.2-progress.md` with task commits and gate evidence.
- Do not write inside the public candidate.
- Preserve the raw PDF deletion outside staging and every task commit.

### Integration Cycle

**RED / Preconditions**

1. Confirm no S36.2 live baseline exists yet.
2. Confirm the raw PDF is the only unrelated private working-tree change.
3. Resolve the public-candidate root without serializing its absolute path.
4. Capture strong before fingerprints for both repositories.

**GREEN / Live observation**

1. Run the CLI with explicit private/public roots and policy, writing only the
   approved evidence paths.
2. Require `scan_status=complete`; findings and non-zero risk counts are expected
   and do not fail the inventory.
3. Require the raw asset to be absent on `worktree`, present on `git_head`, and
   present in `git_history`, without reading its binary content.
4. Require distribution default `not_eligible` and generated staging
   `not_built`.
5. Require no authenticated local-remote finding. If one appears, stop as a
   critical credential boundary without printing or committing its value.
6. Capture after fingerprints and require exact equality with before values.

**REFACTOR / Evidence minimization**

Keep only typed JSON/Markdown receipts, stable hashes, safe paths for reference
remediation, counts, classifications, dispositions, source commit, and policy
hash. Remove absolute roots, command transcripts, excerpts, URLs, values, and
temporary outputs.

## Execution Rules

1. One task, one commit; no partial task commit.
2. Record the focused RED failure before implementing GREEN.
3. Stage exact task paths only; never use broad adds.
4. Inspect the cached name list before every commit.
5. The raw PDF deletion must remain unstaged and uncommitted through S36.2.
6. No write, cleanup, reset, stash, branch operation, or command execution is
   allowed inside the public-candidate repository beyond read-only probes.
7. A credential-risk finding in live local configuration is a critical stop;
   a heuristic tracked-file finding is evidence, not proof of a live secret.

## Risks and Mitigations

| Risk | Mitigation |
|---|---|
| Matched secret or URL leaks through error/output | Raw values remain outside Pydantic models; sentinel matrix covers every serializable and CLI surface |
| Worktree absence is mistaken for canonical deletion | Separate worktree, `HEAD`, and history findings with independent assertions |
| Public candidate dirty content is consumed or changed | Scan canonical `HEAD` only; before/after strong fingerprint equality |
| Binary/oversized file creates false clean claim | Path-only `not_eligible` plus explicit unscanned classification; no public admission |
| Symlink escapes repository boundary | Never follow worktree symlinks; validate Git paths before filesystem access |
| Regex or full-history scan becomes expensive | Policy-bounded text sizes; historical path metadata only; no historical blob scan |
| Test fixtures create live baseline noise | Classify findings and disposition honestly; never suppress solely because a path is a test |
| Evidence commit includes raw PDF | Exact staging plus cached-name inspection before every commit |
| Planning gate appears green without registry support | Installed registry has no `gate-plan`; validate structure manually and record the tooling gap |

## Definition of Implementation Complete

- T1-T4 each have a RED/GREEN or live-integration record and scoped commit.
- Strict policy, typed models, scanner, CLI, and focused gates pass.
- Complete scans may contain risk findings but cannot contain sensitive values.
- Both real repositories have identical before/after strong fingerprints.
- The baseline distinguishes worktree, `HEAD`, history, config, distribution,
  public candidate, and generated-staging state.
- The raw PDF deletion remains outside every S36.2 commit.
- No network, hosted runtime, cloud store, new dependency, remediation, history
  rewrite, or public-candidate mutation occurs.
