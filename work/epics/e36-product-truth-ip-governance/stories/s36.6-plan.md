# S36.6 Plan: Master Acceptance Ledger

## Overview

- **Story:** S36.6 — Master Acceptance Ledger
- **Size:** S in epic scope; complex evidence-control design
- **Execution model:** four sequential TDD commits
- **Estimated implementation:** 75 minutes
- **Primary risk:** a structurally valid ledger being misreported as completed
  product, or copied policy vocabulary drifting from canonical authorities
- **Required live outcome:** contract PASS, mission UNPROVED, 0/42 proved,
  readiness exit 2, deterministic receipts, no external mutation

The estimate is calibrated against completed E36 governance work: S36.1 took
44m06s and S36.4 took 1h05m33s, while the larger S36.5 integration took
1h21m21s. S36.6 reuses their strict-policy and receipt patterns but must encode
42 records and a real two-commit baseline. Actual duration will replace the
estimate; it will not be forced to fit the range.

## Execution Order and Dependencies

```text
T1 strict types/authorities
  └──► T2 canonical ledger/render
         └──► T3 evidence evaluator/CLI
                └──► T4 immutable live baseline
```

The graph is intentionally sequential and acyclic:

- T2 requires T1 to reject a malformed canonical ledger rather than encoding
  data before the contract exists.
- T3 requires the exact committed ledger shape and renderer.
- T4 must bind to the immutable commit containing T1-T3 and therefore cannot
  run in parallel.

No subagent or parallel edit is useful inside this four-file core; parallel
implementation would increase authority/renderer drift and commit ambiguity.

## Gate Policy

| When | Command | Scope |
|------|---------|-------|
| Per task | `rai gate check gate-tests --scope <test_dir>/` | Only tests for the changed module (e.g. `packages/raise-cli/tests/storage/`) |
| Per task | `rai gate check gate-lint` | Full project (fast) |
| Per task | `rai gate check gate-format` | Full project (fast) |
| Per task | `rai gate check gate-types` | Full project |
| End of story | `rai gate check gate-tests --scope packages/<pkg>/` | Changed package only — NOT full suite |
| MR creation | `/rai-mr-create` | Full suite — the ONLY place where unscoped tests run |

Project instantiation: tests are in the root `tests/` package, not under
`packages/<pkg>/`, so every task uses the exact concrete scopes shown above.
The installed RaiSE CLI supports `--scope`. Commands are executed through
`.venv/bin/rai gate check`; pytest/Ruff/Pyright are never invoked directly.
The later `/rai-story-close` lifecycle still owns the mandatory full gate set
and architecture-review marker before local merge; no MR or remote push is
planned for this story.

## Risks and Mitigations

| Risk | Failure mode | Mitigation / promotion condition |
|---|---|---|
| False green | Contract PASS is shown as mission complete | Separate enums, counts, output labels, and exit codes; exact 0/42 live assertion |
| Authority clone | Local-only/legal rules drift inside ledger | Import current loaders/hashes and cross-validate semantics |
| Arbitrary command | YAML verification string becomes executable | Store strict argv data; validator never executes it |
| Self-reference | Receipt claims a commit that does not contain its ledger/verifier | Commit T1-T3 first; generate T4 evidence from that full commit |
| Incomplete inventory | One product-owner outcome disappears | Exact 42 count, contiguous IDs, source coverage, fixed per-epic counts |
| Roadmap contamination | Historical `DONE` becomes proof | Negative test and explicit non-authoritative source classification |
| Unsafe evidence | Paths, source text, company data, URLs, or raw errors leak | Bounded typed fields, safe failure, forbidden sentinel/absolute-path tests |
| Scope drift | S36.6 starts implementing ingestion/cash/meetings/installers | Component allowlist and review of task-owned files before each commit |
| Live defect | Fixture passes but canonical ledger/renderer/CLI fails | T4 real double-run; focused RED + new commit + complete rerun |
