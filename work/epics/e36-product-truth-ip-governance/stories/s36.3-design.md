# S36.3 Design: Reference Removal & Public Vocabulary Boundary

## Problem

The raw reference is absent only from the worktree, while canonical `HEAD`
still tracks it. At the same time, product-facing source trees, identifiers,
filenames, prompts, dashboards, and knowledge metadata disclose the legacy
book/author/methodology source. Prior E11 completion claims are not current
proof: the bounded public candidate still has 50 canonical vocabulary findings
and 17 unrelated dirty entries.

## Value

S36.3 makes the private canonical current tree and the future public boundary
truthful. The raw asset receives an auditable deletion; public-eligible product
source becomes source-neutral; useful private knowledge remains local and
explicitly non-distributable; and S36.5 receives an executable deny-first
contract rather than prose or a broad text-replacement claim.

## Complexity Assessment

**Complex.** The story touches policy, typed validation, a safe CLI, a real Git
deletion, public-facing content, ontology identifiers, a handler/persona,
dashboards, tests, and live private/public-candidate evidence. It has no hosted
integration, schema migration, or new external dependency, but it has high
semantic fan-out and IP/false-claim risk.

Risk gates:

- **IP/publication risk — high:** an incomplete rule could admit a raw or
  derived source into a future export.
- **Semantic-regression risk — high:** mechanical deletion could remove useful
  cash, people, strategy, or execution behavior.
- **Migration risk — high:** legacy ontology IDs, filenames, and the named board
  handler have tracked consumers that must move atomically.
- **Mutation risk — high:** the existing public candidate is dirty and may only
  be observed through `HEAD` plus strong before/after fingerprints.
- **False-closure risk — high:** private current-tree remediation does not clean
  Git history or the already-public candidate.
- **UX gate:** no new interaction or workflow is being designed. User intent is
  explicit: preserve capability while removing source attribution. Existing
  golden cases and handler tests provide the interaction-regression gate, so a
  separate research cycle would not reduce the design uncertainty.
- **Integration gate:** the final task must use the actual private repository,
  actual immutable S36.2 baseline, and actual dirty public candidate. Fixture-
  only proof is insufficient.

## Legacy Sweep

- **S36.2 inventory remains active.** It is the immutable before receipt and is
  linked by hash; it is not superseded.
- **The public-attribution V1 guardrail is superseded.** The rule that recommends
  naming the legacy author/book is replaced by an executable no-public-source
  boundary. Keeping both would be contradictory.
- **The named handler/persona and source-specific execution identifiers are
  replaced atomically.** Old files, classes, IDs, paths, imports, registry
  entries, and tracked tests are deleted or renamed in one migration; no public
  compatibility shim remains.
- **The E11 in-place public repository workflow is legacy evidence.** The dirty
  repository remains read-only and candidate-only. S36.5 will generate a clean
  artifact from the private canonical source instead of mirroring it.
- **`escala-agent/` coexists only as denied private legacy material.** It is not
  a public source root and must never be inferred into the future allowlist.
- **`validators/export.py` coexists** because it validates private coaching
  action-plan structure, not software distribution.

## Drift Risk Review

No drift-hotspot file or catalog is present.

- **AG4 context fan-out:** real. A terminology/ID migration crosses more than
  three modules. Mitigation: one versioned migration matrix, exact call-site
  sweep, focused integrity tests, and separate task commits by boundary.
- **AG2 clone amplification:** avoid a second Git fingerprint or unsafe Git
  runner; reuse `fingerprint_repository()` and the S36.1/S36.2 safe subprocess
  boundary.
- **Clone risk in content:** avoid hand-editing 75 files without a deterministic
  check. The validator, not a one-time replacement script, is the lasting owner
  of the public rule.
- **Artifact-volume risk:** reuse S36.2's pattern: detailed machine data and a
  grouped human summary with a measured size check.

## Approach

Create a deny-first, path-aware public-boundary policy and validator. The policy
defines a **public canary** of source roots that are candidates for a future
export, explicit denied/private roots, prohibited path/text tokens, and
forbidden YAML provenance keys. A passing canary proves vocabulary readiness of
those source paths; it does not manufacture S36.5's final allowlist or release
readiness.

The story then performs two bounded remediations:

1. commit the already-intentional raw-asset deletion while retaining historical
   truth; and
2. neutralize source-specific names/content on the canary surface, including an
   atomic rename of tracked IDs and the named board handler, while leaving
   denied private/reference material available only inside the private repo.

### Path classification

Every tracked path resolves deterministically to one disposition:

```text
explicit denied rule  -> denied
public-canary rule     -> candidate_public
no matching rule       -> not_eligible
unsafe/ambiguous rule  -> incomplete
```

Explicit deny rules have declared precedence over a broad canary root. Overlap
between two public rules, two deny rules with conflicting owners, or any rule
without deterministic precedence is rejected at policy load. `not_eligible`
never means safe or public.

Initial public-canary families:

- root operator/product entry docs and local install/update scripts;
- `coaching/**`;
- `conocimiento/**` after public provenance removal;
- `escala-skills/**`;
- reusable `validators/**` needed by the portable product;
- source-neutral `escala_server/**` runtime/dashboard files;
- source-neutral reusable `templates/**`.

Initial denied families include:

- the raw asset and parsed/OCR/reference dumps;
- `.raise/**`, `work/**`, `governance/**`, and private company state;
- `.agents/**`, `.claude/**`, and `.scaleup/**` internal development copies;
- `metodologias_parsed/**`, `miembro-board/**`, source-ingestion outputs, and
  `escala_server/data/**` derived book data;
- `escala-agent/**` legacy package and internal tests/evidence;
- the legacy attribution file until S36.5 supplies legally reviewed notices.

S36.5 may choose a subset of the canary, but it may never override a denial
without a later versioned policy change and tests.

### Public vocabulary contract

Public-canary path names and bounded UTF-8 text reject case/format variants of:

- the legacy book/framework title as a proper-name token (`Scaling Up`,
  `ScaleUp`, `scaling_up`, and command/path forms that identify the legacy
  product rather than the ordinary lower-case verb “scale up”);
- the named author and former company name;
- the source-specific execution-habits name and identifiers;
- the named board persona, handler, and template identifiers;
- raw/parsed source filenames and explicit “derived from/inspired by” source
  attribution phrases.

Generic domain language remains valid: cash, strategy, people, execution,
meeting rhythm, priorities, accountability, core customer, working capital,
scorecards, and other independently expressed business concepts.

For `conocimiento/**/*.yaml`, the public canary additionally rejects a root
`source:` key. The business node, relationships, tags, fields, and operational
guidance remain; raw filenames, chapters, page/line numbers, and workbook
locations are removed from the public copy.

### Atomic semantic renames

The migration matrix is source-controlled in the design and implemented with a
complete caller sweep:

| Legacy public name | Source-neutral replacement |
|---|---|
| execution tool/worksheet path containing the source surname | `execution-habits.yaml` |
| `tool-rockefeller-habits` | `tool-execution-habits` |
| `worksheet-rockefeller-habits` | `worksheet-execution-habits` |
| named coaching-template path | `advisor-templates.yaml` |
| `VerneHandler` / named handler module | `BusinessAdvisorHandler` / `business_advisor.py` |
| named execution dashboard path | `execution-habits.html` |
| named checklist template path | `execution-habits-checklist.md` |

All tracked imports, graph relationships, registry entries, dashboard mappings,
CLI/server bindings, tests, and examples move in the same task. There is no
storage migration: the knowledge graph is reconstructed from tracked YAML at
load time. Missing identifiers continue to return the existing empty/`None`
behavior; tracked callers are migrated so no silent missing-ID path remains.

### Non-mutation and truth boundary

- The private repository may change only through reviewed S36.3 commits.
- The public candidate is scanned at canonical `HEAD`; dirty/untracked content
  is never read for classification.
- `fingerprint_repository()` must match before and after public-candidate
  inspection across HEAD, branch, status, worktree bytes, config, index, and
  refs.
- The receipt keeps three independent states: private canonical current tree,
  private reachable history, and existing public candidate.
- A passing private canary cannot set `public_candidate_clean=true` or
  `release_ready=true`. Those fields do not exist in the S36.3 model.

## Design Decisions

### D1 — Canary is not an allowlist

S36.3 proves which source families are vocabulary-ready and which are denied.
Only S36.5 may create the complete export manifest, copy a staged artifact, and
claim artifact-level validation.

### D2 — Preserve domain value; remove public provenance

Useful operational knowledge remains. Public `source:` metadata, named
attribution, raw-source locators, and persona simulation are not required for
cash/people/strategy/execution guidance and are removed or kept only in denied
private roots.

### D3 — Rename semantics atomically; no leaking aliases

Compatibility aliases using legacy public names would violate the boundary.
All tracked callers migrate in one task, and graph integrity tests prove no
orphan references. Untracked external state is not silently rewritten.

### D4 — Deny wins, unknown stays closed

An explicit deny cannot be promoted by a broad canary match. An unmatched path
remains `not_eligible`; no heuristic or successful term scan can make it public.

### D5 — Reuse strong fingerprints

S36.3 reuses S36.1's reviewed repository fingerprint and S36.2's immutable
baseline. It does not fork Git-state truth or rescan historical blob content.

### D6 — Safe models are the only output boundary

Receipts contain rule IDs, safe relative locators, counts, hashes,
classifications, source commits, and before/after fingerprints. They never
contain matched text, excerpts, absolute roots, URLs, raw errors, private
filenames, or file contents.

### D7 — No new dependency

Pydantic, PyYAML, Git, and the standard library cover the contract. Supply-chain
review is therefore not applicable.

## Data Contract

Key enums:

```python
class PublicPathDisposition(str, Enum):
    CANDIDATE_PUBLIC = "candidate_public"
    DENIED = "denied"
    NOT_ELIGIBLE = "not_eligible"

class BoundaryStatus(str, Enum):
    PASS = "pass"
    FAIL = "fail"
    INCOMPLETE = "incomplete"

class BoundaryFindingCode(str, Enum):
    PROHIBITED_PATH = "prohibited_path"
    PROHIBITED_TEXT = "prohibited_text"
    PROHIBITED_YAML_KEY = "prohibited_yaml_key"
    RAW_ASSET_TRACKED = "raw_asset_tracked"
    UNSAFE_OR_UNREADABLE = "unsafe_or_unreadable"
    BASELINE_MISMATCH = "baseline_mismatch"
    FINGERPRINT_MISMATCH = "fingerprint_mismatch"
```

A serialized finding contains only:

```json
{
  "rule_id": "public.source_attribution",
  "code": "prohibited_text",
  "surface": "private_head",
  "locator_kind": "relative_path",
  "locator": "escala-skills/escala-welcome/SKILL.md"
}
```

The receipt includes:

- policy SHA-256 and verifier source commit;
- S36.2 baseline file SHA-256, policy hash, and verifier commit;
- raw-asset current/history truth;
- candidate-public, denied, and not-eligible counts/set hashes;
- finding counts grouped by rule/surface/code;
- private and public-candidate strong before/after fingerprints;
- public-candidate legacy finding count as unresolved candidate evidence;
- no `release_ready`, `history_clean`, or `public_candidate_clean` field.

## Processing Flow

```text
load strict S36.3 policy
  -> validate immutable S36.2 baseline hash and typed link
  -> fingerprint private repo and dirty public candidate
  -> enumerate canonical tracked paths deterministically
  -> classify each path: denied / candidate_public / not_eligible
  -> require raw asset absent from private HEAD; observe history metadata
  -> scan candidate-public path names and bounded worktree/HEAD text
  -> reject forbidden YAML provenance keys
  -> inspect public-candidate HEAD for unresolved legacy findings
  -> validate ontology/handler migration integrity
  -> fingerprint both repositories again
  -> require public candidate unchanged and private scan non-mutating
  -> build frozen receipt and render deterministic JSON/Markdown
```

Missing or unsafe inputs fail closed. A denied path may exist privately without
failing the canary; a denied path copied into a future staged artifact will fail
S36.5.

## Runnable Examples

### Complete source-boundary check

```bash
python scripts/check_public_boundary.py \
  --repo . \
  --public-candidate ../agente-de-escalamiento \
  --policy governance/public-boundary.yaml \
  --baseline work/epics/e36-product-truth-ip-governance/stories/s36.2-evidence/baseline.json \
  --format json \
  --json-output /tmp/s36.3-boundary.json \
  --markdown-output /tmp/s36.3-boundary.md
```

Expected exit is `0` only when the raw asset is absent from private `HEAD`, all
candidate-public source is source-neutral, the baseline link is exact, every
required item is readable, and both scans are non-mutating. Known findings in
the read-only public candidate remain reported but do not pretend that S36.3
changed that repository.

Example safe summary:

```json
{
  "baseline_sha256": "3ae688c34b8cb13dcf96bd72198aeee6e4eace0a432b413cc654d1c279943dce",
  "current_tree_raw_asset": "absent",
  "historical_raw_asset": "present",
  "private_boundary_status": "pass",
  "public_candidate_status": "legacy_findings_unresolved"
}
```

The typed S36.3 model intentionally omits a `release_ready` field so callers
cannot infer a release decision from source-boundary evidence.

### Prohibited public source

For a temporary public-canary file containing a prohibited author/source term,
the CLI exits `1`, writes no receipts, and prints only:

```text
public boundary: unable to produce a safe passing receipt
```

No matched term, path, root, exception, or Git output is echoed.

### Generic ESCALA business language

```yaml
id: concept-working-capital
type: concept
name_es: Capital de trabajo
summary: >
  Mide el efectivo atrapado entre pago a proveedores, entrega y cobro.
```

This is valid candidate-public content: it contains domain intelligence without
source attribution or private provenance.

### Denied private provenance

```text
metodologias_parsed/cash_workbook.txt -> denied
work/epics/e36-product-truth-ip-governance/scope.md -> denied
new/unclassified.txt -> not_eligible
```

Neither `denied` nor `not_eligible` can be serialized as public permission.

## Testing Strategy

| Layer | Scenario | Purpose |
|---|---|---|
| Policy | Unknown keys, duplicate rules, unsafe globs, ambiguous overlap, missing deny classes | Prove strict fail-closed schema |
| Classification | Deny precedence, canary paths, unknown paths, path variants | Prove no implicit allow |
| Content | Prohibited path/text/YAML key plus generic business fixtures | Remove attribution without deleting domain value |
| Serialization | Sentinel matched values, roots, URLs, exceptions, JSON/Markdown/CLI/file outputs | Prove safe boundary |
| Git | Raw asset absent in `HEAD` but historical; malformed/missing repo cases | Preserve current/history truth |
| Migration | New IDs/filenames/handler with complete caller and graph-reference integrity | Prevent half-migration/orphans |
| Regression | Existing focused handler, knowledge API, diagnosis, server, and skill golden cases | Preserve verified behavior |
| Integration | Real private repo + immutable S36.2 baseline + dirty public candidate | Prove live boundary and non-mutation |

## Acceptance Criteria Mapping

### MUST

1. Story scenario “raw source leaves canonical current tree” passes with an
   auditable deletion and explicit historical-presence receipt.
2. Story scenarios “public product vocabulary” and “private derived material”
   pass for path, text, YAML provenance, and generic-domain fixtures.
3. Every tracked caller in the semantic rename matrix migrates atomically and
   graph/handler/golden regression tests pass.
4. The real private canary has zero prohibited findings or an explicit denied
   disposition; unknown paths remain not eligible.
5. The real public candidate fingerprint is identical before/after and its
   known legacy findings remain unresolved/candidate-only.
6. The committed delta is deterministic, sanitized, linked to the immutable
   S36.2 baseline, policy hash, and verifier source commit.

### SHOULD

1. Human Markdown remains grouped and bounded while machine JSON retains
   actionable safe locators.
2. Migration receipts list counts and hashes sufficient for S36.5 without
   carrying excerpts or source values.

### MUST NOT

1. No history rewrite, public-candidate mutation, remote operation, publication,
   hosted runtime, cloud database, telemetry, or automatic sync is introduced.
2. No passing receipt claims Git history, the existing public candidate, or a
   future artifact is clean.
3. No public compatibility alias, filename, class, ID, attribution, YAML
   provenance key, or output may preserve the prohibited source identity.
4. No useful business concept is removed solely because it once carried private
   provenance; it is rewritten source-neutrally or kept in a denied private
   path.

## Open Questions

notices remain explicitly delegated to S36.5; S36.3 does not invent legal
conclusions.
