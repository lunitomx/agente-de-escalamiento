# Story: IP, Secret & Reference Exposure Inventory

## User Story

As the ESCALA product owner and release operator,
I want a deterministic, risk-classified inventory of intellectual-property,
reference, secret, private-data, and distribution exposures,
so that remediation and clean export are driven by verified evidence without
leaking sensitive values or rewriting history.

## Acceptance Criteria

### Scenario: Current state and history are not conflated

```gherkin
Given a prohibited raw reference is tracked in `HEAD` but intentionally absent
from the working tree
When the exposure inventory runs
Then the finding identifies the worktree, `HEAD`, and history surfaces
independently
And current absence is not described as historical removal
And historical presence is not described as public-export eligibility
```

### Scenario: Sensitive findings contain locators, never values

```gherkin
Given a file or local Git configuration contains a secret-shaped value or an
authenticated remote
When the exposure inventory runs
Then the finding contains a stable rule ID, surface, classification, and safe
locator
And no credential, secret value, remote URL, or subprocess payload is emitted
And the scanner does not mutate the repository or Git configuration
```

### Scenario: Public candidate is inspected read-only

```gherkin
Given the existing public-candidate repository has unrelated dirty work
When its eligible exposure surfaces are inventoried
Then before and after strong fingerprints are identical
And no file, config, index, ref, branch, or remote is changed
And the result distinguishes candidate state from generated export state
```

### Scenario: Distribution eligibility fails closed

```gherkin
Given a tracked path has no explicit distribution classification
When the inventory derives an export-facing summary
Then that path is classified as not eligible by default
And plans, private evidence, company data, raw references, and secret findings
cannot be inferred as public
```

## Examples (Specification by Example)

| Input state | Surface | Expected classification |
|-------------|---------|-------------------------|
| Raw reference absent from worktree but present in `HEAD` | `worktree`, `git_head` | Worktree absent; `raw_reference` still present in canonical `HEAD` |
| Same raw reference appears in an older commit | `git_history` | Historical presence recorded; no history-rewrite claim |
| Remote contains embedded authentication | `local_git_config` | `credential_risk` with remote name only; URL and value omitted |
| Product skill contains prohibited public attribution | `tracked_tree` | `public_vocabulary` finding with safe relative path and rule ID |
| Dirty public candidate has the same strong before/after fingerprint | `public_candidate` | Read-only inspection proved; findings remain candidate-only |
| Unclassified tracked file | `distribution_candidate` | `not_eligible` until a future allowlist admits it |

## Notes

- This story captures the baseline before S36.3 commits the raw-PDF deletion or
  changes public vocabulary.
- Private inventory evidence may contain safe repository-relative paths, but it
  never contains secret values, credential-bearing URLs, file contents, or
  unsafe subprocess output.
- Git history is observed, not rewritten. Secret rotation and destructive
  history cleanup remain external owner actions if later evidence requires them.
- No hosted service, cloud database, network scanner, or automatic public-repo
  synchronization is introduced.
