# Story: SQLite Database Layer & Schema

## User Story
As a coach using Escala,
I want my data — companies, worksheets, sessions, changes — to persist in a real database,
so that nothing is lost between sessions and I can see what changed over time.

## Acceptance Criteria

### Scenario: Database initializes on first start
```gherkin
Given no escala.db exists
When the server starts or migrate runs
Then escala.db is created with all tables
And the schema includes: companies, worksheets, sessions, changes_log
```

### Scenario: Worksheet data persists
```gherkin
Given I save data to a worksheet via the API
When I restart the server
Then the worksheet data is still there
```

### Scenario: Change tracking records diffs
```gherkin
Given I have existing worksheet data
When I update a value
Then a change log entry is created with before/after diff
And the diff shows exactly what changed
```

### Scenario: Migrate from YAML
```gherkin
Given there is existing YAML data in .scaleup/my-company/
When I run migration
Then all YAML data is imported into SQLite tables
And the YAML files remain as backup
```
