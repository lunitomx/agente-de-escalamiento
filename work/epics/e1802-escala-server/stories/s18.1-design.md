# Design: S18.1 — Server Core

## Problem
Los 22 dashboards de Escala son archivos HTML estáticos sin servidor. No hay API para leer/escribir datos, no hay CLI para gestionar el ciclo de vida del servidor, y no hay infraestructura sobre la cual construir dashboards interactivos.

## Value
Un servidor HTTP local que sirva los dashboards y exponga endpoints API. Esto permite que las historias subsecuentes (S18.3+) añadan interactividad con persistencia. Sin S18.1, no hay base para nada más en E18.

## Approach

Servidor HTTP minimalista en Python puro usando `http.server`. Sin Flask, sin FastAPI — un solo módulo `escala_server.py` (o paquete pequeño) con:

1. **StaticFileHandler**: sirve archivos HTML/CSS/JS desde un root directory configurable
2. **API Router**: dispatch a funciones handler basado en método + ruta
3. **CLI wrapper**: argparse con subcomandos start, stop, status
4. **DAO base layer**: clases abstractas para companies, worksheets, sessions (implementación real en S18.8)
5. **CORS middleware**: headers para permitir desarrollo local

### Components Affected

| Component | Change | Purpose |
|-----------|--------|---------|
| `escala_server/__init__.py` | Create | Package init, version |
| `escala_server/server.py` | Create | HTTP server, request handler, static serving |
| `escala_server/router.py` | Create | API route registry and dispatch |
| `escala_server/handlers.py` | Create | API handler functions (companies, worksheets, sessions) |
| `escala_server/dao.py` | Create | Abstract DAO interface (concrete in S18.8) |
| `escala_server/cli.py` | Create | CLI: start, stop, status |
| `escala_server/cors.py` | Create | CORS middleware |
| `scripts/escala-server` | Create | Entry point script (shebang + CLI call) |

### Design Decisions

| ID | Decision | Rationale |
|----|----------|-----------|
| DD1 | `http.server` nativo | Cero dependencias externas, proporcional para un server local de coaching |
| DD2 | Router propio, no framework | ~50 LOC vs instalar Flask. El routing es simple: método + path → handler |
| DD3 | DAO abstracto separado del handler | S18.8 implementará SQLite sin cambiar la interfaz HTTP |
| DD4 | CLI con argparse | No necesita typer/click para 3 comandos |
| DD5 | DAO usa dicts en memoria inicial | S18.8 reemplazará con SQLite. Interface: get_all, get, create, update |
| DD6 | CORS permite cualquier origen en dev | Accesible desde cualquier puerto local (3000, 5173, 8080) |

### Storage Migration Gate (N/A)
S18.1 no reemplaza almacenamiento — usa dicts en memoria. La migración real (YAML → SQLite) es S18.8.

## Examples

### CLI Usage
```bash
# Start server
$ escala-server start
Server running on http://localhost:8080

# Check status
$ escala-server status
Running (PID: 12345)

# Stop server
$ escala-server stop
Server stopped
```

### API Usage
```bash
# List companies (returns empty array initially)
$ curl http://localhost:8080/api/companies
{"data": [], "status": "ok"}

# Get worksheets for a category
$ curl http://localhost:8080/api/worksheets/cash
{"data": {}, "status": "ok"}

# Update a worksheet
$ curl -X POST http://localhost:8080/api/worksheets/cash/power-of-one \
  -H "Content-Type: application/json" \
  -d '{"palancas": {"precio": 5, "clientes": 10}}'
{"data": {"palancas": {"precio": 5, "clientes": 10}}, "status": "ok"}
```

## Acceptance Criteria

### MUST
- [ ] `escala-server start` inicia server en localhost:8080
- [ ] Servir archivo HTML estático desde ruta configurada funciona
- [ ] GET /api/companies retorna JSON con `{"data": [], "status": "ok"}`
- [ ] POST /api/worksheets/{category}/{tool} acepta JSON y retorna el dato guardado
- [ ] CORS headers presentes en respuestas (Access-Control-Allow-Origin: *)
- [ ] `escala-server stop` termina el proceso
- [ ] `escala-server status` muestra running/stopped

### SHOULD
- [ ] Logging a consola con timestamps
- [ ] Graceful shutdown con SIGINT/SIGTERM
- [ ] Ruta 404 para endpoints no definidos

### MUST NOT
- [ ] Dependencias externas (no Flask, no FastAPI, no typer)
- [ ] Bloquear el terminal (correr en background)
