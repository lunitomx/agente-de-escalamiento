# Design & Plan: S18.8 — SQLite Database Layer

## Approach

1. **Schema** (`escala_server/schema.py`): 7 tablas SQLite con índices, creadas automáticamente
2. **DAO Layer** (`escala_server/daos/`): Un DAO por dominio, implementando SQLite con sqlite3 nativo
3. **Diff Engine** (`escala_server/diff.py`): Compara dos versiones de worksheet data, produce lista de cambios
4. **Migration** (`escala_server/migrate.py`): Lee YAML existente de `.scaleup/my-company/`, importa a SQLite
5. **Integración**: Reemplazar `CompaniesHandler`, `WorksheetsHandler`, `SessionsHandler` en memoria por DAOs SQLite
6. **Tests**: pytest para cada DAO

## Tasks

### T1: Schema
- `schema.py` con CREATE TABLE, índices, y función `init_db()`
- Schema version tracking

### T2: DAO Layer
- `daos/__init__.py`
- `daos/base.py` — BaseDAO con conexión SQLite
- `daos/company_dao.py` — Companies CRUD
- `daos/worksheet_dao.py` — Worksheets CRUD + versionado
- `daos/session_dao.py` — Sessions CRUD
- `daos/change_dao.py` — Changes_log CRUD

### T3: Diff Engine
- `diff.py` — diff recursivo de dos dicts JSON

### T4: Migration from YAML
- `migrate.py` — lee `.scaleup/my-company/data.yaml` y migra a SQLite

### T5: Integration
- Reemplazar handlers.py para usar SQLite DAOs
- Server inicia con init_db()

### T6: Tests
- Test cada DAO con SQLite en memoria
- Test diff engine
- Test migration
