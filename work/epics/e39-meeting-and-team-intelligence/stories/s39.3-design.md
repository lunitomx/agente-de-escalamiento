# S39.3: Temporal Team Signals and Executive Review — Design

## Complexity

Complex: deterministic aggregation over multiple source records and a review contract consumed by local reports, with explicit negative-safety semantics.

## Gemba and legacy sweep

S39.1 owns local source/context and S39.2 owns fact/rhythm contracts. No temporal meeting module or V1 exists in `escala_server`; this story composes those public contracts and adds no alternate storage. Existing coaching skills remain unchanged.

## Approach

Represent each input as `MeetingRecord(context, extraction)`. Normalize only for grouping, retain original fact values locally, and attach every `TeamSignal` to source IDs and evidence counts. Detect repeated blockers/commitments at count ≥2, overdue action/commitment dates against `as_of`, unresolved decision questions, and a simple before/after frequency trend. Build an executive review whose health is `watch` only when supported signals exist, `evidence_supported` when supplied evidence has no material signal, and `evidence_limited`/`unresolved` when inputs do not support a conclusion.

## Components

- Create `escala_server/meetings/analysis.py` with timeline and review contracts/functions.
- Modify `escala_server/meetings/models.py` for record/signal/review contracts.
- Modify `escala_server/meetings/__init__.py` exports.
- Extend `tests/test_e39_meeting_intelligence.py` with temporal fixtures.

## Concrete examples

```python
analysis = build_team_signals(records, as_of=date(2026, 7, 22))
assert {signal.kind for signal in analysis.signals} >= {
    "repeated_blocker", "overdue_commitment", "trend"
}
review = build_executive_review(records, as_of=date(2026, 7, 22))
assert review.health == "watch"
```

Empty evidence:

```python
review = build_executive_review((), as_of=date(2026, 7, 22))
assert review.health == "evidence_limited"
assert review.material_changes == ()
```

## Acceptance criteria

### MUST

- All signal types include source IDs, evidence count and confidence.
- Repeated/overdue/unresolved/trend logic is deterministic and bounded.
- Review distinguishes no supported negative signal from insufficient evidence.
- No raw transcript text, path or inferred sentiment is generated by this layer.

### MUST NOT

- Call cloud services, write files or assign individual scores.
- Treat a single unconfirmed mention as a repeated trend.

## Testing strategy

Synthetic three-meeting timeline; negative empty/unresolved timeline; deterministic signal IDs and source evidence assertions.
