# S39.1: Transcript Intake and Context — Design

## Complexity

Moderate: one new package, two local files/ledger seams, and a bounded parser. No external integrations or schema migration.

## Problem and value

E37 can identify and profile text sources, pero todavía no existe un contrato de meeting ni una forma idempotente de recordar qué transcript ya fue aceptado. Esta story convierte un archivo local en un contexto verificable (o una pregunta explícita) sin copiarlo, mutarlo ni enviar datos a la nube.

## Gemba and legacy sweep

- Reusa `escala_server.workspace.ingestion.build_source_identity` y `WorkspaceConfig`.
- `escala_server.workspace.inbox.scan_inbox` ya tiene semántica de symlinks, directorios y source ledger; no se duplica su identidad. S39.1 añade un ledger de meeting derivado porque necesita guardar contexto y no cambia el ledger E37.
- No hay V1 de meeting intelligence en `escala_server`; nada queda huérfano. Los skills textuales legacy continúan sin cambiar.
- No hay drift hotspot file. AG2 se evita con helpers compartidos y AG4 queda acotado a `escala_server/meetings`.

## Approach

Modelos Pydantic estrictos (`MeetingProvenance`, `MeetingContext`, `MeetingQuestion`, `MeetingIntakeResult`) mantienen rutas relativas, hashes y estados `ready|unresolved|rejected`. `scan_meeting_inbox` solo acepta `.txt/.md/.transcript`, calcula la identidad E37, extrae señales de encabezado/líneas y guarda un ledger JSON atómico bajo `data_root/.escala-meeting-ledger.json`. El texto no se persiste en el ledger; la evidencia queda como hash de línea y rango.

## Components

- Create `escala_server/meetings/models.py`: closed contracts.
- Create `escala_server/meetings/intake.py`: parser/ledger and redacted receipts.
- Create `escala_server/meetings/__init__.py`: public seam.
- Create `tests/test_e39_meeting_intelligence.py`: source/intake cases.

## Concrete examples

```python
config = WorkspaceConfig(
    platform="macos", data_root=root / "data",
    database_path=root / "data" / "escala.sqlite",
    exchange_root=root / "exchange",
)
result = scan_meeting_inbox(config)
assert result.items[0].status == "ready"
assert result.items[0].context.meeting_type == "daily"
assert scan_meeting_inbox(config).items[0].status == "duplicate"
```

Ambiguous input:

```text
Equipo: Operaciones
Participantes: Ana, Luis
Tema: seguimiento
```

→ `status="unresolved"`, question `meeting_type`, no guessed date or type.

## Acceptance criteria

### MUST

- Source identity is derived from E37 and repeat scans are idempotent.
- Supported text files produce context fields or bounded unresolved questions with line evidence.
- Unsupported/symlink/directory entries are rejected without mutation.
- JSON/Markdown receipts contain no machine paths or transcript text.

### SHOULD

- Normalize Spanish/English labels and dates `YYYY-MM-DD`/`DD/MM/YYYY`.

### MUST NOT

- Write to exchange, SQLite, network, or original transcript.
- Infer a person/team performance judgment from missing context.

## Testing strategy

Focused tests cover ready context, duplicate source, ambiguity, unsupported input, symlink/directory, receipt redaction, deterministic IDs and no original mutation.
