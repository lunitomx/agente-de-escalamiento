# S39.4: Local Scheduling and Report Exchange — Design

## Complexity

Moderate: one local file writer, one manifest and an explicit authority check; no new dependency or OS daemon.

## Gemba and legacy sweep

E37 `validate_workspace` already establishes installer-machine authority. E38 demonstrates deterministic local reports with atomic writes and redacted receipts; S39.4 follows that pattern. There is no V1 meeting report writer in `escala_server`, so no orphaned replacement is required.

## Approach

Validate workspace before writes, store a schedule manifest and report artifacts only below `data_root`, and write through temporary files plus `os.replace`. The exchange is read-only and is rejected if it contains `.sqlite`, `.sqlite3` or `.db` files. Markdown/HTML contain the local review; JSON mirrors stable safe fields; receipts include only relative artifact paths, IDs and status.

## Components

- Create `escala_server/meetings/report.py` for schedule, boundary receipt and artifact writer.
- Modify `escala_server/meetings/__init__.py` exports.
- Extend `tests/test_e39_meeting_intelligence.py` with report/boundary cases.
- Create `validators/e39_gates.py`, `scripts/qualify_e39.py` and `work/.../evidence/` for master proof.

## Concrete examples

```python
schedule = schedule_daily_review(config, run_date=date(2026, 7, 22))
artifact = write_executive_report(config, review)
assert artifact.html_path.startswith(".escala-meeting-reports/")
assert validate_report_exchange(config).status == "pass"
```

Negative: placing `exchange/shared.sqlite` returns `fail` with `authoritative_sqlite_sync_forbidden` and does not create report state.

## Acceptance criteria

### MUST

- All writes stay under installer `data_root`; exchange is ordinary filesystem input only.
- Schedule/report artifacts are deterministic, relative and redacted in receipts.
- Authority check rejects exchange database state and exposes the E37 finding.
- Qualification produces exact evidence for REQ-E39-001…007.

### MUST NOT

- Start daemons, call cloud services, copy/mutate transcripts or write SQLite into exchange.

## Testing strategy

Focused tests for deterministic schedule/report, HTML escaping, no source mutation, workspace authority and exchange DB negative; qualification fixture drives all seven requirements.
