# S39.2: Evidence Extraction and Rhythm — Design

## Complexity

Complex: one extraction contract, source freshness validation and a date-window rhythm evaluator consumed by later temporal analysis.

## Gemba and legacy sweep

S39.1 owns source identity/context and leaves transcript bytes in exchange. E39 has no fact extractor V1 in `escala_server`; this story extends the new `meetings` package rather than duplicating E37. No storage migration or new dependency.

## Approach

Read the original transcript only after confirming its current E37 `source_id` matches the intake item. Parse explicit bilingual labels (`Decisión`, `Acción`, `Responsable`, `Vence`, `Bloqueador`, `Riesgo`, `Compromiso`) into immutable facts with line evidence and high confidence. A declared `RhythmRule` evaluates expected dates and returns `supported`, `evidence_missing` or `unresolved`; it never converts missing evidence into a person score.

## Components

- Create `escala_server/meetings/extraction.py` with fact models, parser and rhythm evaluator.
- Modify `escala_server/meetings/models.py` for fact/rhythm contracts.
- Modify `escala_server/meetings/__init__.py` exports.
- Extend `tests/test_e39_meeting_intelligence.py` with extraction and negative cases.

## Concrete examples

```text
Decisión: Mantener proveedor A
Acción: Ana — revisar inventario — vence: 2026-07-25
Bloqueador: aprobación de compras
Riesgo: proveedor atrasado
Compromiso: Luis entregará presupuesto
```

→ six or more facts, each with source ID, exact line and confidence `high`; inline owner/date attach to the action.

```python
assessment = assess_rhythm(
    contexts, RhythmRule(rule_id="daily", meeting_type="daily", cadence_days=1),
    period_start=date(2026, 7, 20), period_end=date(2026, 7, 22),
)
assert assessment.status == "evidence_missing"
assert assessment.person_impact == "not_assessed"
```

## Acceptance criteria

### MUST

- Seven required fact kinds are supported or explicitly unresolved.
- Facts carry stable IDs, source provenance, confidence and optional owner/due date.
- Source replacement or unreadable bytes blocks extraction.
- Rhythm results expose observed/missing dates and never a negative person judgment.

### MUST NOT

- Store transcript text in receipts or create facts from implicit sentiment.
- Treat missing files as a person failure.

## Testing strategy

Unit and integration tests in the E39 focused file; deterministic IDs and source immutability are asserted.
