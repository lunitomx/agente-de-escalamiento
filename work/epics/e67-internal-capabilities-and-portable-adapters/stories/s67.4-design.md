# Diseño S67.4 — Paridad y migración de adaptadores

## Problema y valor

S67.2 empaqueta Codex copiando el catálogo portable validado; S67.3 hace que
Claude referencie el mismo skill y catálogo. Cada contrato pasa sus propias
pruebas, pero faltaba una evidencia única de que ambas superficies preservan
las seis rutas MVP y de que la capa de aliases no volvió a ser una segunda
experiencia pública.

Existe además un catálogo YAML histórico que el router de compatibilidad usa
para resolver 39 aliases heredados. No representa las seis rutas MVP ni se
debe borrar o migrar durante esta historia: S67.4 lo declara como capa interna
de migración y comprueba que no se publique.

## Decisión

Crear un generador/validador local que derive una matriz JSON versionada del
catálogo MVP y de los dos manifiestos. La matriz conservará, por capacidad,
intención, aliases internos, procedure, evidence kinds, specialist profiles y
lifecycle; no copiará metodología. Una prueba construirá el adaptador Codex en
un directorio temporal, resolverá las referencias Claude y comprobará que
ambos coinciden con la matriz. Otra prueba preservará la frontera de aliases.

Codex deja de mantener un texto reducido propio del skill: empaqueta el
`SKILL.md` canónico y sólo adapta su referencia relativa al catálogo que vive
en `core/` dentro del bundle. Así no aparece una segunda implementación de la
experiencia conversacional.

El reporte humano sólo explica la evidencia y el límite del YAML histórico;
el JSON generado es la fuente comprobable y `--check` impide drift.

## Componentes

| Componente | Cambio |
|---|---|
| `validators/adapter_parity.py` | derivar y validar la matriz portable |
| `scripts/verify_s67_4_parity.py` | regenerar o comprobar el reporte local |
| `reports/e67/s67.4-parity.json` | evidencia versionada de las seis rutas |
| `reports/e67/s67.4-parity.md` | explicación breve de alcance y límites |
| `adapters/codex/build_adapter.py` | empaquetar el skill público canónico |
| `tests/test_s67_4_parity_migration.py` | pruebas de paridad y migración |

## Límites

- No se toca `install.sh`: S67.2/S67.3 ya prueban las instalaciones por
  separado. S67.4 usa esas superficies como entrada verificable.
- No se hace routing natural-language ni se cambia `escala_server`.
- El reporte no declara que dos modelos de IA responderán con las mismas
  palabras; sólo certifica el contrato y la superficie instalable.
