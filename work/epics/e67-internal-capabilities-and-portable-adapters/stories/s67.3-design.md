# Diseño S67.3 — Adaptador Claude

## Problema y valor

El bundle ya tiene un núcleo portable (`escala-skills/escala`) y el instalador
dirige una instalación elegida de Claude a una sola ruta. Falta un contrato
visible, mínimo y verificable para Claude Code que indique cómo usar ese núcleo
sin convertir capacidades internas en comandos ni copiar metodología.

El resultado permite que el empaquetado Claude sea auditable: una persona ve
una única puerta, y quien mantenga el producto puede distinguir con precisión
lo que pertenece al core de lo que es una extensión de cliente.

## Gemba y límites

- `install.sh` ya instala únicamente `escala` en `~/.claude/skills` cuando se
  selecciona Claude; S67.3 no lo reescribe porque es superficie compartida con
  S67.2.
- `escala-skills/escala/SKILL.md` es el único contrato conversacional público;
  `capabilities/mvp/catalog.json` es el contrato interno de rutas.
- Los aliases se resuelven dentro del core/catálogo, nunca desde el adaptador.
- La carpeta histórica `.claude/skills/` no es el producto distribuible y no
  se reutiliza.

No hay V1 que deba eliminarse: este adaptador versionado es net-new. No se
identificó riesgo AG2/AG4: sólo se agrega un límite explícito y pruebas que
reutilizan el instalador y el core existentes.

## Decisión

Crear `adapters/claude/CLAUDE.template.md` y un README breve. El template no
incluye procedimiento, alias, lista de capabilities, MCP ni credenciales; sólo
declara que Claude debe delegar al core público instalado, cargar extensiones
únicamente con autorización explícita y no inferir soporte remoto. Las pruebas
comprueban el límite textual, la ausencia de una segunda implementación y el
resultado de instalación limpia existente.

## Componentes

| Componente | Cambio |
|---|---|
| `adapters/claude/CLAUDE.template.md` | crear contrato específico de cliente |
| `adapters/claude/README.md` | crear instrucciones de empaquetado sin comandos públicos |
| `tests/test_claude_adapter.py` | crear validación de frontera e instalación limpia |

## Ejemplos de aceptación

- Al instalar con `--skills-only --platform claude`, el destino contiene el
  enlace `escala` y no capacidades por separado.
- El template nombra el core como autoridad semántica y no enumera rutas MVP.
- El template no contiene `mcp`, secretos, tokens, URLs de conectores ni una
  instrucción que cree estado remoto.
