# S67.6 — Compatibilidad Agent Plugins v1

## Problema

ESCALA ya separa núcleo y adaptadores, pero no publica todavía un paquete que
otros clientes compatibles puedan descubrir mediante el formato abierto Agent
Plugins. Duplicar el empaquetado por plataforma erosionaría la portabilidad que
E67 debe proteger.

## Resultado para la persona usuaria

ESCALA puede instalarse desde un paquete estándar compatible sin exponer una
lista técnica de procedimientos. La experiencia sigue siendo: hablar con
`escala` en lenguaje natural; Cash, People, Strategy y Execution operan como
especialistas internos bajo demanda.

## Alcance

- Generar, desde el core aprobado de E67, un directorio autocontenido con
  `plugin.json` conforme a Agent Plugins v1 y skills bajo `skills/<nombre>/`.
- Validar manifest cerrado, nombre, versión, contención de rutas y descubrimiento
  no recursivo de cada `SKILL.md`.
- Empaquetar sólo `escala` como skill público; conservar capacidades,
  especialistas y extensiones Codex/Claude como implementación privada.
- Aislar cualquier configuración específica bajo namespaces de extensión; el
  core no depende de ella.
- Añadir fixtures de conformance y pruebas de instalación limpia que E68 pueda
  reutilizar.

## Fuera de alcance

- Declarar que Codex, Claude u otro cliente implementan toda la especificación
  de Agent Plugins; sólo se verifican los componentes soportados.
- Habilitar `mcp.json`, OAuth, secretos, conectores o sincronización por defecto.
- Introducir fuentes protegidas, datos de empresa o memoria mutable en el
  paquete distribuible.
- Reemplazar los adaptadores existentes antes de que E68 mida equivalencia real.

## Criterios de aceptación

1. El paquete contiene un único `plugin.json` con el schema canónico v1,
   validado sin descargar schemas durante la instalación.
2. Cada skill válido está en el hijo directo de `skills/`; el único skill
   expuesto al empresario es `escala`.
3. Todas las rutas resuelven dentro de la raíz del plugin; enlaces o recursos
   que escapen la raíz hacen fallar el build o se omiten de forma visible.
4. No contiene `mcp.json` habilitado, secretos, credenciales, datos de empresa
   ni instrucciones metodológicas duplicadas por cliente.
5. Una suite documenta qué componentes se probaron en Codex/Claude y transfiere
   la comparación semántica de modelos a E68.

## Evidencia de fuente

- Agent Plugins Specification v1.0.0, secciones de manifiesto, descubrimiento,
  skills, extensiones, contención y conformance.
- Las capacidades de clientes se verifican contra la matriz pública vigente al
  momento de implementación; no se infieren de esta historia.

## Handoff

S67.6 entrega el build/fixture portable a E68. Si la calificación observa
diferencias semánticas, éstas regresan al contrato de capability/adaptador; no
se corrigen agregando más comandos públicos.
