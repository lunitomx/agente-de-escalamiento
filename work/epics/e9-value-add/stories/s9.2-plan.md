### T2: Trend detection + history persistence (M)

**Goal:** Implement answer→trend mapping and pulse-history.yaml read/write (TDD GREEN).

**Trend mapping (direct, not sum):**
- `answer > 0` → `"improving"`
- `answer == 0` → `"stalling"`
- `answer < 0` → `"regressing"`

**History persistence:**
- Load `.scaleup/my-company/pulse-history.yaml` via `coaching/core.read_yaml()` (empty `{pulses: []}` if missing)
- Append new pulse entry with `date`, `answers`, `trends`, `course_corrections`
- Write via `coaching/core.write_yaml()`
- `prior_pulse_date`: last entry's `date` if history has entries, else `null`

**pulse-history.yaml schema:**
```yaml
pulses:
  - date: "2026-05-06"
    answers:
      people: 1
      strategy: 0
      execution: -1
      cash: 0
      overall: 0
    trends:
      people: improving
      strategy: stalling
      execution: regressing
      cash: stalling
      overall: stalling
    course_corrections:
      - "Execution regressing → run /scaleup-execution"
```

**Files:**
- `coaching/pulse/__init__.py` — extended with trend logic and YAML persistence
- `coaching/pulse/tests/test_pulse.py` — extended: trend tests GREEN, YAML persistence tests

**New tests:**
- `test_trend_all_decisions` — all 5 decision keys produce correct trends
- `test_history_created_on_first_run` — file created with `pulses: []` then entry appended
- `test_history_appended_on_second_run` — second run appends new entry, does not overwrite
- `test_prior_pulse_date_null_on_first_run` — `artifacts["prior_pulse_date"]` is `None` when no history
- `test_prior_pulse_date_populated_on_second_run` — `artifacts["prior_pulse_date"]` matches previous entry date
- `test_invalid_answer_value_returns_error` — value outside `{-1, 0, 1}` goes into `errors` list

**Acceptance:**

### T4: Quality gate validator + SKILL.md adapter (S)

**Goal:** Add pulse.py quality gate validator and thin SKILL.md adapter.

**Quality gate (`.scaleup/agent/validators/pulse.py`):**

Validates the **last entry** in `pulse-history.yaml`:

```python
REQUIRED_ENTRY_KEYS = ["date", "answers", "trends", "course_corrections"]
REQUIRED_DECISION_KEYS = ["people", "strategy", "execution", "cash", "overall"]
VALID_ANSWER_VALUES = {-1, 0, 1}
VALID_TREND_VALUES = {"improving", "stalling", "regressing"}
```

- Reads file path from `sys.argv[1]`
- If `pulses` list is empty → exits 0 (valid, no entries to check)
- Checks last entry for required keys, correct answer values, correct trend values
- Prints errors to stderr: `ERROR: Last entry missing required key: trends`
- Exits `sys.exit(0)` on valid, `sys.exit(1)` on errors

**SKILL.md adapter (`.claude/skills/scaleup-pulse/SKILL.md`):**

Thin wrapper following exact S9.1 export adapter pattern:
1. Check profile exists (prerequisite guard)
2. Invoke core Python with or without piped answers:
   `echo '{"answers": {...}}' | python3 -m coaching.pulse`
3. Present `result["output"]` to user
4. Handle `result["errors"]` if non-empty
5. Run quality gate: `python3 .scaleup/agent/validators/pulse.py .scaleup/my-company/pulse-history.yaml`
6. Show `result["artifacts"]["course_corrections"]` if non-empty

**MUST NOT contain business logic** — adapter is a shell/prompt wrapper only.

## Key Design Decisions (from s9.2-design.md)

1. **Trend = direct mapping of single answer, not sum.** `answer > 0 → improving`, `answer == 0 → stalling`, `answer < 0 → regressing`. Multi-pulse trend lines (moving average) are S9.3 scope.

2. **Validator validates pulse-history.yaml, not a JSON file.** Pulse has no markdown artifact. The durable output is the appended YAML history. The validator reads the file directly.

3. **ROUTING_RULES extracted to coaching/core.** Additive-only — no existing module behavior changes. `coaching/diagnose` and `coaching/export` keep their local copies for now.

4. **Interactive prompting isolated behind single guard.** `if "answers" not in context: answers = _prompt_interactive()`. All unit tests pass answers in context — never touch `input()` path.

5. **pulse-history.yaml as `{pulses: [...]}` not flat list.** Extensible for future top-level metadata.

6. **First-run creates file gracefully.** Creates `{pulses: []}` then appends. `prior_pulse_date` is `null`.
