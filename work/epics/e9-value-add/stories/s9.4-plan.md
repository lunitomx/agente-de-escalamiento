## Task Breakdown

### T1: Core module — engine + formatter + __init__ (S)

**Goal:** Build `coaching/summary/` with pure functions (engine, formatter) and the public `run()` API. TDD RED → GREEN → REFACTOR.

**Files:**
- `coaching/summary/__init__.py` — public `run(context: dict) -> dict` + `__main__` stdin entry point
- `coaching/summary/engine.py` — pure function `build_summary(data: dict) -> dict`
- `coaching/summary/formatter.py` — pure function `format_summary(summary: dict) -> str` (markdown)
- `coaching/summary/tests/__init__.py` — makes tests a package
- `coaching/summary/tests/test_summary.py` — TDD tests (engine logic, formatter output, integration)

**TDD cycle:**

RED — write tests that assert:
- `build_summary()` returns dict with keys: `date`, `duration_minutes`, `decision_focus`, `worksheets_completed`, `tasks_created`, `tasks_completed`, `notes`
- `format_summary()` returns string containing `## Session Summary`
- `format_summary()` includes `### What We Worked On` when worksheets non-empty
- `format_summary()` includes `### Tasks` with created/completed sublists
- `format_summary()` includes `### Key Points` when notes non-empty
- `format_summary()` omits score-change section when `scores_before` is null
- `run()` appends markdown to log file and returns `{"output": ..., "artifacts": ..., "errors": []}`
- `run()` returns `errors` list when `log_file_path` is missing from context

GREEN — implement `engine.py`, `formatter.py`, `__init__.py` until all tests pass.

REFACTOR — extract any repeated formatting logic; ensure I/O is isolated to `__init__.py` only.

**Acceptance:**
- `from coaching.summary import run` imports without error
- `python3 -m coaching.summary` is invocable via stdin JSON
- All summary tests pass (GREEN)
- `scores_before: null` → no score-change section (graceful omit, not error)

**Gate check after T1:**
```bash

rai gate check gate-lint
rai gate check gate-format
rai gate check gate-types
```

### T2: Validator — summary_validator.py (XS)

**Goal:** Add a code-based quality gate that validates `## Session Summary` section is present in a session log file. ADR-5 pattern: no LLM, standalone callable.

**Files:**
- `.scaleup/agent/validators/summary_validator.py` — `validate_summary(log_path: str) -> list[str]`; callable as `__main__`

**TDD cycle:**

RED — add tests in `coaching/summary/tests/test_summary.py`:
- `validate_summary(valid_path)` returns empty list when `## Session Summary` is present
- `validate_summary(missing_section_path)` returns non-empty list with descriptive error message
- `validate_summary(nonexistent_path)` returns non-empty list with file-not-found message

GREEN — implement `summary_validator.py`:
- Read file, check for `## Session Summary` header
- Return `["Missing section: ## Session Summary"]` if absent
- Return `["File not found: <path>"]` if file does not exist
- Print errors to stderr; exit 0 if valid, exit 1 if errors

REFACTOR — ensure consistent error message format with existing validators (`session.py`, `export.py`).

**Acceptance:**
- `python3 .scaleup/agent/validators/summary_validator.py <valid-file>` exits 0
- `python3 .scaleup/agent/validators/summary_validator.py <invalid-file>` exits 1 with readable error on stderr
- Existing `validate_session_log` (session.py) still passes its tests unmodified

### T3: Integration — update scaleup-close SKILL.md + integration test (XS)

**Goal:** Wire the summary module into `scaleup-close` as Step 3.5. Manual integration test confirms end-to-end behaviour with a real session log file.

**Files:**
- `.claude/skills/scaleup-close/SKILL.md` — insert Step 3.5 between Step 3 (quality gate) and Step 4 (confirmation)

**SKILL.md Step 3.5 content (exact):**

After Step 3 quality gate passes, the adapter runs:

```bash
echo '{
  "base_path": ".",
  "log_file_path": "{log_file_path}",
  "date": "{YYYY-MM-DD}",
  "duration_minutes": {N},
  "decision_focus": "{decision}",
  "worksheets_completed": [{worksheets}],
  "tasks_created": [{tasks_created}],
  "tasks_completed": [{tasks_completed}],
  "notes": [{notes}],
  "scores_before": null
}' | python3 -m coaching.summary
```

- Capture return JSON; if `errors` is non-empty, surface to user and abort
- Then run: `python3 .scaleup/agent/validators/summary_validator.py {log_file_path}` → must exit 0
- Continue to Step 4 only when both checks pass

**Adapter rules:**
- MUST NOT contain business logic — only JSON assembly and subprocess invocation
- MUST NOT re-ask the user any questions (all data already collected in Step 1)
- Step 4 confirmation text is unchanged

**Manual integration test (no automated test — verification by inspection):**

1. Create a minimal session log file at `.scaleup/my-company/sessions/2026-05-06.md` with YAML frontmatter + `## Session Notes` section
2. Run `coaching.summary` via stdin JSON pointing to that file
3. Verify `## Session Summary` section appended to the file
4. Verify returned JSON has `errors: []` and `artifacts.summary_appended: true`
5. Run `python3 .scaleup/agent/validators/summary_validator.py .scaleup/my-company/sessions/2026-05-06.md` → exit 0
6. Verify existing `session.py` validator still passes on the same file

**Acceptance:**
- SKILL.md now has Steps 1, 2, 3, 3.5, 4 in sequence
- Step 3.5 contains no business logic
- Integration test passes all 6 verification steps
- No regression: session.py validator still exits 0 on a valid session log

## Risk Register

| Risk | Severity | Mitigation |
|------|----------|-----------|
| Session log file not yet written when Step 3.5 runs | High | Design doc confirms: Step 3.5 runs after Step 2 (file written) and Step 3 (gate passes). Append is safe. |
| `engine.py` mixed with I/O accidentally | Medium | Tests call `build_summary()` and `format_summary()` directly — any I/O in those functions causes test setup to fail immediately. |
| SKILL.md Step 3.5 introduces business logic | Medium | Code review gate: verify adapter contains only JSON assembly + subprocess call, no conditionals on business fields. |
| `scores_before: null` treated as error instead of graceful omit | Low | Explicit test case for null scores_before — formatter must return valid markdown without score-change section. |
| Existing `validate_session_log` regression | Low | T3 integration test runs session.py validator on same file — regression caught before commit. |
