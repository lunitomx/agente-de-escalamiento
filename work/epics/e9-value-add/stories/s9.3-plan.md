Schema (confirmed from real file — PAT-L-7 locked):
```yaml

  - date: "2026-05-06"
    answers: {people: 1, strategy: 0, execution: -1, cash: 0, overall: 0}
    trends: {people: improving, strategy: stalling, execution: regressing, cash: stalling, overall: stalling}
    course_corrections:

```

**Section 2 — Pulse History table:**
- Columns: `Date | People | Strategy | Execution | Cash | Overall`
- Shows trend labels (`improving/stalling/regressing`), not raw answers
- Most-recent pulse first (reverse chronological)
- If no pulse data: `"No pulse data yet. Run /scaleup-pulse to start tracking."`

**Section 3 — Wins:**
```python
wins = [d for d in DECISIONS if last_pulse["trends"].get(d) == "improving"]
```
- If no pulse data: `"No pulse data yet. Run /scaleup-pulse to start tracking."`

**Section 4 — Attention Areas:**
```python
attention = []
for d in DECISIONS:
    if last_pulse["trends"].get(d) == "regressing":
        attention.append((d, "regressing"))
```

- Include routing command: `→ run /scaleup-execution`
- Only 1 pulse entry: stalling-persistence check skipped; regressing check still runs
- If no pulse data: `"No pulse data yet. Run /scaleup-pulse to start tracking."`

### T4: Quality gate validator + SKILL.md adapter (S)

**Goal:** Add `dashboard.py` quality gate validator and thin SKILL.md adapter.

**Quality gate (`.scaleup/agent/validators/dashboard.py`):**

Validates the markdown **output file** for 4 required `##` sections:

```python
REQUIRED_SECTIONS = [
    "## Current Scores",
    "## Pulse History",
    "## Wins",
    "## Attention Areas",
]
```

- Reads file path from `sys.argv[1]`
- Checks each required section is present in file contents
- Prints errors to stderr: `ERROR: Missing required section: ## Wins`

Usage (file-path approach, consistent with `export.py` validator):
```bash
echo '{}' | python3 -m coaching.dashboard | python3 -c "
import sys, json
result = json.loads(sys.stdin.read())
with open('/tmp/dashboard-output.md', 'w') as f:
    f.write(result['output'])
```

## Key Design Decisions (from s9.3-design.md)

1. **`coaching/dashboard/` is net-new, not an extension of `coaching/progress/`.** The story AC phrase "extends coaching/progress/" refers to the product concept, not a Python import relationship. `coaching/progress/` is a worksheet-completion tracker; `coaching/dashboard/` is a pulse-trajectory dashboard. They are independent.

2. **Data source for scores is `company-profile.yaml`, not `diagnosis.yaml`.** The scope doc mentions `diagnosis.yaml`, but that file does not exist. Scores live in `company-profile.yaml` under the `scores` key — confirmed from real file and `coaching/export/_read_scores()`.

3. **Dashboard is read-only — no file writes.** Unlike export (writes an action plan) or pulse (appends history), dashboard only reads and returns a formatted string. Side-effect-free and simple to test.

4. **Validator validates the markdown output string via a file argument.** Following the `export.py` pattern, validator receives a file path. The SKILL.md adapter pipes dashboard output to a temp file. Consistent with existing validator conventions.

5. **Attention "stalling 2+" requires at least 2 pulses.** When only 1 pulse exists, the stalling-persistence check is skipped. Regressing is still flagged with 1 pulse. When 0 pulses, all 3 sections (History/Wins/Attention) show "No pulse data yet."

6. **Pulse history table uses trend labels, not raw answers.** `improving/stalling/regressing` is directly human-readable. The `answers` field is available but not surfaced in the dashboard table.

7. **Import shared constants from `coaching.core`.** `DECISION_LABELS`, `ROUTING_RULES`, `PRIORITY_ORDER` are already in `coaching/core/__init__.py` (extracted during S9.2). Dashboard imports from core — no duplication.
