# S9.1: Action Plan Export — Design

**Story:** S9.1 — Action Plan Export  
**Epic:** E9 — Value-Add Features  
**Date:** 2026-05-06  
**Branch:** story/s9.1/action-plan-export  

---

## Problem & Value

**Problem:** Users completing coaching sessions have no shareable artifact to show their leadership team or board the current state of their company's scaling work. Everything lives in individual markdown files and a YAML profile — useful internally, invisible externally.

**Value:** A single, dated markdown export makes coaching tangible and accountable. Users can share progress with their team or board without screenshotting, copy-pasting, or manually summarizing multiple files.

---

## Gemba Walk Findings

### Coaching module pattern (from `coaching/diagnose/__init__.py`, `coaching/welcome/__init__.py`)

All existing modules follow the same contract:

```python
def run(context: dict) -> dict:
    """Returns dict with keys: output (str), artifacts (dict), errors (list[str])"""
```

- Invoked via stdin JSON: `echo '{"base_path": "."}' | python3 -c "import sys,json; sys.path.insert(0,'.'); from coaching.X import run; print(json.dumps(run(json.loads(sys.stdin.read())), indent=2))"`
- Read with `coaching/core.read_yaml()`, write with `coaching/core.write_yaml()`
- No external deps (stdlib + yaml already present in project)

### Data files available for export (`.scaleup/my-company/`)

| File | Content | Required |
|------|---------|----------|
| `profile.md` | Company info (name, industry, employees) | No — graceful fallback |
| `annual-goal.md` | SMART goal, KPI, connections to 4 decisions | No — graceful fallback |
| `quarterly-focus.md` | Quarter, critical number, 3 rocks | No — graceful fallback |
| `tasks.md` | In Progress / Próximo / Completado boards | No — graceful fallback |

Diagnosis scores live in `.scaleup/agent/memory/company-profile.yaml` (YAML), not in the .md files.

### Quality gate pattern (from `.scaleup/agent/validators/diagnose.py`)

Validators are standalone Python scripts that:
- Read YAML files
- Return `list[str]` of human-readable errors (empty = valid)
- Exit with `sys.exit(1)` when errors found, printing errors to stderr

### SKILL.md adapter pattern (from `.claude/skills/scaleup-diagnose/SKILL.md`)

Adapters are **thin wrappers** — no business logic. They:
1. Load context (check prerequisites)
2. Invoke core Python via `python3 -c "... from coaching.X import run ..."`
3. Present the `result["output"]` to the user
4. Handle errors from `result["errors"]`

## Approach

Follow the identical cross-platform architecture as E8:

```
coaching/export/
    __init__.py          ← ExportEngine.run(context) core logic
    tests/
        test_export.py   ← unit tests

.scaleup/agent/validators/
    export.py            ← quality gate (validates output file sections)

.claude/skills/scaleup-export/
    SKILL.md             ← thin adapter, invokes core Python
```

### Core logic (`coaching/export/__init__.py`)

**Input context keys:**
- `base_path` (str, default `"."`)

**Execution flow:**
1. Read `.scaleup/agent/memory/company-profile.yaml` → get diagnosis scores
2. Read `.scaleup/my-company/profile.md` → company name/context (graceful if missing)
3. Read `.scaleup/my-company/annual-goal.md` → goal section (graceful if missing)
4. Read `.scaleup/my-company/quarterly-focus.md` → priorities section (graceful if missing)
5. Read `.scaleup/my-company/tasks.md` → tasks section (graceful if missing)
6. Assemble 5-section markdown document
7. Write to `.scaleup/my-company/exports/YYYY-MM-DD-action-plan.md`
8. Return `{output, artifacts, errors}` per module contract

**KISS principle:** Read text files as raw strings — no complex parsing. Embed them verbatim into sections (with a header). This avoids fragile markdown parsing and ensures the user sees exactly what they wrote.

### Scores section

The only structured data to read/format is diagnosis scores from YAML:

```python
scores = profile.get("scores", {})  # {people: 3, strategy: 2, ...}
```

These are rendered as a markdown table (same format as `coaching/diagnose`).

### Output file structure (5 required sections)

```markdown
# Action Plan Export
**Company:** Acme Corp
**Date:** 2026-05-06
**Generated by:** ScaleUp Coach

---

## 1. Diagnosis Scores

| Decision  | Score | Level          |
|-----------|-------|----------------|
| People    | 3     | Emergente      |
| Strategy  | 2     | Ad hoc         |
| Execution | 4     | Establecido    |
| Cash      | 1     | No iniciado    |

**Priority focus:** Cash — `/scaleup-cash`

---

## 2. Annual Goal

[content of annual-goal.md verbatim, or placeholder if missing]

---

## 3. Active Priorities (Current Quarter)

[content of quarterly-focus.md verbatim, or placeholder if missing]

---

## 4. Open Tasks & Commitments

[content of tasks.md verbatim, or placeholder if missing]

---

## 5. Next Steps

[generated from priority decision routing, same logic as diagnose module]

---

*Exported: 2026-05-06 | ScaleUp Coach*
```

### Quality gate (`export.py` validator)

Validates the **output file** (not the input) has all 5 required section headers:

```python
REQUIRED_SECTIONS = [
    "## 1. Diagnosis Scores",
    "## 2. Annual Goal",
    "## 3. Active Priorities",
    "## 4. Open Tasks",
    "## 5. Next Steps",
]
```

Returns human-readable errors per section missing. Exits non-zero.

### No new external dependencies

Only stdlib (`datetime`, `pathlib`, `os`) + `yaml` (already a project dependency).

## Acceptance Criteria

### MUST

1. `echo '{"base_path": "."}' | python3 -m coaching.export` produces `.scaleup/my-company/exports/YYYY-MM-DD-action-plan.md`
2. Export includes all 5 sections: diagnosis scores, annual goal, active priorities, open tasks, next steps
3. Quality gate (`export.py`) returns non-zero exit code with human-readable error message when any required section is missing
4. SKILL.md adapter invokes core Python with no inline business logic — adapter is a thin wrapper only
5. Output file is valid markdown with proper `##` level headings for each section

### SHOULD

- Gracefully handle missing optional files (`annual-goal.md`, `quarterly-focus.md`, `tasks.md`) with a placeholder note in that section (e.g., `> Not configured yet. Run /scaleup-welcome.`)
- Include export timestamp at the top and bottom of the document
- Include company name from YAML profile (if available) in the document header

### MUST NOT

- Modify any existing `coaching/` module (`diagnose`, `welcome`, `progress`, `worksheet`, `level`, `router`)
- Introduce any external Python dependency beyond what is already in the project (`yaml` is fine, stdlib is fine)
- Write any file to a path other than `.scaleup/my-company/exports/`
- Contain business logic in the SKILL.md adapter

## Key Design Decisions

1. **Read .md files as raw strings, not parsed structures** — avoids fragile parsing, user sees their own content verbatim. The export is a container for what the user already wrote.

2. **Scores come from YAML, not .md** — `company-profile.yaml` is the structured data source; the `.md` files are human-edited narrative. This matches the diagnose module's approach.

3. **Graceful degradation on all optional files** — a user who hasn't filled in `annual-goal.md` still gets a valid export with a placeholder. This makes the command always safe to run.

4. **Quality gate validates the output file, not the inputs** — this is consistent with the existing validator pattern and provides an end-to-end check on the actual artifact produced.

5. **`__main__.py` for `python -m coaching.export` invocation** — matches Python module convention and allows direct CLI invocation without requiring the user to write the wrapper `-c` string. Pattern already used by other tools in the project.
