## What to improve

- Regex anchoring: the initial validator used `re.search(r"## Session Summary")` which could match embedded substrings; QR correctly flagged the need for `re.search(r"^## Session Summary", content, re.MULTILINE)`. This anchoring pattern should be default for all section-header validators.
- Tautological test: the test `assert "## Session Summary" in "## Session Summary"` was a trivially-true constant assertion that provided zero signal. Tests must assert on actual function output, not hardcoded strings against themselves.
- The QR fix should have been caught in REFACTOR phase of TDD, not post-implementation.

## Heutagogical Checkpoint

1. **What did I learn?** Section-header regex validators must be anchored to line starts (`^` + `re.MULTILINE`) to avoid false positives from embedded text. A tautological assertion (constant in, constant out) has zero test value and should be treated as a linting error.
2. **What would I change about the process?** Add a REFACTOR-phase checklist item: "For any regex matching section headers, verify anchoring." Add a test-review rule: "Every assert must reference the result of a function call, not a hardcoded literal."
3. **Framework improvements?** The QR heuristic now has two concrete checks: (a) YAML null-coalesce (from S9.3), (b) regex anchoring for section headers (from S9.4). Both should be codified as QR review items for coaching module validators.
4. **More capable of now?** S9.5+ can apply anchored regex and non-tautological assertions from the start. The engine+formatter+I/O isolator pattern is now proven across 3 stories — it can be treated as the default coaching module architecture.
