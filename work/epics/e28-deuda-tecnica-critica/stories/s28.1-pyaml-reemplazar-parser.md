# S28.1 — Reemplazar parser YAML casero con PyYAML

**Epic:** E28 — Deuda Técnica Crítica
**Size:** S (1h)
**Status:** Draft
**Dependencies:** S26.2 (pyyaml en pyproject.toml)

## Objetivo

Eliminar las 340 líneas de parser YAML casero en `migrate.py` y reemplazar con `yaml.safe_load()` de PyYAML. El parser existe solo porque PyYAML nunca se declaró como dependencia.

## Archivos

- `escala_server/migrate.py` (eliminar líneas 22-355)

## Cambios

1. Agregar `import yaml` al inicio (tras confirmar S26.2)
2. Reemplazar `read_yaml_file()`:
   ```python
   def read_yaml_file(path: Path) -> Any:
       text = path.read_text(encoding="utf-8")
       if path.suffix.lower() == ".json":
           return json.loads(text)
       return yaml.safe_load(text)
   ```
3. Eliminar estas funciones (~340 LOC):
   - `_parse_simple_yaml` (línea 22)
   - `_parse_yaml_value` (línea 37)
   - `_make_default` (línea 75)
   - `_parse_yaml_list` (línea 80)
   - `_parse_yaml_mapping` (línea 163)
   - `_collect_block_string` (línea 279)
   - `_parse_inline_mapping` (línea 300)
   - `_parse_scalar` (línea 308)
   - `_strip_quotes` (línea 347)

## Criterios de Aceptación

- [ ] `migrate.py` pasa de ~605 LOC a ~250 LOC
- [ ] `migrate_from_yaml` sigue funcionando (verificado con tests de S28.2)
- [ ] Sin imports huérfanos de `re` si ya no se usa para parsing

## Notas

- `yaml.safe_load()` es más seguro que `yaml.load()` — no ejecuta constructores arbitrarios
- PyYAML maneja todo el subset que el parser casero intentaba cubrir
