# S34.1 Design: Evidence Intake Schema

## Complexity

Moderate. The story creates one validator module, one focused test file, and
YAML fixtures. It has no external integrations and no storage migration.

## Problem

ScaleUp has strategy skills, but no typed Voice of Customer evidence contract.
Without a contract, later strategy prompts can cite weak anecdotes or unlabeled
fixtures as if they were real customer proof.

## Value

This story creates the first evidence gate for E34: customer voice records must
carry provenance before they can support Core Customer, Brand Promise, or
Strategy Canvas claims.

## Gemba Findings

- `validators/pipeline_runner.py` already uses Pydantic models plus YAML loading.
  S34.1 should follow that pattern instead of adding another validation style.
- `tests/test_pipeline_runner.py` imports validator modules by file path; S34.1
  should use the same local test pattern.
- `validators/pipelines.py` returns readable validation errors for contract
  failures. S34.1 should expose readable errors in addition to Pydantic models.
- No existing Voice of Customer evidence library or schema was found.
- `governance/drift-hotspots.json` is absent, so no hotspot rank applies.
- `rai schema sum check` reports `schema.sum not found`; this story does not
  change storage schema, so no schema sum update is required.

## Legacy Sweep

Nothing becomes orphaned. This is net-new evidence validation for a previously
unimplemented E34 contract.

## Approach

Create `validators/voice_of_customer.py` with a typed
`CustomerEvidenceRecord`, a `load_evidence_records(path)` YAML loader, and a
`validate_evidence_file(path)` helper that returns a list of readable errors.

Records are strict enough to prevent unsupported strategy use:

- required provenance fields: `source_type`, `source_label`, `captured_at`,
  `context`;
- required evidence fields: `quote`, `customer_segment`, `evidence_tags`;
- required governance fields: `review_status`, `is_fixture`;
- `strategy_usable` is true only for real, approved evidence;
- fixture records are valid only when `is_fixture: true` and remain distinct
  from real customer evidence.

## Components

| Component | Change | Purpose |
|---|---|---|
| `validators/voice_of_customer.py` | create | Typed evidence model, YAML loader, readable validation helper. |
| `tests/test_voice_of_customer.py` | create | Contract tests for valid records, missing provenance, fixtures, invalid enum/status values. |
| `tests/fixtures/voice_of_customer/*.yaml` | create | Representative fixture files for real evidence, missing provenance, and fixture evidence. |

## Decisions

| ID | Decision | Rationale |
|---|---|---|
| D1 | Use Pydantic models. | The repo already uses Pydantic for typed runtime contracts and AGENTS requires typed/Pydantic data structures. |
| D2 | Store test evidence under `tests/fixtures/voice_of_customer/` first. | S34.1 proves the contract without deciding production evidence storage too early. |
| D3 | Keep fixture data strategy-not-usable. | Fixtures are useful for tests but must not be confused with real customer proof. |
| D4 | Validate properties, not strategy mappings. | Mapping belongs to S34.3; S34.1 only says whether evidence is valid and usable. |

## Examples

### Valid Record

```python
from pathlib import Path
from validators.voice_of_customer import load_evidence_records

records = load_evidence_records(Path("tests/fixtures/voice_of_customer/valid.yaml"))
assert records[0].strategy_usable is True
```

### Readable Errors

```python
from pathlib import Path
from validators.voice_of_customer import validate_evidence_file

errors = validate_evidence_file(Path("tests/fixtures/voice_of_customer/missing_provenance.yaml"))
assert "source_label" in errors[0]
```

## Acceptance Criteria

### MUST

- Complete real customer evidence records validate successfully.
- Real records missing source, context, or captured date fail validation with
  readable errors.
- Synthetic examples must be explicitly labeled with `is_fixture: true`.
- Fixture records validate but are not `strategy_usable`.
- Invalid enum/status values fail validation.

### MUST NOT

- Do not normalize raw testimonials in this story.
- Do not map evidence to strategy claims in this story.
- Do not add external dependencies.

## Testing Strategy

| Layer | Test | Purpose |
|---|---|---|
| Unit | valid fixture loads as strategy-usable real evidence | Proves happy path. |
| Unit | missing provenance fixture returns readable errors | Proves no weak evidence passes silently. |
| Unit | fixture evidence is valid but not strategy-usable | Proves fixtures cannot masquerade as real proof. |
| Unit | invalid review status/source type is rejected | Proves controlled vocabulary. |
