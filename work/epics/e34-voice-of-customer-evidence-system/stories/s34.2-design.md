# S34.2 Design: Testimonial Normalization

## Complexity

Moderate. This extends one existing validator module and its focused test file.
No new dependency or storage mechanism is required.

## Problem

S34.1 validates well-formed evidence, but operators often start with raw quotes
or notes. Without a normalizer, missing provenance can be silently invented or
weak raw notes can be treated as evidence.

## Value

This story makes raw customer voice reviewable while preserving gaps. Complete
raw quotes become valid evidence; incomplete raw quotes remain draft, fixture,
or review-needed records and cannot support strategy claims.

## Gemba Findings

- `validators/voice_of_customer.py` already owns the evidence model and readable
  validation helper from S34.1.
- `tests/test_voice_of_customer.py` is the correct scoped test target for this
  story.
- Existing pattern from `validators/pipeline_runner.py`: keep typed helpers in a
  small validator module and test behavior with YAML fixtures.

## Legacy Sweep

No V1 becomes orphaned. S34.2 extends the S34.1 contract with raw quote
normalization.

## Approach

Add a `RawCustomerQuote` model and a `normalize_raw_quotes()` function to
`validators/voice_of_customer.py`.

Normalization rules:

- preserve provided quote text exactly;
- generate stable ids from source label plus quote when `id` is missing;
- use `review_status: draft` for incomplete raw quotes;
- set missing provenance to explicit review markers, not invented facts;
- mark incomplete normalized records as `is_fixture: true` so they validate but
  cannot become strategy-usable;
- detect duplicate `(source_label, quote)` pairs in batch normalization and
  report them.

## Components

| Component | Change | Purpose |
|---|---|---|
| `validators/voice_of_customer.py` | modify | Add raw quote model, normalization result, and duplicate detection. |
| `tests/test_voice_of_customer.py` | modify | Add normalization tests. |
| `tests/fixtures/voice_of_customer/raw_quotes.yaml` | create | Batch fixture with complete, incomplete, and duplicate raw quotes. |

## Acceptance Criteria

### MUST

- Complete raw quotes normalize into valid real evidence records.
- Incomplete raw quotes normalize into reviewable records that are not
  strategy-usable.
- Missing provenance is explicit and not invented.
- Stable ids are generated when raw input has no id.
- Duplicate quote/source pairs are reported and excluded.

### MUST NOT

- Do not map evidence to strategy categories in this story.
- Do not add sentiment scoring.
- Do not write production evidence storage.

## Testing Strategy

| Layer | Test | Purpose |
|---|---|---|
| Unit | complete raw quote normalizes | Proves happy path. |
| Unit | missing provenance stays non-usable | Proves no invented context. |
| Unit | stable generated id | Proves deterministic records. |
| Unit | duplicate raw quote reported/excluded | Proves batch safety. |
