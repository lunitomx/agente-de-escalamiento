# S34.5 Design: Evidence Library Handoff

## Complexity

Simple to moderate. This story is mostly documentation and closure governance,
but it adds tests so the handoff remains discoverable and tied to implemented
APIs.

## Problem

S34.1-S34.4 created the Voice of Customer contract, normalizer, mapper, and
prompt gates. Future skills still need a canonical handoff outside the old
draft folders, and E34 cannot close honestly without stating what was fixture
evidence versus real customer evidence.

## Value

Future strategy work can reuse the VoC evidence system without reading E19/E20
drafts. E34 closure becomes auditable and does not pretend fixture evidence is
real customer proof.

## Gemba Findings

- No `docs/` or `.raise/` Voice of Customer contract currently exists.
- Tests and fixtures live under `tests/fixtures/voice_of_customer/`.
- Implemented API surface lives in `validators/voice_of_customer.py`.
- Strategy prompts now require `CustomerEvidenceRecord` and
  `map_evidence_to_strategy`.

## Legacy Sweep

Old E19/E20 drafts remain historical source context only. S34.5 creates the
canonical handoff so future work does not depend on those draft folders.

## Approach

Create `.raise/evidence/voice-of-customer.md` as the canonical local handoff.
The doc will include:

- implemented API names;
- fixture path;
- future production storage convention;
- loading, normalization, mapping, citation, and gap-handling examples;
- explicit warning that current implementation fixtures are synthetic/test data
  unless a record is supplied and reviewed by an operator.

Add `tests/test_voice_of_customer_handoff.py` to prove the handoff references
the implemented API and does not direct future work to old E19/E20 drafts.

Create E34 `final-audit.md` and `retrospective.md`, then update `scope.md` to
`Complete` only after all evidence exists.

## Components

| Component | Change | Purpose |
|---|---|---|
| `.raise/evidence/voice-of-customer.md` | create | Canonical reusable evidence handoff. |
| `tests/test_voice_of_customer_handoff.py` | create | Contract tests for handoff discoverability. |
| `work/epics/e34-voice-of-customer-evidence-system/final-audit.md` | create | Epic closure evidence matrix. |
| `work/epics/e34-voice-of-customer-evidence-system/retrospective.md` | create | Epic retrospective. |
| `work/epics/e34-voice-of-customer-evidence-system/scope.md` | modify | Mark S34.5 and done criteria complete with evidence. |

## Acceptance Criteria

### MUST

- Handoff doc is outside old E19/E20 draft folders.
- Handoff doc names `CustomerEvidenceRecord`, `normalize_raw_quotes`, and
  `map_evidence_to_strategy`.
- Handoff doc shows how to cite evidence ids and handle gaps.
- Final audit distinguishes fixture data from real customer evidence.
- E34 status changes to Complete only with final audit and retrospective.

### MUST NOT

- Do not implement CRM/review import.
- Do not claim fixture records are real customer evidence.
- Do not close E35.

## Testing Strategy

| Layer | Test | Purpose |
|---|---|---|
| Doc contract | handoff references implemented API | Prevents stale docs. |
| Doc contract | handoff excludes old draft dependency | Prevents E19/E20 draft reliance. |
| Doc contract | final audit distinguishes fixtures | Prevents false closure. |
