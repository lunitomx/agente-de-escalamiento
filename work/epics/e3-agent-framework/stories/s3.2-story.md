# Story S3.2: .gitignore + limpieza del repo

## User Story (Connextra)

**As a** empresario que clona el repo scaleupagent,
**I want** only end-user files in the repository,
**So that** I don't see development artifacts, governance files, or source PDFs that are irrelevant to using the ScaleUp agent.

## Size: S

## Acceptance Criteria (Gherkin)

```gherkin
Feature: .gitignore excludes development-only files

  Scenario: Development governance files are excluded
    Given a fresh clone of the repo
    Then the directory "governance/" should not exist
    And the directory "work/" should not exist
    And the directory ".raise/" should not exist

  Scenario: RaiSE development skills are excluded
    Given a fresh clone of the repo
    Then no files matching ".claude/skills/rai-*" should exist
    And files matching ".claude/skills/scaleup-*" should exist

  Scenario: Build artifacts and source files are excluded
    Given a fresh clone of the repo
    Then no files matching "*.pdf" should exist
    And the directory "build/" should not exist
    And the directory "node_modules/" should not exist
    And the directory "__pycache__/" should not exist

  Scenario: End-user files are present
    Given a fresh clone of the repo
    Then the file "CLAUDE.md" should exist
    And the directory ".scaleup/" should exist
    And the directory ".claude/skills/" should contain scaleup skills
    And the file "README.md" should exist
    And the directory "templates/" should exist if present at root
```

## Dependencies

- None (can run in parallel with S3.1)

## Notes

- The .gitignore must be comprehensive enough that `git clean` + fresh clone yields only user-facing files
- AGENTS.md is a development artifact (RaiSE) and should be excluded
