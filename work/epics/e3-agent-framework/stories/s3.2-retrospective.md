# Retrospective: S3.2 — .gitignore + limpieza del repo

**Story ID:** S3.2
**Epic:** E3 (Agent Framework)
**Size:** S
**Branch:** story/s3.2/gitignore-cleanup

## Summary

Created `.gitignore` with 7 categories separating development-only files (governance/, work/, .raise/, rai-* skills) from product files (.claude/skills/scaleup-*, .scaleup/, templates/). Single implementation commit. Architecture Review passed with two questions carried forward to E5.

## What Went Well

- Clean pattern separation between `rai-*` (excluded) and `scaleup-*` (tracked) skills — the naming convention pays off here
- Proportional solution: Size S story got Size S treatment, no over-engineering
- 7-category structure in .gitignore is readable and maintainable
- Scope was tight and well-defined, no drift

## What to Improve

- Architecture Review flagged that already-tracked files still need `git rm --cached` before .gitignore takes effect on them — this was known but worth documenting as a carry-forward item for E5
- The `.venv/` directory was missing from the initial draft (caught in AR as R2)

## Heutagogical Checkpoint

1. **What did I learn?** `.gitignore` only prevents new tracking of untracked files. Files already committed remain tracked regardless of .gitignore rules. Explicit `git rm --cached` is needed to stop tracking previously committed files.

2. **What would I change about the process?** Nothing significant — the skill cycle was proportional to the story size. Design and plan were lightweight as appropriate for S-size.

3. **Are there improvements for the framework?** No. The existing skill cycle handled this well.

4. **What am I more capable of now?** Better understanding of the boundary between .gitignore (prospective) and git rm --cached (retroactive) for repo cleanup workflows.

## Patterns

No new patterns — straightforward configuration task. Existing patterns were not directly exercised.
