# Design: S3.4 — Estructura `.scaleup/` con defaults para usuario final

## Complexity: Simple

Core sections only.

## Problem

The `.scaleup/` directory currently has two top-level directories: `agent/` (identity, memory, sub-agents) and `knowledge/` (Scaling Up methodology content). There is no dedicated space for the end user's company data. The company profile lives inside `agent/memory/company-profile.yaml` — an internal agent location that is not intuitive for the entrepreneur. There is also no orientation (README) for the user who clones the repo and opens `.scaleup/` for the first time.

## Value

An entrepreneur who clones the repo immediately understands: "my stuff goes in `my-company/`, the agent's brain is in `agent/` and `knowledge/`." Clean separation between user workspace and agent internals. Future E6 features (tasks, sessions, memory) have a home ready.

## Approach

1. Create `.scaleup/my-company/` as the user's workspace directory
2. Add template files with instructional placeholder text (not empty files)
3. Keep existing `agent/memory/company-profile.yaml` as the agent's runtime copy — `my-company/profile.md` is the human-friendly source of truth that the agent reads
4. Add `.scaleup/README.md` as directory orientation
5. Create E6-ready placeholder files in `my-company/`

## Components

| File | Action | Purpose |
|------|--------|---------|
| `.scaleup/my-company/profile.md` | CREATE | Company profile template for the entrepreneur |
| `.scaleup/my-company/annual-goal.md` | CREATE | SMART annual goal template (E6 placeholder) |
| `.scaleup/my-company/quarterly-focus.md` | CREATE | Quarterly focus/rocks template (E6 placeholder) |
| `.scaleup/my-company/tasks.md` | CREATE | Task board template (E6 placeholder) |
| `.scaleup/README.md` | CREATE | Directory structure orientation for end user |

## Decision Log

### D1: Use `.scaleup/my-company/` as user workspace

**Choice:** Create a `my-company/` subdirectory to hold all user-specific data, separate from `agent/` and `knowledge/`.

**Rationale:** Clear mental model — the entrepreneur sees three concerns: their company data (`my-company/`), the agent's configuration (`agent/`), and the methodology reference (`knowledge/`). The name `my-company` is self-documenting and avoids generic names like `data/` or `user/`.

**Alternatives considered:**
- Put profile at `.scaleup/profile.md` (flat) — loses grouping, mixes user data with config
- Use `.scaleup/workspace/` — too generic, does not communicate ownership

### D2: Templates use instructional placeholder text

**Choice:** Each template file contains section headers and placeholder instructions (e.g., `<!-- Replace this with your company name -->`), not empty files.

**Rationale:** An empty file gives no guidance. Markdown with clear instructions teaches the user what information is needed and why. This aligns with the agent's value of "diagnóstico antes de prescripción."

**Alternatives considered:**
- Empty files with a single README — user must read README first, more friction
- YAML templates — less human-friendly for entrepreneurs who are not developers

### D3: Keep `agent/memory/company-profile.yaml` as agent runtime format

**Choice:** Do not delete or move the existing YAML profile. The user fills in `my-company/profile.md` (human-friendly), and future agent logic reads from it. The YAML remains as the agent's structured working copy.

**Rationale:** The YAML is already referenced by agent identity and sub-agent configs. Changing its location is out of scope (no code changes in S3.4). The two files serve different audiences: Markdown for the human, YAML for the agent.

**Alternatives considered:**
- Delete YAML and use only Markdown — breaks existing agent references
- Auto-sync Markdown to YAML — requires code, out of scope for S3.4

## Target Directory Structure

```
.scaleup/
├── README.md                          # NEW — directory orientation
├── my-company/                        # NEW — user workspace
│   ├── profile.md                     # NEW — company profile template
│   ├── annual-goal.md                 # NEW — SMART goal template (E6 placeholder)
│   ├── quarterly-focus.md             # NEW — quarterly rocks template (E6 placeholder)
│   └── tasks.md                       # NEW — task board template (E6 placeholder)
├── agent/                             # EXISTING — agent internals
│   ├── identity/core.md
│   ├── memory/company-profile.yaml
│   └── sub-agents/{people,strategy,execution,cash}.md
└── knowledge/                         # EXISTING — methodology reference
    ├── people/
    ├── strategy/
    ├── execution/
    ├── cash/
    └── references/
```

## Acceptance Criteria

Per s3.4-story.md Gherkin scenarios:
- AC1: Company profile template exists at `.scaleup/my-company/profile.md` with placeholder instructions
- AC2: Template contains zero real company data
- AC3: Directory structure has three intuitive top-level concerns (my-company, agent, knowledge)
- AC4: E6 placeholder files exist (annual-goal.md, quarterly-focus.md, tasks.md)
- AC5: README.md explains the directory structure
