# S3.1+S3.5 — Design: CLAUDE.md del producto

## Problem & Value

**Problem:** El repo no tiene un CLAUDE.md de producto. El actual es de RaiSE (desarrollo). Un empresario que clone el repo no verá al agente ScaleUp — verá a Rai.

**Value:** Con el CLAUDE.md correcto, el empresario clona, abre Claude Code, y tiene un coach ScaleUp experto listo para trabajar. Zero config. Los 19 skills accesibles via slash commands.

## Approach

Crear un CLAUDE.md de producto en la raíz que:
1. Defina la identidad ScaleUp (basándose en `.scaleup/agent/identity/core.md`)
2. Liste los 19 slash commands con descripción y cuándo usarlos
3. Referencie `.scaleup/` como fuente de datos
4. No interfiera con el CLAUDE.md de desarrollo (que vive en `.claude/`)

**Componentes:**

| Componente | Tipo | Descripción |
|------------|------|-------------|
| `CLAUDE.md` (raíz) | modificar | Reemplazar contenido RaiSE con identidad ScaleUp |

**Decisión clave:** El CLAUDE.md actual de RaiSE se mueve a `.claude/` (ya está ahí como project instructions). El de raíz se convierte en el del producto.

## Estructura del CLAUDE.md

Basándome en PAT-BASE-055 (U-shaped attention), la estructura prioriza identidad al inicio y commands al final:

```
1. Identidad (quién soy, qué hago) — TOP ATTENTION
2. Cómo trabajo (valores, boundaries, tono)
3. Estructura de datos (.scaleup/ reference)
4. Flujo de trabajo (welcome → diagnose → work)
5. Slash Commands (tabla de 19 skills) — BOTTOM ATTENTION
```

## Acceptance Criteria

### MUST
1. CLAUDE.md de producto en raíz define identidad ScaleUp (no RaiSE)
2. Los 19 slash commands listados con descripción y agrupados por decisión
3. `/scaleup-welcome` documentado como punto de entrada
4. Referencia a `.scaleup/my-company/` para datos de empresa
5. Referencia a `.scaleup/knowledge/` para base de conocimiento

### SHOULD
1. Aplicar PAT-BASE-055 (info crítica al inicio y final)
2. Tono consistente con `.scaleup/agent/identity/core.md`

### MUST NOT
1. No implementar lógica de coaching (eso es E8)
2. No modificar los skills existentes
3. No incluir instrucciones de desarrollo RaiSE en el CLAUDE.md de producto
