# Story S3.4 — Estructura `.scaleup/` con defaults para usuario final

## User Story

As an empresario that clones the scaleupagent repo,
I want the `.scaleup/` directory to have clean defaults and an empty company profile,
So that I know exactly where to put my company information and the agent can find it.

## Size: S

## Acceptance Criteria

```gherkin
Feature: .scaleup/ directory defaults for end user

  Scenario: Company profile template exists
    Given a freshly cloned scaleupagent repo
    When the user opens .scaleup/
    Then a company profile template exists with placeholder instructions
    And the template is empty of real company data

  Scenario: Directory structure is intuitive
    Given a freshly cloned scaleupagent repo
    When the user explores .scaleup/
    Then directories are named intuitively (my-company/, knowledge/, templates/)
    And the user understands where to put their information

  Scenario: Future-ready structure for E6
    Given the .scaleup/ directory structure
    When E6 (memory, tasks, sessions) work begins
    Then directories for memory/, tasks/, sessions/ exist or are clearly planned
    And annual SMART goal support is accommodated in the structure
```

## Dependencies

- E3 scope initialized (done)
- Existing .scaleup/ content (agent/, knowledge/, templates/)
