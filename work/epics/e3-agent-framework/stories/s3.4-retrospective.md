# Retrospective: S3.4 — Estructura `.scaleup/` con defaults para usuario final

**Story ID:** S3.4
**Epic:** E3 (Agent Framework)
**Size:** S
**Branch:** story/s3.4/scaleup-defaults

## Summary

Created `.scaleup/my-company/` directory with 4 template files (profile.md, annual-goal.md, quarterly-focus.md, tasks.md) using HTML comment placeholders as instructional guides. Added `.scaleup/README.md` explaining the three-concern directory model (my-company/agent/knowledge). Two implementation commits, clean AR and QR passes.

## What Went Well

- Three-concern directory separation (my-company/agent/knowledge) is intuitive — each directory has a clear owner and purpose
- Templates use HTML comments as placeholder instructions rather than empty files — gives the non-technical entrepreneur guidance without requiring them to know the format
- Proportional execution: Size S story, 2 tasks, 2 commits, no drift
- Scope stayed tight — resisted temptation to modify existing agent/memory/company-profile.yaml

## What to Improve

- README references `/scaleup-welcome` skill which does not exist yet — forward references to unbuilt features create broken promises. Need to either create the skill before E5 (distribution) or remove the reference
- Duplication between `my-company/profile.md` (human-facing) and `agent/memory/company-profile.yaml` (agent-facing) is acknowledged but unresolved — E6 should define the single source of truth and sync direction

## Heutagogical Checkpoint

1. **What did I learn?** HTML comments (`<!-- Replace this with... -->`) work well as in-file instructions for template files. They are invisible in rendered Markdown (GitHub, Obsidian) but visible when editing, which is exactly the right behavior for placeholder guidance.

2. **What would I change about the process?** Would validate forward references (like /scaleup-welcome) during Architecture Review rather than catching them as carry-forward items. A simple grep for referenced skills that don't exist could be an AR checklist item.

3. **Are there improvements for the framework?** AR could include a "forward reference check" — scan for references to skills, commands, or paths that don't exist yet and flag them explicitly.

4. **What am I more capable of now?** Better at designing user-facing template structures that balance guidance (HTML comments) with cleanliness (rendered view is clean). Also reinforced the principle that directory structure IS architecture for content-heavy projects.

## Patterns

No new patterns warranting persistence — the HTML-comment-as-instruction technique is useful but narrow in scope. The three-concern separation was a design decision, not a generalizable pattern.
