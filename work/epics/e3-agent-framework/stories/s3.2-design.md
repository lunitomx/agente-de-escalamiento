# Design: S3.2 — .gitignore + limpieza del repo

## Complexity: Simple

Core sections only.

## Problem

No comprehensive .gitignore exists. The current .gitignore only excludes `.raise/rai/personal/`. Development files (governance/, work/, .raise/, rai-* skills, PDFs, build artifacts) would be pushed to the public GitHub repo, exposing internal process artifacts to end users who clone the ScaleUp agent.

## Value

Clean public repo that only contains what the end user needs: CLAUDE.md, .scaleup/, .claude/skills/scaleup-*, templates/, and README.md.

## Approach

Create a comprehensive .gitignore at repo root with category-based sections. Use negation patterns to selectively include scaleup skills while excluding the entire .claude/skills/ directory by default.

## Components

| File | Action | Purpose |
|------|--------|---------|
| `.gitignore` | UPDATE | Add comprehensive exclusion rules |

## Decision Log

### D1: Use .gitignore negation patterns for selective skill inclusion

**Choice:** Exclude `.claude/skills/` broadly, then negate with `!.claude/skills/scaleup-*` to re-include scaleup skills.

**Rationale:** The .claude/skills/ directory contains 31 rai-* skills (development tooling) and 18 scaleup-* skills (product). Negation patterns let us exclude the rai-* bulk without listing each one, while explicitly preserving the product skills.

**Alternatives considered:**
- Move rai-* skills out of .claude/skills/ — breaks RaiSE framework expectations
- Separate repos for dev vs product — unnecessary complexity for this stage

## Expected .gitignore Structure

```gitignore
# ── RaiSE Development Governance ──
governance/
work/
.raise/
AGENTS.md

# ── RaiSE Skills (exclude dev, keep product) ──
.claude/skills/rai-*

# ── Source Files ──
*.pdf

# ── Build & Runtime Artifacts ──
build/
__pycache__/
*.pyc
*.pyo
node_modules/
.venv/

# ── Environment & Secrets ──
.env
.env.*
```

## Acceptance Criteria

Per s3.2-story.md Gherkin scenarios:
- AC1: .gitignore exists at repo root
- AC2: governance/, work/, .raise/ are git-ignored
- AC3: rai-* skills ignored, scaleup-* skills tracked
- AC4: PDFs, build artifacts, env files ignored
- AC5: End-user files (.scaleup/, CLAUDE.md, templates/, scaleup-* skills) remain tracked
