# S10.11 — Instalador dirigido y seguro ante PEP 668

## Problema

La instalación observada en Debian/Ubuntu protegió correctamente el Python del
sistema mediante PEP 668, pero `install.sh` ocultó el fallo de `pip install -e`
con un mensaje de éxito. Además, al detectar varias plataformas instaló y
configuró todas, aunque la intención era instalar Claude Code.

## Resultado para la persona usuaria

La persona elige claramente dónde desea usar ESCALA. El instalador no altera
Hermes, Codex ni MCPs si no fueron seleccionados. Si solicita el runtime
standalone, queda instalado de modo reproducible en el entorno local del
paquete o se informa un error real y recuperable.

## Alcance

- Añadir selección explícita de plataformas y un modo explícito para todas.
- Conservar `--skills-only` como instalación sin runtime Python, compatible con
  una plataforma seleccionada.
- Resolver el intérprete standalone: reutilizar `.venv` válida o crearla con
  `uv`; no usar `--break-system-packages` ni `pip` global.
- Propagar estados de salida, verificar imports en el mismo intérprete y emitir
  resumen/log redactado congruente con el resultado.
- Actualizar README y pruebas de shell/instalación aislada.

## Fuera de alcance

- Cambiar los enlaces ya instalados en el VPS sin orden explícita.
- Instalar o registrar conectores, OAuth, MCPs o credenciales automáticamente.
- Declarar aceptación de hardware/modelos de E42/E68.

## Criterios de aceptación

1. `./install.sh --platform claude` instala sólo la puerta `escala` en Claude
   Code y no crea ni elimina archivos de Codex/Hermes ni configura RaiSE MCP.
2. Varias plataformas sólo se modifican mediante opción explícita; el modo
   ambiguo no tiene efectos laterales.
3. Un sistema PEP 668 instala correctamente en `.venv` con `uv`, o termina con
   código no cero, causa legible y ninguna afirmación de éxito falsa.
4. La validación de módulos se ejecuta con el intérprete realmente instalado.
5. Las pruebas simulan éxito, fallo, PEP 668, `uv` ausente y preservación de
   plataformas no seleccionadas.

## Evidencia de cierre local

- `tests/test_installer_targeting.py` cubre plataforma obligatoria, Claude
  dirigido, instalación total explícita, ausencia de `pip` global y fallo de
  runtime sin enlaces parciales ni éxito falso.
- `tests/test_public_skill_installation.py` conserva la instalación portable
  y verifica además la instalación completa desde un bundle limpio con su
  `.venv`; `tests/test_codex_workspace_contract.py` verifica que el MCP sólo se
  solicita mediante opt-in.
- Gates ejecutados: `bash -n install.sh`, Ruff de pruebas, formato, Pyright y
  regresión completa: **1385 passed, 2 skipped**.
- Esta corrección no altera la instalación existente del VPS. Una instalación
  futura para Claude usa `./install.sh --platform claude`.

## Handoff

E42 recibe una instalación que expresa correctamente su alcance. E67 podrá
reutilizar la selección dirigida al empaquetar sus adaptadores, sin redefinir
la semántica de distribución.
